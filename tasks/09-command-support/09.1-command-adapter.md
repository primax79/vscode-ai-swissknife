# 09.1 — CanonicalCommand model and Claude/Kilo command adapters

> Part of [Command artifact support](plan.md) · spec: [../specs/phase-2-spec.md](../specs/phase-2-spec.md)

## Goal

Add the canonical `CanonicalCommand` model and implement command file reading, writing, parsing, serialization, and listing in `ClaudeAdapter` and `KiloAdapter`.

This task must produce one commit containing only its changes.

## Steps

1. Define `CanonicalCommand` in `src/adapters/types.ts`:
```ts
export interface CanonicalCommand {
  name: string;
  description: string;
  agent?: string;
  model?: string;
  subtask?: boolean;
  body: string;
  extraFields: Record<string, unknown>;
}
```

2. Implement Claude command codec in `src/adapters/claude.ts`:
   - `commandPath(name: string, loc: LocationRef): string` -> `.claude/commands/<name>.md` (project) or `~/.claude/commands/<name>.md` (global)
   - `parseClaudeCommandMarkdown(raw: string, defaultName?: string): CanonicalCommand`
   - `serializeClaudeCommandMarkdown(cmd: CanonicalCommand): string`
   - `readCommand`, `writeCommand`, `listCommands`.

3. Implement Kilo command codec in `src/adapters/kilo.ts`:
   - `commandPath(name: string, loc: LocationRef): string` -> `.kilo/command/<name>.md` (project) or `~/.config/kilo/command/<name>.md` (global)
   - Support both `.kilo/command/` and `.kilo/commands/` on read.
   - `parseKiloCommandMarkdown(raw: string, defaultName?: string): CanonicalCommand`
   - `serializeKiloCommandMarkdown(cmd: CanonicalCommand): string` — **Strict Schema**: emit strictly only `description`, `agent`, `model`, `subtask` in frontmatter (never emit `name:` or unrecognized keys in frontmatter).
   - `readCommand`, `writeCommand`, `listCommands`.

4. Add unit tests in `src/adapters/claude.test.ts` and `src/adapters/kilo.test.ts`.

## Verification

- Run full test suite, lint, typecheck, build.
- Test round-trip serialization and reading of command files in Claude and Kilo.
- Prove Kilo command frontmatter never contains invalid keys that trigger parser errors.
