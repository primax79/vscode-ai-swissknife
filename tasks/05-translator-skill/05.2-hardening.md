# 05.2 — Per-field diagnostics (hardening)

> Part of [Canonical model + translator](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · hardening context: [../../SPEC.md](../../SPEC.md) §2, §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) finding I9

**Goal**: `SPEC.md` §2 promises a conversion diagnostic **per field**;
`src/translator/skill.ts`/`rule.ts` (already merged, task 05.1) only
return one aggregate `diagnostic` for the whole artifact. Add per-field
diagnostics alongside the aggregate one, without breaking the existing
aggregate contract (initiative 06 can keep using the aggregate `overall`
value; a later UI task can surface the per-field detail).

**Depends on**: task 03.4 landing first if you want to diagnose the new
`files: ArtifactFile[]` field it adds to `CanonicalSkill` — if 03.4
hasn't landed yet, diagnose only `name`/`description`/`body`/
`extraFields` and note in your report that `files` still needs a
diagnostic entry once 03.4's field exists.

Steps:

1. In `src/adapters/types.ts`, add:

   ```ts
   export interface FieldDiagnostic {
     path: string; // e.g. "name", "extraFields.customTag", "files[2].mode"
     severity: ConversionDiagnostic;
     message?: string; // required when severity !== 'lossless'
   }
   ```

2. Change `TranslationResult<T>` (`src/translator/skill.ts` and
   `rule.ts`, wherever it's currently defined) to:

   ```ts
   export interface TranslationResult<T> {
     value: T;
     overall: ConversionDiagnostic; // renamed from `diagnostic` — update every caller
     diagnostics: FieldDiagnostic[]; // one entry per inspected field, always non-empty
     notes: string[]; // kept for backward-compat human-readable summary; may be derived from diagnostics
   }
   ```

   Update every call site (`translateSkill`/`translateRule` themselves,
   and anywhere that reads `.diagnostic` — grep for it) to the renamed
   `overall` field. `overall` is the worst (most severe) severity across
   `diagnostics`, computed, not independently set — define an explicit
   severity ordering (`lossless < adapted-with-warning <
   potentially-destructive < unsupported`) and take the max.
3. For each field the translator inspects (`name`, `description`,
   `body`, each key of `extraFields`), push one `FieldDiagnostic` with
   `severity: 'lossless'` for this Phase's identity-translation case
   (Claude↔Kilo `skill`/`rule` — still no real lossy case exists yet,
   per `05/plan.md`'s shared decision) — the point of this task is the
   *shape* being right and populated, not inventing lossy behavior that
   doesn't exist yet.
4. Update `src/translator/skill.test.ts`/`rule.test.ts` for the renamed
   field and the new `diagnostics` array: assert it's non-empty and every
   entry has `severity: 'lossless'` for the existing test cases, plus one
   new test asserting `overall` is computed correctly when you construct
   a `FieldDiagnostic[]` with a mixed severity by hand (test the
   worst-of computation directly, not only through the identity-only
   real translation path, since nothing in this Phase naturally produces
   a non-lossless result to test against).

**Verification**: `npm run typecheck && npm run lint && npm test` all
pass, including every pre-existing test updated for the rename. One
commit containing all changed files — nothing else. After this commit,
update `tasks/00-INDEX.md` to mark initiative 05 fully done (including
this hardening task).
