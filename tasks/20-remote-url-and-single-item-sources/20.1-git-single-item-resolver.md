# 20.1 — `git-single-item` resolver

> Part of [`remote-url` & `git-single-item` sources](plan.md) · spec: [../specs/phase-4-spec.md](../specs/phase-4-spec.md) §6

## Goal

Implement the `git-single-item` `SourceType` (already in the `SourceType`
union in `src/domain/types.ts`, no resolver yet): a Git repo that is itself
one artifact, with no marketplace manifest and no loose sibling-directories
structure — unlike `git-custom`, which scans for multiple sibling
`SKILL.md` dirs.

This task must produce one commit containing only its changes.

## Grounding

- Clone/checkout/mutex machinery to reuse as-is: `KeyedMutex`, the
  clone/checkout git-command sequence in `src/sources/gitCustom.ts` (already
  reused by `src/sources/gitMarketplace.ts` — follow that reuse pattern,
  don't reimplement git plumbing a third time).
- Detection helpers to reuse: `findSkillDirs`/`findAgentFiles`/
  `findCommandFiles`/`findMcpDefinitions` (`src/sources/detect.ts`) —
  applied to the single checked-out root instead of scanned recursively.
- Resolution output shape: `SourceResolution`, `DetectionDiagnostic`
  (`src/sources/types.ts`).

## Steps

1. In `src/sources/gitSingleItem.ts`, clone/checkout the repo (same
   branch/tag/commit pin fields already on `Source` — `branch`/`tag`/
   `commit` in `src/domain/types.ts`) using the shared mutex.
2. Detect the kind of the single artifact at the checked-out root: try
   `SKILL.md` at root first (kind `skill`), then agent/command frontmatter
   patterns, then an MCP config file — reusing `detect.ts`'s parsing logic
   on the root path directly instead of `find*` directory-scanning (those
   scan for *multiple* candidates; here there's exactly one, at a known
   location).
3. If detection is ambiguous (e.g. root has both an `SKILL.md` and a
   separate agent file) or finds nothing recognizable, return a
   `DetectionDiagnostic` explaining why, not a silent empty result.
4. Produce exactly one `Package` with exactly one `Artifact`, per the
   "single-skill repo is a degenerate `Package`" note already in
   `SPEC.md` §1.
5. Add unit tests using a disposable local repo fixture (per the existing
   "portable tests" convention in `CONTEXT.md` — no live network repo),
   covering: skill-at-root, agent-at-root, ambiguous-root diagnostic, and
   unrecognized-root diagnostic.

## Verification

- Run full test suite, lint, typecheck, build.
