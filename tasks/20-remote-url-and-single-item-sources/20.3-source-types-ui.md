# 20.3 — Sources-view wiring & verification

> Part of [`remote-url` & `git-single-item` sources](plan.md) · spec: [../specs/phase-4-spec.md](../specs/phase-4-spec.md) §6

## Goal

Wire both new resolvers into the existing "Add Source" flow and the
resolve/plan pipeline — no new UI concept, both slot into the flow
`git-custom`/`git-marketplace`/`local-folder` already use.

This task must produce one commit containing only its changes.

## Steps

1. Extend the "Add Source" command/quick-pick in `src/ui/sourcesView.ts` to
   offer `git-single-item` and `remote-url` alongside the existing three
   types, with the matching input prompts (repo URL + optional ref for
   `git-single-item`; a single URL for `remote-url`).
2. Wire both resolvers into wherever the resolve/catalog-refresh dispatch by
   `SourceType` already lives (check `src/engine/index.ts` or the resolve
   call sites in `src/ui/availableView.ts`) — extend the existing switch,
   don't add a parallel dispatch path.
3. Add integration tests: add a source of each new type through the same
   path the UI uses, confirm it resolves to a `Package`/`Artifact` and is
   installable through the unmodified install engine.

## Verification

- Run full test suite, lint, typecheck, build.
- Manually: add a `git-single-item` source pointing at a real single-skill
  repo and a `remote-url` source pointing at a raw file URL, refresh, and
  install from each into Claude Code.
