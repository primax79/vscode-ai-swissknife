# 34.2 — Uninstall + Update-to-latest in detail panel

**Depends on:** 31.1 (merged, for `doUpdateInstallation`/
`doUninstallItem`), 31.4 (merged, for the stable composite identity key).

## Why

The Installed detail panel's action list (`src/ui/dashboard.ts:1031-1042`)
only ever renders `Promote` (unmanaged) or `Copy to...`/`Move to...`/
`Edit` (managed) — `Uninstall` and `Update to latest` are real, working
sidebar actions with no Dashboard equivalent (`specs/phase-9-spec.md` §0).

## Scope

- New webview messages `uninstallItem` and `updateItem`, each carrying the
  composite identity key from Initiative 31.4 (`{assistant, scope, kind,
  name}`), **not** the full `ManagedInstallation` object — per
  `specs/phase-9-spec.md` §1.1's security note, the extension-host handler
  must re-resolve the current `ManagedInstallation` from a fresh inventory
  scan using `findInstallationByKey` (31.4) before calling
  `doUninstallItem`/`doUpdateInstallation`, never trust a client-supplied
  object (especially `path`) directly.
- Extend the detail panel's action list
  (`src/ui/dashboard.ts:1031-1042`, client-side `msg.membership ===
  'managed'` branch): add `Uninstall` and, when a drift report shows
  `update-available`/`modified-and-update-available` for the selected
  item, `Update to latest` — both trigger the corresponding message with
  the identity key, same confirmation-dialog UX as the sidebar (these are
  native `showInformationMessage` modal confirmations inside
  `doUninstallItem`/`doUpdateInstallation` themselves, unchanged from
  today — no new confirmation UI needed in the webview).
- After either action succeeds: refresh the Installed table/detail panel
  via the Initiative 32.3 incremental-update pattern (not a full page
  reload), and clear the detail panel's selection if the item was just
  uninstalled (it no longer exists to show detail for).

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green.
- Manual: select a managed item with `update-available` status, click
  `Update to latest` from the Dashboard — confirm identical outcome
  (drift status recalculated, same success message) to the sidebar's
  `Update` command on the same item.
- Manual: select a managed item, `Uninstall` from the Dashboard — confirm
  it's removed from disk and from `state.json` identically to the
  sidebar's `Uninstall` command, and the item disappears from the
  Installed table without a manual refresh.
- Manual, security-focused: confirm the uninstall/update handler actually
  re-resolves from a fresh scan rather than trusting the webview payload —
  e.g. by checking the implementation calls `findInstallationByKey`
  against freshly-read inventory, not by trying to exploit it (this is a
  code-review check, not a live attack simulation).
