# 33.3 — Preview action

**Depends on:** 33.2 (merged).

## Why

`previewArtifact` (`src/ui/availableView.ts:553`) lets the sidebar preview
an available artifact's main file (`SKILL.md` for a skill, the entry file
for other kinds) before installing — entirely unreachable from the
Dashboard today.

## Scope

- New webview message `previewArtifact` with payload identifying the
  artifact (`{sourceId, scope, packageId, artifactId}` or whatever
  identifying tuple `previewArtifact`'s current implementation actually
  needs once re-read — confirm exact fields at `:553-568` before wiring).
- Extension-host handler: look up the matching cached artifact from
  `getCachedSourceGroups()` (same lookup pattern as 33.2) and call
  `availableProvider.previewArtifact(...)` — this opens a read-only
  editor tab via VS Code's own preview mechanism
  (`src/ui/previewProvider.ts`), same as the sidebar; no new preview UI
  needed inside the webview itself, just the trigger.
- Dashboard UI: a "Preview" button/icon per artifact row from 33.2's
  catalog rendering.
- Explicitly out of scope (per `specs/phase-9-spec.md` §4.1): browsing
  auxiliary files inside a multi-file artifact beyond the entry file
  (`ArtifactFileItem`, `src/ui/artifactFileTree.ts`) — this task covers
  only what `previewArtifact` already does today, not a superset of it.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green.
- Manual: preview a skill, an agent, and an mcp-server artifact from the
  Dashboard's catalog view — each opens the same read-only content the
  sidebar's `Preview` command would show for the same artifact.
