# 27.1 — Shared pending-count function + status bar item

> Part of [New Dashboard entry points](plan.md) · spec: [../specs/phase-6-spec.md](../specs/phase-6-spec.md) §3, §4.6

## Goal

A persistent status bar item as a new, additional Dashboard entry point,
backed by a real reusable function rather than the existing local
variables (the recommendation notification's `unsatisfiedCount` is a local
variable inside a once-per-activation closure in `src/extension.ts`'s
`checkRecommendations`; the Dashboard's drift counts only exist inside
`DashboardPanel.update()` while the panel is open — neither is reusable
today). Independent of every other Phase 6 initiative — dispatch
immediately.

This task must produce one commit containing only its changes.

## Steps

1. Add one new exported function (e.g. in `src/extension.ts` or a small new
   `src/engine/pendingCounts.ts`) computing, on demand: the unsatisfied
   `desiredInstallations` count (same local-only, no-network logic already
   in `checkRecommendations` — reuse it, don't reimplement) plus an
   "updates available" count (reading `state.json`'s installations without
   running a full drift check, comparing against a cheap local signal if
   one is available, or accept a slightly more expensive but still
   non-blocking on-demand drift check — pick whichever the existing
   `checkDrift`/`analyzeLocalDrift` machinery makes cheapest without
   duplicating logic).
2. Refactor `checkRecommendations` to call this new function instead of
   computing `unsatisfiedCount` inline — no behavior change to the existing
   notification path.
3. Create a `vscode.StatusBarItem` during `activate()` (`src/extension.ts`),
   `alignment: vscode.StatusBarItem.Alignment.Left` or `Right` (pick
   whichever reads better next to other typical status bar content),
   `command: 'aiSwissknife.openDashboard'` (already exists,
   `src/extension.ts:373`). Push it to `context.subscriptions` for proper
   disposal.
4. Label reflects the new function's counts when nonzero (e.g. "$(dashboard)
   AI Swissknife: 2 updates"), falls back to a plain "$(dashboard) AI
   Swissknife" when there's nothing to flag. Recompute on activation and
   whenever the recommendation-notification path already recomputes counts
   (reuse its trigger points, don't add new file-watcher wiring for this).
5. Do not replace or remove the existing `$(dashboard)` view-title icon
   (`package.json`'s `view/title` entries) — this is additive.

## Verification

- Manual verification: with unsatisfied recommendations present, confirm
  the status bar item shows the right count and clicking it opens the
  Dashboard; with nothing to flag, confirm it still shows and still opens
  the Dashboard.
- Confirm the existing recommendation-notification behavior (initiative 22)
  is unchanged after the `checkRecommendations` refactor — same count, same
  actions.
- Run full test suite, lint, typecheck, build.
