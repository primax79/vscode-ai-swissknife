# 35.5 — Icon-only buttons across the Dashboard

**Depends on:** 35.1, 35.2, 35.3, 35.4 (all merged — this task sweeps the
final button set across every section, dispatch it last so it isn't
immediately invalidated by the other four).

## Why

User: "usiamo icone anzichè scritte nei pulsanti di tutta la dashboard, a
meno che non siano indispensabili le scritte" (use icons instead of text
labels on buttons throughout the dashboard, unless text is
indispensable).

## Design constraint (keep existing style, no new asset pipeline)

The Dashboard's webview does **not** currently load the VS Code Codicon
font — there is no `codicon` CSS class or font asset wired into
`dashboard.ts`'s `<style>`/`<head>` (confirmed by grep — zero
occurrences of `codicon` in the file, unlike the sidebar's tree items
which use real `vscode.ThemeIcon` codicons via `getKindIconName`,
`src/ui/kindIcons.ts`, a completely different rendering path that
doesn't apply to webview HTML). The Dashboard already uses plain Unicode
glyphs as lightweight icons in a few places (`▶` folder caret, `📁`
folder, `⚠️`/`🔴` diagnostics, `★` recommended, `✓` cross-framework
match, `◌`/`●` status markers) — **continue that exact convention**, do
not introduce a codicon font/asset pipeline for this task; that would be
new infrastructure, not "keep existing style."

## Scope

- Audit every `<button>` across all five sections (Overview, Installed,
  Sources & Catalog, Recommendations, plus the header's `+ New Artifact`
  and the detail panel's action buttons) and replace text-only labels
  with a single Unicode glyph, choosing symbols that are visually
  distinct from the ones already in use for unrelated meanings (e.g.
  don't reuse `★`, already meaning "recommended"). Suggested mapping
  (adjust for visual clarity, this is guidance not a mandate — judge by
  how it actually looks, not just by matching this list):
  Add `＋`, Install `⬇`, Preview `👁`, Export `⇧` or `↥`, Remove/Uninstall
  `🗑`, Edit `✎`, Copy `⧉`, Move `⇥` or `➜`, Diff `⇄` or `≷`, Update `⟳`,
  Refresh `↻`, Promote `⇧`.
- **Every icon-only button must keep (or gain) a `title="..."` tooltip
  attribute** with the full action name — this is the accessibility
  replacement for the removed visible text, not optional.
- **Text stays where the label alone would be genuinely ambiguous or
  where the action needs a value/context that only text conveys** — the
  task's own instruction says "unless text is indispensable"; use
  judgment (e.g. a scope-picker inline label like "Global"/"Project"
  next to `+` is probably still text; a lone `Install` button next to an
  unambiguous item is not). Do not blindly strip every `>text<` in the
  file — the toolbar section headings ("Global Sources", "Actionable
  Recommendations", etc.) and filter dropdown option labels are not
  buttons and are out of scope.
- Keep button sizing/padding consistent with the existing `.btn`/
  `.btn-sm`/`.btn-primary`/`.btn-secondary` CSS classes already defined —
  an icon-only button should still hit the same visual weight as today's
  text buttons (may need a small CSS tweak for icon-only padding/
  min-width so buttons don't look cramped, add it to the existing
  `<style>` block, don't inline excessive one-off styles).

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green with zero warnings.
- Manual: click through every section, confirm every action button still
  does exactly what it did before (this is a pure label/rendering
  change), every icon-only button shows its full name on hover, and
  nothing reads as ambiguous at a glance (if you genuinely can't tell
  what a lone icon does without hovering, that's a sign it needed text —
  flag it rather than forcing an icon).
