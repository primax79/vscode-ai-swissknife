# 25.5 — "Move to..." command

> Part of [Move action + Promote disambiguation fix](plan.md) · spec: [../specs/phase-6-spec.md](../specs/phase-6-spec.md) §3, §4.3

## Goal

Wire the new `Move to...` command alongside the existing `syncItem` ("Copy
to Another Assistant/Scope..."), reusing `planSync`'s existing
local-content-based resolution (not re-resolving from the source) for the
target install, and 25.4's primitives for removing the origin. Scoped to
`skill`/`agent`/`command`/`mcp-server` and to `ManagedInstallation` only
(never offered for `ObservedArtifact` — an unmanaged item's path is
`Promote` first, then `Move` if still wanted). Depends on 25.4.

This task must produce one commit containing only its changes.

## Steps

1. Add a new command `aiSwissknife.moveItem` in `src/ui/installedView.ts`,
   modeled on `syncItem` (`src/ui/installedView.ts:406-478`) but only
   accepting `InstalledInstallationItem` (not `ObservedArtifactItem`) and
   only for `inst.kind` in `skill`/`agent`/`command`/`mcp-server` — show a
   clear message and refuse for `hook`/`rule` ("Move isn't supported for
   this kind yet").
2. Same target-picking UX as `syncItem` (assistant `QuickPick`, scope
   `QuickPick`, project-root resolution when scope is `project`).
3. Plan and apply the install into the target via `planSync`/`applyInstall`
   exactly as `syncItem` already does — do not add source re-resolution.
4. **Only after** the install's `outcome.status === 'applied'`, remove the
   origin: for `skill`/`agent`/`command`, call 25.4's `softDeletePath` on
   `inst.path`; for `mcp-server`, call 25.4's `removeMcpServer(inst.name,
   {scope: inst.scope, projectRoot: inst.projectPath})` on the origin
   assistant's adapter. Then remove the origin's record from `state.json`
   (`readState`/`writeState` from `src/domain/registry.ts`, filtering out
   this installation).
5. If the origin-removal step throws after a successful install, report
   `manual-recovery-required` (the existing `ApplyOutcome` variant pattern,
   `src/ui/availableView.ts:579-584`) naming the origin path that needs
   manual attention — the target installation must not be rolled back at
   this point (it already succeeded and is now the source of truth).
6. If the install itself fails or is refused, do not touch the origin at
   all — same refusal messaging `syncItem` already uses.
7. Add the command to `package.json` (`contributes.commands` +
   `view/item/context`, `when: view == aiSwissknife.installed && viewItem
   =~ /^installedInstallation/`, alongside the existing `syncItem` entry)
   with an appropriate icon (e.g. `$(arrow-right)` or similar, distinct
   from `syncItem`'s `$(sync)`).

## Verification

- Manual verification: move a managed skill from global/Claude to
  project/Kilo — confirm it appears correctly at the target and the
  original directory has moved to `.ai-swissknife/_deleted/...` (not
  deleted outright), and `state.json` no longer lists the origin
  installation.
- Manual verification: attempt Move on a `hook`/`rule` item — confirm it's
  refused with a clear message, nothing is touched.
- Add a test simulating an origin-removal failure after a successful
  install, confirming `manual-recovery-required` is reported and the
  target installation is left intact (not rolled back).
- Run full test suite, lint, typecheck, build.
