# 25.3 — promoteAllIdentical: skip multi-candidate items

> Part of [Move action + Promote disambiguation fix](plan.md) · spec: [../specs/phase-6-spec.md](../specs/phase-6-spec.md) §4.4

## Goal

The Dashboard's bulk-promote path (`src/ui/dashboard.ts:33-45`) currently
promotes every observed item whose `match.status === 'identical'`. With
`candidates` (25.1) replacing the single `match`, an item can have more
than one `identical` candidate — bulk-promoting it would need to silently
pick one, which is exactly the ambiguity 25.2's disambiguation flow exists
to resolve. Depends on 25.1 and 25.2 having landed.

This task must produce one commit containing only its changes.

## Steps

1. In `src/ui/dashboard.ts`'s `promoteAllIdentical` message handler, change
   the selection logic from `item.match?.status === 'identical'` to: act
   only on items with exactly 1 candidate (whether `identical` or
   `different` — matching 25.2's single-candidate direct-promote rule).
   Items with >1 candidates are left unpromoted by this bulk action.
2. Report the outcome distinguishing the two cases — e.g. "Promoted N
   item(s). M item(s) skipped (multiple possible sources — use Promote on
   each individually)." — not a silent partial success.
3. Update the client-side button label/behavior in the Dashboard's HTML
   (`src/ui/dashboard.ts`'s `getHtml`) if it currently implies "promote all
   identical" — reword if needed to reflect "promote all unambiguous"
   given the new skip case.

## Verification

- Add/update a test simulating a mixed batch: one item with 1 identical
  candidate (promoted), one with 2 identical candidates (skipped, reported),
  one with 1 different candidate (promoted per 25.2's rule), confirming the
  counts and skip list are correct.
- Run full test suite, lint, typecheck, build.
