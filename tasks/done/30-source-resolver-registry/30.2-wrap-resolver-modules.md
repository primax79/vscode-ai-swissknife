# 30.2 — Incapsulare i cinque moduli risolutori

> Parte di [Registro dei risolutori di sorgenti](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.3, §4.4

## Goal

Un oggetto conforme a `SourceResolver` per ciascun tipo di sorgente, ognuno dei quali incapsula
le esportazioni `resolveXxx`/`resolveArtifactContent` già esistenti di quel modulo.
Puramente aggiuntivo — ogni funzione libera esportata esistente rimane esattamente così com'è
e continua a funzionare per qualsiasi chiamante non ancora migrato.

Questo task deve produrre un singolo commit contenente esclusivamente le proprie modifiche.

## Steps

Per ciascuno dei cinque moduli, aggiungere una nuova costante esportata in fondo
al file (dopo le esportazioni esistenti):

1. `src/sources/localFolder.ts`:

   ```ts
   export const localFolderResolver: SourceResolver = {
     type: 'local-folder',
     displayName: 'Local folder',
     iconThemeId: 'folder',
     resolve: resolveLocalFolder,
     resolveArtifactContent,
   };
   ```

2. `src/sources/gitCustom.ts` → `gitCustomResolver` (`type: 'git-custom'`,
   `displayName: 'Git (custom)'`, `iconThemeId: 'repo'`, `resolve:
   resolveGitCustom`, `resolveArtifactContent`).
3. `src/sources/gitMarketplace.ts` → `gitMarketplaceResolver`
   (`'git-marketplace'`, `'Git marketplace'`, `'extensions'`,
   `resolveGitMarketplace`).
4. `src/sources/gitSingleItem.ts` → `gitSingleItemResolver`
   (`'git-single-item'`, `'Git (single item)'`, `'git-commit'`,
   `resolveGitSingleItem`).
5. `src/sources/remoteUrl.ts` → `remoteUrlResolver` (`'remote-url'`,
   `'Remote URL'`, `'link'`, `resolveRemoteUrl`).

Importare `SourceResolver` da `./types` in ciascun file. Poiché le funzioni
`resolve`/`resolveArtifactContent` di ciascun modulo hanno già firme
compatibili con l'interfaccia (confermato in 30.1/specifica §4.3), assegnarle
direttamente come proprietà dell'oggetto dovrebbe superare il controllo dei tipi senza una
arrow function di wrapper — se TypeScript segnala un'incompatibilità per uno specifico modulo (ad es. un
tipo inferito più restrittivo su un parametro `opts`), incapsulare solo quella singola
funzione in una arrow function (`resolve: (source, opts) => resolveGitCustom(source,
opts)`) invece di modificare l'interfaccia per adattarla.

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build.
- Aggiungere un'asserzione per modulo che verifichi che `xResolver.type` corrisponda al
  letterale `SourceType` reale del modulo e che `xResolver.resolve === resolveXxx`
  (identità — conferma che si tratta della funzione reale e non di una
  reimplementazione accidentale). `localFolder.test.ts`, `gitCustom.test.ts` e
  `gitMarketplace.test.ts` esistono già come file dedicati — aggiungere lì
  l'asserzione. `gitSingleItem` e `remoteUrl` non hanno un file di test dedicato;
  entrambi sono esercitati invece dal file condiviso `src/sources/sources.test.ts`
  (confermato: importa direttamente `resolveGitSingleItem`/`resolveRemoteUrl`)
  — aggiungere lì le loro due asserzioni invece di creare nuovi
  file, rispettando la struttura esistente.
- `grep -rn "Resolver: SourceResolver" src/sources/*.ts` deve mostrare
  esattamente cinque corrispondenze, una per modulo.
