# 30.1 — Interfaccia `SourceResolver`

> Parte di [Registro dei risolutori di sorgenti](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.3

## Goal

Definire la forma condivisa a cui si conformerà ogni risolutore di tipo sorgente —
l'equivalente per `Source.type` dell'interfaccia `Adapter`. Confermato dall'analisi del codice
(specifica §4.3): le esportazioni `resolveXxx`/`resolveArtifactContent` di tutti e cinque i moduli risolutori
condividono già firme compatibili, quindi si tratta di un'estrazione diretta
e non di una riconciliazione.

Questo task deve produrre un singolo commit contenente esclusivamente le proprie modifiche. Aggiunge
soltanto l'interfaccia — nessun modulo risolutore viene ancora toccato (quello è 30.2).

## Steps

1. In `src/sources/types.ts`, aggiungere:
   ```ts
   export interface SourceResolver {
     readonly type: SourceType;
     readonly displayName: string;
     readonly iconThemeId: string;
     resolve(source: Source, opts?: { cacheDir?: string }): Promise<SourceResolution>;
     resolveArtifactContent(
       source: Source,
       pkg: Package,
       artifact: Artifact,
       opts?: { cacheDir?: string }
     ): Promise<ResolvedArtifact<CanonicalSkill | CanonicalAgent | CanonicalCommand | CanonicalMcpServer | CanonicalHook | CanonicalRule>>;
   }
   ```
   Aggiungere gli import necessari (`Package`, `Artifact`, `SourceType`,
   `ResolvedArtifact`, i sei tipi `Canonical*`) — controllare prima cosa
   importa già `src/sources/types.ts`; diversi di questi potrebbero
   essere già nello scope.
2. Assegnare i cinque valori `displayName`/`iconThemeId` (vincolati
   riutilizzando le scelte esistenti di `sourcesView.ts`, specifica §4.3):

   | `type`             | `displayName`        | `iconThemeId`   |
   | ------------------ | --------------------- | ---------------- |
   | `local-folder`      | `Local folder`        | `folder`         |
   | `git-custom`        | `Git (custom)`        | `repo`           |
   | `git-marketplace`   | `Git marketplace`     | `extensions`     |
   | `git-single-item`   | `Git (single item)`   | `git-commit`     |
   | `remote-url`        | `Remote URL`          | `link`           |

   Questi sono semplici dati che 30.2 userà nella costruzione di ciascun oggetto
   wrapper — in questo task non va aggiunto alcun codice oltre all'interfaccia stessa.
3. Non modificare nessuno dei cinque file dei moduli risolutori (`localFolder.ts`,
   `gitCustom.ts`, `gitMarketplace.ts`, `gitSingleItem.ts`, `remoteUrl.ts`)
   né `sourcesView.ts` in questo task.

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build — l'aggiunta di un'interfaccia finora
  inutilizzata non deve modificare alcun comportamento esistente; un'esecuzione verde qui è un
  puro controllo di coerenza sul fatto che il nuovo tipo compili correttamente rispetto ai tipi reali
  `Package`/`Artifact`/`ResolvedArtifact`/`Canonical*`.
- `grep -rn "SourceResolver" src --include="*.ts"` deve mostrare solo la
  dichiarazione di questa nuova interfaccia (e il relativo elenco di import) — nessun utilizzatore per ora.
