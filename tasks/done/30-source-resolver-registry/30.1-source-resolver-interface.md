# 30.1 — `SourceResolver` interface

> Part of [Source-resolver registry](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.3

## Goal

Define the shared shape every source-type resolver will conform to — the
`Source.type` equivalent of the `Adapter` interface. Confirmed by grounding
(spec §4.3): all five resolver modules' `resolveXxx`/`resolveArtifactContent`
exports already share compatible signatures, so this is a straight
extraction, not a reconciliation.

This task must produce one commit containing only its changes. It only
adds the interface — no resolver module is touched yet (that's 30.2).

## Steps

1. In `src/sources/types.ts`, add:
   ```ts
   export interface SourceResolver {
     readonly type: SourceType;
     readonly displayName: string;
     readonly iconThemeId: string;
     resolve(source: Source, opts?: { cacheDir?: string }): Promise<SourceResolution>;
     resolveArtifactContent(
       source: Source,
       pkg: Package,
       artifact: Artifact,
       opts?: { cacheDir?: string }
     ): Promise<ResolvedArtifact<CanonicalSkill | CanonicalAgent | CanonicalCommand | CanonicalMcpServer | CanonicalHook | CanonicalRule>>;
   }
   ```
   Add whatever imports this needs (`Package`, `Artifact`, `SourceType`,
   `ResolvedArtifact`, the six `Canonical*` types) — check what
   `src/sources/types.ts` already imports first; several of these may
   already be in scope.
2. Assign the five `displayName`/`iconThemeId` values (locked in by
   reusing `sourcesView.ts`'s existing choices, spec §4.3):

   | `type`             | `displayName`        | `iconThemeId`   |
   | ------------------ | --------------------- | ---------------- |
   | `local-folder`      | `Local folder`        | `folder`         |
   | `git-custom`        | `Git (custom)`        | `repo`           |
   | `git-marketplace`   | `Git marketplace`     | `extensions`     |
   | `git-single-item`   | `Git (single item)`   | `git-commit`     |
   | `remote-url`        | `Remote URL`          | `link`           |

   These are plain data for 30.2 to use when constructing each wrapper
   object — no code beyond the interface itself goes in this task.
3. Do not modify any of the five resolver module files (`localFolder.ts`,
   `gitCustom.ts`, `gitMarketplace.ts`, `gitSingleItem.ts`, `remoteUrl.ts`)
   or `sourcesView.ts` in this task.

## Verification

- Run full test suite, typecheck, lint, build — adding an unused-so-far
  interface must not change any existing behavior; a green run here is a
  pure sanity check that the new type itself compiles against the real
  `Package`/`Artifact`/`ResolvedArtifact`/`Canonical*` types.
- `grep -rn "SourceResolver" src --include="*.ts"` should show only this
  new interface's own declaration (and its import list) — no consumer yet.
