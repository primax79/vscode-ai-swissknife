# 30.3 — `src/sources/registry.ts` + migrazione dei punti di dispatch

> Parte di [Registro dei risolutori di sorgenti](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.4, §0, §5

## Goal

Aggregare i cinque oggetti wrapper di 30.2 in un unico registro, quindi
sostituire le catene di dispatch `if`/`else-if` su `source.type` con una ricerca
nel registro stesso — l'effettiva rimozione delle duplicazioni, rispecchiando quanto fatto da 29.3 per
gli adapter.

Questo task deve produrre un singolo commit contenente esclusivamente le proprie modifiche.

## Steps

1. Creare `src/sources/registry.ts`:

   ```ts
   import { localFolderResolver } from './localFolder';
   import { gitCustomResolver } from './gitCustom';
   import { gitMarketplaceResolver } from './gitMarketplace';
   import { gitSingleItemResolver } from './gitSingleItem';
   import { remoteUrlResolver } from './remoteUrl';
   import type { SourceResolver } from './types';
   import type { SourceType } from '../domain/types';

   export const ALL_SOURCE_RESOLVERS: readonly SourceResolver[] = [
     localFolderResolver, gitCustomResolver, gitMarketplaceResolver,
     gitSingleItemResolver, remoteUrlResolver,
   ];

   export function getSourceResolver(type: SourceType): SourceResolver {
     const found = ALL_SOURCE_RESOLVERS.find((r) => r.type === type);
     if (!found) throw new Error(`Unsupported source type: ${type}`);
     return found;
   }
   ```

2. Rieseguire prima di migrare (i numeri di riga nella specifica risalgono al 2026-09-08
   e potrebbero essere cambiati):

   ```sh
   grep -n "resolveLocalFolder\|resolveGitCustom\|resolveGitMarketplace\|resolveGitSingleItem\|resolveRemoteUrl" src/engine/discovery.ts src/ui/availableView.ts
   grep -rln "resolveLocalFolder\|resolveGitCustom\|resolveGitMarketplace\|resolveGitSingleItem\|resolveRemoteUrl" src --include="*.ts" | grep -v "\.test\.ts" | grep -v "src/sources/"
   ```

   L'output del secondo comando costituisce l'elenco autorevole di tutti i
   punti di chiamata di produzione da migrare — confermare che includa (almeno)
   `src/engine/discovery.ts` e `src/ui/availableView.ts`, e migrare
   anche ogni altro file riportato.
3. In ciascuno di tali punti di chiamata, sostituire la catena `if (source.type === 'x') {
   resolution = await resolveX(source); } else if (...) { ... }` con:
   ```ts
   const resolver = getSourceResolver(source.type);
   const resolution = await resolver.resolve(source);
   ```
   (adattare i nomi delle variabili e la gestione degli errori al blocco
   `try`/`catch` circostante esistente in ciascun punto di chiamata — non modificare il comportamento
   esistente di gestione degli errori, ma solo il modo in cui viene ottenuta la funzione risolutrice).
4. Rimuovere gli import per singolo file ormai inutilizzati delle cinque funzioni `resolveXxx`
   in ogni file migrato (mantenerli in `src/sources/*.ts`
   stessi e ovunque vengano ancora chiamate direttamente per motivi
   non correlati al dispatch per tipo — verificare prima di eliminare ciascun import).
5. Non toccare i punti di chiamata di `resolveArtifactContent` in questo task a meno che
   non si trovino proprio accanto a una catena di dispatch `resolve` che si sta già
   migrando nello stesso file — se per quelli fosse opportuno un task dedicato separato,
   segnalarlo, ma provare prima a unificare entrambi in un unico passaggio per file
   poiché di solito sono adiacenti.

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build.
- `grep -rn "if (source.type === 'local-folder')" src --include="*.ts"`
  (e l'equivalente per gli altri quattro tipi) deve restituire zero corrispondenze
  al di fuori di `src/sources/*.ts` stesso (dove ciascun modulo controlla ancora legittimamente
  il proprio tipo come guardia, ad es. in `gitCustom.ts` la funzione `resolveArtifactContent`
  che solleva un'eccezione se `source.type !== 'git-custom'`).
- Manualmente nell'Extension Development Host: aggiornare il catalogo (vista
  Sources) con almeno una sorgente `git-custom` e una `local-folder`
  registrate, confermando che entrambe vengano ancora risolte ed elenchino i rispettivi artefatti
  correttamente — questo esercita il dispatch di `discovery.ts` su un vero clone/lettura
  locale, non solo un controllo dei tipi.
