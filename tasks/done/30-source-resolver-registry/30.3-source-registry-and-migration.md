# 30.3 — `src/sources/registry.ts` + migrate dispatch sites

> Part of [Source-resolver registry](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.4, §0, §5

## Goal

Aggregate the five wrapper objects from 30.2 into one registry, then
replace the `if`/`else-if` `source.type` dispatch chains with a lookup
against it — the actual duplication removal, mirroring what 29.3 did for
adapters.

This task must produce one commit containing only its changes.

## Steps

1. Create `src/sources/registry.ts`:

   ```ts
   import { localFolderResolver } from './localFolder';
   import { gitCustomResolver } from './gitCustom';
   import { gitMarketplaceResolver } from './gitMarketplace';
   import { gitSingleItemResolver } from './gitSingleItem';
   import { remoteUrlResolver } from './remoteUrl';
   import type { SourceResolver } from './types';
   import type { SourceType } from '../domain/types';

   export const ALL_SOURCE_RESOLVERS: readonly SourceResolver[] = [
     localFolderResolver, gitCustomResolver, gitMarketplaceResolver,
     gitSingleItemResolver, remoteUrlResolver,
   ];

   export function getSourceResolver(type: SourceType): SourceResolver {
     const found = ALL_SOURCE_RESOLVERS.find((r) => r.type === type);
     if (!found) throw new Error(`Unsupported source type: ${type}`);
     return found;
   }
   ```

2. Re-run before migrating (line numbers in the spec are from 2026-09-08
   and may have shifted):

   ```sh
   grep -n "resolveLocalFolder\|resolveGitCustom\|resolveGitMarketplace\|resolveGitSingleItem\|resolveRemoteUrl" src/engine/discovery.ts src/ui/availableView.ts
   grep -rln "resolveLocalFolder\|resolveGitCustom\|resolveGitMarketplace\|resolveGitSingleItem\|resolveRemoteUrl" src --include="*.ts" | grep -v "\.test\.ts" | grep -v "src/sources/"
   ```

   The second command's output is the authoritative list of every
   production call site to migrate — confirm it matches (at minimum)
   `src/engine/discovery.ts` and `src/ui/availableView.ts`, and migrate
   every other file it reports too.
3. In each such call site, replace the `if (source.type === 'x') {
   resolution = await resolveX(source); } else if (...) { ... }` chain with:
   ```ts
   const resolver = getSourceResolver(source.type);
   const resolution = await resolver.resolve(source);
   ```
   (adjust variable naming/error-handling to match each call site's
   existing surrounding `try`/`catch` — do not change the existing
   error-handling behavior, only how the resolver function is obtained).
4. Remove the now-unused per-file imports of the five `resolveXxx`
   functions in every migrated file (keep them in `src/sources/*.ts`
   themselves and anywhere still calling them directly for a reason
   unrelated to type-dispatch — check before deleting each import).
5. Do not touch `resolveArtifactContent` call sites in this task unless
   they sit right next to a `resolve`-dispatch chain you're already
   migrating in the same file — if a separate dedicated task is warranted
   for those, note it, but attempt to fold both into one pass per file
   first since they're usually adjacent.

## Verification

- Run full test suite, typecheck, lint, build.
- `grep -rn "if (source.type === 'local-folder')" src --include="*.ts"`
  (and the equivalent for the other four types) must return zero matches
  outside `src/sources/*.ts` itself (where each module still legitimately
  self-checks its own type as a guard, e.g. `gitCustom.ts`'s
  `resolveArtifactContent` throwing if `source.type !== 'git-custom'`).
- Manually in the Extension Development Host: refresh the catalog (Sources
  view) with at least a `git-custom` and a `local-folder` source
  registered, confirm both still resolve and list their artifacts
  correctly — this exercises `discovery.ts`'s dispatch on a real clone/
  local read, not just a type-check.
