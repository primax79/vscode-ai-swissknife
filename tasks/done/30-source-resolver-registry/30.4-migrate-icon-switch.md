# 30.4 — Migrare lo switch delle icone di `sourcesView.ts`

> Parte di [Registro dei risolutori di sorgenti](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.3, §5

## Goal

L'ultimo blocco autonomo di diramazione basato su `Source.type`: sostituire
in `sourcesView.ts` lo switch `getSourceTypeIcon` con una ricerca nel
registro costruito da 30.3.

Questo task deve produrre un singolo commit contenente esclusivamente le proprie modifiche.

## Steps

1. In `src/ui/sourcesView.ts`, individuare `getSourceTypeIcon(type: Source['type'])`
   (attualmente uno `switch` che restituisce `new vscode.ThemeIcon('folder' |
   'repo' | 'extensions' | 'git-commit' | 'link')`, con un ramo `default`
   che restituisce `new vscode.ThemeIcon('source-control')`).
2. Sostituirne il corpo con:
   ```ts
   function getSourceTypeIcon(type: Source['type']): vscode.ThemeIcon {
     return new vscode.ThemeIcon(getSourceResolver(type).iconThemeId);
   }
   ```
   importando `getSourceResolver` da `../sources/registry`.
3. Il caso `default` originale restituiva `'source-control'` per un
   tipo non riconosciuto — `getSourceResolver` invece **solleva un'eccezione** per un
   tipo sconosciuto (secondo l'implementazione di 30.3). Poiché `Source['type']` è un'unione
   chiusa dei cinque valori noti, in pratica ciò non costituisce una regressione
   comportamentale, ma prima di rimuovere il fallback occorre confermare che nessun chiamante di `getSourceTypeIcon`
   possa realisticamente ricevere un valore esterno a tale unione (ad es. dalla
   deserializzazione di un `manifest.json` vecchio o malformato) — in caso affermativo, mantenere un blocco `try { ... } catch { return new
   vscode.ThemeIcon('source-control'); }` attorno alla ricerca invece di
   lasciarla andare in eccezione, e indicarlo nel messaggio di commit.

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build.
- `grep -n "getSourceTypeIcon" src/ui/sourcesView.ts` — confermare che il
  corpo della funzione sia ora una delega di una sola riga, e che
  `grep -n "'folder'\|'repo'\|'extensions'\|'git-commit'\|'link'" src/ui/sourcesView.ts`
  non restituisca alcuna corrispondenza (gli id letterali delle icone non risiedono più qui, ma solo in
  `iconThemeId` di ciascun modulo risolutore).
- Manualmente nell'Extension Development Host: confermare che ogni sorgente
  registrata nella vista Sources mostri ancora la stessa icona per tipo rispetto a prima
  di questa modifica (confrontare visivamente con uno screenshot/ricordo dell'albero
  pre-modifica, oppure riaggiungerne una per ciascun tipo e confrontarla con la tabella
  nella specifica §4.3/task 30.1).
