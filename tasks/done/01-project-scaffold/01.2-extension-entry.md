# 01.2 — Entry point e attivazione dell'estensione

> Parte di [Scaffold del progetto](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: un `src/extension.ts` minimale che si attivi in modo pulito
nell'Extension Development Host, con la struttura di cartelle che le iniziative
successive andranno a popolare.

**Riferimenti nel codice**: `references/agent-hub/src/extension.ts` per la
struttura generale di un entry point di estensione VSCode (`activate(context)`/
`deactivate()`), ma la versione di agent-hub collega i propri DB/servizi/webview
— nulla di tutto ciò esiste ancora qui, quindi la versione di questo task è
molto più ridotta.

Passaggi:

1. Creare la struttura di cartelle (segnaposto vuoti in stile `.gitkeep` vanno
   bene dove un'iniziativa successiva popolerà una cartella — non creare file
   speculativi oltre a quanto elencato):
   - `src/extension.ts` — l'entry point (sotto).
   - `src/domain/` — vuota, la popolerà l'iniziativa 02.
   - `src/adapters/` — vuota, la popolerà l'iniziativa 03.
   - `src/sources/` — vuota, la popolerà l'iniziativa 04.
2. Scrivere `src/extension.ts`:
   ```ts
   import * as vscode from 'vscode';

   export function activate(context: vscode.ExtensionContext) {
     console.log('AI Swissknife is now active.');
   }

   export function deactivate() {}
   ```
   Nient'altro — nessun comando, nessuna vista. Le iniziative successive
   estenderanno questo file; non pre-registrare comandi o viste segnaposto che
   l'iniziativa 07 dovrebbe poi rimuovere o rinominare.
3. Build: `npm run build`. Confermare che `dist/extension.js` venga generato
   senza errori esbuild.
4. Avviare l'Extension Development Host (`F5` in VSCode, oppure
   `code --extensionDevelopmentPath=<repo>` se eseguito da script) e confermare,
   tramite la Debug Console o la console degli strumenti di sviluppo della nuova
   finestra, che venga registrato `AI Swissknife is now active.` — ovvero che
   l'estensione si attivi effettivamente, non solo che compili.

**Verifica**: `npm run build` ha successo; `dist/extension.js` esiste; la riga
di log di attivazione compare in un'esecuzione reale dell'Extension Development
Host (non limitarsi a "il codice sembra che lo registrerebbe" — avviarlo
effettivamente). Un unico commit contenente `src/extension.ts` e i segnaposto
delle cartelle vuote — nient'altro.
