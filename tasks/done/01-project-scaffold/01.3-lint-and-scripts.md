# 01.3 — Configurazione lint/format + controllo degli script npm

> Parte di [Scaffold del progetto](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: script `eslint`/`typecheck`/`build` funzionanti, così che la
sezione di verifica di ogni task successivo possa fare affidamento su `npm run lint && npm run
typecheck && npm run build` come gate standard.

**Riferimenti nel codice**: `references/agent-hub/.eslintrc.json` — stessa
struttura, meno il riferimento di progetto `tsconfig.webview.json` (in questa
tranche non esiste alcun tsconfig per webview).

Passaggi:

1. Aggiungere `@typescript-eslint/eslint-plugin`, `@typescript-eslint/parser`,
   `eslint` a `package.json` sotto `devDependencies` (il task 01.1 non li
   includeva — aggiungerli ora) ed eseguire nuovamente `npm install`.
2. Creare `.eslintrc.json` nella radice del repository, modellato su
   `references/agent-hub/.eslintrc.json`:
   `"parserOptions.project": ["./tsconfig.json"]` (progetto singolo, nessun
   progetto webview), stessi `extends`/`rules`/`ignorePatterns` per il resto.
3. Eseguire l'intero gate e confermare che ogni comando termini con codice 0
   senza errori (non solo "nessun crash" — ispezionare effettivamente l'output):
   ```bash
   npm run lint
   npm run typecheck
   npm run build
   ```
4. Se `npm run lint` segnala una qualsiasi violazione reale sul codice del task
   01.2 (`src/extension.ts`), correggerla direttamente — non aggiungere
   un'eccezione alle regole per silenziare un problema reale.

**Verifica**: tutti e tre i comandi (`lint`, `typecheck`, `build`) terminano con
codice 0 sullo stato corrente del repository (l'output dei task 01.1 + 01.2).
Questo corrisponde a un unico commit contenente `.eslintrc.json` e le aggiunte
alle dipendenze in `package.json`/`package-lock.json` — nient'altro. Questo task
completa l'iniziativa 01; dopo questo commit, in `00-INDEX.md` la riga per `01`
deve essere aggiornata a `✅ done`.
