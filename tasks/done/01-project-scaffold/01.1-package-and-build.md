# 01.1 — package.json + strumenti di build

> Parte di [Scaffold del progetto](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: creare `package.json`, `tsconfig.json` e uno script di build
basato su esbuild in modo che l'estensione possa compilare, senza ancora file
sorgente oltre a quelli aggiunti dal task 01.2.

**Riferimenti nel codice** (leggere prima questi file: costituiscono il precedente
reale da seguire nella directory `references/` di questo stesso repository — non
inventare una struttura diversa):

- `references/agent-hub/package.json`
- `references/agent-hub/tsconfig.json`
- `references/agent-hub/esbuild.config.js`

Passaggi:

1. Creare `package.json` nella radice del repository, modellato su
   `references/agent-hub/package.json` ma adattato:
   - `"name": "ai-swissknife"`, `"displayName": "AI Swissknife"`,
     `"description": "Cross-assistant marketplace and management for
     custom skill/agent/mcp/rule repositories (Claude Code, Kilo Code, and
     more)."`, `"version": "0.0.1"`, `"publisher": "TODO-set-before-publish"`.
   - `"repository": {"type": "git", "url":
     "git@github.com:primax79/vscode-ai-swissknife.git"}`.
   - `"engines": {"vscode": "^1.95.0"}` (stessa versione minima di `agent-hub`,
     una baseline reale sufficientemente recente).
   - `"categories": ["AI", "Other"]`.
   - `"activationEvents": ["onStartupFinished"]` — nessun `onUri` (era
     specifico di agent-hub, qui non serve).
   - `"main": "./dist/extension.js"`.
   - `"contributes"`: lasciare `"commands": []` e ancora nessun `"views"`/
     `"viewsContainers"` — il task 07 (UI minimale, un'iniziativa successiva)
     li aggiungerà. Non pre-dichiarare qui gli id delle viste; un blocco
     `contributes` vuoto (o omesso) è corretto per questo task.
   - `"scripts"`: `"vscode:prepublish": "npm run build"`, `"build": "node
     esbuild.config.js"`, `"watch": "node esbuild.config.js --watch"`,
     `"typecheck": "tsc --noEmit"`, `"lint": "eslint src --ext ts"` (il task
     01.3 aggiunge la configurazione eslint da cui dipende — va bene che lo
     script esista prima della configurazione, semplicemente non ci si aspetta
     che `npm run lint` passi finché non viene completato lo 01.3).
   - `"devDependencies"`: `@types/node`, `@types/vscode` (fissare alla stessa
     versione compatibile con `^1.95.0` usata da `agent-hub`), `@types/mocha`,
     `@vscode/test-electron`, `esbuild`, `typescript`. **Non** includere
     `better-sqlite3`, `@electron/rebuild`, `@vscode/webview-ui-toolkit`,
     `zod`, `semver` — nessuno di questi serve per questa tranche (niente DB
     locale, niente webview, niente validazione dello schema del manifest del
     marketplace per ora).
   - Nessuno script `"postinstall"` (era specifico per la ricompilazione
     nativa di `better-sqlite3` in `agent-hub`, qui non applicabile).
2. Creare `tsconfig.json` nella radice del repository, con la stessa struttura di
   `references/agent-hub/tsconfig.json` (`module: commonjs`, `target:
   ES2020`, `outDir: out`, `rootDir: src`, `strict: true`,
   `esModuleInterop: true`, `skipLibCheck: true`,
   `forceConsistentCasingInFileNames: true`, `resolveJsonModule: true`,
   `moduleResolution: node`), `"include": ["src/**/*"]`, `"exclude":
   ["node_modules", ".vscode-test"]` (nessuna esclusione `src/webview/**/*` —
   non c'è alcuna webview in questa tranche).
3. Creare `esbuild.config.js` nella radice del repository, modellato su
   `references/agent-hub/esbuild.config.js` limitatamente al blocco `extensionConfig`
   (entry `./src/extension.ts`, bundle, outfile
   `./dist/extension.js`, `external: ['vscode']`, `format: 'cjs'`,
   `platform: 'node'`, `target: 'node18'`, sourcemap attivo, minificazione quando
   non in modalità watch). **Omettere** interamente il blocco `webviewConfig` —
   non c'è ancora alcun entry point webview.
4. Eseguire `npm install` nella radice del repository per generare
   `package-lock.json` e popolare `node_modules/`.
5. Aggiungere `node_modules/`, `out/`, `dist/`, `*.vsix` a `.gitignore`
   (aggiungere in coda al file esistente, che attualmente contiene solo
   `references` — non rimuovere quella riga).

**Verifica**: `npm install` termina senza errori; `node
esbuild.config.js` fallisce in questa fase con un chiaro errore "entry point
not found" (previsto — `src/extension.ts` non esiste fino al task 01.2)
anziché con un errore di configurazione o sintassi. Questo corrisponde a un
unico commit contenente `package.json`, `package-lock.json`, `tsconfig.json`,
`esbuild.config.js` e l'aggiunta a `.gitignore` — nient'altro.
