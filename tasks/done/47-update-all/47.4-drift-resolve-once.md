# 47.4 — Il controllo di drift risolve ciascuna sorgente una sola volta, non una per elemento

Un task, un commit. Rilevato durante la verifica di 47.1 (2026-10-08). Deciso dall'architetto (delegato dal proprietario).

**Read first:** `plan.md`, `src/engine/drift.ts` (`checkForUpstreamUpdate`: chiama `getSourceResolver(source.type).resolve(source, { homeRoot })` a **ogni chiamata**, quindi un controllo di drift su N installazioni dalla stessa sorgente git esegue N risoluzioni, ciascuna con un `git fetch` di rete), `src/engine/update.ts` (`planUpdateAll`, che mette già in cache la risoluzione per sorgente per la pianificazione ma chiama `checkForUpstreamUpdate` per elemento quando non viene fornito alcun report), `src/ui/installedView.ts` (`checkDrift`: un `checkForUpstreamUpdate` per installazione).

## Cosa fare

1. `checkForUpstreamUpdate(inst, source, homeRoot, opts?)` accetta una `SourceResolution` pre-risolta opzionale (o un piccolo oggetto di cache per esecuzione `{ get(source) }`) e la usa invece di risolvere nuovamente; comportamento invariato quando non viene passato nulla.
2. Un helper `checkDriftForAll(installations, sources, homeRoot?)` in `src/engine/drift.ts` che risolve ciascuna sorgente **una sola volta** per esecuzione (concorrenza 1 per sorgente, le sorgenti possono essere eseguite in parallelo fino a un piccolo limite) e restituisce i report; `InstalledTreeDataProvider.checkDrift` e `planUpdateAll` lo utilizzano.
3. Una sorgente che fallisce segna solo le proprie installazioni come controllo di drift fallito (come oggi), senza mai interrompere l'esecuzione.

## Verification

Test: 5 installazioni da una stessa sorgente -> lo spy del resolver viene chiamato una sola volta (prima erano 5); due sorgenti -> due volte; il fallimento di una sorgente non ferma l'altra e i suoi elementi riportano il fallimento; i test di drift esistenti e i test UI di `checkDrift` restano verdi senza modifiche. `npm test` verde, `npm run build` pulito.
