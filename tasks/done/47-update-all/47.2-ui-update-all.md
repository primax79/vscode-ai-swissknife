# 47.2 — UI: trigger Update all

One task, one commit. Depends on 47.1. Assumptions UA-Q1 / UA-Q2 of the plan apply until the owner changes them.

**Read first:** `plan.md`, `src/engine/update.ts` (47.1), `src/ui/installedView.ts` (`checkDrift`, `driftReports`, per-assistant providers), `src/ui/dashboard.ts` (Installed toolbar, the "Updates Available" stat card, message switch, current filter state `currentEnv` / scope / membership / kind), `package.json` (`view/title` menus for `aiSwissknife.installed.*`), `src/extension.ts` (command registration).

## Do

1. Command `aiSwissknife.updateAll` ("Update All...", icon `$(arrow-circle-up)`): **no argument** = every environment and scope; with an assistant id argument = that environment only. Palette entry for the global one; one `view/title` button on each per-assistant Installed view bound to that environment's id. The button is shown only when the last drift check knows of at least one update; it triggers a drift check first when no report exists.
2. **Flow**: drift check once -> `planUpdateAll` -> a modal summary in words: "N update(s) will be applied (first 10 names, then "and K more")", "M item(s) are modified locally and will be skipped (they would lose your edits)", "K item(s) cannot be updated (reason counts)". Buttons: `Update N`, `Update N + M modified (your version is saved to the trash first)` (only when M > 0), `Cancel`. Then `withProgress` with the item name; one final message `Updated X, skipped Y, failed Z` with "Show details" (output channel listing per-item outcomes, including backup paths); one `checkDrift` + refresh at the end, not per item.
3. **Dashboard**: an icon-only button in the Installed toolbar (tooltip "Update all (N)") and the "Updates Available" stat card made clickable, both acting on the **current filter selection** (env/scope/kind from the filters, passed as the `filter` of `planUpdateAll`); the count N reflects the filters and the button is disabled at 0.
4. Messages and the dialog use Global / Workspace; the single-item `doUpdateInstallation` gains the same locally-modified warning in its modal text (no behaviour change otherwise).

## Verification

`ui.test.ts` with the engine mocked where needed and real temp fixtures where cheap: the command with no argument covers all environments, with an id only that one; the summary modal text for N/M/K; choosing the plain button never touches modified items, the other button passes `includeModified`; one drift check and one refresh per run (spies); the Dashboard button posts the current filter and is disabled at 0; the per-environment `view/title` entry exists with the `when` for each assistant view (JSON check). `npm test` green, `npm run build` clean. Manual: with two outdated items and one locally modified, run Update all and confirm the three behaviours.
