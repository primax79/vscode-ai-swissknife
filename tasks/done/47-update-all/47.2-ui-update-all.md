# 47.2 — UI: attivazione di Update all

Un task, un commit. Dipende da 47.1. Si applicano le assunzioni UA-Q1 / UA-Q2 del piano finché il proprietario non le modifica.

**Read first:** `plan.md`, `src/engine/update.ts` (47.1), `src/ui/installedView.ts` (`checkDrift`, `driftReports`, provider per assistente), `src/ui/dashboard.ts` (barra degli strumenti di Installed, la scheda statistica "Updates Available", switch dei messaggi, stato attuale dei filtri `currentEnv` / scope / membership / kind), `package.json` (menu `view/title` per `aiSwissknife.installed.*`), `src/extension.ts` (registrazione dei comandi).

## Cosa fare

1. Comando `aiSwissknife.updateAll` ("Update All...", icona `$(arrow-circle-up)`): **senza argomento** = tutti gli ambienti e gli scope; con un id assistente come argomento = solo quell'ambiente. Voce nella command palette per quello globale; un pulsante `view/title` su ciascuna vista Installed per assistente associato all'id di quell'ambiente. Il pulsante viene mostrato solo quando l'ultimo controllo di drift rileva almeno un aggiornamento; avvia prima un controllo di drift quando non esiste alcun report.
2. **Flusso**: controllo di drift una sola volta -> `planUpdateAll` -> una modale di riepilogo testuale: "N update(s) will be applied (first 10 names, then "and K more")", "M item(s) are modified locally and will be skipped (they would lose your edits)", "K item(s) cannot be updated (reason counts)". Pulsanti: `Update N`, `Update N + M modified (your version is saved to the trash first)` (solo quando M > 0), `Cancel`. Poi `withProgress` con il nome dell'elemento; un unico messaggio finale `Updated X, skipped Y, failed Z` con "Show details" (canale di output che elenca gli esiti per elemento, inclusi i percorsi di backup); un unico `checkDrift` + aggiornamento alla fine, non per ogni elemento.
3. **Dashboard**: un pulsante di sola icona nella barra degli strumenti di Installed (tooltip "Update all (N)") e la scheda statistica "Updates Available" resa cliccabile, entrambi operanti sulla **selezione attuale dei filtri** (env/scope/kind dai filtri, passati come `filter` di `planUpdateAll`); il conteggio N riflette i filtri e il pulsante è disabilitato quando vale 0.
4. I messaggi e la finestra di dialogo usano Global / Workspace; `doUpdateInstallation` per il singolo elemento acquisisce lo stesso avviso di modifica locale nel testo della propria modale (nessun'altra modifica di comportamento).

## Verification

`ui.test.ts` con il motore simulato tramite mock dove necessario e fixture temporanee reali dove economico: il comando senza argomento copre tutti gli ambienti, con un id solo quello specificato; il testo della modale di riepilogo per N/M/K; scegliere il pulsante standard non tocca mai gli elementi modificati, l'altro pulsante passa `includeModified`; un solo controllo di drift e un solo aggiornamento per esecuzione (spy); il pulsante della Dashboard invia il filtro corrente ed è disabilitato a 0; la voce `view/title` per ambiente esiste con la clausola `when` per ciascuna vista di assistente (controllo JSON). `npm test` verde, `npm run build` pulito. Manuale: con due elementi obsoleti e uno modificato localmente, eseguire Update all e confermare i tre comportamenti.
