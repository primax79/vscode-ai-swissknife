# 10.1 — Modello CanonicalMcpServer e adapter di configurazione MCP per Claude/Kilo

> Parte di [Supporto agli artefatti MCP-server](plan.md) · specifica: [../specs/phase-2-spec.md](../../specs/phase-2-spec.md)

## Goal

Aggiungere il modello canonico `CanonicalMcpServer` e implementare lettura, scrittura e merge delle configurazioni dei server MCP in `ClaudeAdapter` e `KiloAdapter`.

Questo task deve produrre un unico commit contenente solo le proprie modifiche.

## Steps

1. Definire `CanonicalMcpServer` in `src/adapters/types.ts`:
```ts
export interface CanonicalMcpServer {
  id: string;
  type: 'stdio' | 'http' | 'sse';
  command?: string;
  args?: string[];
  url?: string;
  env?: Record<string, string>;
  headers?: Record<string, string>;
  extraFields?: Record<string, unknown>;
}
```

2. Implementare i metodi dell'adapter MCP su `Adapter`:
   - `mcpConfigPath(loc: LocationRef): string`
   - `readMcpServer(id: string, loc: LocationRef): Promise<CanonicalMcpServer | null>`
   - `writeMcpServer(server: CanonicalMcpServer, loc: LocationRef): Promise<void>`
   - `listMcpServers(loc: LocationRef): Promise<string[]>`

3. Implementare in `ClaudeAdapter` (`src/adapters/claude.ts`):
   - `mcpConfigPath(loc)`: `.mcp.json` (progetto) o `~/.claude/settings.json` (globale).
   - Formato: `{ "mcpServers": { "<id>": { "command": "...", "args": [...], "env": {...}, "url": "..." } } }`.

4. Implementare in `KiloAdapter` (`src/adapters/kilo.ts`):
   - `mcpConfigPath(loc)`: `.kilo/mcp.json` (progetto) o `~/.config/kilo/mcp.json` (globale).
   - Formato: `{ "mcp": { "<id>": { "type": "stdio", "command": "...", "args": [...], "env": {...} } } }` (oppure `{ "mcpServers": ... }`).

5. Aggiungere unit test in `src/adapters/claude.test.ts` e `src/adapters/kilo.test.ts`.

## Verification

- Eseguire l'intera suite di test, lint, typecheck e build.
- Testare la serializzazione e la lettura round-trip dei server MCP stdio e http/sse.
- Dimostrare che il merge preserva i server non gestiti già presenti nel file di configurazione.
