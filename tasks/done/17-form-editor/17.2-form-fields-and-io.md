# 17.2 — Structured form, validation & direct adapter read/write

> Part of [Form editor webview](plan.md) · spec: [../specs/phase-4-spec.md](../../specs/phase-4-spec.md) §3

## Goal

Render the actual form fields from 17.1's schema, validate input against
the canonical model's constraints, and load/save by calling each adapter's
own parse/serialize functions directly — **not** `planInstall`/
`PlanInstallParams` (`src/engine/types.ts`), per the locked-in decision in
`phase-4-spec.md` §3 (there is no `Source`/`Package`/`Artifact` triple to
resolve when authoring or hand-editing a local item).

This task must produce one commit containing only its changes.

## Grounding

- Read functions to reuse: `readSkill` (`src/adapters/codec.ts`),
  `parseClaudeAgentMarkdown`/`parseClaudeCommandMarkdown`
  (`src/adapters/claude.ts`), `parseKiloAgentMarkdown`/
  `parseKiloCommandMarkdown` (`src/adapters/kilo.ts`).
- Write functions to reuse: `writeSkill` (`src/adapters/codec.ts`),
  `serializeClaudeAgentMarkdown`/`serializeClaudeCommandMarkdown`
  (`src/adapters/claude.ts`), `serializeKiloAgentMarkdown`/
  `serializeKiloCommandMarkdown` (`src/adapters/kilo.ts`).
- Hash functions to reuse for the `state.json` update after save:
  `canonicalSkillHash`/`canonicalAgentHash`/`canonicalCommandHash`/
  `canonicalMcpServerHash` (`src/adapters/codec.ts`).
- Registry read/write for `state.json`: `src/domain/registry.ts`.

## Steps

1. Webview-side: render each schema field from 17.1 as the matching input
   (text/textarea/list/map/select/checkbox), plus a markdown editor for the
   `body` field where the kind has one, plus a **read-only** "raw fields"
   panel showing `extraFields` verbatim (never editable, never dropped on
   save).
2. Extension-host side: on `load`, dispatch to the right adapter parse
   function by `(assistant, kind)`, populate the panel; on `save`, validate
   (required fields per canonical model, e.g. `name`/`description` non-empty),
   dispatch to the right serialize function, write the file at the path the
   relevant adapter/`ManagedInstallation` already resolves to, recompute the
   content hash, and update `state.json` for that installation (or create a
   new `ManagedInstallation` entry when this is a brand-new item — mark its
   `sourceId` as locally-authored, not from a marketplace source).
3. On validation failure, surface field-level errors in the webview; do not
   write anything to disk.
4. Add unit tests: round-trip (load existing → save unchanged → byte-for-byte
   or semantically-equal per the existing YAML-preservation guarantee) for at
   least one kind per assistant already supported (Claude, Kilo), and one
   "create new" path.

## Verification

- Run full test suite, lint, typecheck, build.
- Manually open the form editor on a real installed skill/agent in the Dev
  Host, edit a field, save, and confirm the file on disk changed only in the
  expected field and `extraFields` survived unchanged.
