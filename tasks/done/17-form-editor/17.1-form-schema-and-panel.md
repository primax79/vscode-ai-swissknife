# 17.1 — Field schema registry & webview scaffold

> Part of [Form editor webview](plan.md) · spec: [../specs/phase-4-spec.md](../../specs/phase-4-spec.md) §3

## Goal

Define the per-kind field schema (which fields the form shows for
`skill`/`agent`/`command`/`mcp-server`/`rule`, per `phase-4-spec.md` §3) and
scaffold `FormEditorPanel` in `src/ui/formEditor.ts`, following the same
`vscode.window.createWebviewPanel` + message-protocol pattern already used
by `DashboardPanel` (`src/ui/dashboard.ts`, initiative 16) — read that file
first, don't invent a new webview-lifecycle pattern.

This task must produce one commit containing only its changes.

## Grounding

- Canonical models to expose fields from: `src/adapters/types.ts`
  (`CanonicalSkill`, `CanonicalAgent`, `CanonicalCommand`,
  `CanonicalMcpServer`, `CanonicalRule`).
- Webview lifecycle pattern to mirror: `src/ui/dashboard.ts`
  (`DashboardPanel`, `postState()`, message listener).
- `hook` is explicitly out of scope here (`phase-4-spec.md` §3) — no
  `CanonicalHook` exists yet (initiative 19).

## Steps

1. In `src/ui/formEditor.ts`, define a field-schema type and one schema
   value per kind (`skill`, `agent`, `command`, `mcp-server`, `rule`) listing
   field name, label, input kind (`text`/`textarea`/`string[]`/`map`/
   `select`/`checkbox`/`markdown-body`), matching the field list in
   `phase-4-spec.md` §3 exactly — no fields beyond what the canonical model
   already has.
2. Implement `FormEditorPanel`: singleton-per-item webview panel manager
   (multiple items can each have their own panel instance, unlike the
   single dashboard), `postState()` sends the schema + current values (or
   empty defaults for "create new"), message listener handles `save` and
   `cancel`.
3. Add unit tests in `src/ui/ui.test.ts` (or a new `src/ui/formEditor.test.ts`
   if `ui.test.ts` is already large) covering: schema completeness (every
   canonical field appears in exactly one kind's schema, none invented),
   panel creation, and message-protocol round-trip with a fake webview.

## Verification

- Run full test suite, lint, typecheck, build.
