# 23.3 — Funzione di ricerca di identità cross-framework

> Parte di [Ricerca di identità cross-framework + accessor condiviso dei contenuti](plan.md) · spec: [../specs/phase-6-spec.md](../../specs/phase-6-spec.md) §3, §4.1

## Goal

Una funzione pura che risponde a "quali altre installazioni rappresentano lo stesso
artefatto logico di questa" — i dati che il pannello di dettaglio della Dashboard (26.2)
mostra come "installato anche in...". Indipendente da 23.1/23.2 — nessuna API di VS Code,
nessuna risoluzione delle sorgenti, legge solamente `ManagedInstallation[]` già in memoria.

Questo task deve produrre un singolo commit contenente solo le proprie modifiche.

## Steps

1. Aggiungere una nuova funzione esportata in `src/engine/` (es.
   `src/engine/crossFrameworkLookup.ts`), senza alcun import delle API di VS Code, seguendo
   il pattern esistente del nucleo puro (`resolveRecommendations` in
   `src/engine/recommendations.ts` è il precedente più vicino):

   ```ts
   type MatchStrategy = 'provenance' | 'name-fallback';

   function findRelatedInstallations(
     target: ManagedInstallation,
     all: ManagedInstallation[]
   ): { installation: ManagedInstallation; strategy: MatchStrategy }[]
   ```
2. Regola di corrispondenza: se `target.sourceId` e `target.artifactId` sono entrambi
   presenti, trovare ogni altra installazione in `all` (escludendo `target`
   stessa — stesso assistant+scope+name+path non è "un'altra" installazione)
   con gli stessi `sourceId` e `artifactId`, etichettata `'provenance'`.
   Altrimenti (se uno dei due manca su `target`), trovare ogni altra installazione
   con gli stessi `name` e `kind`, etichettata `'name-fallback'`.
3. Questa funzione **non** tenta di risolvere l'ambiguità preesistente di collisione di
   `sourceId` tra scope diversi (non-obiettivo nella specifica §2) — un semplice confronto
   `sourceId === sourceId && artifactId === artifactId` è
   corretto secondo la decisione fissata; non aggiungere logica di disambiguazione basata sullo
   scope non richiesta qui.
4. Esportare da `src/engine/index.ts` accanto alle altre esportazioni del motore.

## Verification

- Nuovo `src/engine/crossFrameworkLookup.test.ts` (node:test, nessun mock `vscode`
  necessario) che copra: un target con `sourceId+artifactId` che corrisponde a un'altra
  installazione → un risultato `'provenance'`; un target con la stessa
  provenienza di altre due su assistenti diversi → entrambe restituite; un
  target con `sourceId+artifactId` ma nessun'altra installazione che li condivida
  → array vuoto (**non** deve ripiegare su name+kind quando la provenienza è
  presente ma semplicemente non trova altre corrispondenze); un target privo di
  `sourceId` che corrisponde a un'altra installazione per `name+kind` → un
  risultato `'name-fallback'`; il target stesso non deve mai apparire nel proprio
  elenco di risultati; due installazioni con lo stesso `name+kind` ma `kind`
  diverso non devono corrispondere.
- Eseguire l'intera suite di test, lint, typecheck, build.
