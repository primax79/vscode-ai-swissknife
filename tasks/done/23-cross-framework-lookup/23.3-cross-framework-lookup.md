# 23.3 — Cross-framework identity lookup function

> Part of [Cross-framework identity lookup + shared content accessor](plan.md) · spec: [../specs/phase-6-spec.md](../../specs/phase-6-spec.md) §3, §4.1

## Goal

A pure function answering "which other installations represent the same
logical artifact as this one" — the data the Dashboard detail panel (26.2)
shows as "installed also in...". Independent of 23.1/23.2 — no VS Code API,
no source resolution, only reads `ManagedInstallation[]` already in memory.

This task must produce one commit containing only its changes.

## Steps

1. Add a new exported function in `src/engine/` (e.g.
   `src/engine/crossFrameworkLookup.ts`), no VS Code API import, matching
   the existing pure-core pattern (`resolveRecommendations` in
   `src/engine/recommendations.ts` is the closest precedent):

   ```ts
   type MatchStrategy = 'provenance' | 'name-fallback';

   function findRelatedInstallations(
     target: ManagedInstallation,
     all: ManagedInstallation[]
   ): { installation: ManagedInstallation; strategy: MatchStrategy }[]
   ```
2. Matching rule: if `target.sourceId` and `target.artifactId` are both
   present, match every other installation in `all` (excluding `target`
   itself — same assistant+scope+name+path is not "another" installation)
   with the same `sourceId` and `artifactId`, tagged `'provenance'`.
   Otherwise (either is missing on `target`), match every other installation
   with the same `name` and `kind`, tagged `'name-fallback'`.
3. This function does **not** attempt to fix the pre-existing cross-scope
   `sourceId` collision ambiguity (spec §2 non-goal) — a straightforward
   `sourceId === sourceId && artifactId === artifactId` comparison is
   correct per the locked-in decision, do not add scope-aware
   disambiguation logic that isn't asked for here.
4. Export from `src/engine/index.ts` alongside the other engine exports.

## Verification

- New `src/engine/crossFrameworkLookup.test.ts` (node:test, no `vscode`
  mock needed) covering: a target with `sourceId+artifactId` matching one
  other installation → one `'provenance'` result; a target with the same
  provenance as two others across different assistants → both returned; a
  target with `sourceId+artifactId` but no other installation sharing them
  → empty array (must **not** fall back to name+kind when provenance is
  present but simply doesn't match anything else); a target missing
  `sourceId` matching another installation by `name+kind` → one
  `'name-fallback'` result; the target itself must never appear in its own
  result list; two installations with the same `name+kind` but different
  `kind` must not match.
- Run full test suite, lint, typecheck, build.
