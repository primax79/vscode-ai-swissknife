# 34.2 — Uninstall + Update-to-latest nel pannello di dettaglio

**Depends on:** 31.1 (integrato, per `doUpdateInstallation`/
`doUninstallItem`), 31.4 (integrato, per la chiave di identità composita stabile).

## Perché

L'elenco delle azioni del pannello di dettaglio di Installed (`src/ui/dashboard.ts:1031-1042`)
renderizza solo ed esclusivamente `Promote` (non gestito) oppure `Copy to...`/`Move to...`/
`Edit` (gestito) — `Uninstall` e `Update to latest` sono azioni reali e funzionanti
della sidebar prive di un equivalente nella Dashboard (`specs/phase-9-spec.md` §0).

## Ambito

- Nuovi messaggi webview `uninstallItem` e `updateItem`, ciascuno dei quali trasporta la
  chiave di identità composita dell'Iniziativa 31.4 (`{assistant, scope, kind,
  name}`), **non** l'intero oggetto `ManagedInstallation` — secondo
  la nota di sicurezza di `specs/phase-9-spec.md` §1.1, il gestore nell'extension host
  deve risolvere nuovamente il `ManagedInstallation` corrente a partire da una scansione aggiornata
  dell'inventario usando `findInstallationByKey` (31.4) prima di invocare
  `doUninstallItem`/`doUpdateInstallation`, senza mai fidarsi direttamente di un oggetto
  fornito dal client (specialmente `path`).
- Estendere l'elenco delle azioni del pannello di dettaglio
  (`src/ui/dashboard.ts:1031-1042`, ramo lato client `msg.membership ===
  'managed'`): aggiungere `Uninstall` e, quando un report di drift mostra
  `update-available`/`modified-and-update-available` per l'elemento
  selezionato, `Update to latest` — entrambi inviano il messaggio corrispondente con
  la chiave di identità, mantenendo la stessa UX delle finestre di conferma della sidebar (si tratta di
  conferme modali native `showInformationMessage` interne a
  `doUninstallItem`/`doUpdateInstallation` stessi, invariate rispetto a
  oggi — non serve alcuna nuova UI di conferma nella webview).
- Dopo il successo di una delle due azioni: aggiornare la tabella/il pannello di dettaglio di Installed
  tramite il pattern di aggiornamento incrementale dell'Iniziativa 32.3 (non un ricaricamento completo
  della pagina), e azzerare la selezione del pannello di dettaglio se l'elemento è appena
  stato disinstallato (non esiste più per poterne mostrare il dettaglio).

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi.
- Manuale: selezionare un elemento gestito con stato `update-available`, fare clic su
  `Update to latest` dalla Dashboard — confermare un esito identico
  (stato di drift ricalcolato, stesso messaggio di successo) rispetto al comando
  `Update` della sidebar sullo stesso elemento.
- Manuale: selezionare un elemento gestito, eseguire `Uninstall` dalla Dashboard — confermare che
  venga rimosso dal disco e da `state.json` in modo identico al comando
  `Uninstall` della sidebar, e che l'elemento scompaia dalla
  tabella Installed senza un refresh manuale.
- Manuale, orientato alla sicurezza: confermare che il gestore di uninstall/update
  risolva effettivamente di nuovo l'elemento da una scansione aggiornata invece di fidarsi del payload della webview —
  ad es. verificando che l'implementazione invochi `findInstallationByKey`
  su un inventario appena letto, non tentando di sfruttarla (questo è un
  controllo di code review, non una simulazione di attacco dal vivo).
