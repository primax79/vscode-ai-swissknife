# 34.3 — Cross-refresh wiring

**Depends on:** 34.1, 34.2 (merged). Also touches the combined surface
Initiative 33 added — dispatch after 33 has landed if both are in flight,
to verify the two together rather than each in isolation.

## Why

`specs/phase-9-spec.md` §4.1: every sidebar command that mutates state
also refreshes the status bar and the relevant tree providers. This is
the integration pass proving every Dashboard-triggered mutation
(Initiative 33's Sources/Catalog actions, Initiative 34.1's
recommendation actions, 34.2's Uninstall/Update) does the same — not a
new mechanism, Initiative 32.1 already wired the callback in.

## Scope

- Audit every webview message handler added across Initiative 33 and 34
  (`addSource`, `removeSource`, `exportConfig`, `exportSource`,
  `importConfig`, `installArtifact`, `installFolder`,
  `installSourceGroup`, `installRecommended`, `installRecommendation`,
  `unrecommendRecommendation`, `uninstallItem`, `updateItem`) against the
  cross-refresh callback from Initiative 32.1 — confirm each one that
  should trigger it actually does (some provider methods already call
  `refresh()`/`refreshCatalog()` internally; this task's job is to
  confirm the *status bar* also updates, since that's the piece most
  likely to have been missed per-task since it wasn't each task's
  primary focus).
- Fix any gaps found — this is expected to be a small set of one-line
  additions (calling the callback), not new logic, since the callback
  itself was built in 32.1.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green.
- Manual, for **each** message in the audit list above: trigger it from
  the Dashboard, confirm the status bar's pending-updates/recommendations
  count (`formatStatusBarLabel`/`formatStatusBarTooltip`,
  `src/engine/pendingCounts.ts`) updates without needing to reopen the
  Dashboard or reload the window, and the sidebar's `Sources`/`Installed`
  tree reflects the same change.
