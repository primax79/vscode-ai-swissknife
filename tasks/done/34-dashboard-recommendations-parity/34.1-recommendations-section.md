# 34.1 — Sezione Recommendations

**Depends on:** 31.3 (integrato, per recommend/unrecommend basati su identificatori),
32 (integrata, per il guscio a sezioni).

## Perché

`resolveRecommendations` (`src/engine/recommendations.ts:13-40`) calcola i
bucket `satisfied`/`pending`/`broken` per le installazioni consigliate a livello di
progetto, e l'Iniziativa 27 ha aggiunto un punto di accesso nella barra di stato specificamente
per *raggiungere* la Dashboard a questo scopo — ma la Dashboard non ha mai effettivamente
esposto questi dati (`specs/phase-9-spec.md` §0, §4).

## Ambito

- Extension host: per `resolveRecommendations` calcolare i bucket `pending`/`broken`
  (rispecchiando il modo in cui `AvailableTreeDataProvider` costruisce già il proprio
  `RecommendedGroupItem` per la sidebar, `src/ui/availableView.ts:47,`
  `200,360-368` — leggere direttamente quel percorso di costruzione invece di
  riderivare in modo indipendente la logica di risoluzione) e inviarli come
  messaggio `recommendationsData`. `satisfied` non è necessario nella UI —
  `RecommendedGroupItem` stesso traccia solo i due bucket azionabili,
  come confermato da entrambe le revisioni della specifica.
- UI della Dashboard (sezione Recommendations, segnaposto di 32.2): elencare le
  voci `pending` ciascuna con un pulsante "Install", un sotto-elenco "Broken" per le
  voci `broken` (esponendo il `BrokenReason` — source-not-registered /
  source-resolution-failed / artifact-not-found, in linea con il modo in cui
  `RecommendedBrokenItem` della sidebar li distingue), e un'azione
  "Unrecommend" per ciascuna voce (pending o broken).
- Nuovi messaggi webview:
  - `installRecommended` (installa ogni voce pending) — riutilizza
    `handleInstallRecommended` (`src/ui/recommendations.ts:136`) così com'è.
  - `installRecommendation` (installa **una singola** voce) — nuovo; la bozza
    originale della specifica non lo definiva ed entrambe le revisioni hanno segnalato la lacuna.
    Risolvere la tupla `{artifact, pkg, source, targetAssistant,
    targetScope}` della singola voce (il bucket pending trasporta già questa forma,
    secondo `src/engine/recommendations.ts` nel tipo `pending`) e invocare
    `installResolvedArtifacts` (`src/ui/recommendations.ts:20`) con un
    array di un solo elemento.
  - `unrecommendRecommendation` — invoca
    `unrecommendArtifactForWorkspace(...)` dell'Iniziativa 31.3 con i campi identificativi
    della voce.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi.
- Manuale: con un manifest di progetto contenente almeno un suggerimento pending, uno
  broken (ad es. facendo puntare una voce `desiredInstallations` a una sorgente rimossa),
  e uno satisfied — confermare che la sezione Recommendations della Dashboard
  mostri esattamente quelli pending+broken (non quello
  satisfied), che l'installazione singola e l'installazione di tutti funzionino entrambe e producano lo stesso esito di
  `installRecommended` della sidebar, e che unrecommend rimuova la
  voce da `desiredInstallations` del manifest di progetto nello stesso modo in cui
  opera il comando `unrecommendForWorkspace` della sidebar.
