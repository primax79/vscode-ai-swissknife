# 34.1 — Recommendations section

**Depends on:** 31.3 (merged, for identifier-based recommend/unrecommend),
32 (merged, for the section shell).

## Why

`resolveRecommendations` (`src/engine/recommendations.ts:13-40`) computes
`satisfied`/`pending`/`broken` buckets for project-scoped recommended
installs, and Initiative 27 added a status-bar entry point specifically
to *reach* the Dashboard for this — but the Dashboard has never actually
surfaced this data (`specs/phase-9-spec.md` §0, §4).

## Scope

- Extension-host: compute `resolveRecommendations`'s `pending`/`broken`
  buckets (mirroring how `AvailableTreeDataProvider` already builds its
  `RecommendedGroupItem` for the sidebar, `src/ui/availableView.ts:47,`
  `200,360-368` — read that construction path directly rather than
  re-deriving the resolution logic independently) and send as a
  `recommendationsData` message. `satisfied` is not needed in the UI —
  `RecommendedGroupItem` itself only tracks the two actionable buckets,
  confirmed by both spec reviews.
- Dashboard UI (Recommendations section, placeholder from 32.2): list
  `pending` entries with an "Install" button each, a "Broken" sub-list for
  `broken` entries (surfacing the `BrokenReason` — source-not-registered /
  source-resolution-failed / artifact-not-found, matching how the
  sidebar's `RecommendedBrokenItem` distinguishes these), and an
  "Unrecommend" action per entry (pending or broken).
- New webview messages:
  - `installRecommended` (install every pending entry) — reuses
    `handleInstallRecommended` (`src/ui/recommendations.ts:136`) as-is.
  - `installRecommendation` (install **one** entry) — new; the original
    draft spec didn't define this and both reviews flagged the gap.
    Resolve the one entry's `{artifact, pkg, source, targetAssistant,
    targetScope}` tuple (the pending bucket already carries this shape,
    per `src/engine/recommendations.ts`'s `pending` type) and call
    `installResolvedArtifacts` (`src/ui/recommendations.ts:20`) with a
    single-element array.
  - `unrecommendRecommendation` — calls Initiative 31.3's
    `unrecommendArtifactForWorkspace(...)` with the entry's identifying
    fields.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green.
- Manual: with a project manifest containing at least one pending, one
  broken (e.g. point a `desiredInstallations` entry at a removed source),
  and one satisfied recommendation — confirm the Dashboard's
  Recommendations section shows exactly the pending+broken ones (not
  satisfied), install-one and install-all both work and match the
  sidebar's `installRecommended` outcome, and unrecommend removes the
  entry from the project manifest's `desiredInstallations` the same way
  the sidebar's `unrecommendForWorkspace` command does.
