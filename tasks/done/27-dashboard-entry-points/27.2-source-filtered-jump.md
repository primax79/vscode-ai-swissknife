# 27.2 — "Open in Dashboard" per-source action

> Part of [New Dashboard entry points](plan.md) · spec: [../specs/phase-6-spec.md](../../specs/phase-6-spec.md) §3, §4.6

## Goal

Reveal the Dashboard with a `{ sourceId, sourceScope }` filter pre-applied
and removable, triggered by an explicit per-item action on a `SourceItem`
row — never an automatic filter sync on tree selection (the Dashboard is a
separate, heavier webview panel; auto-revealing it on every sidebar click
would be surprising, unlike the already-shipped Available-view
Sources-selection filter). Depends on 26.1's filter bar/breadcrumb existing.

This task must produce one commit containing only its changes.

## Steps

1. Add a new inline/context command (e.g. `aiSwissknife.openInDashboard`
   distinct from the existing generic `aiSwissknife.openDashboard`, or the
   same command accepting an optional `SourceItem` argument — pick whichever
   reads more consistently with the existing command set in
   `package.json`) on `SourceItem` (`src/ui/sourcesView.ts`).
2. Handler: `DashboardPanel.render()` (opening if not already open, or
   revealing/focusing if it is — same as today), then applies a `Source`
   filter using the composite `{ id: source.id, scope: source.scope }` (not
   a bare `id` string — global and project sources can share one id, same
   precedent as the Available-view's existing source filter,
   `src/ui/availableView.ts:414-417`). Extend 26.1's filter-bar/breadcrumb
   data model with this `Source` dimension if it wasn't already
   generalized to accept it.
3. The filter appears as a removable chip in the breadcrumb (e.g.
   "my-skills-repo (project) ✕"), consistent with the other filter chips
   from 26.1.
4. Add the command to `package.json` (`contributes.commands` +
   `view/item/context` for `sourceItem`, with an appropriate icon).

## Verification

- Manual verification: right-click (or use the inline icon on) a Source
  row, choose "Open in Dashboard" — confirm the Dashboard opens (or comes
  to focus if already open) filtered to that source's items, with a
  removable chip in the breadcrumb; confirm removing the chip returns to
  the unfiltered state; confirm doing this for two sources that share an
  `id` but differ in `scope` produces the correct distinct filter each
  time (not conflated).
- Run full test suite, lint, typecheck, build.
