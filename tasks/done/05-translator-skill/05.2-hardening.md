# 05.2 — Target-typed translation and per-field diagnostics (hardening)

> Part of [Canonical model + translator](plan.md) · spec: [../specs/foundations.md](../../specs/foundations.md) · accepted review decisions: [round 001](../../_reviews/001-hardening-gate-SUMMARY.md) decision 4 and [round 002](../../_reviews/002-hardening-gate-SUMMARY.md) decisions 3 and 17. The prior citation to round-001 decision 9 was incorrect and is retired.

## Goal

Remove unresolvable source-assistant provenance, accept the real adapter target type, and expose diagnostics at field/path granularity without discarding translated output.

This task must produce one commit containing only its changes.

## Grounding

Read `src/adapters/types.ts`, `src/translator/skill.ts`, and every `translateSkill` caller. `Adapter.assistant` is `AssistantId`; the translator signature must compose with it without narrowing casts.

## Steps

1. Change the public signature to `translateSkill(source: CanonicalSkill, targetAssistant: AssistantId): TranslationResult<CanonicalSkill>`. Remove `fromAssistant`: custom-repository content has no reliable source assistant. Retire the `SupportedAssistant` type name after migrating every caller. The dormant `translateRule` currently imports that type, so migrate it to the same target-only `AssistantId` boundary (Claude/Kilo lossless, other targets unsupported) in this commit; do not leave a compile-breaking import or compatibility alias.

2. Replace the aggregate-only result with this concrete shape (reuse the existing `ConversionDiagnostic` union for `overall`):

   ```ts
   export interface TranslationDiagnostic {
     code: string;
     severity: 'info' | 'warning' | 'error';
     field?: 'name' | 'description' | 'body' | 'extraFields' | 'files' | 'target';
     path?: string;
     impact: 'none' | 'adapted' | 'lost' | 'unsupported';
     message: string;
   }

   export interface TranslationResult<T> {
     value: T;
     overall: ConversionDiagnostic;
     diagnostics: TranslationDiagnostic[];
   }
   ```

   Diagnostics identify the affected field (and file path when applicable). A lossless result still carries an explicit informational diagnostic or a documented empty list plus `overall: 'lossless'`; never keep two competing `diagnostic`/`overall` fields.

3. Claude Code and Kilo Code targets return the complete canonical directory payload losslessly. Preserve `extraFields`, auxiliary files, binary content, and modes.

4. Any other `AssistantId` returns `overall: 'unsupported'` with an explicit target diagnostic. It must not throw or pretend to be lossless. The returned value may preserve the source for inspection, but callers branch on `overall` before planning an install.

5. Make input and output names unmistakable at call sites (`resolvedContent`, `translation`, `translation.value`). Task 06.1 validates, hashes, previews, and stores `translation.value`, never the translator input.

## Verification

- Run the full test suite, typecheck, lint, and build.
- Compile skill and dormant rule calls using every `AssistantId`; no cast, source-assistant parameter, or `SupportedAssistant` remains.
- Verify Claude/Kilo lossless translation of nested files, binary content, extra fields, and modes.
- Verify unsupported targets return `overall: 'unsupported'` with a target diagnostic and no exception.
- Use a test translation that changes a field and prove the caller observes `translation.value`, preventing identity-only behavior from hiding regressions.

## Non-goals

- No source-assistant inference.
- No filesystem access.
- No adapters beyond reporting unsupported targets in this phase.
