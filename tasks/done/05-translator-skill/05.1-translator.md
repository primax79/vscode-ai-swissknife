# 05.1 — Traduttore + diagnostiche di conversione

> Parte di [Modello canonico + traduttore](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: un modulo traduttore che converte `CanonicalSkill`/
`CanonicalRule` tra assistenti, restituendo una `ConversionDiagnostic` insieme
al risultato — anche se per l'unica coppia di questa Fase (Claude↔Kilo) la
risposta è sempre `lossless`, il meccanismo deve esistere ed essere testato,
poiché la Fase 2 innesterà nella stessa struttura un caso realmente con perdita
(`agent`).

**Riferimenti nel codice**: SPEC.md §2 "diagnostic for each field" e §4
"canonical model... preserves unrecognized fields." `src/adapters/types.ts`
(iniziativa 03) per `CanonicalSkill`/`CanonicalRule`/`ConversionDiagnostic` —
importarli, non ridefinirli.

Passaggi:

1. Creare `src/translator/skill.ts`:

   ```ts
   import type { CanonicalSkill, ConversionDiagnostic } from '../adapters/types';

   export interface TranslationResult<T> {
     value: T;
     diagnostic: ConversionDiagnostic;
     notes: string[]; // human-readable, empty when diagnostic is 'lossless'
   }

   export function translateSkill(
     source: CanonicalSkill,
     fromAssistant: 'claude-code' | 'kilo-code',
     toAssistant: 'claude-code' | 'kilo-code',
   ): TranslationResult<CanonicalSkill>;
   ```

   Per l'unica coppia di questa Fase, entrambe le direzioni corrispondono alla
   funzione identità su `value` (name/description/body/extraFields invariati)
   con `diagnostic: 'lossless'` e `notes: []` — **ma non cablare "sempre
   lossless" come scorciatoia che salta l'ispezione reale**. Controllare
   effettivamente: se `source.name` o `source.description` violassero i vincoli
   noti della destinazione (Claude Code non ne documenta alcuno oltre a
   "obbligatorio"; si noti in SPEC.md §1 che il formato skill di Copilot per
   VSCode limita `name` a 64 caratteri / minuscole con trattini e `description`
   a 1024 — le CLI di Kilo e Claude Code non impongono tale limite secondo i
   file letti per questa specifica) — se `toAssistant` è specificamente
   `'kilo-code'` o `'claude-code'` (entrambi senza limiti), il controllo è un
   no-op e il risultato è `lossless`; scrivere la funzione in modo che una
   futura destinazione con vincoli reali (Copilot, Fase 2) abbia un punto ovvio
   in cui aggiungere un controllo reale, non un commento che dice "non
   implementato".
   - La traduzione verso lo stesso assistente (`fromAssistant === toAssistant`) è
     sempre `lossless`, banalmente — includerla come caso esplicito, non fare
     affidamento sul fatto che ricada accidentalmente nella logica di identità.
2. Creare `src/translator/rule.ts`, con la stessa struttura, per `CanonicalRule`
   (che ha solo un campo `content` — la traduzione è pura identità per qualsiasi
   coppia in questa Fase, sempre con `diagnostic: 'lossless'`, poiché SPEC.md §5
   stabilisce che entrambi gli assistenti leggono esattamente lo stesso
   formato/contenuto di file senza alcun adattamento).
3. Scrivere `src/translator/skill.test.ts` e `src/translator/rule.test.ts`:
   - Claude→Kilo e Kilo→Claude producono entrambi `lossless` con un `value`
     invariato per una `CanonicalSkill`/`CanonicalRule` rappresentativa
     (costruire l'input a partire da una fixture reale già utilizzata nei test
     dell'iniziativa 04, ad es. leggere
     `agentic-coding-kit/plugins/common-tools/skills/gitignore/SKILL.md` e
     costruire da esso una `CanonicalSkill`, anziché usare un letterale scritto
     a mano privo di provenienza reale).
   - Una `CanonicalSkill` con una mappa `extraFields` non vuota esce comunque
     come `lossless` con `extraFields` invariato (dimostra che la decisione
     "preservare i campi non riconosciuti" regge anche attraverso il livello del
     traduttore, non solo quello dell'adapter).
   - La traduzione verso lo stesso assistente va in cortocircuito restituendo
     `lossless` (verificarlo esplicitamente come caso di test dedicato, non solo
     come effetto collaterale del test tra assistenti diversi).

**Verifica**: entrambi i file di test passano; `npm run lint && npm run
typecheck && npm run build` terminano tutti con codice 0. Un unico commit
contenente `src/translator/skill.ts`, `src/translator/rule.ts` e i relativi due
file di test — nient'altro. Dopo questo commit, aggiornare in `tasks/00-INDEX.md` la riga
dell'iniziativa `05` a `✅ done`.
