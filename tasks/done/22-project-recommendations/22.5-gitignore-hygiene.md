# 22.5 — Git hygiene for the shared manifest

> Part of [Project-scoped recommended installations](plan.md) · spec: [../specs/project-recommendations.md](../../specs/project-recommendations.md) §4.5

## Goal

Make sure the project's machine-local `state.json` never ends up committed
alongside the intentionally-shared `manifest.json`, without ever touching a
workspace's `.gitignore` beyond appending the one missing line — and without
depending on any other task in this initiative, by hooking the one function
every project-scope manifest write already goes through.

Fully independent of 22.1-22.4 (see below). This task must produce one
commit containing only its changes.

## Steps

1. Add a small helper, e.g. `src/domain/gitignore.ts`, exporting
   `ensureStateIgnored(workspaceRoot: string): Promise<void>`:
   - Compute the real project state path via `statePath('project',
     workspaceRoot)` (`src/domain/registry.ts`) — must resolve the actual
     path in use. **Correction from an earlier draft of this task:**
     `statePath`'s legacy-fallback branch triggers when a legacy **state**
     file (`<root>/.ai-swissknife/state.json`) already exists, independent
     of whether a legacy manifest exists — the two files' legacy-vs-standard
     locations are decided separately, each by its own existence check. Do
     not simulate a legacy manifest to test the legacy state path; simulate
     a legacy `state.json`.
   - Check for `<workspaceRoot>/.gitignore`; if it doesn't exist, return
     without creating one (non-goal: no scaffolding from scratch).
   - If it exists, read it; if a line already matches the state path
     (relative to `workspaceRoot`, normalized for `/` separators), return
     without modifying the file.
   - Otherwise append the relative state path as a new line (preserving the
     file's existing trailing-newline convention), write back.
2. Call `ensureStateIgnored(projectRoot)` from inside `writeManifest`
   (`src/domain/registry.ts`) itself, only when `scope === 'project'` and
   `projectRoot` is provided — **not** from individual UI command handlers.
   This is a deliberate change from an earlier draft that would have called
   it from `addSource` and the new 22.1 recommend handlers separately:
   centralizing it in `writeManifest` means this task has no dependency on
   22.1 (or any future project-scope manifest writer) landing first or
   remembering to call it, and it isn't broken by call sites this task
   doesn't know about yet.
3. Do not touch `manifest.json` itself, and do not ignore the whole
   `.vscode/ai-swissknife/` (or legacy `.ai-swissknife/`) directory — only
   the resolved `state.json` path, since `manifest.json` living right next
   to it must stay tracked.

## Steps — explicitly out of scope here

- Creating a `.gitignore` when none exists (Non-goal in the spec).
- Ignoring the global `cache/` directory (`~/.ai-swissknife/cache/`) — that
  lives under the user's home directory, never inside a project's VCS, so
  there is nothing to ignore there.
- Guaranteeing `state.json` can never be committed under any circumstance
  (Non-goal in the spec — this is best-effort hygiene, not an audited
  guarantee: a broader pre-existing ignore rule or a forced `git add` can
  still defeat it).

## Verification

- New `src/domain/gitignore.test.ts` (node:test, temp directories via
  `fs.mkdtempSync`/`os.tmpdir()`, no `vscode` mock needed): no `.gitignore`
  present → file not created; `.gitignore` present without the entry →
  entry appended, rest of file byte-identical otherwise; `.gitignore`
  present with the entry already → file untouched (assert via exact content
  equality); **a pre-existing legacy `state.json`** (not a legacy manifest)
  present at `<root>/.ai-swissknife/state.json` → the appended line matches
  that legacy path, not the standard `.vscode/ai-swissknife/state.json`
  path.
- New/extended test on `writeManifest` itself (`src/domain/registry.test.ts`):
  calling `writeManifest('project', ..., projectRoot)` against a workspace
  with a `.gitignore` and no prior state-path entry results in that entry
  being appended, with no change to `writeManifest('global', ...)`'s
  behavior (global scope must never touch any `.gitignore`).
- Run full test suite, lint, typecheck, build.
- Manually: in a scratch workspace with a `.gitignore` and no other
  AI Swissknife code changed, add a source via the existing Sources view
  (`addSource`, unmodified by this task), confirm the `.gitignore` gained
  exactly one new line for the resolved state path purely as a side effect
  of `writeManifest` — proving the hook doesn't require 22.1 to exist.
