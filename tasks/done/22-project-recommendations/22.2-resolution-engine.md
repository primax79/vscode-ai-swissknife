# 22.2 — Motore di risoluzione delle raccomandazioni

> Parte di [Installazioni consigliate a livello di progetto](plan.md) · spec: [../specs/project-recommendations.md](../../specs/project-recommendations.md) §4.2

## Goal

Una funzione pura e priva di dipendenze dalle API di VS Code che sia il comando di installazione su richiesta
(22.3) sia il prompt all'apertura del workspace (22.4) invocano una volta risolte le
sorgenti, così che "cosa resta da installare" venga deciso in un unico punto testato,
con tre distinte ragioni di errore invece di un unico contenitore indistinto. Blocca
22.3 e 22.4 — non iniziare nessuno dei due finché questo task non è completato.

Questo task deve produrre un singolo commit contenente solo le proprie modifiche.

## Steps

1. Aggiungere `src/engine/recommendations.ts` esportando:

   ```ts
   type SourceResolutionAttempt =
     | { status: 'resolved'; source: Source; packages: Package[] }
     | { status: 'failed'; source: Source; error: string };

   type BrokenReason =
     | { kind: 'source-not-registered' }
     | { kind: 'source-resolution-failed'; error: string }
     | { kind: 'artifact-not-found' };

   function resolveRecommendations(
     desired: DesiredInstallation[],
     installed: ManagedInstallation[],
     registeredSources: Source[],
     resolutionAttempts: Map<string, SourceResolutionAttempt>
   ): {
     satisfied: DesiredInstallation[];
     pending: { desired: DesiredInstallation; artifact: Artifact; pkg: Package; source: Source }[];
     broken: { desired: DesiredInstallation; reason: BrokenReason }[];
   }
   ```

   `resolutionAttempts` contiene voci solo per le sorgenti che qualcuno ha effettivamente
   tentato di risolvere — sarà spesso vuoto o parziale, poiché la risoluzione viene
   avviata solo da un'azione esplicita dell'utente (22.3/22.4), mai dal
   controllo esclusivamente locale all'apertura (primo passaggio di 22.4).
2. La chiave di corrispondenza per `satisfied` è `sourceId + artifactId + assistant`
   confrontata con `ManagedInstallation.sourceId/artifactId/assistant`
   (`src/domain/types.ts:86-99`) — la stessa tripla usata per la deduplicazione in 22.1.
3. Per le voci non presenti in `installed`:
   - Se nessuna voce in `registeredSources` ha `id === desired.sourceId` →
     `broken` con `{ kind: 'source-not-registered' }`.
   - Altrimenti, se `resolutionAttempts.get(desired.sourceId)` è assente →
     **escludere questa voce da tutti e tre i gruppi** (non è stato ancora tentato nulla per
     essa — i chiamanti che hanno risolto solo un sottoinsieme di sorgenti non devono vedere
     il resto non risolto segnalato silenziosamente come broken).
   - Altrimenti, se quel tentativo ha `status: 'failed'` → `broken` con
     `{ kind: 'source-resolution-failed', error }`.
   - Altrimenti (`status: 'resolved'`): cercare in `packages` un `Artifact` con
     `id === desired.artifactId` — trovato → `pending` (con `artifact`,
     `pkg`, `source`); non trovato → `broken` con
     `{ kind: 'artifact-not-found' }`.
4. Esportare `resolveRecommendations` da `src/engine/index.ts` accanto alle
   altre esportazioni del motore (`planInstall`, `applyInstall`, ecc.).
5. Questa funzione non legge file, non chiama `readManifest`/`readState` e non
   risolve alcuna sorgente autonomamente — i chiamanti (22.3, 22.4) passano dati già caricati
   e risoluzioni già tentate, mantenendola banalmente testabile con unit test
   e coerente con il modo in cui `planInstall` ecc. sono già strutturati (nucleo
   puro, I/O ai confini).

## Verification

- Nuovo `src/engine/recommendations.test.ts` (node:test, nessun mock `vscode`
  necessario poiché questo modulo non importa mai `vscode`) che copra: input vuoto →
  tutto vuoto; corrispondenza installata → `satisfied`; voce non installata risolvibile
  con un tentativo `'resolved'` contenente il suo artefatto → `pending`
  con `artifact`/`pkg`/`source` corretti; un `sourceId` assente da
  `registeredSources` → `broken` con `source-not-registered`; una sorgente registrata
  **senza** voce in `resolutionAttempts` → la voce non appare in
  nessuno dei tre gruppi; una sorgente registrata con un tentativo `'failed'`
  → `broken` con `source-resolution-failed` e la stringa di errore originale;
  un tentativo `'resolved'` i cui `packages` non contengono `artifactId` →
  `broken` con `artifact-not-found`; input misto che produce tutti e tre i
  gruppi contemporaneamente più una voce saltata (non tentata).
- Eseguire l'intera suite di test, lint, typecheck, build.
