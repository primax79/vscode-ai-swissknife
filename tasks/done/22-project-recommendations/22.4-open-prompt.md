# 22.4 — Workspace-open detection + notification

> Part of [Project-scoped recommended installations](plan.md) · spec: [../specs/project-recommendations.md](../../specs/project-recommendations.md) §4.3

## Goal

On opening a project-scope workspace, surface a VS Code-native notification
offering to install whatever this project recommends and isn't yet
installed — mirroring the workspace-extension-recommendations UX cited in
the spec — using a **local-only, network-free** check, without ever
delaying activation.

**Deliberately not a re-implementation of source resolution**: this task's
own detection pass reads only `manifest.json` and `state.json` (both already
on disk) — it must not call any source resolver, since this codebase has no
Workspace Trust integration anywhere (`grep -rn "isTrusted" src` — no
matches) and no timeout on `git-custom` resolution
(`src/sources/gitCustom.ts`); silently cloning repositories as a side effect
of opening a folder would be a new, unreviewed network surface. Actual
resolution only happens once the user clicks `Install All` or `Review`,
reusing 22.3's already-built resolve-and-install path.

Depends on 22.2 and 22.3. This task must produce one commit containing only
its changes.

## Steps

1. In `src/extension.ts`'s `activate()`, after existing view/command
   registration, kick off a fire-and-forget async function — call it, do not
   `await` it inline in a way that blocks `activate()`'s return, and attach
   an explicit `.catch((err) => console.error('[ai-swissknife] recommendation check failed', err))`
   (there is no existing comparable async startup call in `activate()` to
   mirror — this task establishes the pattern, so the error handling must be
   explicit rather than assumed-safe).
2. Inside that function:
   - Resolve the workspace root (reuse `getWorkspaceRoot`/whatever
     `src/ui/workspacePicker.ts` already exposes for a non-interactive
     lookup — the existing picker being interactive is fine, since callers
     like `AvailableTreeDataProvider` already default to the first folder
     silently per the spec's multi-root non-goal; follow that same
     precedent here, do not add a new picker prompt at activation).
     No-op if no workspace is open.
   - `readManifest('project', root)`, `readState('project', root)`.
   - Count `desiredInstallations` entries with no matching
     `sourceId + artifactId + assistant` in `state.installations` — this is
     the entire "local-only" check; no source resolution, no
     `resolveRecommendations` call at this stage.
   - Read
     `context.workspaceState.get<boolean>('aiSwissknife.ignoreRecommendations')`
     — if true, stop here.
3. If the unsatisfied count is `> 0`, call
   `vscode.window.showInformationMessage` with a message naming the count
   (e.g. `"This workspace recommends 3 AI Swissknife item(s) not yet
   installed."`) and actions `Install All`, `Review`,
   `Don't ask again for this workspace`.
   - `Install All` → invoke 22.3's resolve-and-install handler directly
     (factor it so it's callable both from the `installRecommended` command
     and from here, rather than duplicating the resolution/preview/install
     sequence).
   - `Review` → reveal/focus the Available view and its "Recommended"
     grouping from 22.3.
   - `Don't ask again for this workspace` →
     `context.workspaceState.update('aiSwissknife.ignoreRecommendations', true)`.
4. Guard against firing more than once per activation (a simple boolean
   flag is enough — there is no legitimate case for two notifications in one
   session).

## Verification

- Extend `src/ui/ui.test.ts`'s `vscode` mock (or a new test file) with a
  fake `ExtensionContext` (`workspaceState.get`/`update` backed by an
  in-memory map) and a fake `window.showInformationMessage` that records
  the message/actions passed and resolves with a chosen action string.
- Unit tests: unsatisfied entries present + no suppression flag →
  notification fires with the correct count and **no source resolution is
  attempted** (assert via a spy on the resolver functions that it was never
  called during this detection pass); suppression flag set → no
  notification and no resolution attempted; zero unsatisfied entries → no
  notification; choosing `Don't ask again for this workspace` persists the
  flag in the fake `workspaceState`; choosing `Install All` triggers 22.3's
  resolve-and-install path (assert via a spy, not a real filesystem write).
- Run full test suite, lint, typecheck, build.
- Manually in the Extension Development Host: add a recommendation (22.1),
  reload the window, confirm the notification appears exactly once, confirm
  no network/clone activity happens until `Install All` or `Review` is
  actually clicked, and each action behaves as specced.
