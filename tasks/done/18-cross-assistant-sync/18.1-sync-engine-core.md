# 18.1 — `planSync` engine core

> Part of [Cross-assistant sync](plan.md) · spec: [../specs/phase-4-spec.md](../../specs/phase-4-spec.md) §4

## Goal

Implement `planSync` in a new `src/engine/sync.ts`: given an origin
`ManagedInstallation` and a target `(assistant, scope, projectRoot?)`,
produce the same `SupportedInstallPlan`/`UnsupportedInstallPlan` union
already defined in `src/engine/types.ts`, so the existing, unmodified
`applyInstall`/verify functions (`src/engine/apply.ts`) can execute it
without any change — per the locked-in decision in `phase-4-spec.md` §4:
sync must not fork a second apply/rollback path.

This task must produce one commit containing only its changes.

## Grounding

- `ManagedInstallation` shape: `src/domain/types.ts`.
- Existing plan shape to match: `SupportedInstallPlan`,
  `UnsupportedInstallPlan`, `PreparedInstall`, `ProposedFile`,
  `ExistingFile` (`src/engine/types.ts`).
- Existing translators to reuse unmodified: `translateSkill`
  (`src/translator/skill.ts`), `translateAgent` (`src/translator/agent.ts`),
  `translateCommand` (`src/translator/command.ts`), `translateMcp`
  (`src/translator/mcp.ts`), `translateRule` (`src/translator/rule.ts`).
- Origin-side read functions: same ones task 17.2 uses
  (`readSkill`/`parseClaudeAgentMarkdown`/`parseKiloAgentMarkdown`/etc.),
  dispatched on `installation.assistant`/`installation.kind`.
- `applyInstall` entry point to reuse unchanged: `src/engine/apply.ts`.

## Steps

1. In `src/engine/sync.ts`, implement `planSync(installation: ManagedInstallation, target: {assistant, scope, projectRoot?}): Promise<PreparedInstall>`:
   - Read the origin's current on-disk content via the matching adapter
     parse function.
   - Translate to the target assistant via the existing translator for
     that `kind`.
   - Diff against any existing files at the target path (reuse the same
     existing-file-hash comparison logic `planInstall` already has in
     `src/engine/plan.ts` — extract a shared helper if it isn't already
     one, rather than copy-pasting the diff loop).
   - Return the same `PreparalInstall`/`SupportedInstallPlan` shape,
     with `sourceId` set to a synthetic value identifying the sync origin
     (e.g. `sync:<installation.assistant>:<installation.scope>:<installation.name>`)
     so provenance stays inspectable without inventing a new `Source`.
2. Do not modify `src/engine/apply.ts` — `planSync`'s output must be
   consumable by the existing `applyInstall` as-is.
3. Add unit tests: same-kind same-assistant sync (should be lossless), a
   lossy cross-assistant case (e.g. `agent` Kilo→Claude, tools/permissions
   mapping), and a case where the target already has a conflicting file.

## Verification

- Run full test suite, lint, typecheck, build.
