# 04.2 — git-custom resolver

> Part of [Source resolver](plan.md) · spec: [../specs/foundations.md](../../specs/foundations.md)

**Goal**: resolve a `Source` of `type: 'git-custom'` (a generic HTTPS/SSH
git repo URL, optional branch/tag/commit pin) into `Package[]`, by
cloning/fetching it to a local cache directory and then reusing task
04.1's `findSkillDirs`/detection logic on the checkout — do not duplicate
the detection logic.

**Grounding**: SPEC.md §1 `git-custom` Source entry ("auth delegated to
Git credentials already present on the machine", "branch/tag/commit pin
configurable"). This repo itself
(`/Users/Alfredo/works/ai-coding-tools/ai-swissknife`, its own `.git`) is
a convenient, always-available real git repo to test cloning behavior
against — you don't need network access to a remote host to test `git
clone`/`fetch` mechanics; a `file://` URL or a local path clone against
this very repo (or a temp repo you `git init` for the test) is a real git
operation, not a mock.

Steps:

1. Create `src/sources/gitCustom.ts`:

   ```ts
   import type { Source, Package } from '../domain/types';

   export interface GitCustomOptions {
     cacheDir: string; // where checkouts live, e.g. ~/.ai-toolkit/cache/sources/<sourceId>/
   }

   export async function resolveGitCustom(source: Source, opts: GitCustomOptions): Promise<Package[]>;
   ```

   - Use `child_process.execFile('git', [...])` (promisified), not a
     third-party git library — auth is delegated to whatever `git` on
     `PATH` already has configured (SSH agent, credential helper), which
     only works if you actually shell out to the real `git` binary, not a
     JS reimplementation.
   - If `opts.cacheDir/<derived-from-source-id>` doesn't exist yet: `git
     clone <source.url> <path>` (add `--branch <source.branch>` if set).
     If it already exists: `git fetch` then `git checkout` the resolved
     ref (`source.commit` takes precedence over `source.tag` over
     `source.branch` over the remote's default branch — implement that
     precedence order explicitly, don't just always use `HEAD`).
   - After checkout, call `findSkillDirs`/the local-folder resolution
     logic from task 04.1 (`src/sources/detect.ts`,
     `src/sources/localFolder.ts`) against the checkout path, and set
     each resulting `Package.sourceId` to `source.id` (the local-folder
     resolver from 04.1 doesn't know about a git `Source`'s id, since it
     takes a `local-folder`-typed `Source` — either call
     `findSkillDirs(checkoutPath)` directly here rather than going through
     `resolveLocalFolder`, or construct a synthetic `local-folder` `Source`
     wrapping the checkout path and reuse `resolveLocalFolder` unchanged —
     pick whichever keeps the code simpler, and say which you picked in
     your report).
   - Surface clear, distinct errors for: repo not found/auth failure (git
     exits non-zero on clone/fetch — propagate `stderr` in the thrown
     error, don't swallow it), and ref not found (git exits non-zero on
     checkout — same).
2. Write `src/sources/gitCustom.test.ts`:
   - Set up a real local git repo in a temp directory as the test fixture
     (`git init`, add a couple of real skill directories copied from one
     of task 04.1's fixtures, commit, optionally create a second branch
     with a different skill added) — a real repo, not a mock of `git`.
   - Test: `resolveGitCustom` against a `file://`-style local path (or a
     plain local path — check what your `git clone` invocation accepts;
     git supports cloning from a local path directly without `file://`)
     with no branch/tag/commit pin resolves the default branch and finds
     the expected skills.
   - Test: with a `tag` or `commit` pin set to an earlier state (before
     the second skill was added, if you set that up), resolves only the
     skills present at that point — this specifically verifies the
     precedence/checkout logic actually pins to the right ref, not just
     "whatever's on disk now".
   - Test: cloning twice (second call reuses the cache dir via fetch, not
     a fresh clone) still returns the correct, current result.
   - Test: a nonexistent local path as `source.url` produces a clear
     thrown error (not a silent empty result).
