# 04.1 — Rilevamento del formato + resolver per cartella locale

> Parte di [Resolver delle sorgenti](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: attraversare un albero di directory arbitrario e produrre
`Package[]` contenenti `Artifact[]` di tipo `skill`, senza richiedere alcun
manifest — questa è la logica centrale di "format detection" descritta in
SPEC.md §2.2 e il componente che `04.2` (git-custom) riutilizza sopra un
checkout git.

**Riferimenti nel codice**: tre directory fixture reali e strutturate in modo
diverso su cui eseguire i test (non inventare fixture esclusivamente sintetiche):

- `/Users/Alfredo/works/ai-coding-tools/agentic-coding-kit/plugins/common-tools/skills/gitignore/`
  — una skill reale situata un livello sotto `plugins/<plugin>/skills/`.
- `references/cc-swiss-knife/plugins/core/skills/documentation-standards/`
  (relativo a questo repository) — stessa struttura annidata, repository
  diverso.
- `~/.claude/skills/` — piatta, un solo livello (`~/.claude/skills/<name>/
  SKILL.md`), nessuna directory intermedia `plugins/`.

Passaggi:

1. Creare `src/sources/detect.ts`:

   ```ts
   import type { Package, Artifact } from '../domain/types';

   export interface DetectedSkillDir {
     path: string; // absolute path to the directory containing SKILL.md
     name: string; // from SKILL.md frontmatter, not the directory name — they can differ
   }

   export function findSkillDirs(rootDir: string): Promise<DetectedSkillDir[]>;
   ```

   Implementazione: attraversare ricorsivamente `rootDir` (usare `fs.readdir` con
   `{withFileTypes: true}`, non una libreria glob di terze parti — qui non
   serve), cercando qualsiasi directory che contenga direttamente un file
   `SKILL.md`. Leggere il frontmatter di quel `SKILL.md` quanto basta per
   estrarre `name` (riutilizzare l'approccio di estrazione del frontmatter
   dell'adapter Claude, task 03.2, se quel task è già stato completato —
   controllare `src/adapters/claude.ts`; se non è ancora presente, scrivere qui
   un estrattore minimale e autonomo del nome dal frontmatter e annotare nel
   report finale che il task 03.2 dovrà consolidare i due in un unico helper
   condiviso in seguito, senza bloccarsi su questo).
   - **Interrompere la ricorsione in una directory una volta identificata come
     directory di una skill** — le sottodirectory proprie di una skill (ad es.
     `scripts/`, `references/`) non devono essere scansionate alla ricerca di
     file `SKILL.md` annidati; una skill è una foglia a questo scopo.
   - Ignorare `node_modules`, `.git` e qualsiasi directory con prefisso dotfile
     durante l'attraversamento (prestazioni + correttezza — non scendere in
     `.git/`, che può contenere contenuto blob arbitrario che per caso
     corrisponde per nome a `SKILL.md` in qualche oggetto storico, sebbene
     improbabile; il vero motivo è semplicemente che non si tratta mai di una
     skill reale).
   - Nessun limite di profondità per il resto — i repository reali annidano le
     skill a profondità non uniformi (vedere le tre fixture sopra: 1 livello, 2
     livelli tramite `plugins/` e piatta).
2. Creare `src/sources/localFolder.ts`:

   ```ts
   import type { Source, Package } from '../domain/types';

   export async function resolveLocalFolder(source: Source): Promise<Package[]>;
   ```

   Per una `Source` con `type: 'local-folder'`, chiamare `findSkillDirs(source.localPath!)`
   e mappare ciascun risultato in un `Package` degenere (SPEC.md §1: "a
   single-skill repo is a degenerate `Package` with exactly one
   `Artifact`") — un `Package` per ogni directory di skill rilevata in questo
   task (non tentare ancora di raggruppare skill adiacenti in un `Package`
   condiviso; tale euristica di raggruppamento, se mai necessaria, appartiene
   alla Fase 2). Ogni `Package.id`/`Artifact.id` deve essere una stringa stabile
   e deterministica derivata dal percorso della skill (ad es. un hash o lo
   stesso percorso relativo) — non un UUID casuale, così che risolvere due volte
   la stessa cartella produca gli stessi id.
3. Scrivere `src/sources/detect.test.ts` e `src/sources/localFolder.test.ts`
   eseguendo `findSkillDirs`/`resolveLocalFolder` su **tutte e tre** le
   directory fixture reali elencate sopra (percorsi assoluti — leggerle
   direttamente, senza copiarle prima in una directory fixture temporanea) e
   verificando:
   - Il conteggio esatto delle skill trovate in ciascuna (calcolarlo prima
     elencando ciò che è effettivamente presente con `find <dir> -name
     SKILL.md`, non tirare a indovinare un numero).
   - Il `name` di ogni skill rilevata corrisponde a quanto effettivamente
     presente nel frontmatter di quel `SKILL.md` (verificare a campione almeno
     uno per ciascuna directory fixture).
   - Le sottodirectory annidate di una skill rilevata (ad es. una cartella
     `scripts/` al suo interno, se presente in una delle tre fixture) non
     vengono restituite a loro volta come skill separate.

**Verifica**: i file di test passano sulle fixture reali (non versioni mockate o
copiate); `npm run lint && npm run typecheck && npm run
build` terminano tutti con codice 0. Un unico commit contenente
`src/sources/detect.ts`, `src/sources/localFolder.ts` e i relativi due file di
test — nient'altro.
