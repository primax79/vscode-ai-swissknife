# 04.1 — Format detection + local-folder resolver

> Part of [Source resolver](plan.md) · spec: [../specs/foundations.md](../../specs/foundations.md)

**Goal**: walk an arbitrary directory tree and produce `Package[]`
containing `Artifact[]` of kind `skill`, without requiring any manifest —
this is the core "format detection" logic SPEC.md §2.2 describes, and the
piece `04.2` (git-custom) reuses on top of a git checkout.

**Grounding**: three real, differently-shaped fixture directories to test
against (don't invent synthetic-only fixtures):

- `/Users/Alfredo/works/ai-coding-tools/agentic-coding-kit/plugins/common-tools/skills/gitignore/`
  — a real skill one level under `plugins/<plugin>/skills/`.
- `references/cc-swiss-knife/plugins/core/skills/documentation-standards/`
  (relative to this repo) — same nested shape, different repo.
- `~/.claude/skills/` — flat, one level (`~/.claude/skills/<name>/
  SKILL.md`), no intermediate `plugins/` directory.

Steps:

1. Create `src/sources/detect.ts`:

   ```ts
   import type { Package, Artifact } from '../domain/types';

   export interface DetectedSkillDir {
     path: string; // absolute path to the directory containing SKILL.md
     name: string; // from SKILL.md frontmatter, not the directory name — they can differ
   }

   export function findSkillDirs(rootDir: string): Promise<DetectedSkillDir[]>;
   ```

   Implementation: recursively walk `rootDir` (use `fs.readdir` with
   `{withFileTypes: true}`, not a third-party glob library — this doesn't
   need one), looking for any directory that directly contains a
   `SKILL.md` file. Read that `SKILL.md`'s frontmatter far enough to
   extract `name` (reuse the frontmatter-splitting approach from the
   Claude adapter, task 03.2, if that task has landed — check
   `src/adapters/claude.ts`; if it hasn't landed yet, write a minimal,
   self-contained frontmatter-name extractor here and note in your report
   that task 03.2 should consolidate the two into one shared helper
   later, don't block on it).
   - **Stop recursing into a directory once it's identified as a skill
     dir** — a skill's own subdirectories (e.g. `scripts/`, `references/`)
     must not be scanned for nested `SKILL.md` files; a skill is a leaf
     for this purpose.
   - Skip `node_modules`, `.git`, and any dotfile-prefixed directory
     during the walk (performance + correctness — don't descend into
     `.git/`, which can contain arbitrary blob content that happens to
     match `SKILL.md` by name in some historical object, though unlikely;
     the real reason is simply that it's never a real skill).
   - No depth limit otherwise — real repos nest skills at inconsistent
     depths (see the three fixtures above: 1 level, 2 levels via
     `plugins/`, and flat).
2. Create `src/sources/localFolder.ts`:

   ```ts
   import type { Source, Package } from '../domain/types';

   export async function resolveLocalFolder(source: Source): Promise<Package[]>;
   ```

   For a `Source` of `type: 'local-folder'`, call `findSkillDirs(source.localPath!)`
   and map each result to a degenerate `Package` (SPEC.md §1: "a
   single-skill repo is a degenerate `Package` with exactly one
   `Artifact`") — one `Package` per detected skill dir in this task (don't
   try to group sibling skills into a shared `Package` yet; that grouping
   heuristic, if ever needed, is a Phase 2 concern). Each `Package.id`/
   `Artifact.id` should be a stable, deterministic string derived from the
   skill's path (e.g. a hash or the relative path itself) — not a random
   UUID, so re-resolving the same folder twice produces the same ids.
3. Write `src/sources/detect.test.ts` and `src/sources/localFolder.test.ts`
   running `findSkillDirs`/`resolveLocalFolder` against **all three**
   real fixture directories listed above (absolute paths — read them
   directly, don't copy them into a temp fixture dir first) and asserting:
   - The exact count of skills found in each (compute this yourself by
     first listing what's actually there with `find <dir> -name
     SKILL.md`, don't guess a number).
   - Every detected skill's `name` matches what's actually in that
     `SKILL.md`'s frontmatter (spot-check at least one per fixture
     directory).
   - Nested subdirectories of a detected skill (e.g. a `scripts/` folder
     inside one, if any of the three fixtures has one) are not
     themselves returned as separate skills.

**Verification**: the test files pass against the real fixtures (not
mocked/copied versions); `npm run lint && npm run typecheck && npm run
build` all exit 0. One commit containing `src/sources/detect.ts`,
`src/sources/localFolder.ts`, and their two test files — nothing else.
