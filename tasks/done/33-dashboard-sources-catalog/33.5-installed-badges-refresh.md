# 33.5 — Badge "Installed in" + aggiornamento del catalogo

**Depends on:** 33.4 (integrato).

## Perché

Il catalogo della sidebar mostra già in quali assistenti è installato un
artefatto, tramite descrizione/tooltip e non nell'etichetta (secondo la
copertura di `src/ui/ui.test.ts`: *"shows which assistants an artifact is installed in via
description and tooltip, not the label"*) — la vista catalogo della Dashboard
(33.2) finora renderizza le righe senza tale indicatore. Inoltre, ogni
mutazione di 33.1/33.4 richiede il refresh incrociato tra provider e barra di stato
prescritto da `specs/phase-9-spec.md` §4.1, che non è ancora stato cablato end-to-end
in nessun singolo task.

## Ambito

- Estendere `catalogData` (33.2) affinché includa lo stato installed-in di ciascun
  artefatto — `AvailableTreeDataProvider` lo traccia già tramite
  `installedByArtifactKey` (costruito durante `refreshCatalog`, secondo quanto rilevato dalla revisione di Codex
  — riconfermare il nome esatto del campo/accessor leggendo
  la classe) — esporlo nel payload invece di ricalcolare
  in modo indipendente lo stato di installazione nella Dashboard.
- UI della Dashboard: renderizzare un piccolo set di badge/icone per ciascuna riga artefatto del catalogo
  (riutilizzando il linguaggio visivo esistente `assistant-icon`/pill del CSS di
  `src/ui/dashboard.ts`, secondo il vincolo "mantieni lo stile esistente"
  della specifica) che mostri quali assistenti lo hanno già installato.
- Cablare `refreshCatalog` (rispecchiando `aiSwissknife.refreshCatalog`,
  `src/extension.ts:409`) come azione della Dashboard (ad es. un pulsante di aggiornamento nella
  sezione Sources & Catalog), e confermare che ogni percorso di mutazione di 33.1/33.4
  (`addSource`, `removeSource`, `importConfig`, `installArtifact`,
  `installFolder`, `installSourceGroup`) attivi effettivamente
  `availableProvider.refreshCatalog()` (alcuni lo fanno già internamente,
  come verificato per singolo metodo durante quei task — questo task costituisce il controllo
  finale end-to-end, non nuova logica per ciascuno) **e** il refresh della barra di stato e
  dei provider della sidebar tramite la callback dell'Iniziativa 32.1.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi.
- Manuale: installare un artefatto dalla vista catalogo della Dashboard, confermare che
  il relativo badge "installed in" compaia senza bisogno di un
  `refreshCatalog` manuale — dimostra che il refresh incrociato scatta effettivamente.
- Manuale: attivare `refreshCatalog` dalla Dashboard dopo aver modificato esternamente
  il contenuto di una sorgente (ad es. toccando i file di una sorgente
  local-folder) — confermare che la vista catalogo recepisca la modifica, in linea con quanto
  fa il comando `refreshCatalog` della sidebar.
