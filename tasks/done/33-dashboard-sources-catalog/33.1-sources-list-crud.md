# 33.1 — Elenco delle sorgenti + CRUD

**Depends on:** 32 (integrata, per il guscio a sezioni e il cablaggio dei provider).

## Perché

`SourcesTreeDataProvider.addSource`/`.removeSource`/`.exportConfig`/
`.exportSource`/`.importConfig` (`src/ui/sourcesView.ts:185,294,340,391,422`)
esistono oggi solo come comandi della sidebar (`src/extension.ts:399-407`) — la
Dashboard non può aggiungere, rimuovere o trasferire alcuna sorgente
(`specs/phase-9-spec.md` §0).

## Ambito

- Sezione **Sources & Catalog** di `src/ui/dashboard.ts` (contenitore segnaposto
  di 32.2): renderizzare due gruppi di scope (Global/Project), ciascuno dei quali
  elenca le proprie sorgenti — riutilizzare la forma dei dati di `SourcesTreeDataProvider.getChildren()`
  (`src/ui/sourcesView.ts:115-183`, la suddivisione `ScopeGroupItem`/
  `SourceItem`) come fonte di verità per cosa renderizzare, letta direttamente tramite
  `readManifest()` (in linea con il modo in cui `DashboardPanel.update()`
  legge già le sorgenti oggi a `:246,261`) invece di riderivare
  uno stato specifico dell'albero della sidebar.
- Azioni di intestazione per gruppo di scope: `+ Add Source`, e per riga sorgente:
  `Remove`, `Export`, più `Export All` / `Import` a livello di sezione.
- Nuovi messaggi webview `addSource` (`{scope?}`), `removeSource`
  (`{sourceId, scope}`), `exportConfig`, `exportSource` (`{sourceId,
  scope}`), `importConfig` — i gestori nell'extension host invocano direttamente
  `sourcesProvider.addSource(scope)`/`.removeSource(...)`/ecc.
  (32.1 ha già cablato `sourcesProvider` in `DashboardPanel`). Questi
  metodi mostrano già i propri prompt `showQuickPick`/`showInputBox`/
  `showSaveDialog`/`showOpenDialog` (secondo l'esplicito non-obiettivo del §2 di `specs/phase-9-spec.md`
  — i prompt nativi restano nativi) — il gestore della Dashboard
  si limita a invocarli e quindi ri-renderizza l'elenco delle sorgenti tramite
  `postMessage` (secondo il pattern di aggiornamento incrementale dell'Iniziativa 32.3, non una
  sostituzione completa dell'HTML) più il refresh incrociato del §4.1 (barra di stato +
  `sourcesProvider.refresh()`/`availableProvider.refreshCatalog()` della sidebar
  — la maggior parte di questi metodi invoca già `refreshCatalog()`/`refresh()`
  internamente; verificare prima di aggiungere una seconda chiamata ridondante).
- Notare che il flusso di conferma esistente di `removeSource` avvisa già quando una
  sorgente è referenziata da elementi installati/desiderati (`src/ui/sourcesView.ts:311-324`)
  — questo comportamento viene preservato automaticamente poiché la Dashboard invoca lo stesso
  metodo e non una reimplementazione.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi.
- Manuale: dalla Dashboard, aggiungere una sorgente global, aggiungere una sorgente project,
  esportarne una, esportarle tutte, rimuoverne una (con e senza installazioni
  dipendenti, per esercitare il percorso di conferma), importare un file di configurazione
  — l'esito di ciascuna azione deve corrispondere esattamente all'attivazione del comando
  equivalente nella sidebar (stessi prompt, stesso stato finale del manifest), e
  l'albero `Sources` della sidebar deve riflettere la modifica senza un ricaricamento
  manuale (dimostra il cablaggio del refresh incrociato).
