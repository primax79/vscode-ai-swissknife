# 33.1 — Sources list + CRUD

**Depends on:** 32 (merged, for the section shell and provider wiring).

## Why

`SourcesTreeDataProvider.addSource`/`.removeSource`/`.exportConfig`/
`.exportSource`/`.importConfig` (`src/ui/sourcesView.ts:185,294,340,391,422`)
exist only as sidebar commands (`src/extension.ts:399-407`) today — the
Dashboard cannot add, remove, or transfer a source at all
(`specs/phase-9-spec.md` §0).

## Scope

- `src/ui/dashboard.ts`'s **Sources & Catalog** section (placeholder
  container from 32.2): render two scope groups (Global/Project), each
  listing its sources — reuse `SourcesTreeDataProvider.getChildren()`'s
  own data shape (`src/ui/sourcesView.ts:115-183`, the `ScopeGroupItem`/
  `SourceItem` split) as the source of truth for what to render, read via
  `readManifest()` directly (matching how `DashboardPanel.update()`
  already reads sources today at `:246,261`) rather than re-deriving
  sidebar-tree-specific state.
- Header actions per scope group: `+ Add Source`, and per source row:
  `Remove`, `Export`, plus a section-level `Export All` / `Import`.
- New webview messages `addSource` (`{scope?}`), `removeSource`
  (`{sourceId, scope}`), `exportConfig`, `exportSource` (`{sourceId,
  scope}`), `importConfig` — extension-host handlers call
  `sourcesProvider.addSource(scope)`/`.removeSource(...)`/etc. directly
  (32.1 already wired `sourcesProvider` into `DashboardPanel`). These
  methods already show their own `showQuickPick`/`showInputBox`/
  `showSaveDialog`/`showOpenDialog` prompts (per `specs/phase-9-spec.md`
  §2's explicit non-goal — native prompts stay native) — the Dashboard
  handler just calls them and then re-renders the source list via
  `postMessage` (per Initiative 32.3's incremental-update pattern, not a
  full HTML replace) plus the cross-refresh from §4.1 (status bar +
  sidebar `sourcesProvider.refresh()`/`availableProvider.refreshCatalog()`
  — most of these methods already call `refreshCatalog()`/`refresh()`
  internally, confirm before adding a redundant second call).
- Note `removeSource`'s existing confirmation flow already warns when a
  source is referenced by installed/desired items (`src/ui/sourcesView.ts:311-324`)
  — this is preserved automatically since the Dashboard calls the same
  method, not a reimplementation.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green.
- Manual: from the Dashboard, add a global source, add a project source,
  export one, export-all, remove one (with and without dependent
  installations, to exercise the confirmation path), import a config file
  — each action's outcome must match triggering the equivalent sidebar
  command exactly (same prompts, same resulting manifest state), and the
  sidebar's `Sources` tree must reflect the change without a manual
  reload (proves the cross-refresh wiring).
