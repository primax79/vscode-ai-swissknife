# 33.3 — Azione di anteprima

**Depends on:** 33.2 (integrato).

## Perché

`previewArtifact` (`src/ui/availableView.ts:553`) consente alla sidebar di visualizzare in anteprima
il file principale di un artefatto disponibile (`SKILL.md` per una skill, il file di ingresso
per gli altri tipi) prima dell'installazione — funzionalità oggi del tutto irraggiungibile dalla
Dashboard.

## Ambito

- Nuovo messaggio webview `previewArtifact` con payload che identifica
  l'artefatto (`{sourceId, scope, packageId, artifactId}` o qualunque
  tupla identificativa richieda effettivamente l'implementazione attuale di `previewArtifact`
  una volta riletta — verificare i campi esatti a `:553-568` prima del cablaggio).
- Gestore nell'extension host: cercare l'artefatto corrispondente in cache da
  `getCachedSourceGroups()` (stesso pattern di ricerca di 33.2) e invocare
  `availableProvider.previewArtifact(...)` — questo apre un tab
  editor in sola lettura tramite il meccanismo di anteprima proprio di VS Code
  (`src/ui/previewProvider.ts`), esattamente come nella sidebar; non serve alcuna nuova UI di anteprima
  dentro la webview stessa, ma solo l'innesco.
- UI della Dashboard: un pulsante/icona "Preview" per ciascuna riga artefatto del rendering
  del catalogo di 33.2.
- Esplicitamente fuori ambito (secondo `specs/phase-9-spec.md` §4.1): la navigazione
  dei file ausiliari all'interno di un artefatto multi-file oltre il file di ingresso
  (`ArtifactFileItem`, `src/ui/artifactFileTree.ts`) — questo task copre
  solo ciò che `previewArtifact` fa già oggi, non un suo sovrainsieme.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi.
- Manuale: visualizzare in anteprima una skill, un agent e un artefatto mcp-server dalla
  vista catalogo della Dashboard — ciascuno apre lo stesso contenuto in sola lettura che
  il comando `Preview` della sidebar mostrerebbe per lo stesso artefatto.
