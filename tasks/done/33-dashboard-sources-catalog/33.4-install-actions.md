# 33.4 — Azioni di installazione

**Depends on:** 31.2 (integrato, per i metodi di installazione `do*` disaccoppiati),
33.2 (integrato, per le righe del catalogo da cui installare).

## Perché

Questo è il flusso principale "scopri e installa qualcosa di nuovo"
(`aiSwissknife.installArtifact`/`installFolder`/`installSourceGroup`,
`src/extension.ts:409-421`) — oggi del tutto assente dalla Dashboard.
L'Iniziativa 31.2 (integrata) ha già svolto il lavoro preparatorio: `doInstallSourceGroup`,
`doInstallFolder` e `doInstallArtifact` esistono tutti su
`AvailableTreeDataProvider` come punti di ingresso basati su identificatori semplici, e
`installBatch` è pubblico — verificarne le firme attuali esatte
leggendo direttamente `src/ui/availableView.ts` (31.2 è stato integrato in modo indipendente e
potrebbe averli strutturati in modo leggermente diverso dalla bozza iniziale); questo
task li collega alla webview, non li costruisce.

## Ambito

- Nuovi messaggi webview `installArtifact`, `installFolder`,
  `installSourceGroup` che trasportano i campi identificativi richiesti dalle firme
  reali di `doInstallArtifact`/`doInstallFolder`/`doInstallSourceGroup`
  di 31.2 (`{sourceId, scope, ...}` più `targetAssistant`/
  `targetScope` una volta selezionati) — il selettore di assistente/scope di destinazione rimane un
  `showQuickPick` nativo secondo il non-obiettivo della specifica (§2), attivato dal
  gestore nell'extension host esattamente come fanno già oggi questi metodi.
  **Le sue opzioni di assistente devono provenire da `getEnabledAdapters()`
  (`src/adapters/registry.ts`), mai da `ALL_ADAPTERS`** — confermato ancora
  vero al 2026-09-08 in `src/ui/availableView.ts:552,790` per i
  selettori esistenti attivati dalla sidebar; questa è una regola di progetto vincolata
  (`tasks/CONTEXT.md`, "Any `showQuickPick` that lets the user pick a
  TARGET assistant...") che **non** si propaga automaticamente se l'implementazione
  di questo task copia la logica del selettore in un nuovo punto di chiamata invece
  di invocare direttamente i metodi esistenti — preferire la chiamata diretta a
  `doInstallArtifact`/`doInstallFolder`/`doInstallSourceGroup` così come sono (costruiscono
  già il proprio selettore filtrato correttamente) rispetto alla reimplementazione
  del selettore nel gestore di messaggi della Dashboard.
- L'anteprima prima dell'installazione e l'anteprima batch (`showPreview`/
  `showBatchPreview`) rimangono nel loro flusso di anteprima nativo di VS Code esistente —
  riutilizzarlo così com'è, senza reimplementazioni dentro la webview.
- UI della Dashboard: azione "Install" per riga artefatto, per gruppo cartella e
  per sorgente (dalla riga sorgente di 33.1) — ciascuna invia il messaggio
  corrispondente, dopodiché (secondo il pattern di aggiornamento incrementale dell'Iniziativa 32.3)
  l'extension host risponde con i dati aggiornati del catalogo/stato installato invece
  di ricaricare l'intera pagina.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi.
- Manuale: installare un singolo artefatto, un'intera cartella e un'intera sorgente
  dalla Dashboard, per almeno due tipi diversi (ad es. skill +
  mcp-server) — confermare esiti identici (stesse scritture su manifest/stato,
  stessi prompt di gestione dei conflitti) rispetto all'attivazione del comando
  equivalente nella sidebar, e confermare che l'albero `Installed` della sidebar rifletta la nuova
  installazione senza un ricaricamento manuale.
- Manuale: innescare un conflitto (installare qualcosa già installato) dalla
  Dashboard — confermare che compaia lo stesso prompt di conferma di sovrascrittura mostrato dalla
  sidebar e che rifiutandolo lo stato resti invariato.
- Manuale: con almeno un assistente disabilitato tramite
  `aiSwissknife.enabledAssistants`, avviare un'installazione dalla Dashboard
  — confermare che il selettore dell'assistente di destinazione escluda quello disabilitato, esattamente
  come avviene nei comandi di installazione della sidebar.
