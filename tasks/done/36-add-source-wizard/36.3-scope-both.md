# 36.3 — Selezione multi-scope + gestione degli id duplicati

Un task, un commit. Dipende da 36.2. Q3 e Q4 sono decise.

**Read first:** `plan.md`, `src/ui/sourcesView.ts` (post-36.2), `src/domain/registry.ts:97-135` (`toDesiredSource`: il percorso di progetto deve trovarsi dentro il workspace, il percorso globale sotto la home), `src/engine/configTransfer.ts:75`.

## Cosa fare

- Trasformare il passo dello scope in una selezione multipla (Global e/o Workspace, almeno uno); continua a essere saltato quando `forceScope` è impostato.
- `local-folder`: chiedere un percorso per ciascuno scope selezionato, in modo indipendente, validando ciascuno rispetto al vincolo del proprio scope al momento dell'input (`validateInput`) usando la stessa regola di `toDesiredSource`, così che l'errore compaia durante la digitazione e non al momento della scrittura. Offrire il selettore di cartella per ciascuno. Tipi git e `remote-url`: un solo URL per tutti gli scope.
- Scrivere un `DesiredSource` per scope (stesso id, nome, tipo). Se una scrittura successiva fallisce, segnalare quale scope è riuscito e quale è fallito (nessun rollback silenzioso). Restituire la prima `Source` scritta.
- Id duplicato in uno scope di destinazione: (Q3, decisa): modale "Replace?" per scope; "No" salta solo quello scope e gli altri proseguono. Nessun workspace aperto (Q4, decisa): il passo dello scope offre solo Global, con un suggerimento su una riga per aprire una cartella; Workspace non è mai selezionabile, quindi non serve alcuna gestione post-selezione.

## Verification

`ui.test.ts`: entrambi gli scope con due percorsi locali diversi scrivono due manifest con lo stesso id e `localPath` diversi; un percorso di progetto fuori dal workspace viene rifiutato all'input; solo-global e solo-project continuano a funzionare; il messaggio di errore sulla seconda scrittura indica lo scope; un id duplicato mostra il prompt e rispetta "No". `npm test` verde, `npm run build` pulito.
