# 06.1 — Risolvere, tradurre e preparare un'anteprima immutabile

> Parte di [Motore di installazione](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md) · decisioni di revisione accettate: [round 001](../../_reviews/001-hardening-gate-SUMMARY.md) e [round 002](../../_reviews/002-hardening-gate-SUMMARY.md), in particolare le decisioni 1, 6, 8, 10, 15 e 16. Questo file sostituisce tutte le bozze precedenti.

## Goal

Risolvere il contenuto reale della skill, tradurlo per la destinazione selezionata, calcolare un'anteprima esatta rispetto a una directory di destinazione sicura e restituire un `PreparedInstall` discriminato il cui ramo supportato contiene l'esatto payload tradotto che verrà successivamente approvato dall'utente.

Questo task deve produrre un unico commit contenente solo le proprie modifiche.

## Riferimenti nel codice

Leggere i contratti reali di `SourceResolution`, `ResolvedArtifact<CanonicalSkill>`, adapter, traduttore e `canonicalSkillHash` dai task 02.3–05.2. Rieseguire `rg` su ogni chiamante prima di modificare le firme.

## Contratto

Definire un risultato discriminato; i piani non supportati non devono trasportare contenuto plausibile:

```ts
export interface UnsupportedInstallPlan {
  supported: false;
  sourceId: string;
  packageId: string;
  artifactId: string;
  reason: string;
  diagnostics?: TranslationDiagnostic[];
}

export interface SupportedInstallPlan {
  supported: true;
  sourceId: string;
  packageId: string;
  artifactId: string;
  targetAssistant: AssistantId;
  targetScope: Scope;
  targetDir: string;
  sourceRevision?: ResolvedRevision;
  conflict: boolean;
  existingFiles: Array<{ path: string; contentHash: string }>;
  proposedFiles: Array<{ path: string; contentHash: string; mode?: number }>;
  diagnostics: TranslationDiagnostic[];
}

export type PreparedInstall =
  | { supported: false; plan: UnsupportedInstallPlan }
  | {
      supported: true;
      plan: SupportedInstallPlan;
      content: CanonicalSkill;
      contentHash: string;
    };
```

`planInstall()` riceve la `Source` a runtime, il `Package` e l'`Artifact` selezionati, l'adapter di destinazione, lo scope/radice del progetto di destinazione e le opzioni del resolver richieste per il tipo di sorgente. Restituisce `Promise<PreparedInstall>` ed esegue esclusivamente letture.

## Steps

1. Rifiutare i tipi non supportati restituendo `{ supported: false, plan: { supported: false, ... } }`. La Fase 1 supporta solo `artifact.kind === 'skill'`; non risolvere, tradurre, calcolare hash o ispezionare una destinazione per altri tipi.

2. Smistare in base a `source.type` verso il corretto `resolveArtifactContent()` tipizzato e chiamare il risultato `resolvedContent`. Popolare esattamente `plan.sourceRevision = pkg.version`; i pacchetti locali lo lasciano naturalmente undefined.

3. Chiamare `translateSkill(resolvedContent.content, targetAdapter.assistant)`. Se `overall === 'unsupported'`, restituire il ramo non supportato con il relativo motivo e le diagnostiche; non creare contenuto fittizio. Per una traduzione supportata, tutte le successive operazioni di validazione, calcolo hash, diff e il `content` restituito utilizzano **`translation.value`**, mai `resolvedContent.content`.

4. Validare il nome della skill tradotta e tutti i percorsi del payload con le regole del codec condiviso. Risolvere la directory di destinazione esclusivamente tramite `targetAdapter.skillDir(translation.value.name, {scope, projectRoot})` — non usare mai `skillPath()`.

5. Ispezionare `targetDir` con `lstat`:

   - `ENOENT` indica una nuova installazione e uno snapshot esistente vuoto.
   - Una directory reale viene attraversata ricorsivamente con `lstat`; registrare l'insieme esatto normalizzato dei file regolari e i relativi hash.
   - Un symlink non viene mai seguito. Rifiutare symlink, file regolari, socket, device, FIFO, directory/voci illeggibili o qualsiasi altro stato della destinazione che non sia una directory.

6. Costruire l'elenco esatto dei file proposti a partire dalla serializzazione deterministica di `SKILL.md` più `translation.value.files`, inclusi i permessi (mode) ove definiti. Calcolare l'insieme esplicito dei file non coperti (`existingFiles` meno `proposedFiles`, per percorso). Se l'insieme dei file non coperti non è vuoto, forzare 06.2 al rifiuto (la Fase 1 può solo sostituire percorsi già presenti nel payload proposto). Esiste un conflitto quando la directory di destinazione non è vuota o qualsiasi percorso proposto collide. L'anteprima deve mostrare aggiunte, sostituzioni, diagnostiche di traduzione, percorso di destinazione, scope e revisione (non includere rimozioni arbitrarie).

7. Calcolare `contentHash` esclusivamente tramite la funzione condivisa `canonicalSkillHash(translation.value)`. Restituire il ramo supportato con `content: translation.value`. Trattare l'oggetto come immutabile per convenzione (il congelamento è consentito ma non sostituisce la verifica al momento dell'applicazione in 06.2).

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build.
- Un test double del traduttore che modifica descrizione/corpo/contenuto dei file dimostra che `PreparedInstall.content`, gli hash proposti e `contentHash` derivano tutti da `translation.value`.
- La pianificazione Git imposta `sourceRevision` all'esatto `pkg.version`; la pianificazione locale lo lascia undefined.
- I rami per tipo non supportato e destinazione non supportata non contengono `content`/`contentHash` e non eseguono alcuna modifica sulla destinazione.
- I casi di destinazione mancante, directory popolata, symlink, file regolare, socket e destinazione illeggibile si comportano come specificato; nessun symlink viene seguito.
- Lo snapshot esistente include ogni file attualmente presente nella destinazione così che 06.2 possa rilevare eventuali aggiunte avvenute dopo l'anteprima.

## Non-obiettivi

- Nessuna scrittura, staging, UI di approvazione o aggiornamento del registro.
- Nessuna installazione di artefatti diversi dalle skill.
