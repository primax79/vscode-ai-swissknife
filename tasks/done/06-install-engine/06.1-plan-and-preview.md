# 06.1 — Resolve, translate, and prepare an immutable preview

> Part of [Install engine](plan.md) · spec: [../specs/foundations.md](../../specs/foundations.md) · accepted review decisions: [round 001](../../_reviews/001-hardening-gate-SUMMARY.md) and [round 002](../../_reviews/002-hardening-gate-SUMMARY.md), especially decisions 1, 6, 8, 10, 15, and 16. This file supersedes all earlier drafts.

## Goal

Resolve real skill content, translate it for the selected target, compute an exact preview against a safe target directory, and return a discriminated `PreparedInstall` whose supported branch contains the exact translated payload later approved by the user.

This task must produce one commit containing only its changes.

## Grounding

Read the real `SourceResolution`, `ResolvedArtifact<CanonicalSkill>`, adapter, translator, and `canonicalSkillHash` contracts from tasks 02.3–05.2. Re-`rg` every caller before changing signatures.

## Contract

Define a discriminated result; unsupported plans must not carry plausible content:

```ts
export interface UnsupportedInstallPlan {
  supported: false;
  sourceId: string;
  packageId: string;
  artifactId: string;
  reason: string;
  diagnostics?: TranslationDiagnostic[];
}

export interface SupportedInstallPlan {
  supported: true;
  sourceId: string;
  packageId: string;
  artifactId: string;
  targetAssistant: AssistantId;
  targetScope: Scope;
  targetDir: string;
  sourceRevision?: ResolvedRevision;
  conflict: boolean;
  existingFiles: Array<{ path: string; contentHash: string }>;
  proposedFiles: Array<{ path: string; contentHash: string; mode?: number }>;
  diagnostics: TranslationDiagnostic[];
}

export type PreparedInstall =
  | { supported: false; plan: UnsupportedInstallPlan }
  | {
      supported: true;
      plan: SupportedInstallPlan;
      content: CanonicalSkill;
      contentHash: string;
    };
```

`planInstall()` receives the runtime `Source`, selected `Package` and `Artifact`, target adapter, target scope/project root, and resolver options required for the source type. It returns `Promise<PreparedInstall>` and performs reads only.

## Steps

1. Reject unsupported kinds as `{ supported: false, plan: { supported: false, ... } }`. Phase 1 supports only `artifact.kind === 'skill'`; do not resolve, translate, hash, or inspect a target for other kinds.

2. Dispatch by `source.type` to the correct typed `resolveArtifactContent()` and name the result `resolvedContent`. Populate `plan.sourceRevision = pkg.version` exactly; local packages naturally leave it undefined.

3. Call `translateSkill(resolvedContent.content, targetAdapter.assistant)`. If `overall === 'unsupported'`, return the unsupported branch with its reason and diagnostics; do not create dummy content. For supported translation, all later validation, hashing, diffing, and returned `content` use **`translation.value`**, never `resolvedContent.content`.

4. Validate the translated skill name and all payload paths with the shared codec rules. Resolve the target directory exclusively via `targetAdapter.skillDir(translation.value.name, {scope, projectRoot})` — never use `skillPath()`.

5. Inspect `targetDir` with `lstat`:

   - `ENOENT` means a fresh install and an empty existing snapshot.
   - A real directory is walked recursively with `lstat`; record the exact normalized set of regular files and hashes.
   - A symlink is never followed. Refuse symlinks, regular files, sockets, devices, FIFOs, unreadable directories/entries, or any other non-directory target state.

6. Build the exact proposed file list from deterministic `SKILL.md` serialization plus `translation.value.files`, including modes where defined. Calculate the explicit uncovered-files set (`existingFiles` minus `proposedFiles`, by path). If the uncovered-files set is non-empty, force 06.2 to refuse (Phase 1 may only ever replace paths already present in the proposed payload). A conflict exists when the target directory is non-empty or any proposed path collides. The preview must show additions, replacements, translation diagnostics, target path, scope, and revision (do not include arbitrary removals).

7. Compute `contentHash` only with shared `canonicalSkillHash(translation.value)`. Return the supported branch with `content: translation.value`. Treat the object as immutable by convention (freezing is allowed but not a substitute for apply-time verification in 06.2).

## Verification

- Run the full test suite, typecheck, lint, and build.
- A translator test double that changes description/body/file content proves `PreparedInstall.content`, proposed hashes, and `contentHash` all derive from `translation.value`.
- Git planning sets `sourceRevision` to the exact `pkg.version`; local planning leaves it undefined.
- Unsupported kind and unsupported target branches contain no `content`/`contentHash` and perform no target mutation.
- Missing target, populated directory, symlink, regular file, socket, and unreadable target cases behave as specified; no symlink is followed.
- The existing snapshot includes every current target file so 06.2 can detect additions after preview.

## Non-goals

- No writes, staging, approval UI, or registry update.
- No non-skill install.
