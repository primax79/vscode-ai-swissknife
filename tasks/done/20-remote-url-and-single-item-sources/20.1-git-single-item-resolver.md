# 20.1 — Resolver `git-single-item`

> Parte di [Sorgenti `remote-url` e `git-single-item`](plan.md) · spec: [../specs/phase-4-spec.md](../../specs/phase-4-spec.md) §6

## Goal

Implementare il valore `git-single-item` di `SourceType` (già presente nell'unione `SourceType`
in `src/domain/types.ts`, ma ancora privo di resolver): un repository Git che rappresenta esso stesso
un singolo artefatto, senza manifesto marketplace e senza struttura a directory
affiancate — a differenza di `git-custom`, che scansiona molteplici directory
`SKILL.md` affiancate.

Questo task deve produrre un singolo commit contenente solo le proprie modifiche.

## Riferimenti nel codice

- Meccanismo di clone/checkout/mutex da riutilizzare così com'è: `KeyedMutex`, la
  sequenza di comandi git di clone/checkout in `src/sources/gitCustom.ts` (già
  riutilizzata da `src/sources/gitMarketplace.ts` — seguire quel pattern di riutilizzo,
  senza reimplementare le operazioni git una terza volta).
- Helper di rilevamento da riutilizzare: `findSkillDirs`/`findAgentFiles`/
  `findCommandFiles`/`findMcpDefinitions` (`src/sources/detect.ts`) —
  applicati alla singola radice estratta invece che tramite scansione ricorsiva.
- Struttura dell'output di risoluzione: `SourceResolution`, `DetectionDiagnostic`
  (`src/sources/types.ts`).

## Steps

1. In `src/sources/gitSingleItem.ts`, clonare/estrarre il repository (usando gli stessi
   campi di fissaggio branch/tag/commit già presenti su `Source` — `branch`/`tag`/
   `commit` in `src/domain/types.ts`) tramite il mutex condiviso.
2. Rilevare il tipo del singolo artefatto nella radice estratta: provare
   prima `SKILL.md` nella radice (tipo `skill`), poi i pattern di frontmatter di agent/command,
   infine un file di configurazione MCP — riutilizzando la logica di parsing di `detect.ts`
   direttamente sul percorso radice invece della scansione di directory `find*` (quelle
   scansionano *molteplici* candidati; qui ce n'è esattamente uno, in una posizione
   nota).
3. Se il rilevamento è ambiguo (es. la radice ha sia uno `SKILL.md` sia un
   file agent separato) o non trova nulla di riconoscibile, restituire una
   `DetectionDiagnostic` che spieghi il motivo, non un risultato vuoto silenzioso.
4. Produrre esattamente un `Package` con esattamente un `Artifact`, secondo la
   nota "un repository a singola skill è un `Package` degenere" già presente in
   `SPEC.md` §1.
5. Aggiungere unit test usando una fixture di repository locale usa e getta (secondo la convenzione
   esistente dei "test portabili" in `CONTEXT.md` — nessun repository di rete live),
   coprendo: skill nella radice, agent nella radice, diagnostica per radice ambigua e
   diagnostica per radice non riconosciuta.
