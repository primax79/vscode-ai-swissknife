# 20.2 — Resolver `remote-url`

> Parte di [Sorgenti `remote-url` e `git-single-item`](plan.md) · spec: [../specs/phase-4-spec.md](../../specs/phase-4-spec.md) §6

## Goal

Implementare il valore `remote-url` di `SourceType` (già nell'unione, ma ancora privo di resolver):
un singolo file o piccolo manifesto recuperato tramite semplice HTTP(S) — senza Git
(es. un URL raw di gist/file).

Questo task deve produrre un singolo commit contenente solo le proprie modifiche.

## Riferimenti nel codice

- Il campo `Source.url` esiste già (`src/domain/types.ts`) — questo
  resolver è il primo a usarlo effettivamente per un recupero non-git.
- Convenzione di caching da rispettare: lo schema di directory di cache già usato da
  `gitCustom.ts`/`gitMarketplace.ts` (opzione `cacheDir`, vedere
  `GitMarketplaceResolveOptions` in `src/sources/gitMarketplace.ts`) — riutilizzare
  la stessa convenzione della directory di base, con un sottopercorso diverso.
- Struttura dell'output di risoluzione: `SourceResolution`, `DetectionDiagnostic`
  (`src/sources/types.ts`).

## Steps

1. In `src/sources/remoteUrl.ts`, recuperare `Source.url` via HTTPS (`https` integrato di Node
   / `fetch` globale, nessuna nuova dipendenza), rilevare il tipo di contenuto
   dal corpo scaricato nello stesso modo in cui `gitSingleItem` (20.1) fa per una
   radice estratta (provare frontmatter in stile `SKILL.md`, poi agent/command,
   infine JSON MCP) — condividere la logica di rilevamento con 20.1 invece di
   duplicarla se 20.1 arriva prima (controllare il task fratello in `20-remote-url-and-single-item-sources`
   prima di scrivere un secondo rilevatore).
2. Nuovo recupero basato sull'hash del contenuto: memorizzare l'ultimo hash visto (o l'ETag se il
   server ne invia uno) accanto al file in cache; saltare il nuovo download durante il refresh
   se invariato, rispettando il comportamento di "diff rispetto alla cache precedente"
   già richiesto da `SPEC.md` §2 per il refresh del catalogo in generale.
3. Rifiutare per impostazione predefinita gli URL non-HTTPS (HTTP solo se la `Source` dell'utente
   lo abilita esplicitamente — trattare il semplice HTTP come un confine di fiducia da segnalare,
   non consentito silenziosamente) e limitare la dimensione della risposta per evitare di scaricare un
   file di dimensioni illimitate.
4. Produrre esattamente un `Package`/`Artifact`, con la stessa struttura di pacchetto degenere
   di 20.1.
5. Aggiungere unit test su un server fixture locale (o un fetch simulato) — nessuna
   chiamata di rete live nella suite di test, secondo la convenzione dei "test portabili".

## Verification

- Eseguire l'intera suite di test, lint, typecheck, build.
