# 02.2 — Store del registro (lettura/scrittura JSON, globale + progetto)

> Parte di [Tipi di dominio + store del registro](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: un piccolo modulo che legge e scrive il file JSON del registro in
entrambi gli scope, con scritture atomiche e nessuna dipendenza dalle API di
VSCode (deve essere testabile con unit test usando il semplice modulo `fs` di
Node).

**Riferimenti nel codice**: SPEC.md §1 "Registry / Lockfile" e §4 "Registry
store" per il requisito di doppia istanza (globale/progetto) con schema
condiviso.

Passaggi:

1. Creare `src/domain/registry.ts`:

   ```ts
   import type { Source, ManagedInstallation } from './types';

   export interface RegistryFile {
     sources: Source[];
     installations: ManagedInstallation[];
   }

   export function emptyRegistry(): RegistryFile {
     return { sources: [], installations: [] };
   }

   export function registryPath(scope: 'global' | 'project', projectRoot?: string): string {
     // global: os.homedir() + '/.ai-toolkit/registry.json'
     // project: requires projectRoot; projectRoot + '/.ai-toolkit/registry.json'
     // throw a clear Error if scope === 'project' and projectRoot is missing —
     // do not silently fall back to global.
   }

   export async function readRegistry(scope: 'global' | 'project', projectRoot?: string): Promise<RegistryFile> {
     // if the file doesn't exist yet, return emptyRegistry() — this is the
     // normal first-run state, not an error condition.
     // if the file exists but fails to JSON.parse, throw a clear Error
     // naming the file path — do not silently treat a corrupt file as empty,
     // that would silently discard a user's existing registry.
   }

   export async function writeRegistry(scope: 'global' | 'project', data: RegistryFile, projectRoot?: string): Promise<void> {
     // atomic write: write to `<path>.tmp-<random>`, then fs.rename() over
     // the real path (rename is atomic on the same filesystem — this is the
     // "atomic and recoverable" requirement from SPEC.md §2 "apply", reused
     // here for the simpler registry-write case).
     // ensure the parent directory exists first (fs.mkdir with recursive:
     // true) — the global `~/.ai-toolkit/` directory won't exist on a fresh
     // machine.
   }
   ```

   Implementare il corpo delle tre funzioni seguendo i commenti sopra — i
   commenti costituiscono la specifica di ciascuna funzione, non sono riempitivi
   da cancellare.
2. Non aggiungere alcun import delle API di VSCode (`import * as vscode from 'vscode'`)
   in questo file — deve essere puro Node così da poter essere testato tramite
   unit test senza l'Extension Development Host. `projectRoot` è un semplice
   parametro stringa che il chiamante (un'iniziativa successiva, quando ci sarà
   codice di UI/attivazione) risolverà a partire da
   `vscode.workspace.workspaceFolders` — tale risoluzione NON appartiene a
   questo file.
3. Scrivere un piccolo file di test `src/domain/registry.test.ts` (semplice
   `assert` di Node + una struttura compatibile con `node --test`, oppure `mocha`
   se si preferisce — controllare quale dei due è già presente in `package.json`
   sotto `devDependencies` dall'iniziativa 01 e usare quello, non
   aggiungere un secondo test runner) che copra:
   - `readRegistry` su un percorso inesistente restituisce `emptyRegistry()`.
   - `writeRegistry` seguito da `readRegistry` preserva esattamente gli stessi
     dati (scrivere un `Source` e una `ManagedInstallation` con un paio di campi
     ciascuno, rileggerli, verificare la deep-equality).
   - `readRegistry` su un file contenente JSON non valido solleva un'eccezione,
     con un messaggio che include il percorso del file.
   - `registryPath('project')` senza `projectRoot` solleva un'eccezione.
   Usare una directory temporanea (`os.tmpdir()` + una sottocartella univoca,
   ripulita dopo ogni test) per tutto questo — non toccare mai la vera directory
   `~/.ai-toolkit/` durante i test.
4. Aggiungere uno script `"test"` a `package.json` se non ne esiste già uno che
   esegue questo file di test, ed eseguirlo.

**Verifica**: il file di test passa; `npm run typecheck` e `npm run
lint` terminano entrambi con codice 0. Un unico commit contenente
`src/domain/registry.ts`, `src/domain/registry.test.ts` ed eventuali modifiche a
`package.json`/lockfile necessarie per eseguire il test — nient'altro. Dopo
questo commit, aggiornare in `00-INDEX.md` la riga dell'iniziativa `02` a
`✅ done`.
