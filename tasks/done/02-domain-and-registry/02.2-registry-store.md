# 02.2 — Registry store (read/write JSON, global + project)

> Part of [Domain types + registry store](plan.md) · spec: [../specs/foundations.md](../../specs/foundations.md)

**Goal**: a small module that reads/writes the registry JSON file at
either scope, with atomic writes, and no VSCode API dependency (must be
unit-testable with plain Node `fs`).

**Grounding**: SPEC.md §1 "Registry / Lockfile" and §4 "Registry store"
for the two-instance (global/project), shared-schema requirement.

Steps:

1. Create `src/domain/registry.ts`:

   ```ts
   import type { Source, ManagedInstallation } from './types';

   export interface RegistryFile {
     sources: Source[];
     installations: ManagedInstallation[];
   }

   export function emptyRegistry(): RegistryFile {
     return { sources: [], installations: [] };
   }

   export function registryPath(scope: 'global' | 'project', projectRoot?: string): string {
     // global: os.homedir() + '/.ai-toolkit/registry.json'
     // project: requires projectRoot; projectRoot + '/.ai-toolkit/registry.json'
     // throw a clear Error if scope === 'project' and projectRoot is missing —
     // do not silently fall back to global.
   }

   export async function readRegistry(scope: 'global' | 'project', projectRoot?: string): Promise<RegistryFile> {
     // if the file doesn't exist yet, return emptyRegistry() — this is the
     // normal first-run state, not an error condition.
     // if the file exists but fails to JSON.parse, throw a clear Error
     // naming the file path — do not silently treat a corrupt file as empty,
     // that would silently discard a user's existing registry.
   }

   export async function writeRegistry(scope: 'global' | 'project', data: RegistryFile, projectRoot?: string): Promise<void> {
     // atomic write: write to `<path>.tmp-<random>`, then fs.rename() over
     // the real path (rename is atomic on the same filesystem — this is the
     // "atomic and recoverable" requirement from SPEC.md §2 "apply", reused
     // here for the simpler registry-write case).
     // ensure the parent directory exists first (fs.mkdir with recursive:
     // true) — the global `~/.ai-toolkit/` directory won't exist on a fresh
     // machine.
   }
   ```

   Fill in the three function bodies per the comments above — the
   comments are the spec for each function, not filler to delete.
2. Do not add any VSCode API import (`import * as vscode from 'vscode'`)
   to this file — it must be pure Node so it can be unit-tested without
   the Extension Development Host. `projectRoot` is a plain string
   parameter the caller (a later initiative, once there's UI/activation
   code) resolves from `vscode.workspace.workspaceFolders` — that
   resolution does NOT belong in this file.
3. Write a small test file `src/domain/registry.test.ts` (plain Node
   `assert` + a `node --test` compatible structure, or `mocha` if you
   prefer — check which one `package.json`'s `devDependencies` already
   has from initiative 01 and use that one, don't add a second test
   runner) covering:
   - `readRegistry` on a non-existent path returns `emptyRegistry()`.
   - `writeRegistry` then `readRegistry` round-trips the same data
     (write a `Source` and a `ManagedInstallation` with a couple of
     fields each, read it back, assert deep-equality).
   - `readRegistry` on a file containing invalid JSON throws, with a
     message that includes the file path.
   - `registryPath('project')` with no `projectRoot` throws.
   Use a temp directory (`os.tmpdir()` + a unique subfolder, cleaned up
   after each test) for all of this — never touch the real
   `~/.ai-toolkit/` during tests.
4. Add a `"test"` script to `package.json` if one doesn't already run
   this test file, and run it.

**Verification**: the test file passes; `npm run typecheck` and `npm run
lint` both exit 0. One commit containing `src/domain/registry.ts`,
`src/domain/registry.test.ts`, and any `package.json`/lockfile change
needed to run the test — nothing else. After this commit, update
`00-INDEX.md`'s row for initiative `02` to `✅ done`.
