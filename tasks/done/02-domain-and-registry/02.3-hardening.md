# 02.3 — Persistenza portabile e artefatti risolti tipizzati (hardening)

> Parte di [Tipi di dominio + store del registro](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md) · decisioni di revisione accettate: [round 001](../../_reviews/001-hardening-gate-SUMMARY.md) e [round 002](../../_reviews/002-hardening-gate-SUMMARY.md), in particolare le decisioni 4, 7, 8 e 19. Richiede il codec condiviso di 03.4; questo file sostituisce ogni bozza precedente.

## Goal

Rendere la persistenza realmente portabile e rendere type-safe il confine tra metadati e contenuto. Un manifest di progetto non deve mai serializzare percorsi assoluti specifici della macchina, mentre la risoluzione del contenuto delle skill deve restituire una `CanonicalSkill` senza cast e non deve entrare in race condition su un checkout Git condiviso.

Questo task costituisce un'unità verificabile in modo indipendente e deve produrre un unico commit contenente solo le proprie modifiche.

## Riferimenti nel codice

Prima di modificare il codice, rieseguire `rg` per ogni chiamante di `readRegistry`, `writeRegistry`, `resolveArtifactContent`, `resolveGitCustom` e `findSkillDirs`; il codice si è spostato durante le revisioni di hardening. Leggere `src/domain/types.ts`, `src/domain/registry.ts`, `src/sources/localFolder.ts`, `src/sources/gitCustom.ts` e `src/adapters/types.ts`.

## Steps

1. Rinominare ogni percorso dati a runtime sotto `src/` da `.ai-toolkit` a `.ai-swissknife`. Non c'è alcuna migrazione: non esistono dati utente rilasciati sotto il vecchio nome.

2. Aggiungere la provenienza della revisione:

   ```ts
   export interface ResolvedRevision {
     commit: string;
     requestedRef?: string;
   }
   ```

   `Package.version` e `ManagedInstallation.sourceRevision` usano questo tipo. Per le sorgenti Git, `commit` è lo SHA estratto e `requestedRef` è il branch/tag/ref richiesto dalla `Source`; non introdurre alcun alias per `requestedRef`. Dichiarare esplicitamente che `sourceRevision` sostituisce/rimuove il campo legacy `ManagedInstallation.installedVersion`. I pacchetti da cartella locale non hanno una revisione risolta.

3. Aggiungere un contenitore di contenuto tipizzato senza parametro generico predefinito:

   ```ts
   export interface ResolvedArtifact<T> {
     artifact: Artifact;
     content: T;
   }
   ```

   Entrambi gli entry point del resolver delle skill devono restituire `Promise<ResolvedArtifact<CanonicalSkill>>`. È vietato un cast `unknown` non controllato su questo confine.

4. Implementare la risoluzione del contenuto delle skill in entrambi i moduli sorgente. Validare `artifact.kind === 'skill'`, individuare la directory catturata dal rilevamento e chiamare il codec condiviso `readSkill()` di 03.4. Rifiutare esplicitamente una mancata corrispondenza tra pacchetto/artefatto/sorgente. Ciascuna funzione restituisce `Promise<ResolvedArtifact<CanonicalSkill>>`.

5. In `gitCustom.ts`, introdurre un unico helper mutex esportato per directory di cache. Sia `resolveGitCustom()` sia il `resolveArtifactContent()` Git devono usare lo stesso lock. Il resolver del contenuto lo mantiene durante il checkout di `pkg.version.commit` **e l'intera lettura della directory**, così che un'altra chiamata di elenco o lettura contenuto non possa cambiare il checkout condiviso tra queste operazioni. Il task 04.3 estende e sottopone a stress-test questo stesso helper; non deve creare una seconda mappa di lock.

6. Sostituire il singolo file di registro con questi contratti persistiti:

   ```ts
   export interface DesiredSource {
     id: string;
     type: Source['type'];
     scope: Scope;
     name?: string;
     url?: string;
     branch?: string;
     tag?: string;
     commit?: string;
     localPath?: string; // relative to the scope root; never absolute
   }

   export interface DesiredInstallation {
     sourceId: string;
     artifactId: string;
     assistant: AssistantId;
     scope: Scope;
     requestedRef?: string;
   }

   export interface ManifestFile {
     schemaVersion: number;
     sources: DesiredSource[];
     desiredInstallations: DesiredInstallation[];
   }

   export interface StateFile {
     schemaVersion: number;
     installations: ManagedInstallation[];
   }
   ```

   Il manifest rappresenta l'intento condivisibile; lo stato rappresenta lo stato di installazione locale alla macchina osservato. `ObservedArtifact` non viene persistito in nessuno dei due.

7. Aggiungere una conversione esplicita al confine di persistenza:

   - `toDesiredSource(source, workspaceRoot?, homeRoot?)` rimuove `projectPath` (presente solo a runtime). Un percorso locale di progetto viene persistito come relativo a `workspaceRoot`; un percorso locale globale viene persistito come relativo alla home dell'utente. Rifiutare la scrittura quando il percorso si trova al di fuori della radice del proprio scope.
   - `fromDesiredSource(desired, workspaceRoot?, homeRoot?)` ricostruisce una `Source` a runtime, risolvendo il `localPath` relativo rispetto alla radice del workspace selezionato per lo scope di progetto o alla radice home per lo scope globale, e ripristinando `projectPath` solo a runtime.
   - Non serializzare mai un `projectPath` o `localPath` assoluto in nessuno dei due scope.

8. Esporre le funzioni puro-Node `readManifest`, `writeManifest`, `readState` e `writeState`. Usare `~/.ai-swissknife/{manifest,state}.json` a livello globale e `<workspace>/.ai-swissknife/{manifest,state}.json` per lo scope di progetto. Mantenere le scritture atomiche tramite file temporaneo più rename. I file mancanti restituiscono valori vuoti con lo schema corrente. Le versioni di schema sconosciute falliscono in modo sicuro (fail closed) con un errore chiaro.

9. Aggiornare le esportazioni e tutti i chiamanti attuali. Non lasciare alias chiamati `installations` su `ManifestFile`; l'unico nome accettato è `desiredInstallations`.

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build.
- Testare il round-trip di una `DesiredSource` di progetto: il JSON persistito non contiene né il percorso assoluto del workspace né `projectPath`; la rilettura con un'altra radice di workspace risolve lo stesso intento relativo sotto la nuova radice.
- Testare il rifiuto dei percorsi di progetto esterni al workspace e dei percorsi globali esterni alla radice home.
- Testare file mancanti, scritture atomiche e mancata corrispondenza della versione dello schema in modo indipendente per manifest e stato.
- Testare la risoluzione del contenuto locale e Git come `ResolvedArtifact<CanonicalSkill>` senza cast.
- Aggiungere un test di interleaving in cui `resolveArtifactContent()` si mette in pausa dopo il checkout mentre `resolveGitCustom()` richiede un altro ref; dimostrare che la lettura del contenuto rimane a `pkg.version.commit` perché il lock condiviso copre checkout più lettura.

## Non-obiettivi

- Nessuna migrazione da `.ai-toolkit`.
- Nessuna scrittura di installazione e nessuna UI.
- Nessun catalogo/cache degli elementi osservati persistito.
- Nessuna operazione di rete sulle sorgenti oltre al comportamento esistente del resolver.
