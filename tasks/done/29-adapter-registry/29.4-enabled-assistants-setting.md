# 29.4 — Enabled-assistants VS Code setting

> Part of [Adapter registry & config](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.5, §3 (Locked-in decisions), §2 (Non-goals)

## Goal

A native VS Code setting controlling which assistants' sidebar sections
are visible, plus the registry-driven provider/view registration in
`extension.ts` that the note's "foreach, non una serie di if" ask is
actually about at the wiring layer.

This task must produce one commit containing only its changes.

## Steps

1. Add to `package.json`'s `contributes` (this extension declares **no**
   `configuration` today — confirm with `grep -n '"configuration"'
   package.json` before starting, so you place this as a new top-level key
   under `contributes`, not merged into something else):
   ```json
   "configuration": {
     "title": "AI Swissknife",
     "properties": {
       "aiSwissknife.enabledAssistants": {
         "type": "array",
         "items": {
           "type": "string",
           "enum": ["claude-code", "kilo-code", "github-copilot", "codex-cli", "gemini-cli"]
         },
         "default": ["claude-code", "kilo-code", "github-copilot", "codex-cli", "gemini-cli"],
         "description": "Which AI assistants show their own sidebar section and appear in assistant pickers."
       }
     }
   }
   ```
2. In `src/adapters/registry.ts` (29.2), add
   `getEnabledAdapters(): Adapter[]` — reads
   `vscode.workspace.getConfiguration('aiSwissknife').get<AssistantId[]>('enabledAssistants', ALL_ADAPTERS.map(a => a.assistant))`
   (the explicit default argument matters: an empty/missing setting must
   fall back to "all enabled," matching the `package.json` default, not
   "none") and filters `ALL_ADAPTERS` to just the ids present.
3. In `src/extension.ts`'s `activate()`: replace the five hand-written
   `const claudeProvider = new AssistantTreeDataProvider(installedProvider,
   'claude-code'); const kiloProvider = ...` lines (re-confirm current
   shape first — this file changed under 29.3 already) with one loop over
   `ALL_ADAPTERS` building a `Map<AssistantId, AssistantTreeDataProvider>`
   (or equivalent), and register a `vscode.window.registerTreeDataProvider`
   call per entry via that same loop instead of five separate calls.
4. Add a small `syncEnabledAssistantContextKeys()` helper (in
   `extension.ts`, or a new tiny `src/ui/enabledAssistants.ts` if it grows
   past a few lines) that, for every adapter in `ALL_ADAPTERS`, calls
   `vscode.commands.executeCommand('setContext', \`aiSwissknife.enabled.${adapter.assistant}\`,
   enabledIds.includes(adapter.assistant))`. Call it once during
   `activate()` (after computing `getEnabledAdapters()`) and again inside a
   `vscode.workspace.onDidChangeConfiguration(e => { if
   (e.affectsConfiguration('aiSwissknife.enabledAssistants')) { ... } })`
   listener registered in `context.subscriptions`.
5. For each of the five `contributes.views` entries under
   `aiSwissknife.installed.<assistant-id>` in `package.json`, add
   `"when": "aiSwissknife.enabled.<assistant-id>"` (e.g.
   `"when": "aiSwissknife.enabled.claude-code"` on the Claude Code entry).
   Do not add a `when` to the `aiSwissknife.sources` view — that one is not
   assistant-specific.

## Verification

- Run full test suite, typecheck, lint, build.
- Unit test (extend `src/extension.ts`'s existing test coverage in
  `src/ui/ui.test.ts` if that is where `activate()` is already exercised —
  confirm by grepping for `extension.activate` in that file first):
  `getEnabledAdapters()` with no setting configured returns all 5; with
  the mock `vscode.workspace.getConfiguration` returning
  `['claude-code']`, returns exactly that one adapter (identity-checked
  against `claudeAdapter`, not just id-string-checked).
- Manually in the Extension Development Host: open Settings, search
  "AI Swissknife", confirm the multi-select array setting appears with the
  right description and all 5 enum values; uncheck one assistant, confirm
  its sidebar section disappears **without a window reload** (the
  `onDidChangeConfiguration` listener is the thing being verified here);
  re-check it, confirm the section reappears.
