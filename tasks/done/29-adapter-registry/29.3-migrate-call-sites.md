# 29.3 — Migrate every duplicated adapter-selection site

> Part of [Adapter registry & config](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §0, §5

## Goal

Delete every duplicated copy of "pick an adapter/id-list for one of the 5
assistants" and replace it with a call into `src/adapters/registry.ts`
(29.2). This is the task that actually pays down the duplication the spec
documents — 29.1/29.2 only built the tool.

This task must produce one commit containing only its changes (if it grows
too large for one commit, split by call-site group in the order listed
below and say so explicitly rather than force one commit — but attempt one
first, this is mechanical enough that it likely fits).

## Steps

Re-run these greps yourself before starting — the spec's line numbers are
from 2026-09-08 and may have shifted:

```sh
grep -rn "getAdapter" src/engine/discovery.ts src/engine/drift.ts src/engine/sync.ts src/ui/formEditor.ts
grep -rn "'claude-code', 'kilo-code', 'github-copilot', 'codex-cli', 'gemini-cli'" src --include="*.ts"
grep -n "claudeAdapter\|kiloAdapter\|copilotAdapter\|codexAdapter\|geminiAdapter" src/ui/installedView.ts src/ui/availableView.ts src/ui/recommendations.ts src/engine/apply.ts
```

1. **Delete the four verbatim-duplicated `getAdapter(assistant, homeRoot?)`
   functions** in `src/engine/discovery.ts`, `src/engine/drift.ts`,
   `src/engine/sync.ts`, `src/ui/formEditor.ts`. Replace every call site
   that passed a `homeRoot` with `getAdapterWithHomeRoot(id, homeRoot)` and
   every call without one with `getAdapter(id)`, both imported from
   `../adapters/registry` (adjust relative path per file). Remove the
   now-unused per-file imports of the five adapter *classes* if nothing
   else in that file still constructs one directly (`readState`-style
   files may still need `ClaudeAdapter` etc. for unrelated reasons — check
   before deleting an import).
2. **Replace the independent 5-way ternaries** in
   `src/ui/installedView.ts` (`removeManagedInstallation`),
   `src/ui/availableView.ts` (`installArtifact`'s target/origin adapter
   lookups), and `src/engine/apply.ts` with `getAdapter(assistant)`.
3. **`src/ui/recommendations.ts`**: this one currently constructs *fresh*
   `new KiloAdapter()`/`new CopilotAdapter()`/etc. instances locally purely
   to build its own ternary (confirmed spec §0) — replace the whole
   pattern with `getAdapter(item.targetAssistant)` from the registry (the
   shared singleton, not a fresh instance — matches every other call
   site's behavior and removes the redundant allocation).
4. **Replace the nine duplicated literal `['claude-code', 'kilo-code',
   'github-copilot', 'codex-cli', 'gemini-cli']` arrays** (`extension.ts`
   ×3, `installedView.ts` ×2, `availableView.ts` ×2, `discovery.ts` ×1 —
   re-confirm the exact current count/locations with the grep above) with
   `ALL_ADAPTERS.map(a => a.assistant)` where an id list is genuinely what's
   needed, or `ALL_ADAPTERS` directly where the call site immediately maps
   over it anyway (e.g. `discovery.ts:77`'s `const assistants: AssistantId[]
   = [...]` used right after to loop and call `getAdapter(assistant)` per
   entry — that whole pattern collapses to `for (const adapter of
   ALL_ADAPTERS)`, dropping the intermediate id lookup entirely).
5. For the three `showQuickPick` call sites that build assistant-picker
   items with an icon (`src/ui/installedView.ts` ×2, `src/ui/availableView.ts`
   ×2 — re-confirm count/locations), migrate `iconPath: getAssistantIconPath(id,
   this.extensionUri)` to `iconPath: new vscode.ThemeIcon(adapter.iconId)`,
   built from `ALL_ADAPTERS.map(a => ({ label: a.assistant, iconPath: new
   vscode.ThemeIcon(a.iconId) }))` instead of the current
   `(['claude-code', ...] as const).map((id) => ({ label: id, iconPath:
   getAssistantIconPath(id, this.extensionUri) }))`. Do **not** delete
   `src/ui/assistantIcons.ts`'s `getAssistantIconPath` itself in this task
   even if it becomes unused here — confirming zero remaining callers and
   removing dead code is out of scope (spec §2 Non-goals); leave a
   `// TODO(29.3): getAssistantIconPath may now be unused, verify before deleting`
   comment above its definition instead if this task empties out its last
   caller.
6. Do not touch `src/ui/sourcesView.ts`'s `getSourceTypeIcon` or any
   `source.type` dispatch — that is initiative 30, a different registry.

## Verification

- Run full test suite, typecheck, lint, build. This task touches the
  install/sync/drift pipeline (`discovery.ts`, `drift.ts`, `sync.ts`,
  `apply.ts`) directly — these are hardening-gated per `tasks/CONTEXT.md`,
  so a clean full run (not just "it compiles") is the bar, not a smoke
  test.
- `grep -rn "assistant === 'claude-code'" src --include="*.ts" | grep -v test` and
  `grep -rn "'claude-code', 'kilo-code', 'github-copilot', 'codex-cli', 'gemini-cli'" src --include="*.ts"`
  must return **zero** matches outside `src/adapters/` itself (where the
  literal ids are the actual source of truth, e.g. inside each class's
  `readonly assistant = '...'` and inside `registry.ts`'s
  `getAdapterWithHomeRoot` lookup table) — this is the objective "did the
  duplication actually go away" check, not a vibe check.
- Manually in the Extension Development Host: move an item between
  assistants (exercises `sync.ts`), check drift on a modified item
  (exercises `drift.ts`), install a new artifact (exercises `discovery.ts`/
  `apply.ts`) — confirm no regression in the assistant-picker QuickPicks'
  icons (now `ThemeIcon`-based instead of SVG-`Uri`-based; should look the
  same or better, not broken/missing).
