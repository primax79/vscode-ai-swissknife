# 29.1 — `Adapter` acquisisce `displayName`/`iconId`

> Parte di [Registro degli adapter e configurazione](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.1, §3 (Decisioni vincolate)

## Goal

Aggiungere i due campi puramente descrittivi che ogni attuale punto di chiamata già
rideriva ad hoc (una stringa di visualizzazione e un'icona) direttamente sull'interfaccia `Adapter`
e sulle sue cinque implementazioni — nessuna modifica comportamentale a nessun
metodo esistente.

Questo task deve produrre un singolo commit contenente esclusivamente le proprie modifiche.

## Steps

1. In `src/adapters/types.ts`, aggiungere all'interfaccia `Adapter`:
   ```ts
   readonly displayName: string;
   readonly iconId: string;
   ```
   Rileggere prima l'interfaccia (`src/adapters/types.ts:69-100+`) per posizionare
   questi campi accanto al campo esistente `readonly assistant: AssistantId`, non
   alla fine.
2. Implementare entrambi i campi come proprietà di classe su ciascuna delle cinque classi
   adapter, usando questi valori esatti (vincolati nella specifica, §3):

   | Assistente        | `displayName`     | `iconId`                        |
   | ----------------- | ------------------ | -------------------------------- |
   | `claude-code`      | `Claude Code`      | `ai-swissknife-claude-code`      |
   | `kilo-code`        | `Kilo Code`        | `ai-swissknife-kilo-code`        |
   | `github-copilot`   | `GitHub Copilot`   | `ai-swissknife-github-copilot`   |
   | `codex-cli`        | `Codex CLI`        | `ai-swissknife-codex-cli`        |
   | `gemini-cli`       | `Gemini CLI`       | `ai-swissknife-gemini-cli`       |

   Riferimenti di file/riga per la dichiarazione esistente `readonly assistant` accanto a cui
   posizionare i nuovi campi: `src/adapters/claude.ts:352`,
   `kilo.ts:240`, `copilot.ts:24`, `codex.ts:19`, `gemini.ts:19`.
3. **Non** toccare nessun altro metodo di queste classi, e non toccare ancora
   `src/ui/assistantIcons.ts` (ancora utilizzato altrove finché 29.3/29.5
   non migreranno i suoi chiamanti) né alcuna voce `contributes.icons`/`contributes.views`
   in `package.json` (già corrette, qui costituiscono riferimenti in sola lettura).

## Verification

- Eseguire l'intera suite di test, typecheck, lint, build (`npm test`, `npm run lint`,
  `npm run build` — verificare prima i nomi attuali degli script in `package.json`).
- `npx tsc --noEmit` non deve mostrare nuovi errori — l'aggiunta di campi obbligatori a un'interfaccia
  implementata esattamente da cinque classi note non deve influenzare alcun
  altro file, poiché nulla costruisce un oggetto letterale ad hoc tipizzato come
  `Adapter` al di fuori di quelle cinque classi (confermare con
  `grep -rn ": Adapter = {" src --include="*.ts"` che deve restituire solo le
  costruzioni dei singleton `new XAdapter()`, mai un oggetto letterale).
- Verificare a campione un adapter (ad es. `claudeAdapter.displayName === 'Claude Code'`
  e `claudeAdapter.iconId === 'ai-swissknife-claude-code'`) in una rapida sessione
  REPL di Node o in un test temporaneo — non lasciare file di test temporanei
  se ne viene aggiunto uno solo per questo controllo.
