# 29.1 — `Adapter` gains `displayName`/`iconId`

> Part of [Adapter registry & config](plan.md) · spec: [../specs/adapter-and-source-registries.md](../../specs/adapter-and-source-registries.md) §4.1, §3 (Locked-in decisions)

## Goal

Add the two purely-descriptive fields every current call site already
re-derives ad hoc (a display string, an icon) directly onto the `Adapter`
interface and its five implementations — no behavior change to any
existing method.

This task must produce one commit containing only its changes.

## Steps

1. In `src/adapters/types.ts`, add to the `Adapter` interface:
   ```ts
   readonly displayName: string;
   readonly iconId: string;
   ```
   Re-read the interface first (`src/adapters/types.ts:69-100+`) to place
   these next to the existing `readonly assistant: AssistantId` field, not
   at the end.
2. Implement both fields as class properties on each of the five adapter
   classes, using these exact values (locked in the spec, §3):

   | Assistant         | `displayName`     | `iconId`                        |
   | ----------------- | ------------------ | -------------------------------- |
   | `claude-code`      | `Claude Code`      | `ai-swissknife-claude-code`      |
   | `kilo-code`        | `Kilo Code`        | `ai-swissknife-kilo-code`        |
   | `github-copilot`   | `GitHub Copilot`   | `ai-swissknife-github-copilot`   |
   | `codex-cli`        | `Codex CLI`        | `ai-swissknife-codex-cli`        |
   | `gemini-cli`       | `Gemini CLI`       | `ai-swissknife-gemini-cli`       |

   Files/line anchors for the existing `readonly assistant` declaration to
   place the new fields next to: `src/adapters/claude.ts:352`,
   `kilo.ts:240`, `copilot.ts:24`, `codex.ts:19`, `gemini.ts:19`.
3. Do **not** touch any other method on these classes, and do not touch
   `src/ui/assistantIcons.ts` yet (still consumed elsewhere until 29.3/29.5
   migrate its callers) or any `contributes.icons`/`contributes.views`
   entry in `package.json` (already correct, these are read-only references
   here).

## Verification

- Run full test suite, typecheck, lint, build (`npm test`, `npm run lint`,
  `npm run build` — confirm current script names in `package.json` first).
- `npx tsc --noEmit` must show no new errors — adding required fields to an
  interface implemented by exactly five known classes should not affect any
  other file, since nothing constructs an ad-hoc object literal typed as
  `Adapter` outside those five classes (confirm with
  `grep -rn ": Adapter = {" src --include="*.ts"` returning only the
  singleton `new XAdapter()` constructions, never an object literal).
- Spot-check one adapter (e.g. `claudeAdapter.displayName === 'Claude Code'`
  and `claudeAdapter.iconId === 'ai-swissknife-claude-code'`) in a quick
  Node REPL or a throwaway test — do not leave a throwaway test file behind
  if you add one for this check only.
