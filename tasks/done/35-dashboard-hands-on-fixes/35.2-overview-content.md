# 35.2 — Contenuto del tab Overview

**Depends on:** nulla oltre all'attuale `main`.

## Perché

`getOverviewHtml()` (`src/ui/dashboard.ts:636-640`) è un segnaposto
letterale (`<p>Overview section placeholder</p>`) rimasto dall'Iniziativa
32.2, che ha costruito il guscio delle sezioni ma ha esplicitamente rimandato
il contenuto di ogni sezione tranne Installed.

## Ambito

- `getOverviewHtml()` diventa una vera vista iniziale a colpo d'occhio, costruita a partire
  dai dati che `update()` raccoglie già (non servono nuovi metodi di recupero dati —
  passarvi gli esistenti `allSources`/`allManaged`/`allObserved`/
  `driftReports` e il gruppo di suggerimenti in cache, esattamente come
  `getInstalledSectionHtml`/`getRecommendationsHtml` ricevono già
  i propri dati come parametri):
  - Una riga di chip statistici che riutilizza il CSS esistente `.stat-chip`/`.stats-ribbon`
    già definito (`:` cercare `stats-ribbon` nel blocco `<style>`)
    — Managed Installations, Updates Available, Modified Locally,
    Unmanaged Discovered (gli stessi numeri mostrati dalla barra del tab Installed,
    senza ricalcolarli in modo diverso), più Pending Recommendations (da
    `pending.length` del gruppo consigliato in cache) e il conteggio delle Sources
    (global + project).
  - Pulsanti/link di salto rapido verso ciascuna delle altre sezioni (Installed, Sources &
    Catalog, Recommendations) — facendo clic su uno di essi si cambia il tab attivo
    (riutilizzare la funzione di cambio tab lato client già definita da 32.2,
    senza duplicarla).
  - Un breve elenco "modificati di recente / richiedono attenzione": fino a 5 elementi
    gestiti il cui stato di drift è `update-available`,
    `modified-and-update-available` o `modified-locally`, ciascuno reso come
    riga cliccabile che apre il pannello di dettaglio di quell'elemento nel tab Installed
    (riutilizzare la funzione client esistente `selectRow`/apertura pannello di dettaglio
    invece di costruirne una seconda).
- Mantenere l'invio dei dati di questa sezione coerente con il pattern incrementale
  `postMessage` stabilito a partire dall'Iniziativa 32.3 — non
  reintrodurre un percorso di riassegnazione completa dell'HTML per l'aggiornamento di Overview.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi con zero avvisi.
- Manuale: aprire la Dashboard, confermare che il tab Overview mostri numeri reali e
  corretti corrispondenti alla barra del tab Installed, che l'elenco degli elementi
  che richiedono attenzione mostri solo elementi con effettivi problemi di drift (stato
  vuoto se non ce ne sono), e che ogni link di salto rapido cambi correttamente tab.
