# 35.4 — Catalog rows as a real table

**Depends on:** nothing beyond current `main`.

## Why

Screenshot from hands-on testing: `renderCatalogLevel`'s
`AvailableArtifactItem` branch (`src/ui/dashboard.ts:674-698`) lays out
each artifact row as a flex container (`display: flex; justify-content:
space-between`) with a free-wrapping description in the middle. Since
flex children don't align across sibling rows the way table/grid columns
do, a long description wraps to 2-3 lines and the kind pill / name /
buttons end up at inconsistent horizontal positions row to row — ragged,
hard to scan. User: "riusciamo a trasformare questa vista in una
tabella?" (can we turn this view into a table?).

## Scope

- `src/ui/dashboard.ts`: convert `renderCatalogLevel`'s artifact-row
  rendering (and the equivalent folder-row rendering just above it,
  `:655-673`, for visual consistency within the same list) from ad-hoc
  flex divs to a real fixed-column layout — either an actual `<table>`
  per source's catalog, or a CSS Grid with `grid-template-columns` (pick
  whichever is a smaller diff given the existing nested/indented
  structure for folders — a `<table>` is awkward to nest per folder
  level, CSS Grid with a consistent column template reused at every
  nesting depth is likely the better fit here, but verify against the
  real current indentation markup before deciding).
  Columns: Kind (fixed width) | Name (fixed width) | Description
  (flexible, truncated with `text-overflow: ellipsis` + a `title`
  attribute carrying the full text — don't just let it wrap and push
  everything around) | Installed-in badges | Actions (fixed width, right
  aligned).
- Apply the same fixed-column treatment to `getSourcesCatalogHtml`'s
  source-row rendering (`:717-736`) for consistency — same ragged-wrap
  risk exists there for long `url`/`localPath` values.
- Keep every existing interaction (toggleFolder, toggleSource, Preview/
  Install buttons, diagnostics rendering) working exactly as-is — this is
  a layout-only change, not a functional one.
- Reuse existing CSS custom properties/tokens (`var(--border)`, etc.) —
  no new color values, matches the project's "keep existing style"
  constraint.

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green with zero warnings.
- Manual: expand a source with several artifacts including at least one
  with a long, multi-sentence description — confirm every row's kind
  pill/name/badges/buttons line up in fixed columns regardless of
  description length, with the description itself truncating (not
  wrapping and pushing siblings) and showing the full text on hover via
  `title`.
- Manual: nested folders still indent/expand correctly, diagnostics still
  render distinctly, all existing buttons still work.
