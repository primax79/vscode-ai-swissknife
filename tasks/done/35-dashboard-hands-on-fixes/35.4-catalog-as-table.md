# 35.4 — Righe del catalogo come vera tabella

**Depends on:** nulla oltre all'attuale `main`.

## Perché

Screenshot dai test pratici: in `renderCatalogLevel` il ramo `AvailableArtifactItem`
(`src/ui/dashboard.ts:674-698`) dispone
ciascuna riga artefatto come contenitore flex (`display: flex; justify-content:
space-between`) con una descrizione a ritorno a capo libero nel mezzo. Poiché
gli elementi figli di un contenitore flex non si allineano tra righe adiacenti come fanno le colonne
di una tabella/griglia, una descrizione lunga va a capo su 2-3 righe e la pill del tipo, il nome e i
pulsanti finiscono in posizioni orizzontali incoerenti da una riga all'altra — risultato disordinato e
difficile da scorrere visivamente. Utente: "riusciamo a trasformare questa vista in una
tabella?".

## Ambito

- `src/ui/dashboard.ts`: convertire il rendering delle righe artefatto di `renderCatalogLevel`
  (e il corrispondente rendering delle righe cartella subito sopra,
  `:655-673`, per coerenza visiva all'interno dello stesso elenco) da div flex ad hoc
  a un vero layout a colonne fisse — o una vera `<table>`
  per il catalogo di ciascuna sorgente, oppure una CSS Grid con `grid-template-columns` (scegliere
  la soluzione che produce il diff più contenuto data la struttura annidata/indentata
  esistente per le cartelle — una `<table>` è scomoda da annidare per ogni livello di
  cartella, mentre una CSS Grid con un template di colonne coerente riutilizzato a ogni
  profondità di annidamento è probabilmente la scelta migliore qui, ma verificare prima rispetto al
  markup di indentazione attuale reale prima di decidere).
  Colonne: Kind (larghezza fissa) | Name (larghezza fissa) | Description
  (flessibile, troncata con `text-overflow: ellipsis` + un attributo `title`
  contenente il testo completo — non lasciarla andare a capo spostando
  tutto il resto) | Badge Installed-in | Actions (larghezza fissa, allineata a
  destra).
- Applicare lo stesso trattamento a colonne fisse al rendering delle righe sorgente di `getSourcesCatalogHtml`
  (`:717-736`) per coerenza — anche lì esiste lo stesso rischio di ritorno a capo disordinato
  per valori lunghi di `url`/`localPath`.
- Mantenere ogni interazione esistente (toggleFolder, toggleSource, pulsanti Preview/
  Install, rendering della diagnostica) funzionante esattamente così com'è — questa è
  una modifica solo di layout, non funzionale.
- Riutilizzare le custom property/i token CSS esistenti (`var(--border)`, ecc.) —
  nessun nuovo valore di colore, in linea con il vincolo di progetto "mantieni lo stile
  esistente".

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi con zero avvisi.
- Manuale: espandere una sorgente con diversi artefatti, incluso almeno uno
  con una descrizione lunga di più frasi — confermare che in ogni riga la pill del tipo,
  il nome, i badge e i pulsanti siano allineati in colonne fisse indipendentemente dalla
  lunghezza della descrizione, con la descrizione stessa troncata (senza
  andare a capo spostando gli elementi adiacenti) e che mostri il testo completo al passaggio del mouse tramite
  `title`.
- Manuale: le cartelle annidate continuano a indentarsi/espandersi correttamente, la diagnostica continua a
  essere renderizzata in modo distinto e tutti i pulsanti esistenti continuano a funzionare.
