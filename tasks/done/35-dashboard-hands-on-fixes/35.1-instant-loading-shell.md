# 35.1 — Instant loading shell

**Depends on:** nothing beyond current `main`.

## Why

`DashboardPanel.update()` (`src/ui/dashboard.ts:461-...`) gathers
`allSources`/`allManaged`/`allObserved` via `await readManifest(...)`/
`await scanInstalledInventory(...)` calls **before** ever assigning
`this._panel.webview.html` (the assignment only happens inside the
`if (!this._htmlInitialized)` branch, after all those awaits resolve).
Until that first assignment, the webview shows its default (black)
background — VS Code doesn't paint anything else. This is what the user
sees as "everything is black until it refreshes."

## Scope

- `src/ui/dashboard.ts`: in `static render(...)`, immediately after
  creating the panel (`vscode.window.createWebviewPanel(...)`) and before
  constructing `DashboardPanel` (which triggers `update()`), synchronously
  assign a minimal loading shell to `panel.webview.html` — reuse the same
  `<style>` block / CSS custom properties as the real page (so there's no
  flash-of-different-theme when the real content replaces it), showing:
  the header, the section tabs (disabled/inert until real data loads), and
  an empty table with a centered spinner + "Loading…" row in the tbody
  (matching the existing `.spinner` CSS class already used elsewhere in
  the file, e.g. the scan indicator).
- `DashboardPanel`'s constructor already calls `this.update()` at the end
  (`:360`-ish) — no change needed there; `update()`'s own first real
  `webview.html` assignment (Phase A) naturally replaces this loading
  shell once data is ready, exactly as it does today for the
  already-initialized case, just now with a non-blank starting point.
- Do not change `update()`'s actual data-fetching logic — this task is
  purely "show something immediately," not "fetch faster."

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` all
  green with zero warnings.
- Manual: open the Dashboard on a workspace with enough installed items
  that the scan takes a perceptible moment — confirm the loading shell
  (not a black screen) is visible immediately, replaced by real content
  once ready, with no visible flash/flicker of mismatched styling between
  the two.
