# 35.1 — Guscio di caricamento istantaneo

**Depends on:** nulla oltre all'attuale `main`.

## Perché

`DashboardPanel.update()` (`src/ui/dashboard.ts:461-...`) raccoglie
`allSources`/`allManaged`/`allObserved` tramite chiamate `await readManifest(...)`/
`await scanInstalledInventory(...)` **prima** di assegnare
`this._panel.webview.html` (l'assegnazione avviene solo dentro il ramo
`if (!this._htmlInitialized)`, dopo la risoluzione di tutti quegli await).
Fino a quella prima assegnazione, la webview mostra il proprio sfondo predefinito (nero)
— VS Code non disegna nient'altro. Questo è ciò che l'utente
vede come "è tutto nero finché non fa il refresh".

## Ambito

- `src/ui/dashboard.ts`: in `static render(...)`, subito dopo aver
  creato il pannello (`vscode.window.createWebviewPanel(...)`) e prima di
  costruire `DashboardPanel` (che innesca `update()`), assegnare in modo sincrono
  un guscio minimo di caricamento a `panel.webview.html` — riutilizzare lo stesso
  blocco `<style>` / le stesse custom property CSS della pagina reale (così non si verifica alcun
  lampo di tema differente quando il contenuto reale lo sostituisce), mostrando:
  l'intestazione, i tab di sezione (disabilitati/inerti finché i dati reali non sono caricati) e
  una tabella vuota con uno spinner centrato + riga "Loading…" nel tbody
  (in linea con la classe CSS esistente `.spinner` già usata altrove nel
  file, ad es. nell'indicatore di scansione).
- Il costruttore di `DashboardPanel` invoca già `this.update()` alla fine
  (`:360` circa) — non serve alcuna modifica lì; in `update()` la prima vera assegnazione a
  `webview.html` (Fase A) sostituisce naturalmente questo guscio di
  caricamento non appena i dati sono pronti, esattamente come avviene oggi per il caso
  già inizializzato, ma ora partendo da una schermata non vuota.
- Non modificare la logica effettiva di recupero dati di `update()` — questo task riguarda
  esclusivamente "mostrare qualcosa immediatamente", non "recuperare i dati più velocemente".

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi con zero avvisi.
- Manuale: aprire la Dashboard su un workspace con abbastanza elementi installati
  da rendere percepibile la durata della scansione — confermare che il guscio di caricamento
  (e non una schermata nera) sia visibile immediatamente e venga sostituito dal contenuto reale
  non appena pronto, senza alcun lampo o sfarfallio visibile di stili incoerenti tra
  i due stati.
