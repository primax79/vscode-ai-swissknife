# 35.5 — Pulsanti con sola icona in tutta la Dashboard

**Depends on:** 35.1, 35.2, 35.3, 35.4 (tutti integrati — questo task passa in rassegna
il set finale di pulsanti in ogni sezione; avviarlo per ultimo così che non venga
immediatamente invalidato dagli altri quattro).

## Perché

Utente: "usiamo icone anzichè scritte nei pulsanti di tutta la dashboard, a
meno che non siano indispensabili le scritte".

## Vincolo di progettazione (mantenere lo stile esistente, nessuna nuova pipeline di asset)

La webview della Dashboard attualmente **non** carica il font VS Code Codicon
— non c'è alcuna classe CSS `codicon` né alcun asset di font collegato in
`dashboard.ts` dentro `<style>`/`<head>` (confermato tramite grep — zero
occorrenze di `codicon` nel file, a differenza degli elementi dell'albero della sidebar
che usano veri codicon `vscode.ThemeIcon` tramite `getKindIconName`,
`src/ui/kindIcons.ts`, un percorso di rendering completamente diverso che
non si applica all'HTML della webview). La Dashboard usa già semplici glifi
Unicode come icone leggere in diversi punti (`▶` freccia cartella, `📁`
cartella, `⚠️`/`🔴` diagnostica, `★` consigliato, `✓` corrispondenza cross-framework,
`◌`/`●` indicatori di stato) — **proseguire esattamente con quella convenzione**, senza
introdurre un font codicon o una pipeline di asset per questo task; ciò costituirebbe
nuova infrastruttura e non il rispetto del vincolo "mantieni lo stile esistente".

## Ambito

- Passare in rassegna ogni `<button>` in tutte e cinque le sezioni (Overview, Installed,
  Sources & Catalog, Recommendations, più `+ New Artifact` nell'intestazione
  e i pulsanti di azione del pannello di dettaglio) e sostituire le etichette di solo testo
  con un singolo glifo Unicode, scegliendo simboli visivamente
  distinti da quelli già in uso per significati non correlati (ad es.
  non riutilizzare `★`, che significa già "consigliato"). Mappatura suggerita
  (da adattare per chiarezza visiva, si tratta di un'indicazione e non di un obbligo — valutare in base a
  come appare effettivamente, non limitandosi a seguire questa lista):
  Add `＋`, Install `⬇`, Preview `👁`, Export `⇧` o `↥`, Remove/Uninstall
  `🗑`, Edit `✎`, Copy `⧉`, Move `⇥` o `➜`, Diff `⇄` o `≷`, Update `⟳`,
  Refresh `↻`, Promote `⇧`.
- **Ogni pulsante con sola icona deve mantenere (o acquisire) un attributo tooltip `title="..."`**
  con il nome completo dell'azione — questo è il sostituto di accessibilità
  per il testo visibile rimosso, e non è opzionale.
- **Il testo rimane laddove la sola etichetta risulterebbe effettivamente ambigua o
  dove l'azione necessita di un valore/contesto che solo il testo può trasmettere** — l'istruzione
  stessa del task specifica "a meno che non siano indispensabili le scritte"; usare
  buon senso (ad es. un'etichetta inline del selettore di scope come "Global"/"Project"
  accanto a `+` probabilmente resta testuale; un singolo pulsante `Install` accanto a un
  elemento non ambiguo invece no). Non rimuovere ciecamente ogni `>text<` nel
  file — le intestazioni di sezione della barra degli strumenti ("Global Sources", "Actionable
  Recommendations", ecc.) e le etichette delle opzioni dei menu a tendina dei filtri non sono
  pulsanti e sono fuori ambito.
- Mantenere dimensioni e padding dei pulsanti coerenti con le classi CSS esistenti `.btn`/
  `.btn-sm`/`.btn-primary`/`.btn-secondary` già definite —
  un pulsante con sola icona deve comunque mantenere lo stesso peso visivo degli odierni
  pulsanti testuali (potrebbe servire un piccolo ritocco CSS per padding/larghezza minima
  dei pulsanti con sola icona affinché non appaiano compressi; aggiungerlo al blocco
  `<style>` esistente senza inserire eccessivi stili inline una tantum).

## Verification

- `npm run typecheck && npm run lint && npm test && npm run build` tutti
  verdi con zero avvisi.
- Manuale: navigare in ogni sezione, confermare che ciascun pulsante di azione continui
  a fare esattamente ciò che faceva prima (questa è una pura modifica di etichetta/rendering),
  che ogni pulsante con sola icona mostri il proprio nome completo al passaggio del mouse, e
  che nulla risulti ambiguo a colpo d'occhio (se non si riesce davvero a capire
  cosa faccia una singola icona senza passarvi sopra il mouse, è segno che serviva il testo —
  segnalarlo invece di forzare un'icona).
