# 21.1 — Gemini `agent` verification spike

> Part of [Codex CLI & Gemini CLI adapters](plan.md) · spec: [../specs/phase-4-spec.md](../../specs/phase-4-spec.md) §7

## Goal

Per `SPEC.md` §1 (`agent` row, Gemini CLI column) and §5 ("`agent` on
Gemini CLI" risk entry): there is no solid confirmation of a standalone
Gemini CLI `agent` format outside an extension bundle. This must be
verified directly against the `google-gemini/gemini-cli` repo, not assumed
absent by analogy with Codex/Copilot. This task is verification only — no
adapter code.

This task must produce one commit containing only its changes (the
`CONTEXT.md` update).

## Steps

1. Check whether `google-gemini/gemini-cli` (or its documentation) is
   already available locally in this workspace (siblings like
   `kilocode-dev/`, `agentic-coding-kit/` were cited elsewhere in
   `CONTEXT.md` as already-cloned references — check first before fetching
   anything new).
2. If not available locally, fetch only the specific documentation/source
   needed to answer the question (an `agent`/persona/subagent concept
   outside of the "Extension" bundling mechanism already modeled as
   `Package` per `SPEC.md` §5's resolved "bundle/pack" entry) — do not
   pull the entire repo.
3. Record the finding in `tasks/CONTEXT.md` as a new locked-in decision:
   either "Gemini CLI has a standalone `agent` format at `<path>`, schema
   `<fields>`" (with citation) enabling 21.3 to implement it, or "Gemini CLI
   has no standalone `agent` format as of `<version/date>` — the Gemini
   adapter's `agent` support is `unsupported` in the translator, not a
   parse/serialize implementation" (also with citation).

## Verification

- The `CONTEXT.md` entry cites the specific source (file, doc page, or
  version) that settled the question, not a paraphrase.
- 21.3's `agent` section is written to match whichever finding is recorded
  here — it must not contradict it.
