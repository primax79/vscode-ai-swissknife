# 40.5 — Filter bar: pill groups for Env, Scope, Membership (and Kind), visually grouped

One task, one commit. Depends on 40.2 (it changes the same client filter code) and 40.4 (scope icons). Markup/CSS and the thin client glue only: the filtering rules themselves are 40.2's.

**Read first:** `plan.md`, `src/ui/dashboard.ts`: filter markup `:1147-1182` (env pills + two `<select>`s + kind `tab-btn` row), the `setScopeFilter`/`setMembershipFilter` functions (`~:1855-1870`, they write `select.value`), `setKindFilter`, breadcrumb/chips code (`:1886-1900`), the `inventoryData` handler's env-pill refresh (`:2053-2060`, which replaces the **first** `.filters-bar .filter-group`), CSS `.filter-group`/`.filter-pill` (`:1466-1471`), `src/ui/scopeIcons.ts` (40.4).

## Problem (owner feedback with screenshot, 2026-10-08)

Env is a row of icon pills, but Scope and Membership are native `<select>` dropdowns ("Scope: Global", "Membership: All") — visually inconsistent and ugly; Kind is a third look (tab buttons) in a separate toolbar. Nothing tells the user which controls belong together.

## Do

1. Replace both `<select>`s with single-select **pill groups** using the same `.filter-pill` look as env: Scope = `All` / Global (globe icon) / Workspace (folder icon) with the 40.4 icons; Membership = `All` / `● Managed` / `◌ Unmanaged` (same glyphs as the state badges). Same `active` styling, same keyboard behaviour as env pills (buttons, `aria-pressed`).
2. **Visual grouping**: one filter panel with one block per dimension — each block has a small uppercase muted label (ENV, SCOPE, MEMBERSHIP, KIND) and its pills inside a subtle bordered/segmented container; blocks separated by spacing/dividers and wrapping on narrow widths (label stays with its pills). Move the Kind pills into the same panel in the same pill style (replace `tab-btn`); the text search stays at the end of the panel.
3. Keep `setScopeFilter(value)`, `setMembershipFilter(value)`, `setEnvFilter`, `setKindFilter` as the single entry points (the Dashboard's other code calls them, e.g. `openInDashboard` / breadcrumb removal at `:1887`); update the active pill instead of `select.value`. Giving each group its own id removes the `.filters-bar .filter-group` "first group" assumption at `:2053`; the env refresh must target the env group by id.
4. Breadcrumb chips (`:1895+`) and `removeChip` keep working for scope/membership/kind/env.
5. Theme: only existing CSS variables (works in light/dark/high-contrast), no hard-coded colors.

## Non-goals

No change to what each filter matches (40.2), to the Overview/Sources/Recommendations tabs, or to the sidebar.

## Verification

`ui.test.ts`: the rendered Installed section contains no `<select id="scopeFilter">`/`membershipFilter`; clicking a scope/membership pill calls the same setter and marks exactly one pill per group active; `setScopeFilter('global')` called programmatically (from the breadcrumb or `openInDashboard`) activates the Global pill; env pills still refresh on `inventoryData` without touching the other groups; the four group labels are present. `npm test` green, `npm run build` clean. Manual in the Extension Development Host: the bar reads as four labelled groups, wraps cleanly when the panel is narrow, looks right in a light and a dark theme.
