# 24.2 — Preview-before-install action

> Part of [Diff-vs-original + preview-before-install](plan.md) · spec: [../specs/phase-6-spec.md](../../specs/phase-6-spec.md) §4.2

## Goal

Let a user see what will actually be installed before confirming, reusing
content `planInstall` already resolved — genuinely free, no new resolution.
Independent of initiative 23 and of 24.1 — can be dispatched immediately.

This task must produce one commit containing only its changes.

## Steps

1. In `AvailableTreeDataProvider.installArtifact` and `installBatch`
   (`src/ui/availableView.ts:476-729`), after `planInstall` returns
   `prepared` and before the existing `showInformationMessage` confirm
   dialog, add a `Preview` action alongside the existing `Install`/
   `Overwrite` choices.
2. `Preview` opens `prepared.content` read-only (a virtual document via a
   `TextDocumentContentProvider`, same custom-scheme pattern as 24.1 if
   that task has landed — otherwise introduce it here and 24.1 reuses it).
   For `skill`, show the primary `SKILL.md`'s content specifically, not an
   attempt to render an entire folder; `prepared.plan.proposedFiles` lists
   the other files by path for reference.
3. After previewing, the user must still see the original confirm dialog
   (`Install`/`Overwrite`) — `Preview` does not itself install anything, it
   only reads.
4. Apply the same `Preview` addition to `installBatch`'s confirm flow,
   scoped to previewing one item at a time from the batch (e.g. a
   secondary `QuickPick` to choose which item to preview), not a combined
   view of the whole batch.

## Verification

- Manual verification: trigger install on an Available item, choose
  `Preview`, confirm the resolved/translated content displays correctly,
  confirm choosing `Install` afterward still installs correctly (i.e.
  `Preview` has no side effects on the subsequent install).
- Run full test suite, lint, typecheck, build.
