# 07.3 — Vista Installed (basata sul registro) (rivisto)

> Parte di [UI minimale](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md) · rivisto secondo [../../SPEC.md](../../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../../_inbox/analyzed/codex-analysis-2.md) rilievo I12

**Questo file sostituisce una versione precedente di questo task** solo in
quanto ora legge il file di stato separato (02.3) anziché il registro combinato
originale, ed espone un hook di aggiornamento che 07.2 chiama dopo
un'installazione riuscita.

**Obiettivo**: una vista ad albero che elenca ogni `ManagedInstallation` dal
file di stato, raggruppata per assistente × scope, con un modo per consentire a
07.2 di attivare un aggiornamento dopo aver installato qualcosa.

**Riferimenti nel codice**: in `src/domain/registry.ts` la funzione `readState` (02.3, non
il precedente `readRegistry`); `src/ui/sourcesView.ts` (07.1) per lo schema
consolidato.

Passaggi:

1. Aggiungere in `package.json` sotto `contributes.views["ai-swissknife"]`:
   `{ "id": "aiSwissknife.installed", "name": "Installed" }`.
2. Creare `src/ui/installedView.ts`:
   - `vscode.TreeDataProvider` che legge `readState` (sia globale sia di
     progetto). Richiedere il riutilizzo del selettore condiviso della cartella
     di workspace di 07.1 per il caricamento dello stato di progetto multi-root
     (disabilitare il caricamento dello stato di progetto con zero cartelle,
     aggiornare quando cambia la cartella selezionata). Livello superiore = un
     nodo per ciascuna coppia `(assistant, scope)` effettivamente presente,
     figli = le relative `ManagedInstallation` (label = nome, description =
     kind, tooltip = `installedAt` + commit di `sourceRevision` se presente).
   - Esporre un metodo `refresh(): void` che emette
     `onDidChangeTreeData` — è ciò che 07.2 chiama dopo un `applyInstall`
     riuscito. Esportare l'istanza del provider (o un piccolo accessor) dal
     punto in cui `src/extension.ts` la costruisce, così che il gestore del
     comando di 07.2 possa raggiungerla; non costringere 07.2 a rileggere
     autonomamente il file di stato solo per innescare un aggiornamento della UI.
3. Registrare il provider in `src/extension.ts`.
4. Stessa disciplina di verifica dell'attivazione dei task precedenti.

**Verifica**: Eseguire l'intera suite di test, typecheck, lint e build. Un unico
commit contenente la modifica a `package.json` e `src/ui/installedView.ts` —
nient'altro. Dopo questo commit, aggiornare in `tasks/00-INDEX.md` la riga dell'iniziativa `07` a `✅ done` — questo completa end-to-end la tranche
verticale consolidata della Fase 1. Verificare inoltre, come controllo finale di
integrazione se un Extension Development Host è raggiungibile nell'ambiente:
registrare una sorgente `git-custom` che punta a un piccolo repository reale,
aggiornare il catalogo, installare una skill su Claude Code nello scope di
progetto e confermare che compaia nella vista Installed. Se un Extension
Development Host non è effettivamente raggiungibile nell'ambiente, dichiararlo
esplicitamente anziché omettere questa nota.
