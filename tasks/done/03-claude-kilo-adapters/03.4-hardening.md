# 03.4 — Codec condiviso delle skill e payload sicuro della directory (hardening)

> Parte di [Adapter Claude + Kilo](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md) · decisioni di revisione accettate: [round 001](../../_reviews/001-hardening-gate-SUMMARY.md) e [round 002](../../_reviews/002-hardening-gate-SUMMARY.md), in particolare le decisioni 2 e 12. Questo è il primo task di hardening aperto: 02.3 utilizza il suo codec, mentre 04.3 estende il contratto del suo detector.

## Goal

Creare un unico codec per l'intera directory della skill, preservare percorsi relativi sicuri e permessi di esecuzione, e rendere le skill malformate rilevate visibili come diagnostiche strutturate invece di farle sparire silenziosamente o interrompere l'elaborazione delle skill valide adiacenti.

Questo task deve produrre un unico commit contenente solo le proprie modifiche.

## Riferimenti nel codice

Leggere e rieseguire `rg` su tutti i chiamanti di `parseSkillMarkdown`, `serializeSkillMarkdown`, `readSkill`/`writeSkill` degli adapter, `findSkillDirs` e le funzioni dei resolver locale/Git (`resolveLocalFolder`, `resolveGitCustom`) prima di effettuare modifiche. Notare che il task 02.3 aggiungerà successivamente i due entry point `resolveArtifactContent`.

## Steps

1. Definire `CanonicalSkillFile { path: string; content: Uint8Array; mode?: number }`, rendere obbligatorio `CanonicalSkill.files: CanonicalSkillFile[]` e definire `CanonicalSkillDocument = Omit<CanonicalSkill, 'files'>`. `parseSkillMarkdown()` analizza solo il testo di `SKILL.md` e restituisce `CanonicalSkillDocument`; `readSkill(skillDir)` si occupa di caricare ricorsivamente l'intero payload allegando `files`.

2. Aggiungere funzioni condivise utilizzate da entrambi gli adapter ed entrambi i resolver delle sorgenti:

   - `readSkill(skillDir): Promise<CanonicalSkill>` legge `SKILL.md` più ogni file regolare discendente.
   - `writeSkill(skill, skillDir): Promise<void>` scrive in modo deterministico `SKILL.md` e `files`, crea le directory genitore e applica ogni `mode` definito tramite `chmod`.
   - `canonicalSkillHash(skill): string` restituisce un hash SHA-256 esadecimale minuscolo calcolato su una serializzazione stabile dei campi scalari, dei campi extra ordinati e dei file ordinati per percorso normalizzato inclusi contenuto e mode. Fornire un vettore di test fisso condiviso da 03.4 e 06. I task 06.1/06.2 importano esattamente questa funzione; non devono esistere due algoritmi di hash.

3. Validare ogni percorso di file prima di unirlo a una destinazione. Accettare esclusivamente percorsi relativi POSIX normalizzati e non vuoti. Rifiutare percorsi assoluti, forme con lettera di unità/UNC, percorsi vuoti o `.`, attraversamento `..`, byte NUL, percorsi normalizzati duplicati e qualsiasi percorso uguale a `SKILL.md`. Applicare anche un controllo di contenimento post-risoluzione.

4. Attraversare le directory con `lstat`, senza mai seguire implicitamente i symlink. Rifiutare symlink, socket, device, FIFO e voci illeggibili. Solo i file regolari e le directory reali appartengono a un payload canonico. Preservare i bit di permesso portabili necessari allo scrittore (almeno i bit di esecuzione); ignorare proprietario e timestamp.

   Durante la discovery delle sorgenti, ignorare `.git`, `node_modules` e le voci di esclusione esplicite, ma non tutte le dot-directory: repository validi possono collocare le skill sotto `.claude/skills` o un'altra dot-directory.

5. Definire in `src/sources/types.ts` un'interfaccia TypeScript concreta `DetectionDiagnostic` con `severity`, `path`, `message` e un'unione di stringhe letterali `code` (o costanti stringa stabili documentate) che coprano frontmatter/nome non valido, percorso non sicuro e skill illeggibile. Definire inoltre `SkillDetectionResult { skills: DetectedSkillDir[]; diagnostics: DetectionDiagnostic[] }`.

6. Modificare `findSkillDirs()` affinché restituisca `Promise<SkillDetectionResult>`. Un candidato malformato viene saltato e produce una diagnostica; gli elementi adiacenti validi restano. Errori infrastrutturali che rendono illeggibile la radice possono far fallire l'intera operazione.

7. Ripristinare `Adapter.skillDir(name, loc): string` (restituisce la directory della skill, ad es. `path.dirname(skillPath(...))`). Implementarlo in entrambi gli adapter Claude e Kilo insieme al lavoro sul codec.

8. Aggiornare ogni costruttore/copia attuale di `CanonicalSkill`, entrambi gli adapter, i passthrough del traduttore, i test e i punti di chiamata dei resolver locale/Git affinché il commit superi il typecheck con `files` obbligatorio. Il comportamento di traduzione esistente deve copiare l'intero array di file senza condividere riferimenti a buffer di byte mutabili. I chiamanti del resolver consumano `result.skills` in questo commit; il task 04.3 trasporterà successivamente `result.diagnostics` pubblicamente. Esportare `readSkill()`/`writeSkill()`/`canonicalSkillHash()` per 02.3 e 06; non fare riferimento alle funzioni `resolveArtifactContent()` non ancora create.

## Verification

- Eseguire l'intera suite di test, typecheck, lint e build.
- Effettuare il round-trip di una directory con file di testo/binari annidati e un file eseguibile; il contenuto e i bit di mode supportati vengono preservati.
- Rifiutare i casi di traversal, percorso assoluto, duplicato normalizzato, symlink, socket, file illeggibile e collisione con `SKILL.md` senza scrivere al di fuori della destinazione.
- Una fixture contenente una skill valida e una malformata restituisce il rilevamento valido più una diagnostica strutturata.
- La discovery raggiunge una skill sotto `.claude/skills` continuando a escludere `.git` e `node_modules`.
- Testare che gli adapter Claude e Kilo utilizzino lo stesso codec e producano un contenuto canonico equivalente.
- Verificare `skillDir === path.dirname(skillPath)` per entrambi gli scope globale e di progetto sia nell'adapter Claude sia in quello Kilo.

## Non-obiettivi

- Nessuna garanzia di formattazione YAML byte-per-byte; è richiesta la preservazione semantica del frontmatter.
- Nessun supporto ai symlink.
- Nessun codec per artefatti diversi dalle skill.
