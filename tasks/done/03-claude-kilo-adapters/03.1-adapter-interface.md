# 03.1 — Interfaccia Adapter

> Parte di [Adapter Claude + Kilo](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: definire il contratto condiviso `Adapter` implementato
dall'adapter di ogni assistente, limitato esclusivamente a `skill`+`rule`
(secondo la decisione condivisa in `plan.md`), più le rappresentazioni canoniche
in memoria da cui e verso cui vengono letti e scritti entrambi i tipi.

**Riferimenti nel codice**: SPEC.md §4 "Adapter per assistant" e le righe della
tabella `skill`/`rule` in §1 (`SPEC.md` nella radice del repository, leggere
entrambi prima di scrivere questo file).

Passaggi:

1. Creare `src/adapters/types.ts`:

   ```ts
   import type { AssistantId, Scope } from '../domain/types';

   export interface CanonicalSkill {
     name: string;
     description: string;
     body: string; // the markdown content after the frontmatter
     extraFields: Record<string, unknown>; // unrecognized frontmatter fields, preserved verbatim (SPEC.md §4 "canonical model")
   }

   export interface CanonicalRule {
     content: string; // raw file content, no frontmatter parsing — CLAUDE.md/AGENTS.md are plain markdown (SPEC.md §1)
   }

   export interface LocationRef {
     scope: Scope;
     projectRoot?: string; // required when scope === 'project'
   }

   export interface Adapter {
     readonly assistant: AssistantId;

     skillPath(name: string, loc: LocationRef): string;
     readSkill(name: string, loc: LocationRef): Promise<CanonicalSkill | null>; // null if not found, not an error
     writeSkill(skill: CanonicalSkill, loc: LocationRef): Promise<void>;
     listSkills(loc: LocationRef): Promise<string[]>; // names only

     rulePath(loc: LocationRef): string;
     readRule(loc: LocationRef): Promise<CanonicalRule | null>;
     writeRule(rule: CanonicalRule, loc: LocationRef): Promise<void>;
   }
   ```

2. `extraFields` su `CanonicalSkill` esiste specificamente affinché un
   round-trip (leggere una skill scritta da un utente con campi frontmatter
   aggiuntivi non richiesti da `SKILL.md` e poi riscriverla invariata) non perda
   tali campi — questa è la decisione "canonical model preserves unrecognized
   fields" di SPEC.md §4; non rimuovere questo campo per semplificare il tipo.
3. Nessuna implementazione in questo file — nessun import `fs`, nessuna logica
   di unione dei percorsi. Quello appartiene ai task 03.2/03.3.
4. Eseguire `npm run typecheck` — passa (nulla implementa ancora l'interfaccia,
   questo conferma solo che il file stesso compila).

**Verifica**: `npm run typecheck` e `npm run lint` terminano con codice 0. Un
unico commit contenente solo `src/adapters/types.ts`.
