# 03.2 — Adapter Claude Code

> Parte di [Adapter Claude + Kilo](plan.md) · specifica: [../specs/foundations.md](../../specs/foundations.md)

**Obiettivo**: implementare l'interfaccia `Adapter` (da 03.1) per Claude Code,
coprendo esclusivamente `skill` e `rule`.

**Riferimenti nel codice**: su questa macchina esistono già esempi reali —
`~/.claude/skills/` contiene vere cartelle di skill (ad es. `conflict-resolver/`),
e `~/.claude/agents/*.md` mostra la convenzione a file singolo per un tipo
diverso (non usata qui, utile solo per osservare la convenzione affine). Leggere
inoltre `agentic-coding-kit/plugins/*/skills/*/SKILL.md` (diversi file reali, ad
es. `agentic-coding-kit/plugins/common-tools/skills/gitignore/SKILL.md`) per la
struttura reale del frontmatter (`name`, `description`, talvolta campi
aggiuntivi — prendere nota di eventuali campi extra trovati,
`CanonicalSkill.extraFields` deve preservarli nel round-trip).

Passaggi:

1. Creare `src/adapters/claude.ts` che implementa `Adapter` da
   `src/adapters/types.ts`:
   - `assistant = 'claude-code'`.
   - `skillPath(name, loc)`: `path.join(loc.scope === 'global' ?
     os.homedir() : loc.projectRoot!, loc.scope === 'global' ? '' :
     '', '.claude', 'skills', name, 'SKILL.md')` — sistemare la logica di join
     in modo che sia corretta per entrambi gli scope (globale: `~/.claude/skills/<name>/
     SKILL.md`; progetto: `<projectRoot>/.claude/skills/<name>/SKILL.md`).
     Sollevare un errore chiaro se `scope === 'project'` e `projectRoot` è
     mancante (stessa disciplina dello store del registro, task 02.2).
   - `readSkill(name, loc)`: leggere il file `SKILL.md` in `skillPath(...)`.
     Effettuare il parsing del frontmatter YAML (delimitato da righe `---`) per
     ottenere `name`/`description`; inserire ogni altra chiave del frontmatter
     in `extraFields`; tutto ciò che segue il `---` di chiusura è `body`.
     Restituire `null` se il file non esiste (usare `fs.access` o intercettare
     specificamente `ENOENT` — non mascherare altri errori come "non trovato").
   - `writeSkill(skill, loc)`: serializzare il frontmatter (YAML: `name`,
     `description`, poi le chiavi di `extraFields` nell'ordine di inserimento) +
     `---` - `body`, scrivere in `skillPath(...)`, creando le directory
     genitore necessarie (`fs.mkdir` ricorsivo).
   - `listSkills(loc)`: leggere la directory `.claude/skills/` (globale o di
     progetto), restituire l'elenco dei nomi delle sottodirectory che contengono
     un file `SKILL.md` — ignorare qualsiasi sottodirectory che non lo contenga
     (non andare in errore per una cartella estranea che non è una skill).
   - `rulePath(loc)`: `~/.claude/CLAUDE.md` (globale) oppure
     `<projectRoot>/CLAUDE.md` (progetto).
   - `readRule`/`writeRule`: semplice lettura/scrittura del file, nessun parsing
     del frontmatter (`CanonicalRule.content` è il testo grezzo del file) —
     restituire `null` da `readRule` se il file non esiste.
2. Usare solo moduli built-in di Node (`fs/promises`, `path`, `os`) — nessuna
   dipendenza da librerie di parsing YAML a meno che non ne sia già presente una
   in `package.json` (controllare prima; se non ce ne sono, scrivere un parser
   minimale per la separazione del frontmatter — il formato è un semplice
   `---\nkey: value\n...\n---\nbody`, non serve un parser YAML completo per i
   due campi obbligatori + eventuali campi stringa piatti aggiuntivi di `skill`).
   Se un valore richiede legittimamente YAML completo (ad es. una lista), è
   consentito aggiungere una dipendenza minimale (`yaml` o `js-yaml`) — indicare
   quale e perché nel report finale anziché sceglierne una silenziosamente.
3. Scrivere `src/adapters/claude.test.ts` che copra, su una directory temporanea
   (mai la vera `~/.claude/`):
   - Round-trip: `writeSkill` seguito da `readSkill` restituisce gli stessi
     `name`/`description`/`body` e qualsiasi `extraFields` passato in input.
   - `readSkill` su una skill inesistente restituisce `null`, non solleva
     un'eccezione.
   - `listSkills` restituisce solo le directory contenenti `SKILL.md`, data una
     directory fixture con una cartella skill valida e una cartella priva di
     `SKILL.md`.
   - Round-trip di `rulePath`/`readRule`/`writeRule` per entrambi gli scope.

**Verifica**: il file di test passa; `npm run lint && npm run
typecheck && npm run build` terminano tutti con codice 0. Un unico commit
contenente `src/adapters/claude.ts`, `src/adapters/claude.test.ts` ed eventuali
nuove dipendenze aggiunte a `package.json`/lockfile — nient'altro.
