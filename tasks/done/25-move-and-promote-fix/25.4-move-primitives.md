# 25.4 — Primitive di Move: metodo removeMcpServer dell'adapter + helper di soft-delete

> Parte di [Azione Move + correzione della disambiguazione di Promote](plan.md) · spec: [../specs/phase-6-spec.md](../../specs/phase-6-spec.md) §3, §4.3

## Goal

Secondo la semplificazione indicata dall'utente (confermata): nessun motore generico che "inverta la
pipeline resolve→plan→preview→apply" per la disinstallazione. `skill` (una
directory) e `agent`/`command` (un singolo file) vengono rimossi **spostando**
`inst.path` in una posizione affiancata di soft-delete invece di usare `fs.rm`, così che un
`Move` accidentale sia recuperabile a mano. `mcp-server` non ha un file
autonomo da spostare — è una voce in una configurazione condivisa — quindi richiede un nuovo
metodo dell'adapter che riscriva la configurazione rimuovendo tale voce. Confermato:
oggi non esiste alcun metodo `delete`/`remove` sull'interfaccia `Adapter` per nessun tipo
(`src/adapters/types.ts:71-101`). Indipendente da 25.1-25.3 — tocca file
diversi.

Questo task deve produrre un singolo commit contenente solo le proprie modifiche.

## Steps

1. Aggiungere `removeMcpServer(id: string, loc: LocationRef): Promise<void>`
   all'interfaccia `Adapter` in `src/adapters/types.ts`, accanto agli esistenti
   `readMcpServer`/`writeMcpServer` (righe 90-91).
2. Implementarlo in tutti e 5 gli adapter (`src/adapters/claude.ts`,
   `src/adapters/kilo.ts`, `src/adapters/copilot.ts`,
   `src/adapters/codex.ts`, `src/adapters/gemini.ts`) — leggere il file di
   configurazione MCP condiviso dell'assistente (lo stesso file già scritto da `writeMcpServer`;
   verificare percorso/formato esatto per ciascun adapter leggendo prima ogni implementazione di
   `writeMcpServer`, es. `src/adapters/claude.ts:599`), rimuovere la
   voce indicizzata da `id` e riscrivere il file. Se la voce non esiste,
   non fare nulla (non lanciare eccezioni).
3. Aggiungere una nuova funzione helper di soft-delete (es. in un nuovo
   `src/engine/softDelete.ts` o accanto ad `apply.ts`) —
   `softDeletePath(originalPath: string, kind: ItemKind, name: string):
   Promise<string>` — che sposti un file o una directory in
   `.ai-swissknife/_deleted/<kind>/<name>-<ISO timestamp>/` (affiancata al punto in cui
   si trova la radice dei dati dell'assistente; riutilizzare l'helper esistente
   che risolve tale radice — controllare `src/domain/registry.ts` per la
   convenzione della radice `.ai-swissknife`) usando `fs.promises.rename` (o un
   fallback di copia+eliminazione se `rename` fallisce tra filesystem/dispositivi diversi),
   restituendo il percorso finale sottoposto a soft-delete affinché il chiamante possa segnalarlo se
   necessario.
4. **Non** collegare il comando `Move` stesso in questo task — quello è il task 25.5,
   mantenuto separato affinché queste primitive possano prima essere testate con unit test in isolamento.

## Verification

- Testare con unit test `removeMcpServer` su un file fixture di configurazione condivisa per ciascun
  adapter: confermare che la voce di destinazione venga rimossa e che le altre voci rimangano
  intatte (rispecchiando il pattern di test esistente "Round-trip: writeMcpServer merges server
  and preserves existing servers" già presente nelle suite di test degli adapter).
- Testare con unit test `softDeletePath` su una fixture temporanea: un file viene spostato
  intatto nella posizione `_deleted` con contenuto recuperabile; una directory
  (che simula una skill) viene spostata ricorsivamente intatta; il percorso originale non
  esiste più al termine.
- Eseguire l'intera suite di test, lint, typecheck, build.
