# 25.4 — Move primitives: removeMcpServer adapter method + soft-delete helper

> Part of [Move action + Promote disambiguation fix](plan.md) · spec: [../specs/phase-6-spec.md](../../specs/phase-6-spec.md) §3, §4.3

## Goal

Per the user's own simplification (confirmed): no generic "reverse the
resolve→plan→preview→apply pipeline" engine for uninstalling. `skill` (a
directory) and `agent`/`command` (a single file) are removed by **moving**
`inst.path` into a sibling soft-delete location instead of `fs.rm`, so an
accidental `Move` is recoverable by hand. `mcp-server` has no standalone
file to move — it's one entry in a shared config — so it needs a new
adapter method that rewrites the config with that entry removed. Confirmed:
no `delete`/`remove` method exists on the `Adapter` interface for any kind
today (`src/adapters/types.ts:71-101`). Independent of 25.1-25.3 — different
files.

This task must produce one commit containing only its changes.

## Steps

1. Add `removeMcpServer(id: string, loc: LocationRef): Promise<void>` to the
   `Adapter` interface in `src/adapters/types.ts`, alongside the existing
   `readMcpServer`/`writeMcpServer` (lines 90-91).
2. Implement it in all 5 adapters (`src/adapters/claude.ts`,
   `src/adapters/kilo.ts`, `src/adapters/copilot.ts`,
   `src/adapters/codex.ts`, `src/adapters/gemini.ts`) — read the assistant's
   shared MCP config file (same file `writeMcpServer` already writes,
   confirm exact path/format per adapter by reading each `writeMcpServer`
   implementation first, e.g. `src/adapters/claude.ts:599`), remove the
   entry keyed by `id`, write the file back. If the entry doesn't exist,
   no-op (do not throw).
3. Add a new soft-delete helper function (e.g. in a new
   `src/engine/softDelete.ts` or alongside `apply.ts`) —
   `softDeletePath(originalPath: string, kind: ItemKind, name: string):
   Promise<string>` — that moves a file or directory into
   `.ai-swissknife/_deleted/<kind>/<name>-<ISO timestamp>/` (sibling to
   wherever the assistant's data root is, reuse whatever existing helper
   resolves that root — check `src/domain/registry.ts` for the
   `.ai-swissknife` root convention) using `fs.promises.rename` (or a
   copy+delete fallback if `rename` fails across filesystems/devices),
   returning the final soft-deleted path for the caller to report if
   needed.
4. Do **not** wire the `Move` command itself in this task — that's 25.5,
   kept separate so these primitives can be unit-tested in isolation first.

## Verification

- Unit test `removeMcpServer` against a fixture shared-config file per
  adapter: confirm the target entry is removed and other entries survive
  untouched (mirrors the existing "Round-trip: writeMcpServer merges server
  and preserves existing servers" test pattern already in the adapter test
  suites).
- Unit test `softDeletePath` against a temp fixture: a file gets moved
  intact to the `_deleted` location with recoverable content; a directory
  (simulating a skill) gets moved recursively intact; the original path no
  longer exists afterward.
- Run full test suite, lint, typecheck, build.
