# 22.2 — Recommendation resolution engine

> Part of [Project-scoped recommended installations](plan.md) · spec: [../specs/project-recommendations.md](../specs/project-recommendations.md) §4.2

## Goal

One pure, VS Code-API-free function that both the on-demand install command
(22.3) and the workspace-open prompt (22.4) call into once they've resolved
sources, so "what's left to install" is decided in exactly one tested place,
with three distinct broken reasons instead of one collapsed bucket. Gates
22.3 and 22.4 — do not start either until this ships.

This task must produce one commit containing only its changes.

## Steps

1. Add `src/engine/recommendations.ts` exporting:

   ```ts
   type SourceResolutionAttempt =
     | { status: 'resolved'; source: Source; packages: Package[] }
     | { status: 'failed'; source: Source; error: string };

   type BrokenReason =
     | { kind: 'source-not-registered' }
     | { kind: 'source-resolution-failed'; error: string }
     | { kind: 'artifact-not-found' };

   function resolveRecommendations(
     desired: DesiredInstallation[],
     installed: ManagedInstallation[],
     registeredSources: Source[],
     resolutionAttempts: Map<string, SourceResolutionAttempt>
   ): {
     satisfied: DesiredInstallation[];
     pending: { desired: DesiredInstallation; artifact: Artifact; pkg: Package; source: Source }[];
     broken: { desired: DesiredInstallation; reason: BrokenReason }[];
   }
   ```

   `resolutionAttempts` only contains entries for sources someone actually
   tried to resolve — it will often be empty or partial, since resolution is
   only triggered by an explicit user action (22.3/22.4), never by the
   local-only open-time check (22.4's first pass).
2. Matching key for `satisfied` is `sourceId + artifactId + assistant`
   against `ManagedInstallation.sourceId/artifactId/assistant`
   (`src/domain/types.ts:86-99`) — same triple used for dedup in 22.1.
3. For entries not in `installed`:
   - If no entry in `registeredSources` has `id === desired.sourceId` →
     `broken` with `{ kind: 'source-not-registered' }`.
   - Else if `resolutionAttempts.get(desired.sourceId)` is absent →
     **skip this entry from all three buckets** (nothing was attempted for
     it yet — callers that only resolved a subset of sources must not have
     the unresolved rest silently reported as broken).
   - Else if that attempt has `status: 'failed'` → `broken` with
     `{ kind: 'source-resolution-failed', error }`.
   - Else (`status: 'resolved'`): search `packages` for an `Artifact` with
     `id === desired.artifactId` — found → `pending` (carrying `artifact`,
     `pkg`, `source`); not found → `broken` with
     `{ kind: 'artifact-not-found' }`.
4. Export `resolveRecommendations` from `src/engine/index.ts` alongside the
   other engine exports (`planInstall`, `applyInstall`, etc.).
5. This function does not read files, call `readManifest`/`readState`, or
   resolve any source itself — callers (22.3, 22.4) pass already-loaded
   data and already-attempted resolutions, keeping it trivially unit-testable
   and consistent with how `planInstall` etc. are already structured (pure
   core, I/O at the edges).

## Verification

- New `src/engine/recommendations.test.ts` (node:test, no `vscode` mock
  needed since this module never imports `vscode`) covering: empty input →
  all empty; an installed match → `satisfied`; a resolvable non-installed
  entry with a `'resolved'` attempt containing its artifact → `pending`
  with correct `artifact`/`pkg`/`source`; a `sourceId` absent from
  `registeredSources` → `broken` with `source-not-registered`; a registered
  source with **no** entry in `resolutionAttempts` → the entry appears in
  none of the three buckets; a registered source with a `'failed'` attempt
  → `broken` with `source-resolution-failed` and the original error string;
  a `'resolved'` attempt whose `packages` don't contain the `artifactId` →
  `broken` with `artifact-not-found`; mixed input producing all three
  buckets simultaneously plus a skipped (unattempted) entry.
- Run full test suite, lint, typecheck, build.
