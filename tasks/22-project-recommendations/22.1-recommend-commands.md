# 22.1 — Recommend/unrecommend commands + tree decoration

> Part of [Project-scoped recommended installations](plan.md) · spec: [../specs/project-recommendations.md](../specs/project-recommendations.md) §4.1

## Goal

Let a curator explicitly mark a project-scope artifact as recommended (or
undo it), writing directly into the already-shared `manifest.json` via the
existing `readManifest`/`writeManifest` (`src/domain/registry.ts`) — no new
schema, no new file.

This task must produce one commit containing only its changes.

## Steps

1. Add commands `aiSwissknife.recommendForWorkspace` and
   `aiSwissknife.unrecommendForWorkspace` to `package.json`'s `contributes.commands`
   and register them in `src/extension.ts`, following the exact pattern
   `aiSwissknife.addSource`/`removeSource` already use.
2. **From the Available view** (`src/ui/availableView.ts`): the handler
   receives an `AvailableArtifactItem`, which carries only `source`, `pkg`,
   `artifact` — **no `assistant`** (confirmed: `AvailableArtifactItem`'s
   constructor at `src/ui/availableView.ts:55-61` has no such field). Prompt
   for a target assistant with the same `showQuickPick(['claude-code',
   'kilo-code', 'github-copilot', 'codex-cli', 'gemini-cli'], ...)` list
   `installBatch` already uses (`src/ui/availableView.ts:479-484`) before
   writing the entry.
3. **From the Installed view** (`src/ui/installedView.ts`): the handler
   receives an installed item with a real `assistant`, but
   `ManagedInstallation.sourceId`/`artifactId` are optional
   (`src/domain/types.ts:86-99`) — a promoted `ObservedArtifact`
   (`src/engine/discovery.ts`) or a Form-Editor-created item
   (`src/ui/formEditor.ts`) can have neither. If either is missing, show
   `vscode.window.showWarningMessage("This item isn't tracked to a source and can't be recommended.")`
   and return without writing anything.
4. Only offer/act when the underlying source's `scope === 'project'` — these
   commands must not appear (or must no-op with a clear message) for
   global-scope items, per the spec's locked "recommendation scope is
   project only" decision.
5. `recommendForWorkspace`: `readManifest('project', projectRoot)`, push a
   `DesiredInstallation { sourceId, artifactId, assistant, scope: 'project' }`
   deduped by `sourceId + artifactId + assistant` (filter existing matches
   before pushing, mirroring `addSource`'s filter-then-push dedup),
   `writeManifest(...)`.
6. `unrecommendForWorkspace`: same read, filter out the matching entry,
   write back.
7. Add `contributesMenus`/`when`-clause entries so both commands appear only
   in the right context (`aiSwissknife.available` / `aiSwissknife.installed`
   view item context menus), mirroring how `removeSource`'s menu entry is
   scoped to `sourceItem` today. Use a regex/prefix match on `viewItem`
   (e.g. `viewItem =~ /^availableArtifact/`) rather than an exact-value
   match, so the new `:recommended` `contextValue` suffix from step 8 still
   satisfies existing menu entries for other commands (`installArtifact`,
   etc.) instead of hiding them.
8. Tree decoration: **`getTreeItem` on both providers is synchronous**
   (`vscode.TreeItem`, not `Promise<vscode.TreeItem>` —
   `src/ui/sourcesView.ts`'s `getTreeItem` is the same shape) and must not
   call `readManifest` itself. Instead, compute the recommended set once
   inside `getChildren` (already `async` and already the place
   `SourcesTreeDataProvider.getChildren` calls `readManifest` today) and
   attach it to each constructed `AvailableArtifactItem`/installed item at
   creation time (e.g. an `isRecommended: boolean` field on the item), so
   `getTreeItem` only ever reads a value that's already on the item. Set a
   distinguishing `description`/`iconPath` (e.g. a star `ThemeIcon`) and a
   `contextValue` suffix (e.g. `availableArtifact:recommended`, keeping the
   existing prefix so unrelated `when`-clauses for other commands still
   match — see step 7) so the menu can show "Unrecommend" instead of
   "Recommend" for already-recommended items.
9. After a successful write, call `refresh()` on **both** the
   `AvailableTreeDataProvider` and the `InstalledTreeDataProvider`, not only
   the one the action was invoked from — today's file watchers
   (`setupFileWatchers` in `src/extension.ts`) only refresh Sources and
   Installed, not Available, so a recommendation made from the Installed
   view would otherwise leave the Available view's decoration stale (and
   vice versa).

## Verification

- Run full test suite, lint, typecheck, build.
- Unit test (extending `src/ui/ui.test.ts`'s `vscode` mock as needed):
  recommend an item from Available (mock `showQuickPick` to return an
  assistant) → assert the manifest's `desiredInstallations` gains exactly
  one deduped entry with that assistant; call recommend again on the same
  item/assistant → still exactly one entry; unrecommend → entry removed;
  recommend on a global-scope item → no manifest change and a clear message
  shown; recommend on an installed item with no `sourceId`/`artifactId` →
  no manifest change and the specific warning message shown.
- Manually in the Extension Development Host: recommend an Available item,
  confirm the star decoration appears in both Available and (after
  installing it) Installed views without needing to trigger any other
  refresh, confirm `.vscode/ai-swissknife/manifest.json` (or the legacy path
  if present) contains the new entry.
