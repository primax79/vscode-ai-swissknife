## Cosa fare

`src/engine/claudeCli.ts` con un esecutore iniettabile (`run(args, opts) => {stdout, stderr, code}`) in modo che i test non avviino mai il binario `claude`:

- `resolveClaudeBinary()` secondo lo spike (PATH, poi i fallback), memorizzato in cache; solleva `ClaudeCliNotFound` elencando i percorsi cercati.
- Funzioni di lettura tipizzate: `listPlugins()`, `listAvailablePlugins()`, `pluginDetails(id)`, `listMarketplaces()`; ciascuna effettua il parsing in modo difensivo (campi sconosciuti ignorati, campi opzionali mancanti tollerati, output malformato -> `ClaudeCliParseError` con l'output grezzo allegato), utilizza i timeout definiti dallo spike e verifica il requisito minimo di versione della CLI.
- Tipi di dominio: `ClaudePlugin { id, name, marketplace, version, scope: 'user'|'project'|'local', enabled, installPath, projectPath?, projectEnabled?, installedAt, lastUpdated }` e `ClaudePluginDetails { components: { skills, agents, commands?, hooks, mcpServers, lspServers }, alwaysOnTokens }`.
- Le funzioni di scrittura sono **dichiarate qui ma implementate in 45.4/45.5**; questo task contiene solo la lettura.

## Verification

`claudeCli.test.ts` con fixture copiate dagli output reali registrati nei risultati (list, available, details, marketplaces; includere un plugin installato in due ambiti, uno disabilitato, uno con `projectPath`): risultati del parsing esatti; campo extra sconosciuto ignorato; JSON troncato -> `ClaudeCliParseError`; binario non trovato -> `ClaudeCliNotFound` con l'elenco cercato; timeout -> errore tipizzato; versione obsoleta -> errore tipizzato con la versione minima. Nessun test avvia il vero `claude`. Uno smoke test opzionale (saltato a meno che `AISK_REAL_CLAUDE=1`) esegue `list --json` contro la CLI reale. `npm test` verde, `npm run build` pulito.
