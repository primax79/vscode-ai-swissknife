# 45.2 — `ClaudeCli` wrapper and read model

One task, one commit. Depends on 45.1 (the contract in `notes/45.1-findings.md` overrides anything below that it contradicts). No `vscode` import; no UI.

**Read first:** `plan.md` (locked-in decisions), `notes/45.1-findings.md`, `src/sources/gitProcess.ts` (the `runGit` pattern: execFile, timeout, error shaping), `src/engine/types.ts`.

## Do

`src/engine/claudeCli.ts` with an injectable executor (`run(args, opts) => {stdout, stderr, code}`) so tests never spawn `claude`:

- `resolveClaudeBinary()` per the spike (PATH, then the fallbacks), cached; throws `ClaudeCliNotFound` listing what was searched.
- Typed read functions: `listPlugins()`, `listAvailablePlugins()`, `pluginDetails(id)`, `listMarketplaces()`; each parses defensively (unknown fields ignored, missing optional fields tolerated, malformed output -> `ClaudeCliParseError` with the raw output attached), uses the timeouts from the spike, and checks the CLI version gate.
- Domain types: `ClaudePlugin { id, name, marketplace, version, scope: 'user'|'project'|'local', enabled, installPath, projectPath?, projectEnabled?, installedAt, lastUpdated }` and `ClaudePluginDetails { components: { skills, agents, commands?, hooks, mcpServers, lspServers }, alwaysOnTokens }`.
- Write functions are **declared here but implemented in 45.4/45.5**; this task contains read only.

## Verification

`claudeCli.test.ts` with fixtures copied from the real outputs recorded in the findings (list, available, details, marketplaces; include a plugin installed at two scopes, one disabled, one with `projectPath`): parse results exactly; unknown extra field ignored; truncated JSON -> `ClaudeCliParseError`; binary not found -> `ClaudeCliNotFound` with the searched list; timeout -> typed error; old version -> typed error with the minimum version. No test spawns the real `claude`. One opt-in smoke test (skipped unless `AISK_REAL_CLAUDE=1`) runs `list --json` against the real CLI. `npm test` green, `npm run build` clean.
