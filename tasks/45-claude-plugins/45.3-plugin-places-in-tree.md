# 45.3 — Posizioni dei plugin nell'albero Installed e nella Dashboard (sola lettura)

Un task, un commit. Dipende da 45.2 e da 40.1 (modello delle posizioni), 40.2 (renderer), 40.4 (icone degli ambiti). Le ipotesi CP-Q3 / CP-Q4 del piano si applicano finché l'owner non le modifica.

**Read first:** `plan.md`, `src/engine/claudeCli.ts` (45.2), `src/engine/installedTree.ts` (40.1), `src/ui/dashboard.ts` e la barra laterale `installedView.ts` per l'ambiente Claude, `src/ui/scopeIcons.ts`.

## Cosa fare

1. Estendere il modello delle posizioni con il tipo `plugin` (solo Claude): un'installazione di plugin è una **posizione** (assistente Claude, ambito user->Global / project->Workspace / local->Workspace (private) con la propria variante di icona e tooltip, stato enabled | disabled | update-available se la CLI lo riporta) i cui **figli** sono i componenti del plugin ottenuti da `details` (skills, agents, commands, hooks, MCP, con i relativi conteggi) e la cui riga genitore mostra il **costo in token sempre attivi** (un piccolo badge, ad es. "~1,000 tok").
2. Caricare tramite `ClaudeCli` in modo asincrono (l'albero viene renderizzato subito, i plugin appaiono quando `list --json` risponde, con una riga di caricamento); gli errori mostrano un'unica riga attenuata "Claude plugins unavailable: <reason>" (CLI mancante/obsoleta), mai un toast di errore.
3. **Rilevamento dei duplicati**: per ciascuna skill/agent/command di un plugin, segnalare un artefatto sciolto dello stesso tipo e nome nello stesso ambiente Claude (Global/Workspace); mostrare un indicatore "duplicate" con un tooltip che nomina entrambe le posizioni. Solo rilevamento, nessuna azione.
4. Sia la barra laterale (vista Claude) sia la Dashboard (albero Installed) lo mostrano; sola lettura: il clic sulla riga apre il pannello di dettaglio con id, marketplace, versione, commit, percorso di installazione, ambito, componenti, costo in token.
5. Totali: le statistiche di intestazione includono il conteggio "Plugins"; i filtri (40.5) ricevono la pill di tipo "Plugins".

## Verification

Con un `ClaudeCli` simulato (mock) che restituisce le fixture registrate: una riga genitore per ogni installazione di plugin con l'icona/badge di ambito corretto, figli da details, badge dei token; un plugin installato in due ambiti produce due posizioni; quello disabilitato appare attenuato; il percorso con CLI mancante mostra la riga attenuata e null'altro si rompe; una skill sciolta con lo stesso nome di una skill del plugin attiva l'indicatore di duplicato. `npm test` verde, `npm run build` pulito. Manuale con la CLI reale: appaiono i 10 plugin della macchina dell'owner.
