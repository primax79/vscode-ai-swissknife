# 45.1 — Spike: cosa garantisce la CLI `claude plugin`

Ricerca, nessun codice di prodotto. Esecutore: questa sessione (richiede la CLI reale). Output `notes/45.1-findings.md`. **Regola di isolamento:** non sperimentare mai sulla reale `~/.claude` dell'owner: verificare per prima cosa se la CLI rispetta una directory di configurazione alternativa (ad es. la variabile d'ambiente `CLAUDE_CONFIG_DIR`; verificarlo con `claude plugin list --json` in una directory temporanea e con un marketplace usa e getta); se non è possibile alcun isolamento, limitare lo spike ai comandi di sola lettura (`list`, `details`, `marketplace list`, `list --available`) e dichiararlo.

**Read first:** `specs/claude-plugins-study.md` sezione 1, `claude plugin --help` e l'help di ogni sottocomando usato di seguito, `references/claude/` (documentazione dei plugin), `src/sources/gitProcess.ts` (lezioni su PATH/timeout).

## Domande a cui rispondere (con il comando eseguito e il relativo output come evidenza, oppure "unverified" + motivo)

1. **Individuazione del binario**: quando VS Code viene avviato dalla GUI (nessun PATH della shell), `claude` viene trovato? Dove risiede su questa macchina (`which claude`, destinazione del symlink) e quali fallback dovrebbe tentare il wrapper (`~/.claude/local/claude`, `/opt/homebrew/bin`, `~/.local/bin`)?
2. **Stabilità del JSON**: elenco completo dei campi di `list --json`, `list --available --json`, `details --json` (`details` dispone di una modalità JSON? in caso contrario la forma testuale è analizzabile: registrare entrambe), `marketplace list --json`. Quali campi sono opzionali?
3. **Ambiti**: semantica esatta di `--scope user|project|local` su install/enable/disable/uninstall/update; come la CLI determina il progetto (cwd vs `--project`?); in cosa `projectEnabled` differisce da `enabled`; cosa accade allo stesso plugin installato in due ambiti.
4. **Comportamento non interattivo**: quali comandi possono mostrare prompt; se ogni comando dispone di un flag/codice di uscita che lo fa fallire invece di restare in attesa; codici di uscita in caso di errore; formato di stderr.
5. **Effetti collaterali di `enable`/`disable`**: quale file cambia (impostazioni utente vs progetto vs locale) e se una sessione Claude in esecuzione recepisce la modifica.
6. **Installazione di un marketplace con sorgente comando**: cosa riporta `--json` (`shownCommand.sha256`) in modo che la UI possa mostrarlo prima della conferma.
7. **Tempistiche**: durata tipica di `list --json`, `details`, `update` (per impostare i timeout del wrapper).
8. **Controllo di versione**: output di `claude --version` e versione minima richiesta dai comandi sopra indicati (in modo che il wrapper possa rifiutare CLI più vecchie con un messaggio chiaro).
