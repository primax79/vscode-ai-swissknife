# 45.1 — Spike: what the `claude plugin` CLI guarantees

Research, no product code. Executor: this session (needs the real CLI). Output `notes/45.1-findings.md`. **Isolation rule:** never experiment against the owner's real `~/.claude`: first find out whether the CLI honors an alternative config dir (e.g. the `CLAUDE_CONFIG_DIR` environment variable; verify it with `claude plugin list --json` under a temp dir and a throwaway marketplace); if no isolation is possible, restrict the spike to read-only commands (`list`, `details`, `marketplace list`, `list --available`) and say so.

**Read first:** `specs/claude-plugins-study.md` section 1, `claude plugin --help` and the help of every subcommand used below, `references/claude/` (plugin docs), `src/sources/gitProcess.ts` (PATH/timeout lessons).

## Questions to answer (with the command run and its output as evidence, or "unverified" + reason)

1. **Discovery of the binary**: when VS Code is launched from the GUI (no shell PATH), is `claude` found? Where does it live on this machine (`which claude`, symlink target) and which fallbacks should the wrapper try (`~/.claude/local/claude`, `/opt/homebrew/bin`, `~/.local/bin`)?
2. **JSON stability**: full field list of `list --json`, `list --available --json`, `details --json` (does `details` have a JSON mode? the text form is parseable otherwise: record both), `marketplace list --json`. Which fields are optional?
3. **Scopes**: exact semantics of `--scope user|project|local` on install/enable/disable/uninstall/update; how the CLI decides the project (cwd vs `--project`?); how `projectEnabled` differs from `enabled`; what happens to the same plugin installed at two scopes.
4. **Non-interactive behaviour**: which commands can prompt; does every command have a flag/exit code that makes it fail instead of waiting; exit codes for failure; stderr format.
5. **Side effects of `enable`/`disable`**: which file changes (user settings vs project vs local) and whether a running Claude session reflects it.
6. **Install of a command-source marketplace**: what `--json` reports (`shownCommand.sha256`) so the UI can show it before confirmation.
7. **Timing**: typical duration of `list --json`, `details`, `update` (to set the wrapper's timeouts).
8. **Version gating**: output of `claude --version` and the minimum version the commands above need (so the wrapper can refuse older CLIs with a clear message).

## Deliverable

`notes/45.1-findings.md`: one section per question with evidence, then the **wrapper contract** the next task implements (commands, args, parsed shapes, timeouts, error taxonomy). Anything that contradicts a plan assumption is listed at the top and the plan/tasks are corrected before 45.2 is dispatched.
