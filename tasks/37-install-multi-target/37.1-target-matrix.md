# 37.1 — Engine helper: plan the assistant × scope matrix

One task, one commit. No `vscode` import, no UI change.

**Read first:** `../CONTEXT.md`, `plan.md`, `src/engine/plan.ts:117` (`planInstall`, `PlanInstallParams`, `PreparedInstall`), `src/engine/apply.ts:35` (`applyInstall`, outcome union), `src/engine/index.ts`.

## Do

Create `src/engine/installMatrix.ts`:

- `planInstallMatrix({ items, assistants, scopes, projectRoot? })` → for every (item, assistant, scope) call `planInstall`; return `{ targets: Array<{ item, assistant, scope, prepared }>, summary }`.
- `summary`: counts of `new`, `conflict`, `unsupported` (each unsupported keeps `prepared.plan.reason`), plus the list of targets per bucket.
- Scope `project` with no `projectRoot` yields targets marked unsupported with reason "no workspace open" and never throws (defensive: the UI already hides Project when there is no workspace, plan Q2).
- `applyInstallMatrix(targets, { overwrite: boolean })` → applies only `new` targets, plus `conflict` ones when `overwrite`; sequential (not parallel — targets may share files such as an MCP config); returns per-target `ApplyOutcome`. A failure in one target never stops the others.

## Verification

`src/engine/installMatrix.test.ts` using the fixtures/patterns of `install.test.ts`: 2 assistants × 2 scopes for one skill → 4 planned targets; a pre-existing install shows as `conflict` and is skipped without `overwrite`, replaced with it; an assistant that does not support the kind is `unsupported` with a reason; project scope without root does not throw; failure injected in the 2nd target leaves the 1st applied and the 3rd attempted. `npm test` green, `npm run build` clean.
