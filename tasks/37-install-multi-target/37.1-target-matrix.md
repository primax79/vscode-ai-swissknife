# 37.1 — Helper del motore: pianificare la matrice assistente × ambito

Un task, un commit. Nessun import `vscode`, nessuna modifica alla UI.

**Read first:** `../CONTEXT.md`, `plan.md`, `src/engine/plan.ts:117` (`planInstall`, `PlanInstallParams`, `PreparedInstall`), `src/engine/apply.ts:35` (`applyInstall`, unione degli esiti), `src/engine/index.ts`.

## Cosa fare

Creare `src/engine/installMatrix.ts`:

- `planInstallMatrix({ items, assistants, scopes, projectRoot? })` → per ogni (item, assistant, scope) invocare `planInstall`; restituire `{ targets: Array<{ item, assistant, scope, prepared }>, summary }`.
- `summary`: conteggi di `new`, `conflict`, `unsupported` (ogni elemento non supportato conserva `prepared.plan.reason`), più la lista dei target per categoria.
- L'ambito `project` senza `projectRoot` produce target marcati come non supportati con motivo "no workspace open" e non solleva mai eccezioni (difensivo: la UI nasconde già Project quando non c'è un workspace aperto, piano Q2).
- `applyInstallMatrix(targets, { overwrite: boolean })` → applica solo i target `new`, più quelli `conflict` quando `overwrite` è attivo; esecuzione sequenziale (non parallela — i target possono condividere file come una configurazione MCP); restituisce `ApplyOutcome` per ciascun target. Un errore su un target non interrompe mai gli altri.

## Verification

`src/engine/installMatrix.test.ts` usando le fixture e i pattern di `install.test.ts`: 2 assistenti × 2 ambiti per una skill → 4 target pianificati; un'installazione preesistente risulta `conflict` e viene saltata senza `overwrite`, sostituita con esso; un assistente che non supporta il tipo risulta `unsupported` con un motivo; l'ambito progetto senza root non solleva eccezioni; un errore iniettato nel 2° target lascia il 1° applicato e il 3° tentato. `npm test` verde, `npm run build` pulito.
