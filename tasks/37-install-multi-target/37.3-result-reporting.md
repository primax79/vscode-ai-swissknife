# 37.3 — Per-target outcome reporting

One task, one commit. Depends on 37.2.

**Read first:** `plan.md`, the outcome handling in `availableView.ts` (`switch (outcome.status)` for `applied` / `refused` / `rolled-back` / `manual-recovery-required`), `37.1`'s per-target outcomes.

## Note from the 37.1 verification

`applyInstallMatrix` (src/engine/installMatrix.ts on branch `kilo/fbac7d820930`) returns status `refused` both for a real refusal and for a target skipped because it already exists (conflict without `overwrite`) or is unsupported. Derive the "skipped (existing)" and "unsupported" counts from `outcome.target.prepared` (`supported`, `plan.conflict`), not from `status` alone.

## Do

Replace the per-flow result messages with one reporter: a single notification summarizing `applied / skipped (existing) / unsupported / failed` counts; on any failure, offer "Show details" opening an output-channel listing target, status and reason. `manual-recovery-required` for any target stays a modal error listing the paths (current behaviour, `:657-662`). Refresh Installed once at the end, not once per target.

## Verification

`ui.test.ts`: mixed outcomes (applied, refused, rolled-back) produce one summary message and one refresh call; `manual-recovery-required` still raises the modal with paths. `npm test` green, `npm run build` clean.
