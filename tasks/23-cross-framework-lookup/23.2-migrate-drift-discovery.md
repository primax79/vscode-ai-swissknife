# 23.2 — Migrate drift.ts and discovery.ts onto the shared accessor

> Part of [Cross-framework identity lookup + shared content accessor](plan.md) · spec: [../specs/phase-6-spec.md](../specs/phase-6-spec.md) §3, §4.2

## Goal

Replace `checkForUpstreamUpdate`'s (`src/engine/drift.ts:130-234`) and
discovery's matching loop's (`src/engine/discovery.ts:216-306`) own inline
resolve+translate-then-hash logic with calls to 23.1's shared
`resolveAndTranslate` (or whatever it was named) — this closes their
existing gap versus `plan.ts` (only 3 of 5 source types, no `hook`/`rule`)
as a side effect, and fixes the pre-existing `analyzeLocalDrift` bug where
`hook`/`rule` installations are always reported as drifted because no disk
hash is ever computed for them (`src/engine/drift.ts:61-109` has no branch
for those two kinds).

This task must produce one commit containing only its changes. Depends on
23.1 having landed.

## Steps

1. In `src/engine/drift.ts`'s `checkForUpstreamUpdate`, replace the
   type-specific resolve calls (`resolveLocalFolderContent`/
   `resolveGitCustomContent`/`resolveGitMarketplaceContent`, lines ~183-190)
   and the per-kind `translate*` + `canonical*Hash` calls (lines ~194-206)
   with one call to 23.1's shared function, extended to cover all 5 source
   types automatically as a consequence.
2. In `src/engine/drift.ts`'s `analyzeLocalDrift`, add the missing `hook`
   and `rule` branches to the kind-dispatch `if`/`else if` chain (lines
   ~61-109) — read the current file's disk content via the target
   adapter's `readHook`/`readRule` (already exist on the `Adapter`
   interface, `src/adapters/types.ts:95-101`) and compute
   `canonicalHookHash`/`canonicalRuleHash` (already exist,
   `src/adapters/codec.ts`) exactly like the existing `agent`/`command`
   branches do. This closes the always-reports-drifted bug for these two
   kinds.
3. In `src/engine/discovery.ts`'s matching loop (lines 216-306), replace the
   per-source-type resolve/resolve-content branches with calls to 23.1's
   shared function — same effect, closes the 2 missing source types
   (`git-single-item`, `remote-url`) and 2 missing kinds (`hook`, `rule`)
   for the purposes of this loop's resolution step specifically. **Do not**
   change the loop's `match`-overwriting behavior in this task — that is
   initiative 25's job (25.1); this task only changes *what content gets
   resolved and compared*, not how many candidates are kept.
4. Re-run every existing test that exercises `checkForUpstreamUpdate`,
   `analyzeLocalDrift`, and the discovery matching loop — confirm none
   regress. Existing fixtures that use `local-folder`/`git-custom`/
   `git-marketplace` sources and `skill`/`agent`/`command`/`mcp-server`
   kinds must produce identical results to before.

## Verification

- Add test cases (extending existing `drift.test.ts`/`discovery.test.ts`
  fixtures) proving: a managed `hook` installation with matching disk/state
  content now reports `up-to-date` (not `modified-locally`); a managed
  `rule` installation likewise; a `git-single-item` or `remote-url` source
  now participates in discovery matching (previously silently skipped).
- Run full test suite, lint, typecheck, build.
