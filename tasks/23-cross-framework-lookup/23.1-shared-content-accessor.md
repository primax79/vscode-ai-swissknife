# 23.1 — Extract shared resolve+translate content accessor

> Part of [Cross-framework identity lookup + shared content accessor](plan.md) · spec: [../specs/phase-6-spec.md](../specs/phase-6-spec.md) §3, §4.2

## Goal

`src/engine/plan.ts`'s `resolveContentFromSource` (`src/engine/plan.ts:52-71`)
plus the per-kind translation calls that follow it in `planInstall` are the
**only** implementation in this codebase that resolves an artifact's content
from all 5 source types and translates it for all 6 kinds. `drift.ts` and
`discovery.ts` each have their own narrower, duplicated version (3 source
types, 4 kinds — no `hook`/`rule`). This task extracts `plan.ts`'s version
into a standalone, reusable function **without changing `planInstall`'s
observable behavior** — 23.2 migrates the other two call sites onto it.

This task must produce one commit containing only its changes.

## Steps

1. Read `src/engine/plan.ts` in full before touching it — `resolveContentFromSource`
   (lines 52-71) resolves; the six per-kind branches later in the file
   (`rule` ~103-133, `hook` ~199-229, `mcp-server` ~295+, `command` ~401+,
   `agent` ~532+, `skill` ~662+) each call the matching `translate*` function
   (`translateRule`, `translateHook`, `translateMcpServer`, `translateCommand`,
   `translateAgent`, `translateSkill` — all in `src/translator/`) on the
   resolved content.
2. Add a new exported function, e.g. in `src/engine/plan.ts` itself (co-located
   with `resolveContentFromSource`, no need for a new file) or a new
   `src/engine/content.ts` if that reads cleaner once written:

   ```ts
   async function resolveAndTranslate(
     source: Source,
     pkg: Package,
     artifact: Artifact,
     targetAssistant: AssistantId,
     resolverOpts?: ...  // whatever resolveContentFromSource already accepts
   ): Promise<{ translated: <the per-kind canonical union>; diagnostic: ConversionDiagnostic }>
   ```

   It must dispatch by `artifact.kind` exactly like `planInstall` already
   does, calling `resolveContentFromSource` then the matching `translate*`
   function, returning the translated canonical value and its
   `ConversionDiagnostic`. Match `planInstall`'s existing kind-dispatch
   structure precisely — do not invent a new dispatch shape.
3. Refactor `planInstall`'s six per-kind branches to call this new function
   instead of inlining `resolveContentFromSource` + `translate*` themselves.
   `planInstall`'s subsequent steps (hashing, building the `PreparedInstall`,
   conflict detection) are unchanged — only the resolve+translate step moves.
4. Export the new function from `src/engine/index.ts` alongside the existing
   engine exports.
5. Do **not** touch `drift.ts` or `discovery.ts` in this task — that's 23.2,
   kept separate so this extraction can be verified in isolation first
   against `planInstall`'s existing test coverage.

## Verification

- Run the full existing test suite (`npm test`) — every existing
  `plan.test.ts`/`apply.test.ts` (or equivalent) test for `planInstall` must
  still pass unchanged, proving the refactor didn't change `planInstall`'s
  behavior for any of the 6 kinds.
- `npm run typecheck && npm run lint && npm run build`.
- Add a focused unit test for the new function directly (one case per kind,
  reusing whatever fixtures the existing `plan.ts` tests already have) if no
  existing test exercises it at this granularity.
