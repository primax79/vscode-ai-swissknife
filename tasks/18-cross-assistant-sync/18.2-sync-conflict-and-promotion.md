# 18.2 — Conflict policy & on-the-fly promotion

> Part of [Cross-assistant sync](plan.md) · spec: [../specs/phase-4-spec.md](../specs/phase-4-spec.md) §4

## Goal

Add a skip/overwrite/cancel conflict resolution reusable for both a single
sync and a batch sync, and let `planSync`/the sync UI action accept an
`ObservedArtifact` as origin by promoting it to a `ManagedInstallation`
first via the existing promotion engine, instead of requiring the user to
promote manually before syncing.

This task must produce one commit containing only its changes.

## Grounding

- Existing binary overwrite/cancel pattern to extend (add "skip", don't
  replace the mechanism): `src/ui/availableView.ts:377-390` (single item)
  and `:490-525` (batch).
- Promotion engine to reuse unchanged: `promoteObservedArtifact`
  (`src/engine/discovery.ts`, initiative 14).

## Steps

1. Extend the conflict-prompt helper (extract one if the two call sites in
   `availableView.ts` don't already share a function) to a 3-way choice:
   Skip / Overwrite / Cancel — for batch sync, "skip" applies per-conflicting-item
   without cancelling the whole batch, matching the existing "N of M conflict"
   count message style.
2. In the sync entry point (`src/engine/sync.ts` or a thin wrapper), accept
   either a `ManagedInstallation` or an `ObservedArtifact` as origin; when
   given the latter, call `promoteObservedArtifact` first, then proceed with
   the resulting `ManagedInstallation` through the normal `planSync` path.
3. Add unit tests: skip leaves the target file untouched and reports
   `skipped` in the outcome; overwrite proceeds through `applyInstall`
   exactly as an install conflict does; promoting-then-syncing an
   `ObservedArtifact` ends with both a new `ManagedInstallation` for the
   promoted origin and one for the synced target.

## Verification

- Run full test suite, lint, typecheck, build.
