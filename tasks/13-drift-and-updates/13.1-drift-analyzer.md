# 13.1 — Drift analyzer engine

> Part of [Drift & update detection](plan.md) · spec: [../specs/phase-3-spec.md](../specs/phase-3-spec.md)

## Goal

Implement `analyzeDrift` in `src/engine/drift.ts` that compares a `ManagedInstallation` against current disk state.

This task must produce one commit containing only its changes.

## Steps

1. Define `DriftStatus` and `DriftReport` in `src/engine/types.ts`:
```ts
export type DriftStatus =
  | 'up-to-date'
  | 'modified-locally'
  | 'update-available'
  | 'modified-and-update-available'
  | 'missing-on-disk';

export interface DriftReport {
  installation: ManagedInstallation;
  status: DriftStatus;
  diskHash?: string;
  sourceHash?: string;
  details?: string;
}
```

2. Create `src/engine/drift.ts`:
   - `analyzeLocalDrift(installation: ManagedInstallation, homeRoot?: string): Promise<DriftReport>`
   - Dispatches by `installation.kind`:
     - `skill`: checks directory existence with `lstat`, reads skill via `readSkill(installation.path)`, computes `canonicalSkillHash`, compares with `installation.contentHash`.
     - `agent`: checks file existence, reads agent via `readAgent`, computes `canonicalAgentHash`, compares with `installation.contentHash`.
     - `command`: checks file existence, reads command via `readCommand`, computes `canonicalCommandHash`, compares with `installation.contentHash`.
     - `mcp-server`: reads target config file via `readMcpServer`, computes `canonicalMcpServerHash`, compares with `installation.contentHash`.
   - If path missing / deleted: returns `status: 'missing-on-disk'`.
   - If hash differs: returns `status: 'modified-locally'`.
   - If hash matches: returns `status: 'up-to-date'`.

3. Add unit tests in `src/engine/drift.test.ts`.

## Verification

- Run full test suite, lint, typecheck, build.
- Test drift analysis for untouched, locally modified, and deleted skills, agents, commands, and MCP servers.
