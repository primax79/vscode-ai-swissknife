# 19.2 — `CanonicalHook` model & Claude/Copilot adapters

> Part of [`hook` kind + active `rule` merge](plan.md) · spec: [../specs/phase-4-spec.md](../specs/phase-4-spec.md) §5

## Goal

Add `CanonicalHook` to `src/adapters/types.ts` and implement parse/serialize
for Claude Code and GitHub Copilot at the paths **19.1** confirmed. Do not
start this task until 19.1's `CONTEXT.md` entry is in place.

This task must produce one commit containing only its changes.

## Grounding

- Schema fields per `SPEC.md` §1 `hook` row (near-identical between Claude
  and Copilot per that table): event name (`PreToolUse`/`PostToolUse`/
  `UserPromptSubmit`/`SessionStart`/`Stop`/`SubagentStart`/`SubagentStop`/
  `PreCompact`), `type`, `command`, per-OS command overrides
  (`windows`/`linux`/`osx`), `cwd`, `env`, `timeout`.
- Paths: whatever 19.1 recorded in `CONTEXT.md` — do not re-derive from the
  pre-verification candidates in `SPEC.md` §5.
- Existing adapter pattern to follow: `src/adapters/claude.ts`/
  `src/adapters/copilot.ts` (parse/serialize pairs, same file/frontmatter
  style already used for `agent`/`command`).

## Steps

1. Add `CanonicalHook` to `src/adapters/types.ts` with the fields above,
   plus `extraFields` for forward-compatibility, matching the existing
   canonical-model style (see `CanonicalMcpServer` for a similarly
   structured, non-markdown example).
2. Implement parse/serialize in `src/adapters/claude.ts` and
   `src/adapters/copilot.ts` at 19.1's confirmed paths.
3. Add a `hook` translator (`src/translator/hook.ts`) following the existing
   translator pattern (`src/translator/agent.ts` as the closest structural
   analogue) — event names and schema are near-identical per `SPEC.md` §1,
   so this is likely close to lossless between Claude and Copilot; still
   emit the standard diagnostic for any field that doesn't map 1:1.
4. Add `'hook'` to the `ItemKind`-dispatch switch statements the codebase
   already has (e.g. wherever `PreparedInstall`/`planInstall` branches per
   kind in `src/engine/plan.ts` and `src/engine/types.ts`) — extend, don't
   duplicate, the existing per-kind dispatch structure.
5. Add unit tests: parse/serialize round-trip for both assistants, and a
   translation test Claude↔Copilot.

## Verification

- Run full test suite, lint, typecheck, build.
