# 19.1 — Hook path verification spike

> Part of [`hook` kind + active `rule` merge](plan.md) · spec: [../specs/phase-4-spec.md](../specs/phase-4-spec.md) §5

## Goal

Close the contradiction `SPEC.md` §5 flags for `hook`: two official VSCode
sources disagree on the real paths for both Claude Code (standalone,
outside the plugin context) and GitHub Copilot, and Kilo Code has **no data
collected at all**. This task is verification only — **no adapter or
canonical-model code is written here**; that's 19.2, gated on this task's
findings.

This task must produce one commit containing only its changes (the
`CONTEXT.md` update + any scratch verification notes needed to justify it —
not application code).

## Grounding

- `SPEC.md` §1 `hook` row and §5 "`hook` — paths still ambiguous" entry list
  the exact conflicting candidates already found: `.github/hooks/*.json` vs
  `.claude/settings.json`/`.claude/settings.local.json` (read natively) vs
  `~/.copilot/hooks` vs plugin-scoped `hooks.json`/`hooks/hooks.json` vs an
  agent-scoped `hooks` field in `.agent.md`.
- `references/vscode_doc/` — local mirror of the official docs, `INDEX.md`
  for the listing (`CONTEXT.md` "Reference material" section) — check both
  the overview page and the dedicated hooks reference page named in
  `SPEC.md` §5, since they're the two that disagree.
- Kilo: no data collected yet per `SPEC.md` §1 — check
  `agentic-coding-kit/plugins/agent-tooling-meta/skills/kilo-plugin-manager/`
  and `kilocode-dev/packages/kilo-vscode/` (sibling dirs, already used to
  ground the Claude/Kilo adapters per `CONTEXT.md`) for any hook-equivalent
  concept before concluding it's genuinely absent.

## Steps

1. Read both conflicting VSCode doc pages in `references/vscode_doc/` and
   record, verbatim with page reference, what each one claims for Claude
   Code and Copilot hook paths.
2. Search `kilo-plugin-manager` and `kilocode-dev` sources for any
   hook-equivalent (event name, config key, file path) — record findings
   even if the answer is "not found."
3. If the contradiction cannot be resolved from local references alone (e.g.
   both docs are equally authoritative and neither is marked stale), a real
   test install in a scratch workspace with VSCode Insiders (or reading the
   Copilot extension's bundled source directly) is the tiebreaker — do not
   guess or average the two candidates.
4. Record the resolved paths (or "still unresolved, defer" if genuinely
   inconclusive) as a new locked-in decision in `tasks/CONTEXT.md`,
   following the existing entry style (decision + **Why:**), replacing the
   current "hook — paths still ambiguous" framing with the closed answer.

## Verification

- The new `CONTEXT.md` entry cites the specific page/file/line that settled
  each path, not a paraphrase — a fresh reader must be able to re-derive the
  same conclusion from the citation alone.
- If genuinely inconclusive after real verification (not just "I didn't have
  time to check"), the entry says so explicitly and 19.2 is blocked/flagged
  until it's closed — never silently pick one candidate to unblock the
  schedule.
