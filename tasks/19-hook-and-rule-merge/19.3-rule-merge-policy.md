# 19.3 — Non-destructive `rule` merge policy

> Part of [`hook` kind + active `rule` merge](plan.md) · spec: [../specs/phase-4-spec.md](../specs/phase-4-spec.md) §5

## Goal

Turn `rule` from "adapter exists, dormant" (`CONTEXT.md`'s "`rule` is
deferred to Phase 2" entry) into an actual install/sync target, using a
non-destructive merge policy instead of overwriting
`CLAUDE.md`/`AGENTS.md`/`copilot-instructions.md` wholesale, per the policy
in `phase-4-spec.md` §5: demarcated managed block
(`<!-- ai-swissknife:managed:<sourceId> -->` … `<!-- /ai-swissknife:managed -->`),
appended if absent, replaced in place if already present, surrounding
content never touched.

This task must produce one commit containing only its changes.

## Grounding

- Existing dormant adapter: `src/translator/rule.ts` (`translateRule`,
  currently lossless for `claude-code`/`kilo-code`, `unsupported` otherwise
  — keep that translation logic, this task adds the merge layer around
  installing/applying it, not a new translation).
- Why this was blocked before: `CONTEXT.md`'s "`rule` is deferred to Phase
  2" entry — installing a rule safely needs exactly this merge/composition
  policy, which didn't exist until now.
- Apply/verify pattern to extend: `src/engine/apply.ts` — `rule` needs a
  distinct write strategy (merge-into-existing-file) instead of the
  create/overwrite-file strategy every other kind uses; keep the other
  kinds' apply path untouched.

## Steps

1. Implement the merge function (e.g. `mergeRuleContent(existing: string,
   sourceId: string, newContent: string): string` in `src/translator/rule.ts`
   or a new `src/engine/ruleMerge.ts`): find the existing managed block for
   `sourceId` if present and replace only that block; otherwise append a new
   block at the end of the file (creating the file if it doesn't exist yet).
2. Wire `rule` into `planInstall`/`applyInstall` (`src/engine/plan.ts`,
   `src/engine/apply.ts`): plan produces a diff of the *merge result*, not
   just the new block, so preview shows exactly what changes in the target
   file; apply calls the merge function instead of a plain write, still
   through the same atomic-write/rollback transaction every other kind uses
   (`CONTEXT.md`'s hardening-gate invariants apply unchanged).
3. Update `src/engine/types.ts`'s `PreparedInstall` union if a `rule` branch
   doesn't already return usable content (the type predates this task since
   `rule` was dormant — check before assuming it needs no change).
4. Add unit tests: install into a file that doesn't exist yet (creates it),
   into a file with unrelated existing content (appends, existing content
   untouched), and update-in-place (replaces its own prior managed block
   only, leaving a second sourceId's block and all surrounding content
   untouched).

## Verification

- Run full test suite, lint, typecheck, build.
- Manually install a `rule` into a project that already has a hand-written
  `CLAUDE.md` and confirm the hand-written content is byte-identical after
  install, with only the new managed block appended.
