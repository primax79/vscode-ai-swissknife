# 30.2 — Wrap the five resolver modules

> Part of [Source-resolver registry](plan.md) · spec: [../specs/adapter-and-source-registries.md](../specs/adapter-and-source-registries.md) §4.3, §4.4

## Goal

One `SourceResolver`-conforming object per source type, each wrapping that
module's already-existing `resolveXxx`/`resolveArtifactContent` exports.
Purely additive — every existing free-function export stays exactly as-is
and keeps working for any caller not yet migrated.

This task must produce one commit containing only its changes.

## Steps

For each of the five modules, add one new exported constant at the bottom
of the file (after its existing exports):

1. `src/sources/localFolder.ts`:

   ```ts
   export const localFolderResolver: SourceResolver = {
     type: 'local-folder',
     displayName: 'Local folder',
     iconThemeId: 'folder',
     resolve: resolveLocalFolder,
     resolveArtifactContent,
   };
   ```

2. `src/sources/gitCustom.ts` → `gitCustomResolver` (`type: 'git-custom'`,
   `displayName: 'Git (custom)'`, `iconThemeId: 'repo'`, `resolve:
   resolveGitCustom`, `resolveArtifactContent`).
3. `src/sources/gitMarketplace.ts` → `gitMarketplaceResolver`
   (`'git-marketplace'`, `'Git marketplace'`, `'extensions'`,
   `resolveGitMarketplace`).
4. `src/sources/gitSingleItem.ts` → `gitSingleItemResolver`
   (`'git-single-item'`, `'Git (single item)'`, `'git-commit'`,
   `resolveGitSingleItem`).
5. `src/sources/remoteUrl.ts` → `remoteUrlResolver` (`'remote-url'`,
   `'Remote URL'`, `'link'`, `resolveRemoteUrl`).

Import `SourceResolver` from `./types` in each file. Since each module's
`resolve`/`resolveArtifactContent` functions already have compatible
signatures with the interface (confirmed in 30.1/spec §4.3), assigning them
directly as object properties should type-check without a wrapper
arrow function — if TypeScript disagrees for a specific module (e.g. a
stricter inferred type on one `opts` parameter), wrap only that one
function in an arrow (`resolve: (source, opts) => resolveGitCustom(source,
opts)`) rather than changing the interface to accommodate it.

## Verification

- Run full test suite, typecheck, lint, build.
- Add one assertion per module checking `xResolver.type` matches the
  module's real `SourceType` literal and `xResolver.resolve === resolveXxx`
  (identity — confirms it's the real function, not an accidental
  re-implementation). `localFolder.test.ts`, `gitCustom.test.ts`, and
  `gitMarketplace.test.ts` already exist as dedicated files — add the
  assertion there. `gitSingleItem` and `remoteUrl` have no dedicated test
  file; both are exercised from the shared `src/sources/sources.test.ts`
  instead (confirmed: it imports `resolveGitSingleItem`/`resolveRemoteUrl`
  directly) — add their two assertions there rather than creating new
  files, matching the existing layout.
- `grep -rn "Resolver: SourceResolver" src/sources/*.ts` should show
  exactly five matches, one per module.
