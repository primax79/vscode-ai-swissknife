# 06.1 — Plan + preview (revised)

> Part of [Install engine](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · revised per [../../SPEC.md](../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) finding B4

**This supersedes an earlier version of this task file.** The earlier
version took `artifactContent: unknown` from an unspecified caller and
produced a plan with only a single target path — both gaps are closed by
initiatives 02.3/03.4/04.3, which this task now depends on and must use.

**Goal**: given a `Package`+`Artifact` already resolved by an initiative
04 resolver, compute a complete `InstallPlan` — every file that would be
created/modified/removed, conflicts, and diagnostics — with no filesystem
writes.

**Grounding**: read `src/domain/types.ts` (`ResolvedArtifact`,
`ResolvedRevision` from 02.3), `src/adapters/types.ts` (`CanonicalSkill`
with `files: ArtifactFile[]` from 03.4, `FieldDiagnostic`/
`TranslationResult` from 05.2), and the resolvers'
`resolveArtifactContent` (02.3) before writing this file — this task is
orchestration of already-built pieces.

Steps:

1. Create `src/install/plan.ts`:

   ```ts
   import type { Package, Artifact, AssistantId, Scope } from '../domain/types';
   import type { Adapter, FieldDiagnostic, ConversionDiagnostic } from '../adapters/types';

   export type FileOperation = 'create' | 'replace' | 'remove';

   export interface PlannedFile {
     relativePath: string; // relative to the artifact's own root (e.g. "SKILL.md", "scripts/run.sh")
     operation: FileOperation;
     existingContentHash?: string; // set when operation === 'replace', the hash of what's there now
   }

   export interface InstallPlan {
     artifactId: string;
     artifactKind: Artifact['kind'];
     sourceRevision?: import('../domain/types').ResolvedRevision;
     targetAssistant: AssistantId;
     targetScope: Scope;
     targetProjectRoot?: string;
     targetRootPath: string; // the artifact's root dir/file on the target side
     files: PlannedFile[];
     conflict: boolean; // true if targetRootPath already exists in ANY form
     conflictPolicy: 'skip' | 'overwrite' | 'merge' | 'undecided';
     diagnostics: FieldDiagnostic[];
     overall: ConversionDiagnostic;
     supported: boolean; // false if artifactKind has no adapter support yet (e.g. anything but 'skill' in Phase 1) — plan() must still return a plan object explaining why, not throw
   }

   export async function planInstall(
     pkg: Package,
     artifact: Artifact,
     sourceAssistant: AssistantId,
     targetAdapter: Adapter,
     targetScope: Scope,
     targetProjectRoot?: string,
   ): Promise<InstallPlan>;
   ```

2. Implementation:
   - Only `artifact.kind === 'skill'` is `supported: true` in this Phase
     (per `specs/foundations.md`'s skill-only-for-resolvers decision,
     reinforced by `tasks/CONTEXT.md`'s rule-deferred-to-Phase-2
     decision) — for any other kind, return a plan with `supported:
     false`, an explanatory diagnostic, empty `files`, and
     `conflict: false`, rather than throwing. The caller (07.2) decides
     what to do with an unsupported plan (most likely: don't offer
     Install at all for non-skill artifacts yet, but that's a UI
     decision, not this function's).
   - Call the artifact's resolver's `resolveArtifactContent(pkg,
     artifact)` (02.3) to get the real `CanonicalSkill` (with its `files`
     payload from 03.4).
   - Call `translateSkill` (05.2) with `sourceAssistant`/
     `targetAdapter.assistant` to get `diagnostics`/`overall`.
   - `targetRootPath` = `targetAdapter.skillPath(content.name, {scope:
     targetScope, projectRoot: targetProjectRoot})`.
   - Build `files`: one `PlannedFile` for `SKILL.md` itself plus one per
     entry in `content.files` (from 03.4), each with `relativePath`
     relative to `targetRootPath`'s parent. For each, check existence on
     disk; `operation: 'replace'` + `existingContentHash` (hash the
     existing file) if present, `'create'` otherwise. This function
     never deletes anything server-side in this Phase — no `'remove'`
     operations are produced yet (a future reinstall-with-fewer-files
     case is out of scope here, note it in your report as a known gap,
     don't build removal detection now).
   - `conflict` is true iff `targetRootPath` (the skill's root directory)
     already exists at all, regardless of individual file operations.
   - `conflictPolicy` starts as `'undecided'` — this function does not
     decide it; the caller (UI, 07.2) sets it based on user choice before
     calling `applyInstall` (06.2). Validate in 06.2 that `apply` refuses
     to proceed with `conflictPolicy: 'undecided'` when `conflict` is
     true.
   - Validate `content.name` via `validateSkillName` (03.4) and each
     `content.files[].relativePath` via `validateRelativeFilePath` (03.4)
     **before** building any `PlannedFile` — a validation failure here
     must produce a plan with `supported: false` and a diagnostic
     explaining why, not throw an uncaught exception up through the UI.
3. Write `src/install/plan.test.ts`:
   - No conflict: plan against an empty temp target dir, confirm
     `conflict: false`, every file `operation: 'create'`.
   - Conflict: pre-create the target skill dir with different content,
     confirm `conflict: true`, `operation: 'replace'` with a real
     `existingContentHash`, and — this is the core "plan never writes"
     guarantee, test it directly — the pre-existing file is byte-identical
     after `planInstall` returns (read it back, compare).
   - Unsupported kind: an `Artifact` with `kind: 'agent'` produces
     `supported: false` and doesn't throw.
   - A malicious `content.files[].relativePath` (e.g. `"../../evil"`)
     produces `supported: false` with a diagnostic naming the rejected
     path, not a thrown error and not a `PlannedFile` with that path.

**Verification**: the test file passes, in particular the
plan-never-writes and path-validation cases; `npm run lint && npm run
typecheck && npm run build` all exit 0. One commit containing
`src/install/plan.ts` and `src/install/plan.test.ts` — nothing else.
