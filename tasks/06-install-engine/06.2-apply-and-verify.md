# 06.2 — Apply + verify + registry recording

> Part of [Install engine](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md)

**Goal**: given an `InstallPlan` (task 06.1) the caller has decided to
proceed with, actually write the file atomically, re-read it back to
verify, and record a `ManagedInstallation` in the registry (initiative
02.2).

**Grounding**: SPEC.md §2.4 "apply"/"verify" bullets. `src/domain/
registry.ts` (initiative 02.2) for `writeRegistry`/`readRegistry` — reuse
them, don't re-implement JSON persistence here.

Steps:

1. Create `src/install/apply.ts`:
   ```ts
   import type { InstallPlan } from './plan';
   import type { Adapter, CanonicalSkill, CanonicalRule } from '../adapters/types';
   import type { ManagedInstallation } from '../domain/types';

   export interface ApplyResult {
     installation: ManagedInstallation;
     verified: boolean;
   }

   export async function applyInstall(
     plan: InstallPlan,
     content: CanonicalSkill | CanonicalRule,
     targetAdapter: Adapter,
     artifactMeta: { sourceId?: string; packageId?: string; artifactId?: string; installedVersion?: string },
   ): Promise<ApplyResult>;
   ```
2. Implementation:
   - Call `targetAdapter.writeSkill(...)` or `.writeRule(...)` (branch on
     which `content` shape was passed — a `'name' in content` check
     distinguishes `CanonicalSkill` from `CanonicalRule` at runtime, or
     thread the `kind` through from the `InstallPlan` if that's cleaner;
     your choice, state which in the report).
   - **Verify**: immediately re-read via `targetAdapter.readSkill(...)`/
     `.readRule(...)` at the same location, and compare the result to
     what was written (structural equality on the fields that matter —
     `name`/`description`/`body`/`extraFields` for skill, `content` for
     rule). Set `verified: true` only if this actually matches; if it
     doesn't, **do not throw** — return `verified: false` and let the
     caller (the UI, a later initiative) decide how to surface that,
     since a false verification after a real write is a signal, not
     necessarily a fatal error, and this function's contract is "report
     what happened," not "guarantee it."
   - **contentHash**: compute a simple hash (e.g. `crypto.createHash
     ('sha256')` over the canonical content) and store it on the
     `ManagedInstallation.contentHash` field — this is the "hash saved at
     apply time" SPEC.md §3.6 requires for later drift detection (Phase
     3), even though nothing reads it back to detect drift yet in this
     Phase.
   - Build the `ManagedInstallation` record from `plan` + `artifactMeta` +
     `new Date().toISOString()` for `installedAt`, then call
     `readRegistry`/append/`writeRegistry` (initiative 02.2) for the
     correct scope — **read-modify-write, not a blind overwrite**: read
     the current registry, push the new installation (or replace an
     existing entry with the same `(assistant, scope, projectPath, kind,
     name)` key if reinstalling), write it back.
3. Write `src/install/apply.test.ts`, against a temp directory and a temp
   registry path (never the real `~/.ai-toolkit/` or a real assistant
   config dir):
   - Happy path: apply a `CanonicalSkill`, confirm the file exists at the
     expected path with the expected content, `verified: true`, and the
     registry (read back via `readRegistry`) now contains exactly one
     matching `ManagedInstallation` with a non-empty `contentHash`.
   - Reinstall: apply the same artifact twice (e.g. simulating an update
     with different `content`), confirm the registry still has exactly
     one entry for that `(assistant, scope, kind, name)` — not two
     duplicates — and that its `contentHash` changed to reflect the new
     content.

**Verification**: the test file passes, especially the no-duplicate-entry
reinstall case; `npm run lint && npm run typecheck && npm run build` all
exit 0. One commit containing `src/install/apply.ts` and
`src/install/apply.test.ts` — nothing else. After this commit, update
`tasks/00-INDEX.md`'s row for initiative `06` to `✅ done`.
