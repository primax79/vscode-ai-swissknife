# 43.2 — Engine: disable / enable for file kinds

One task, one commit. Depends on 43.1 (findings: layout A cleared for Kilo, unverified for the others). No UI. Decided by the architect within the owner's decisions D-Q1 a / D-Q2 a (first iteration: skill, agent, command only).

**Read first:** `plan.md` (locked-in decisions), `notes/43.1-findings.md`, `src/adapters/types.ts` (the `Adapter` interface), `src/adapters/{claude,kilo}.ts` (path layout of skills/agents/commands per scope), `src/domain/types.ts` (`ManagedInstallation`), `src/domain/registry.ts` (state schema, `readState`/`writeState`, `SCHEMA_VERSION`), `src/domain/stateLock.ts` (`withStateLock`, merged in 46.3), `src/engine/softDelete.ts` (rename + EXDEV fallback pattern).

## Do

1. **Adapter hook**: add to the adapter interface `getDisabledPath(kind, name, loc): string | undefined`. Layout A: `<assistant root>/_disabled/<kind>/<name>` where `<assistant root>` is the parent of the active `skills|agents|commands` dir (e.g. `~/.kilo/_disabled/skills/foo`, `<project>/.claude/_disabled/agents/bar.md`); kinds other than skill/agent/command return `undefined`. Implement for `kilo-code` (cleared) and `claude-code` (marked unverified: expose `disableSupport: 'verified' | 'unverified' | 'unsupported'` on the adapter; Claude `unverified`, others `unsupported` and `getDisabledPath` returns `undefined`).
2. `src/engine/disable.ts` (no `vscode` import): `planDisable(inst)`, `applyDisable(plan)`, `applyEnable(inst)`: a single `rename` (EXDEV fallback copy+delete as in `softDelete.ts`), parent directories created; enabling returns the item to its exact original path; **never overwrites**: if the target exists (enable: an active item with the same name now exists) return a typed `{ status: 'conflict', existingPath }` and do nothing; unsupported kind or adapter → typed `{ status: 'unsupported', reason }`.
3. **State**: add optional `disabled?: boolean` and keep `path` pointing at the real current location of the files. Disabling a managed installation sets `disabled: true` and the new `path`; enabling clears it and restores `path`. Write the state with `withStateLock`; if the state write fails after the move, roll the move back. Reads treat a missing flag as enabled; bump `SCHEMA_VERSION` only if the loader validates strictly (state if you did).
4. **Drift** (`src/engine/drift.ts`): a `disabled` installation is analysed at its current path and must never produce `missing-on-disk` for being moved; (`update` of a disabled item is out of scope here: it must be refused with a clear reason until 43.3 defines it).

## Verification

`src/engine/disable.test.ts` on temp fixtures (real files, Kilo adapter with a temp `homeRoot`/project): disable then enable restores byte-identical files at the original path for a skill dir, an agent file and a command file at global and project scope; state flag and `path` follow each step; enable with a same-name active item present returns `conflict` and changes nothing; unsupported kind (`mcp-server`) and unsupported adapter return `unsupported`; failure injected in the state write rolls the move back; drift on a disabled item does not report `missing-on-disk`; a Kilo fixture proves the disabled path is outside the scanned dirs (path does not start with the active dir). Existing tests untouched and green. `npm test` green, `npm run build` clean.
