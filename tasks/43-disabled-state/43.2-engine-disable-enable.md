# 43.2 — Motore: disabilita / abilita per i tipi basati su file

Un task, un commit. Dipende da 43.1 (risultati: layout A validato per Kilo, non verificato per gli altri). Nessuna UI. Deciso dall'architetto nell'ambito delle decisioni dell'owner D-Q1 a / D-Q2 a (prima iterazione: solo skill, agent, command).

**Read first:** `plan.md` (decisioni consolidate), `notes/43.1-findings.md`, `src/adapters/types.ts` (l'interfaccia `Adapter`), `src/adapters/{claude,kilo}.ts` (layout dei percorsi di skills/agents/commands per ambito), `src/domain/types.ts` (`ManagedInstallation`), `src/domain/registry.ts` (schema dello stato, `readState`/`writeState`, `SCHEMA_VERSION`), `src/domain/stateLock.ts` (`withStateLock`, unito in 46.3), `src/engine/softDelete.ts` (pattern rename + fallback EXDEV).

## Cosa fare

1. **Hook dell'adapter**: aggiungere all'interfaccia dell'adapter `getDisabledPath(kind, name, loc): string | undefined`. Layout A: `<assistant root>/_disabled/<kind>/<name>` dove `<assistant root>` è il genitore della directory attiva `skills|agents|commands` (ad es. `~/.kilo/_disabled/skills/foo`, `<project>/.claude/_disabled/agents/bar.md`); i tipi diversi da skill/agent/command restituiscono `undefined`. Implementare per `kilo-code` (validato) e `claude-code` (marcato non verificato: esporre `disableSupport: 'verified' | 'unverified' | 'unsupported'` sull'adapter; Claude `unverified`, gli altri `unsupported` e `getDisabledPath` restituisce `undefined`).
2. `src/engine/disable.ts` (nessun import `vscode`): `planDisable(inst)`, `applyDisable(plan)`, `applyEnable(inst)`: un singolo `rename` (fallback EXDEV copy+delete come in `softDelete.ts`), creazione delle directory genitore; l'abilitazione riporta l'elemento esattamente al suo percorso originale; **non sovrascrive mai**: se il target esiste (abilitazione: esiste ora un elemento attivo con lo stesso nome) restituire un `{ status: 'conflict', existingPath }` tipizzato e non fare nulla; tipo o adapter non supportato → `{ status: 'unsupported', reason }` tipizzato.
3. **Stato**: aggiungere il campo opzionale `disabled?: boolean` e mantenere `path` puntato alla reale posizione corrente dei file. Disabilitare un'installazione gestita imposta `disabled: true` e il nuovo `path`; abilitarla rimuove il flag e ripristina `path`. Scrivere lo stato con `withStateLock`; se la scrittura dello stato fallisce dopo lo spostamento, annullare lo spostamento. Le letture trattano un flag mancante come abilitato; incrementare `SCHEMA_VERSION` solo se il loader effettua una validazione stretta (dichiarare se è stato fatto).
4. **Drift** (`src/engine/drift.ts`): un'installazione `disabled` viene analizzata al suo percorso corrente e non deve mai produrre `missing-on-disk` per il fatto di essere stata spostata; (`update` di un elemento disabilitato è fuori ambito qui: deve essere rifiutato con un motivo chiaro finché 43.3 non lo definisce).
