# 43.3 — Inventory: disabled places, also for unmanaged items

One task, one commit. Depends on 43.2 (merged: `getDisabledPath`, `planDisable/applyDisable/applyEnable`, `disabled` flag on managed installations) and 40.1 (merged: `src/engine/installedTree.ts`). No UI. Decided by the architect (owner decisions D-Q1 a, D-Q2 a, D-Q3 a).

**Read first:** `plan.md`, `notes/43.1-findings.md`, `src/engine/disable.ts` (43.2), `src/engine/discovery.ts` (`scanInstalledInventory`, `ObservedArtifact`), `src/engine/installedTree.ts` (40.1: `Place`, state union, severity table, `buildInstalledTree`), `src/adapters/{kilo,claude}.ts` (`getDisabledPath`, `disableSupport`), `src/domain/types.ts`.

## Do

1. **Adapter helper**: `getDisabledRoot(kind, loc): string | undefined` = the `_disabled/<kind>` directory (the `dirname` of what `getDisabledPath` returns for a dummy name, implemented explicitly rather than by trickery) for adapters whose `disableSupport !== 'unsupported'`.
2. **Scan**: `scanInstalledInventory` additionally scans each supported adapter's disabled roots (per scope, per kind skill/agent/command) and returns those items as `ObservedArtifact`s with `disabled: true` (add the optional field to the type). They are self-describing (assistant and scope from the root they live under, kind from the folder). Items that belong to a **managed** installation with `disabled: true` (state `path` inside a disabled root) are returned as managed (not duplicated as observed). Matching against sources (`identical`/`different`) is computed exactly as for active observed items. A disabled item is never reported `missing-on-disk`.
3. **Disable / enable for unmanaged items** (no state record exists): `planDisableObserved(obs)` / `applyDisableObserved(plan)` / `applyEnableObserved(obs)` in `src/engine/disable.ts` with the same rename / EXDEV / never-overwrite / typed `conflict` | `unsupported` semantics as 43.2; the layout is self-describing so no state is written. `promote` of a disabled observed item is refused with "Enable it first".
4. **Place model** (`installedTree.ts`): add `disabled` to the `Place` state (managed or unmanaged) and to the severity table as the **lowest** severity (a disabled place never masks a real problem on another place of the same object; when every place of an object is disabled, `worstState` is `disabled`). `Place` gets `disabled: boolean`.

## Verification

Tests on temp fixtures (Kilo adapter with temp home/project): a disabled unmanaged skill/agent/command is returned as observed with `disabled: true`, correct assistant/scope/kind; a managed disabled installation appears once (managed), not also as observed; an identical-to-source disabled copy shows match `identical`; disable then enable of an observed item restores byte-identical files; enable conflict and unsupported cases; promote refused; `buildInstalledTree` with an object that has one enabled and one disabled place keeps the enabled place's severity as `worstState` and an all-disabled object reports `disabled`. Existing tests untouched and green. `npm test` green, `npm run build` clean.
