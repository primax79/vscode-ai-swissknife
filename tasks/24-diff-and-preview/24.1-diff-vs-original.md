# 24.1 — Diff-vs-original command

> Part of [Diff-vs-original + preview-before-install](plan.md) · spec: [../specs/phase-6-spec.md](../specs/phase-6-spec.md) §3, §4.2

## Goal

A new command showing a real diff between an installed/discovered item and
its resolved original, using initiative 23's shared resolve+translate
accessor (23.1/23.2) instead of any ad-hoc resolution. Depends on 23.2
having landed and merged.

This task must produce one commit containing only its changes.

## Steps

1. Add a new command (e.g. `aiSwissknife.diffAgainstOriginal`) available:
   - From `InstalledInstallationItem` when its drift report status is
     `modified-locally` or `modified-and-update-available`
     (`src/ui/installedView.ts`, `DriftReport` type in
     `src/engine/types.ts`).
   - From `ObservedArtifactItem` when `observed.match?.status === 'different'`
     (`src/engine/discovery.ts`).
2. Handler resolves the "original" via 23's shared accessor (called fresh —
   no cached content exists to reuse, per the spec's explicit correction):
   for a managed item, resolve+translate from its `sourceId`/`artifactId`'s
   registered source at the assistant's native format; for an unmanaged
   item, resolve+translate using the matched `sourceId`/`packageId`/
   `artifactId` from `observed.match`.
3. For `skill` (a directory, not a single file): diff only the primary
   `SKILL.md` file's content; if any resource files also differ, show a
   plain informational message listing them (not a folder-level diff).
4. For `rule`: diff the extracted demarcated block
   (`<!-- ai-swissknife:managed:${sourceId} -->` … `<!-- /ai-swissknife:managed -->`,
   see the markers already used in `src/engine/apply.ts`'s rule-apply path)
   against the canonical rule's translated content — not the whole shared
   file.
5. For `mcp-server`: diff the specific JSON entry for this server's `id`
   against the translated original — not the whole shared config file.
6. For every other kind (`agent`, `command`), diff the whole file — it's
   already a standalone unit.
7. Use `vscode.diff(leftUri, rightUri, title)`. The "original" side has no
   real on-disk file — write it to a `TextDocumentContentProvider` under a
   custom scheme (e.g. `ai-swissknife-diff:`) rather than a temp file on
   disk, so nothing is left behind after the diff editor closes.
8. Per the locked-in "original means current upstream" decision: do not
   attempt to resolve the exact `sourceRevision.commit` that was installed
   — resolve whatever the source currently returns. No special-casing for
   `modified-and-update-available` beyond what the diff naturally shows
   (combined local+upstream delta is expected and acceptable for this
   pass).

## Verification

- Manual verification: install a skill, hand-edit its `SKILL.md` on disk,
  run drift check, confirm the new diff command appears and shows a
  correct diff. Repeat for an `agent` or `command`. If a `rule`/`mcp-server`
  fixture is easy to construct, verify the extracted-unit diffing
  specifically (not diffing the whole shared file).
- Unit test whatever pure logic can be isolated (e.g. the demarcated-block
  extraction for `rule`, the JSON-entry extraction for `mcp-server`) without
  requiring the VS Code diff editor itself.
- Run full test suite, lint, typecheck, build.
