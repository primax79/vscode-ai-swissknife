# 46.1 — CLI skeleton and read-only commands

One task, one commit. No change to any `src/ui/` file.

**Read first:** `../CONTEXT.md`, `plan.md` (the contract), `esbuild.config.js`, `package.json` (`main`, `files`/`.vscodeignore`, `scripts`), `src/domain/registry.ts` (`readManifest`, `readState`, roots), `src/engine/{discovery,drift,plan,installMatrix}.ts`, `src/sources/registry.ts`, `src/adapters/registry.ts` (`getEnabledAdapters` falls back to all adapters when `vscode` is missing), and for the pattern `../vscode-mcp-dap-debugger/src/cli/` (commander usage, JSON-only stdout) without copying its MCP parts.

## Do

1. **Build**: a second esbuild entry `src/cli/main.ts` -> `dist/cli.js` (node, cjs, shebang), `bin` entry `ai-swissknife` in `package.json`, included in the vsix. Add `commander` as the only new dependency (state it in the commit message). A build-time check fails when `dist/cli.js` contains `require('vscode')` or `from 'vscode'` anywhere.
2. **Global options** per the plan contract (`--workspace`, `--home`, `--assistants`), a single `emit(json)` / `fail(code, message)` helper so stdout stays pure JSON, and typed error codes (`INVALID_ARGUMENT`, `NOT_FOUND`, `SOURCE_RESOLUTION_FAILED`, `INTERNAL`).
3. **Commands** (each returns JSON, documented with a short example in `--help`):
   - `sources` : global + workspace sources with `{id, type, scope, url|localPath, branch|tag}`.
   - `catalog [--source <id>] [--kind <k>]` : resolves the sources (using the hardened resolvers) and lists artifacts `{sourceId, scope, packageId, artifactId, kind, name, description, version}`; per-source failures are reported inside the result (`diagnostics`), not as a global failure.
   - `installed [--scope global|project] [--assistant <id>] [--kind <k>]` : managed + observed items with `{key, kind, name, assistant, scope, membership, path, sourceId?, match?: identical|different}` (`scanInstalledInventory`).
   - `updates` : drift report per managed item (`up-to-date | update-available | modified-locally | modified-and-update-available | missing-on-disk`).
   - `item <key>` : detail: origin, installed-in places, diff availability (no diff body; add `--diff` to include a unified diff, size-capped).
   - `plan-install --source <id> --artifact <id> --assistants a,b --scopes global,project [--overwrite-check]` : the `planInstallMatrix` summary (new / conflict / unsupported with reasons per assistant x scope), **never applies**.
4. The commands never write any file (assert in tests by snapshotting the temp tree before and after).
