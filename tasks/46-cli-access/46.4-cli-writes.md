One task, one commit (if the extraction makes it larger, report and propose a split). Depends on 46.1 (CLI), 46.3 (lock), 46.5 (merged: `src/cli/gates.ts` with `requireWrite` / `refuseCodeKinds`, `--allow-code-kinds`, plan-only without `--write`), 47.1 (`planUpdateAll` / `applyUpdateAll`) and 42.1 (trash engine: `listTrash`, `restoreFromTrash`, `deleteFromTrash`, `emptyTrash`). **Read first:** `plan.md` (the CLI contract), `src/cli/{definitions,commands,main,types,gates,output}.ts` (new commands go through the single definition table so `describe` covers them), `src/engine/{update,redistribute,installMatrix,softDelete,discovery}.ts`, `src/ui/installedView.ts` (`removeManagedInstallation`, `doUninstallItem`: the logic to move into the engine), `src/ui/sourcesView.ts` (add/remove source manifest edits, duplicate-id handling), `src/sources/sourceDefaults.ts` (`validateLocation`, `deriveSourceDefaults`), `src/domain/stateLock.ts`.

## Do

All commands: plan-only without `--write` (print what would happen, change nothing), applied with `--write`; `hook` / `mcp-server` kinds refused unless `--allow-code-kinds`; JSON on stdout per the contract; every file change inside `withStateLock`; every apply output lists the files it changed and, when it overwrote or removed something, where the previous version was saved.

1. **Extract into the engine** (no `vscode`; the UI methods then call the extracted functions with unchanged behaviour and tests): `uninstallInstallation(inst, { mode: 'soft' | 'hard' })` (state record removal + `softDeletePath` for soft, `fs.rm` for hard) and the source manifest mutations `addSourceToManifest` / `removeSourceFromManifest` (validated with the 44.1/36.1 validators, duplicate id rule: `DUPLICATE_ID` unless `--replace`).
2. `apply-install` with the same arguments as `plan-install` plus `--overwrite`: re-plans internally with `planInstallMatrix`, applies only new targets, conflicts only with `--overwrite` (previous version to the trash), returns per-target outcomes.
3. `uninstall <key> [--hard]` (soft = move to the trash is the default; `--hard` is permanent and must be explicit).
4. `source add <type> <location> [--id <id>] [--name <name>] [--scope global|project] [--replace]` (id/name derived with `deriveSourceDefaults` when omitted) and `source remove <id> --scope ...`.
5. `update [<key>] [--all] [--scope] [--assistant] [--source] [--kind] [--include-modified]` built on `planUpdateAll` / `applyUpdateAll` (47.1): one item by key or all; modified-locally copies skipped unless `--include-modified` (their previous version goes to the trash, as in 47.1); the output per item adds `oldRevision` / `newRevision` (the source commit or version recorded before and after) and `changedFiles: { added, changed, removed }` (reuse the file-tree comparison helper written for `redistribute`; extract it into a shared module if it is private there).
6. `trash list` (read-only, both scopes, newest first), `trash restore <id> [--to <path>]` and `trash empty [--scope]` (the last two need `--write`; restore never overwrites and reports a conflict as a typed error).
