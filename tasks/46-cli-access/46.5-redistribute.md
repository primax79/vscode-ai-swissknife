# 46.5 — `redistribute`: push an edited skill to its installed copies (v1: installed from a local folder)

One task, one commit. Owner request 2026-10-08 ("a command available to agents to redistribute skills when they modify them", clarified: "if installed from a local folder"). Design and decisions: `specs/dev-deploy-study.md` (DD-Q2: modified-locally copies are skipped unless `--force`, previous version to the trash; DD-Q3: nothing is installed where there is no copy unless `--install-missing`; DD-Q4: command name and place). Depends on 46.1 (CLI skeleton), 46.3 (lock), 47.1 (`planUpdate`, `applyUpdateAll`, merged), 47.4 (`checkDriftForAll`, merged). **Do not edit AGENTS.md in this task** (Kilo's non-interactive runs are denied that edit; the architect updates it afterwards).

**Read first:** `plan.md` (the CLI contract), `specs/dev-deploy-study.md` sections 3-5, `src/cli/{main,commands,definitions,types,output}.ts`, `src/engine/{update,drift,installMatrix,softDelete}.ts`, `src/domain/registry.ts` (`fromDesiredSource`, manifests), `src/sources/localFolder.ts`.

## Do

1. **Engine** `src/engine/redistribute.ts` (no `vscode` import):
   - `planRedistribute({ target, installations, sources, assistants?, scopes?, items?, force?, installMissing?, homeRoot?, projectRoot? })` where `target` is a folder path **or** an installed item name/key. Resolve the registered `local-folder` source(s) whose `localPath` equals the folder or contains it (project-scope relative paths resolved as `toDesiredSource` does); a name/key resolves to the source of that installation. No matching `local-folder` source → typed `NOT_A_LOCAL_FOLDER_SOURCE` error naming what was found (v1 never touches other origins).
   - For every managed installation whose `sourceId` is such a source (all scopes and assistants, then filtered by the options), classify with the drift machinery: `identical` (nothing to do), `stale` (the folder's content hash differs and the installed copy is unmodified), `modified-locally` (installed files changed after install: skipped unless `force`), `missing-on-disk`, and `orphan` (the artifact no longer exists in the folder: reported, never deleted).
   - With `installMissing`: for each artifact in the folder and each requested assistant x scope without a managed installation from this source, plan an install through `planInstallMatrix` (reported as `missing`/`new`).
   - `applyRedistribute(plan)`: applies the `stale` items (and `modified-locally` ones only with `force`, after copying the previous version to the trash exactly as `applyUpdateAll` does) and the planned new installs, sequentially, one failure never stopping the rest; per target `{ item, kind, assistant, scope, path, classification, action, oldHash, newHash, changedFiles: { added, changed, removed }, backupPath? }` (compute `changedFiles` by comparing the installed tree before/after).
2. **CLI** `redistribute <path-or-item>` registered through the single command-definition table (so `describe` covers it): options `--item <name...>`, `--assistants`, `--scope global|project`, `--force`, `--install-missing`, `--write`. **Without `--write` it prints the plan and changes nothing** (output `{ "mode": "plan", "targets": [...] }`); with `--write` it applies (`{ "mode": "applied", "targets": [...] }`). Kinds `hook` and `mcp-server` are refused (`KIND_NOT_ALLOWED`) unless `--allow-code-kinds` is also given. Implement the gate as a small shared helper (`requireWrite`, `refuseCodeKinds`) that the future write commands of 46.4 will reuse; errors `WRITE_NOT_ENABLED` / `KIND_NOT_ALLOWED` follow the plan's JSON error shape. Applying runs inside the existing state lock (the install engine already takes it).
3. Never modify anything outside the known roots; paths from the command line are resolved and validated against the registered source's `localPath`.

## Verification

Tests on temp fixtures with real files (a `local-folder` source registered in a temp home/workspace manifest, two skills installed to `claude-code` and `kilo-code`, global and project): editing a skill in the folder → plan lists the copies as `stale`, nothing changes on disk (snapshot the temp tree before/after) ; `--write` updates them, outputs old/new hashes and the right `changedFiles`; an installed copy edited by hand is `modified-locally` and skipped, with `--force` it is overwritten and its previous version exists under `_deleted/` (content equals the pre-update content); a skill removed from the folder is reported `orphan` and its installed copy is still there; `--install-missing` installs into an assistant/scope that had no copy and without it nothing is installed; a folder that is not a registered local-folder source → `NOT_A_LOCAL_FOLDER_SOURCE`; `hook`/`mcp-server` refused without `--allow-code-kinds`; JSON on stdout is exactly one document and exit codes are non-zero on errors; `describe` lists `redistribute`. The existing CLI tests stay green. `npm test` green, `npm run build` clean.
