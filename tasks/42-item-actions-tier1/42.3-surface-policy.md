# 42.3 — Surface policy: fixed inline trio + context menu by state

One task, one commit. Depends on 39.2 (the actions exist), 40.2 (tree rows) and 42.2. No registry (plan, locked-in decisions).

**Owner decision (AS-Q4, 2026-10-08):** always show **Favorite, Uninstall, Update** inline (enabled or disabled depending on the state, so the icons keep stable positions); every other action that applies to the item's state goes in the **context menu** (right-click).

**Read first:** `plan.md`, `specs/actions-study.md` section 3, `package.json` (`commands`, `menus.view/item/context`, current `inline@1..5` on installed rows ~:366-460; the `contextValue` strings carry the state, e.g. `installedInstallation:modified-locally`, `observedArtifactItem:different`), `src/ui/installedView.ts` (where `contextValue` is built, `:249` and `:299`), `src/ui/dashboard.ts` row rendering (40.2) and message switch. VS Code docs for command `enablement` in `../references/vscode_doc/` (check how disabled tree-item actions render before relying on it; if a disabled inline action is NOT rendered greyed-out, say so in the Final Report and fall back to the `when`-hidden variant for that icon, keeping order).

## Definitions

- **Favorite** = the existing Recommend / Unrecommend for workspace (`recommendForWorkspace` `$(star-empty)` / `unrecommendForWorkspace` `$(star-full)`); the icon reflects the state (empty star / full star). Confirmed by the owner (2026-10-08): "Preferiti" = Recommend / Unrecommend for workspace.
- Managed item (`installedInstallation[:status][:recommended]`) inline trio, in this fixed order: **Favorite**, **Update** (enabled only for `update-available` and `modified-and-update-available`, disabled otherwise), **Uninstall** (always enabled; opens the soft/hard Remove modal of 39.2).
- Unmanaged item (`observedArtifactItem[:one|:many][:different|:identical]`): the owner's trio does not apply, so its fixed inline trio (confirmed by the owner, 2026-10-08) is **Promote** (enabled), **Diff** (enabled only when it differs from a source), **Remove** (soft/hard modal of 39.2). No Favorite/Update slots on unmanaged rows.
- **Context menu** (right-click), grouped, shows every other action *applicable to the state*, never greyed filler: Preview, Diff (managed: only when modified), Edit, Copy to..., Move to..., Install to other environments (41), Reveal in File Explorer, Copy path, Open source repository (42.2), Promote/Unmanage when applicable, Restore-related entries are not here.
- Available (catalog) and source rows are out of scope for this task.

## Do

1. `package.json`: command `enablement` for Update and Diff (context keys derived from `viewItem`, e.g. `viewItem =~ /:(update-available|modified-and-update-available)/`) so the inline trio keeps its positions; the inline entries use `group: inline@1..3` in the order above; move everything else from `inline` to `view/item/context` groups with proper `when` predicates.
2. **Dashboard rows (icon-only):** the same trio by membership, with the same enabled/disabled logic, plus an overflow `...` button that opens a plain dropdown with the context-menu set. The detail panel keeps the full set with icon + label (39.4).
3. Append the resulting action x state x surface table to `specs/actions-study.md` under "What shipped".

Manual in the Extension Development Host: three stable icons per row, Update greyed when nothing to update, right-click lists the rest.
