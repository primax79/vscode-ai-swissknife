# 42.2 — Helper di navigazione

Un task, un commit. Nessuna modifica al motore.

**Read first:** `plan.md`, `package.json` (pattern di comandi e menu), `src/ui/installedView.ts` (come gli elementi espongono `installation.path` / `observed.path`), `src/ui/dashboard.ts` (switch dei messaggi, area delle azioni del pannello di dettaglio), `src/domain/types.ts` (`sourceId`, `sourceRevision`, `url` della sorgente).

## Cosa fare

Tre piccoli comandi, ciascuno utilizzabile dalla barra laterale (menu contestuale, non inline) e dalla Dashboard (barra delle azioni del pannello di dettaglio e menu di overflow di riga di 42.3; finché 42.3 non esiste, solo nella barra di dettaglio):

- `aiSwissknife.revealInOS` ("Reveal in File Explorer" / Finder): `vscode.commands.executeCommand('revealFileInOS', uri)` sul percorso dell'elemento.
- `aiSwissknife.copyPath`: `vscode.env.clipboard.writeText(path)` più una conferma nella barra di stato.
- `aiSwissknife.openSourceRepo` ("Open Source Repository"): per gli elementi con una sorgente, aprire l'URL git della sorgente (e, quando il commit della revisione è noto e l'host è in stile GitHub/GitLab/Gitea, l'URL del commit) con `vscode.env.openExternal`; nascosto quando l'elemento non ha sorgente o la sorgente è una cartella locale.

Icone: `$(folder-opened)`, `$(copy)`, `$(link-external)`. I pulsanti del pannello di dettaglio hanno icona + breve etichetta; le righe compatte sono solo icona.

## Verification

`ui.test.ts`: ogni comando invoca la corretta API vscode con il percorso / URL dell'elemento (spy); `openSourceRepo` non viene offerto per elementi da cartella locale o senza sorgente; i messaggi della Dashboard vengono instradati agli stessi handler. `npm test` verde, `npm run build` pulito.
