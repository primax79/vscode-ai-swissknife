# 42.1 — Restore from trash (engine + command)

One task, one commit. Depends on 39.2 (which defines the soft/hard Remove and writes to `_deleted/`).

**Read first:** `../CONTEXT.md`, `plan.md`, `src/engine/softDelete.ts` (layout `<.ai-swissknife>/_deleted/<kind>/<name>-<timestamp>/`, `softDeletePath`), `src/ui/installedView.ts` (`removeManagedInstallation`, `doUninstallItem`), `src/domain/registry.ts` (`manifestPath`), `src/engine/types.ts`.

## Problem

Soft-delete moves items to `_deleted/` but nothing can bring them back, so "recoverable" is only true by hand (study observation 1).

## Do

1. Engine, no `vscode`: in `src/engine/softDelete.ts` add `listTrash(scope, projectRoot?, homeRoot?)` returning `{ kind, name, deletedAt, trashPath, originalPath? }[]` newest first, and `restoreFromTrash(entry, targetPath, opts)` that moves it back (rename, EXDEV fallback copy+delete as `softDeletePath` does). The original path must be recorded at delete time: extend `softDeletePath` to write a small sidecar `<trashDir>/.origin.json` (`{ originalPath, assistant?, scope, kind, name, deletedAt }`); entries without a sidecar (deleted before this change) are listed as "origin unknown" and restorable only to a path the user picks.
2. Also add `deleteFromTrash(entry)` (permanent removal of one trash entry, `fs.rm` recursive) and `emptyTrash(scope?, projectRoot?, homeRoot?)` (permanently removes every entry of the given scope, or both scopes when omitted, returns the count and the entries that failed) for the Dashboard and sidebar surfaces (42.4, 42.5); this task provides and tests them, and adds the command `aiSwissknife.emptyTrash` ("Empty Trash...", `$(clear-all)`): modal confirmation "Permanently delete N item(s) from the trash? This cannot be undone." with the choices Global / Workspace / Both when both have entries (Workspace only when a workspace is open), then a summary message. Empty trash is also in the command palette.
2b. Restore never overwrites: if `originalPath` exists, return a conflict and let the caller ask (Restore under another name / Cancel).
3. For entries that were managed installations, restoring does **not** recreate the state record (they come back as unmanaged files and can be promoted); say so in the confirmation message.
4. UI: command `aiSwissknife.restoreFromTrash` ("Restore from Trash...", `$(history)`), in the Installed view title menu and the command palette; QuickPick over both scopes (workspace entries only when a workspace is open), each item `label = name`, `description = kind · scope · deleted <relative time>`, then confirm and restore. Message after: "Restored <name> to <path>".
5. Vocabulary: scope shown as "Workspace"/"Global" (CONTEXT.md).

## Verification

`softDelete.test.ts`: delete then list shows the entry with the sidecar origin; restore puts the files back byte-identical; conflict returned when the original exists; `emptyTrash` removes only the requested scope, returns the right count and reports a failing entry without stopping the others; entry without sidecar listed as origin unknown; EXDEV fallback path covered as the existing tests do. `ui.test.ts`: command lists both scopes' entries, no workspace -> only global, restore message. Tests use temp dirs only. `npm test` green, `npm run build` clean.
