# 42.5 — Sidebar Trash view

One task, one commit. Depends on 42.1.

**Read first:** `plan.md`, `package.json` (`views` for the sidebar container, `commands`, `menus.view/item/context`), `src/extension.ts` (view/provider registration ~:100-210), `src/ui/installedView.ts` (tree provider pattern, `ThemeIcon` usage), `src/engine/softDelete.ts` (42.1).

## Do

- New view `aiSwissknife.trash` named "Trash", **collapsed by default**, last in the container, with `when: aiSwissknife.trashHasItems` so it does not exist while the trash is empty (set the context key with `setContext` on activation and after every delete/restore/refresh; refresh also on `_deleted` file watcher or on the existing refresh commands).
- A small `TrashProvider` (TreeDataProvider): one item per entry, `label = name`, `description = <kind> · <Global|Workspace> · <relative time>`, tooltip with original path, icon from `getKindIconName(kind)`; no grouping.
- Inline icons per item (icon-only): Restore (`$(history)`) and Delete permanently (`$(trash)`, modal confirmation: cannot be undone). Title-bar actions: Refresh and **Empty Trash** (`aiSwissknife.emptyTrash` of 42.1, `$(clear-all)`); after emptying, the context key becomes false and the view disappears. Commands `aiSwissknife.trashRestore` / `aiSwissknife.trashDelete` take the tree item and call the same engine functions as the command of 42.1 and the Dashboard.
- Workspace entries appear only when a workspace is open.

## Verification

`ui.test.ts`: provider lists entries with the expected label/description; context key true when entries exist and false when empty (spy on `setContext`); restore/delete commands call the engine with the right entry; Empty Trash in the title bar calls `emptyTrash` and hides the view afterwards; after an action the view and the key refresh. `package.json` check: valid JSON and the view `when` references the key. `npm test` green, `npm run build` clean.
