# 47.4 — Drift check resolves each source once, not once per item

One task, one commit. Found while verifying 47.1 (2026-10-08). Decided by the architect (delegated by the owner).

**Read first:** `plan.md`, `src/engine/drift.ts` (`checkForUpstreamUpdate`: it calls `getSourceResolver(source.type).resolve(source, { homeRoot })` on **every call**, so a drift check over N installations from the same git source runs N resolves, each a `git fetch` over the network), `src/engine/update.ts` (`planUpdateAll`, which already caches the resolution per source for planning but calls `checkForUpstreamUpdate` per item when no report is supplied), `src/ui/installedView.ts` (`checkDrift`: one `checkForUpstreamUpdate` per installation).

## Do

1. `checkForUpstreamUpdate(inst, source, homeRoot, opts?)` accepts an optional pre-resolved `SourceResolution` (or a small per-run cache object `{ get(source) }`) and uses it instead of resolving again; behaviour unchanged when none is passed.
2. A helper `checkDriftForAll(installations, sources, homeRoot?)` in `src/engine/drift.ts` that resolves each source **once** per run (concurrency 1 per source, sources may run in parallel up to a small bound) and returns the reports; `InstalledTreeDataProvider.checkDrift` and `planUpdateAll` use it.
3. A failing source marks only its own installations as drift-check failed (as today), never aborts the run.

## Verification

Tests: 5 installations from one source -> the resolver spy is called once (was 5); two sources -> twice; one source failing does not stop the other and its items report the failure; the existing drift tests and the `checkDrift` UI tests stay green untouched. `npm test` green, `npm run build` clean.
