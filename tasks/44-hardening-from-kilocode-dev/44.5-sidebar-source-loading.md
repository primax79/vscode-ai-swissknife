# 44.5 — Sidebar: per-source loading state

One task, one commit. Depends on 38.1 (`refreshSource`, `resolveSourceGroup`). Plan F7.

**Read first:** `plan.md` (F7), `src/ui/availableView.ts` (`doRefreshCatalog`, the group items), `src/ui/sourcesView.ts` (`SourceItem`, tree rendering), 38.1's result, `kilocode-dev/.kilo/plans/agent-behaviour-skills-tab-loading-indicator.md` (the pattern Kilo planned).

## Problem

Sources resolve one after another; while one is slow or stuck (SSH hang up to the 120 s git timeout) the sidebar shows nothing for the others and nothing says what is happening.

## Do

Show a spinner icon (`$(sync~spin)` ThemeIcon) and description "Refreshing..." on a source item while its group is being resolved (both in the full refresh and in `refreshSource`), replacing it with the normal icon and the item count or the error when done; the other sources render as soon as they are resolved instead of all-at-once at the end. Keep the existing failed-source diagnostic behaviour.

## Verification

`ui.test.ts`: during a deliberately delayed resolver, the tree reports a loading item for that source and fully rendered items for the finished ones; after resolution the loading state is gone; a failing source shows its diagnostic as before. `npm test` green, `npm run build` clean.
