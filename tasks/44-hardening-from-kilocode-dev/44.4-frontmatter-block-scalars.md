## Problem (reproduced)

`description: >` (or `|`, `>-`, `|-`) followed by indented lines yields the description `">"`; a plain scalar continued on indented lines is cut at the first line. Colons inside plain values are already handled (do not regress that).

## Do

Extend the line-based parser (no new YAML dependency) to handle, for `name` and `description`: folded `>` / literal `|` block scalars with optional chomping indicators (`-`, `+`) — join folded lines with a space, literal lines with `\n`, trim — and plain/quoted scalars continued on indented lines. Apply the same fix to the codec's equivalent parsing for agents/commands if it has the same weakness (list what you found in the Final Report either way).
