# 44.6 — Le modifiche alla configurazione Kilo non devono riformattare le voci adiacenti né spostarne i commenti

Un task, un commit. Seguito di 44.3, individuato dalla verifica indipendente dell'architetto con Kilo reale il 2026-10-09. Deciso dall'architetto (delegato dall'owner).

**Read first:** `notes/44.3-findings.md`, `src/adapters/kilo.ts` (le chiamate `jsonc.modify` / `applyEdits` nei metodi di scrittura/rimozione MCP, ~:690-730) e `src/adapters/kilo.test.ts`.

## Problema (riprodotto con l'adapter reale)

File di partenza:

```jsonc
{
  // my personal Kilo config
  "model": "google/gemini-3.8-flash", // keep this
  "mcp": {
    "existing": { "type": "remote", "url": "https://example.com/mcp" }, // do not touch
  },
  /* block comment */
  "theme": "dark",
}
```

Dopo l'installazione di due server tramite l'adapter: (a) la voce `"existing"` non toccata è stata **riformattata** (espansa su più righe), e (b) il suo commento finale `// do not touch` è finito dopo la `},` della **nuova ultima voce**, per cui il commento ora annota il server sbagliato. Causa: `jsonc.modify(..., { formattingOptions })` riformatta l'oggetto contenitore attorno al punto di inserimento e inserisce prima della virgola/commento finale della voce precedente.

## Cosa fare

Rendere la modifica **minimale**: le uniche modifiche al file sono il testo della voce `mcp.<id>` aggiunta/sostituita/rimossa. Provare, in quest'ordine, e mantenere la prima soluzione che soddisfa i test: (1) `formattingOptions: { insertSpaces: true, tabSize: 2, keepLines: true }` (verificare che la versione installata di jsonc-parser lo supporti); (2) calcolare la modifica direttamente con `jsonc.parseTree`: individuare l'ultima proprietà dell'oggetto `mcp`, estendere il punto di inserimento oltre la sua `,` finale e qualsiasi **commento finale sulla stessa riga**, quindi inserire `\n<indent>"<id>": <value>` gestendo la virgola in modo che il file resti valido; la sostituzione di un id esistente modifica solo l'intervallo del valore di quella proprietà; la rimozione elimina solo quella proprietà (e la relativa virgola finale / commento sulla stessa riga). Le nuove voci vengono formattate con indentazione di 2 spazi rispetto al genitore; le voci adiacenti non vengono mai toccate.

## Verification

Test su file temporanei usando esattamente il file di partenza mostrato sopra: dopo l'installazione di `swk-new` (stdio) e `swk-remote` (http), il diff rispetto all'originale contiene **solo** le righe aggiunte per le due voci e la virgola necessaria sulla riga della voce precedente **senza spostare `// do not touch`** (che resta sulla riga di `existing`); l'installazione in un file senza chiave `mcp`, in un `{}` vuoto, in un file con indentazione a 4 spazi e in uno con tabulazioni mantiene lo stile di indentazione proprio di ciascun file; la sostituzione di un id modifica solo quella voce; la disinstallazione di entrambi ripristina il file originale **byte per byte**; il risultato viene sempre analizzato correttamente da `jsonc.parse` e da Kilo reale (smoke test opzionale `AISK_REAL_KILO=1`: notare che `kilo mcp list` stesso può aggiungere le chiavi `$schema` e `permission` al file, comportamento proprio di Kilo, quindi effettuare il confronto prima di eseguirlo). I test esistenti di 44.3 restano verdi. `npm test` verde, `npm run build` pulito.
