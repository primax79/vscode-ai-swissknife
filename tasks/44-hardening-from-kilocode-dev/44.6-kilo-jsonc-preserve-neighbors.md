# 44.6 — Kilo config edits must not reformat neighbours or displace their comments

One task, one commit. Follow-up of 44.3, found by the architect's independent check with the real Kilo on 2026-10-09. Decided by the architect (delegated by the owner).

**Read first:** `notes/44.3-findings.md`, `src/adapters/kilo.ts` (the `jsonc.modify` / `applyEdits` calls in the MCP write/remove methods, ~:690-730) and `src/adapters/kilo.test.ts`.

## Problem (reproduced with the real adapter)

Starting file:

```jsonc
{
  // my personal Kilo config
  "model": "google/gemini-3.8-flash", // keep this
  "mcp": {
    "existing": { "type": "remote", "url": "https://example.com/mcp" }, // do not touch
  },
  /* block comment */
  "theme": "dark",
}
```

After installing two servers through the adapter: (a) the untouched `"existing"` entry was **reformatted** (expanded to several lines), and (b) its trailing comment `// do not touch` ended up after the **new last entry's** `},`, i.e. the comment now annotates the wrong server. Cause: `jsonc.modify(..., { formattingOptions })` reformats the enclosing object around the insertion point and inserts before the previous entry's trailing comma/comment.

## Do

Make the edit **minimal**: the only changes to the file are the added/replaced/removed `mcp.<id>` entry text. Try, in this order, and keep the first that satisfies the tests: (1) `formattingOptions: { insertSpaces: true, tabSize: 2, keepLines: true }` (check the installed jsonc-parser version supports it); (2) compute the edit yourself with `jsonc.parseTree`: locate the `mcp` object's last property, extend the insertion point over its trailing `,` and any **same-line trailing comment**, then insert `\n<indent>"<id>": <value>` with the comma handled so the file stays valid; replacing an existing id edits only that property's value range; removing deletes only that property (and its own trailing comma/same-line comment). New entries are pretty-printed with 2-space indentation relative to their parent; neighbours are never touched.

## Verification

Tests on temp files using the exact starting file above: after installing `swk-new` (stdio) and `swk-remote` (http), the diff against the original contains **only** added lines for the two entries and the comma needed on the previous entry's line **without moving `// do not touch`** (it stays on the `existing` line); installing into a file with no `mcp` key, into an empty `{}`, into a file with 4-space indentation and into one with tabs keeps each file's own indentation style; replacing an id changes only that entry; uninstalling both restores the original file **byte for byte**; the result always parses with `jsonc.parse` and with the real Kilo (opt-in smoke test `AISK_REAL_KILO=1`: note that `kilo mcp list` itself may add `$schema` and `permission` keys to the file, which is Kilo's own behaviour, so compare before running it). Existing 44.3 tests stay green. `npm test` green, `npm run build` clean.
