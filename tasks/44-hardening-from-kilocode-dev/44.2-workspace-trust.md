# 44.2 — Workspace Trust

Un task, un commit dopo una breve indagine. Esecutore: sessione dedicata (richiede l'Extension Development Host).

**Read first:** `plan.md` (F2), `package.json`, `src/extension.ts` (attivazione e `refreshCatalog()` automatico), `src/ui/availableView.ts` (`doRefreshCatalog`: lettura del manifest di progetto e risoluzione delle sorgenti), `references/vscode_doc/INDEX.md` (cercare le pagine "Workspace Trust" / "untrustedWorkspaces"; il grep precedente per la chiave del manifest non aveva trovato nulla, quindi individuare la pagina corretta per titolo).

## Cosa fare

1. **Indagare e registrare** (in `../notes/44.2-findings.md`): cosa fa oggi VS Code con questa estensione in un workspace in Restricted Mode (nessuna dichiarazione): viene abilitata? Verificare nell'Extension Development Host aprendo una cartella non attendibile. Citare la pagina della documentazione.
2. **Dichiarare** `capabilities.untrustedWorkspaces`: `{ "supported": "limited", "description": "..." }` in `package.json` (o il valore giustificato dai risultati).
3. **Filtro di sicurezza**: quando `vscode.workspace.isTrusted` è falso, `doRefreshCatalog` non deve risolvere le sorgenti a livello di progetto (nessun git, nessuna rete) e non deve leggere percorsi controllati dal progetto a scopo di esecuzione; le sorgenti globali continuano a funzionare. Mostrare un avviso su una riga nella vista Sources ("Project sources are disabled in Restricted Mode: trust this workspace to enable them", vocabolario Workspace) e rieseguire il refresh su `vscode.workspace.onDidGrantWorkspaceTrust`.
4. Le installazioni e gli aggiornamenti che eseguono codice o effettuano fetch (planInstall/applyInstall per l'ambito progetto, Update, Install elsewhere) vengono rifiutati con lo stesso avviso finché il workspace non è attendibile.

## Verification

`ui.test.ts`: con `isTrusted=false` le sorgenti del manifest di progetto non vengono risolte (spy del resolver non invocato) mentre quelle globali sì; la concessione della fiducia avvia un refresh; l'installazione nell'ambito progetto viene rifiutata con l'avviso. File dei risultati scritto con la citazione della documentazione. `npm test` verde, `npm run build` pulito. Manuale: aprire una cartella non attendibile contenente un manifest di progetto con una sorgente git, confermare che non avvenga alcun clone.
