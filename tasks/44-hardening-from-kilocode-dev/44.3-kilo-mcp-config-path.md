# 44.3 — Kilo MCP config: write where Kilo actually reads

Two phases. Phase 1 is a verification spike executed by the architect session (needs the real Kilo CLI); Phase 2 is delegated only after Phase 1 confirms the problem. Plan F3.

**Read first:** `plan.md` (F3), `src/adapters/kilo.ts` (MCP read/write/remove at ~:470-650, `mcpConfigPath`), `src/adapters/kilo.test.ts`, `SPEC.md` (the Kilo cell of the `mcp-server` row, ~:135, and the resolved note ~:412), the real Kilo code: `kilocode-dev/packages/opencode/src/kilocode/config/overlay.ts` (`files`, `dirs`, `projectTarget`, `globalTarget`), `.../kilocode/mcp-migrator.ts`, `kilocode-dev/packages/core/src/v1/config/config.ts:230` (`mcp` schema), `kilocode-dev/docs/specs/multi-repo-marketplace-analysis.md` §2.9.

## Phase 1 — verify (record in `../notes/44.3-findings.md`)

With a throwaway HOME and temp workspace, install an MCP server through our Kilo adapter (global and project), then ask the real Kilo what it loaded (`kilo mcp list` or the equivalent CLI/`kilo run` check, whichever exists; cite the command). Also try the same server placed in the `mcp` field of `kilo.jsonc`. Record: does Kilo load the `mcp.json` entry, yes/no; does it load the `kilo.jsonc` one. Also record the real target-file discovery for project and global scope. If Kilo **does** load `mcp.json`, stop: close F3 as not-a-bug and say so; Phase 2 is cancelled.

## Phase 2 — fix (only if Phase 1 shows `mcp.json` is ignored)

1. Add `jsonc-parser` (the parser Kilo uses) as the one new dependency; say so in the commit message.
2. Kilo adapter MCP read/write/remove target the real config file: discovery order `kilo.jsonc`, `kilo.json`, `opencode.jsonc`, `opencode.json`; project: `.kilo`/`.kilocode` dir or project root (as `projectTarget`), global: the Kilo global config dir; if none exists create `kilo.jsonc` in `.kilo` (project) or the global config dir. Edit only the `mcp.<id>` key with `jsonc-parser`'s `modify`/`applyEdits` so comments and formatting survive; never rewrite the whole document.
3. Map our canonical MCP model to Kilo's `mcp` entry shape (`core/src/v1/config/config.ts:230`, `.../config/mcp.ts`): read it from the real schema, do not guess field names.
4. Legacy: if a previous version of this extension wrote `mcp.json` entries, `readMcpServer`/discovery still reads them (so Installed/Uninstall keep working) and Uninstall removes them there; new installs never write `mcp.json`.
