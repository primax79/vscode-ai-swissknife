# 44.3 — Kilo MCP config: write where Kilo actually reads

Phase 1 (verification with the real Kilo) is done and confirmed the problem; Phase 2 is the fix. Plan F3.

**Read first:** `plan.md` (F3), `src/adapters/kilo.ts` (MCP read/write/remove at ~:470-650, `mcpConfigPath`), `src/adapters/kilo.test.ts`, `SPEC.md` (the Kilo cell of the `mcp-server` row, ~:135, and the resolved note ~:412), the real Kilo code: `kilocode-dev/packages/opencode/src/kilocode/config/overlay.ts` (`files`, `dirs`, `projectTarget`, `globalTarget`), `.../kilocode/mcp-migrator.ts`, `kilocode-dev/packages/core/src/v1/config/config.ts:230` (`mcp` schema), `kilocode-dev/docs/specs/multi-repo-marketplace-analysis.md` §2.9.

## Phase 1 — DONE (2026-10-08): confirmed, see `notes/44.3-findings.md`

With the real Kilo 7.4.5 in an isolated HOME: entries written by our adapter to `~/.config/kilo/mcp.json` and `<project>/.kilo/mcp.json` are **ignored** ("No MCP servers configured"); our `stdio` shape placed in `kilo.jsonc` makes Kilo declare the **whole configuration invalid**; the correct shape (`{type:"local", command:[...], environment}` / `{type:"remote", url, headers}`) in `kilo.jsonc` is loaded, at global and project scope, even with `//` comments. **Phase 2 is required and must change the file AND the entry shape together** (fixing only the path would break users' Kilo configs).

## Phase 2 — fix (delegated)

1. Add `jsonc-parser` (the parser Kilo itself uses) as the one new dependency; say so in the commit message.
2. **Target file** (both scopes): the first existing of `kilo.jsonc`, `kilo.json`, `opencode.jsonc`, `opencode.json` — global: in the Kilo global config dir (`<home>/.config/kilo/`, also accept `config.json` last); project: in `<project>/.kilo/` or `<project>/.kilocode/`, else the same names at the project root; if none exists create `kilo.jsonc` in `<home>/.config/kilo/` (global) or `<project>/.kilo/` (project). Mirror `kilocode-dev/packages/opencode/src/kilocode/config/overlay.ts` (`files`, `dirs`, `projectTarget`, `globalTarget`).
3. **Shape mapping** (source of truth: `kilocode-dev/packages/core/src/v1/config/mcp.ts`; read the structs, do not guess): canonical `stdio` → `{ type: "local", command: [command, ...args], environment: env }` (omit empty/undefined fields, no `enabled`); canonical `http`/`sse` → `{ type: "remote", url, headers }`. Reading maps back: `local` → `stdio` (`command[0]`, rest as `args`, `environment` or `env` as `env`), `remote` → `http`. Unknown/extra fields (`cwd`, `timeout`, `enabled`, `oauth`) are preserved through `extraFields` on read and written back on update when present.
4. **Write with `jsonc-parser`'s `modify` + `applyEdits`** so comments, key order and formatting survive: only the `mcp.<id>` key is edited, never the whole document rewritten; removal deletes only that key (and the `mcp` object if it becomes empty only if it was created by us — otherwise leave it).
5. **Legacy**: `readMcpServer`/discovery still also read `mcp.json` entries (old installs by this extension stay visible and removable); `removeMcpServer` removes from the real config AND from a legacy `mcp.json` if the id is there; new installs never write `mcp.json`.
6. Where the adapter is used by `planInstall`/`applyInstall` for `mcp-server` kinds, make sure the plan's `targetDir`/`proposedFiles` point at the real config file, and that conflict detection looks at the real file.

## Verification

Unit tests on temp files: a `kilo.jsonc` with `//` comments and trailing commas survives install and uninstall byte-for-byte except the changed key; stdio and http entries are written in the exact Kilo shapes; read maps them back; both scopes; target-file discovery order; creation of `kilo.jsonc` when none exists; legacy `mcp.json` entry still discoverable and removable; no write to `mcp.json`. **Opt-in real-Kilo smoke test** (skipped unless `AISK_REAL_KILO=1`, run by the architect before merging): isolated `HOME`, install through the adapter, then `kilo mcp list` lists the server (status failed is fine for a non-MCP command). `npm test` green, `npm run build` clean.
