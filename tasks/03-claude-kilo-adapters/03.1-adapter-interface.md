# 03.1 — Adapter interface

> Part of [Claude + Kilo adapters](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md)

**Goal**: define the shared `Adapter` contract that every assistant's
adapter implements, scoped to `skill`+`rule` only (per `plan.md`'s shared
decision), plus the canonical in-memory representations both kinds are
read into/written from.

**Grounding**: SPEC.md §4 "Adapter per assistant" and §1's `skill`/`rule`
table rows (repo root `SPEC.md`, read both before writing this file).

Steps:

1. Create `src/adapters/types.ts`:

   ```ts
   import type { AssistantId, Scope } from '../domain/types';

   export interface CanonicalSkill {
     name: string;
     description: string;
     body: string; // the markdown content after the frontmatter
     extraFields: Record<string, unknown>; // unrecognized frontmatter fields, preserved verbatim (SPEC.md §4 "canonical model")
   }

   export interface CanonicalRule {
     content: string; // raw file content, no frontmatter parsing — CLAUDE.md/AGENTS.md are plain markdown (SPEC.md §1)
   }

   export interface LocationRef {
     scope: Scope;
     projectRoot?: string; // required when scope === 'project'
   }

   export interface Adapter {
     readonly assistant: AssistantId;

     skillPath(name: string, loc: LocationRef): string;
     readSkill(name: string, loc: LocationRef): Promise<CanonicalSkill | null>; // null if not found, not an error
     writeSkill(skill: CanonicalSkill, loc: LocationRef): Promise<void>;
     listSkills(loc: LocationRef): Promise<string[]>; // names only

     rulePath(loc: LocationRef): string;
     readRule(loc: LocationRef): Promise<CanonicalRule | null>;
     writeRule(rule: CanonicalRule, loc: LocationRef): Promise<void>;
   }
   ```

2. `extraFields` on `CanonicalSkill` exists specifically so a round-trip
   (read a skill written by a human with extra frontmatter fields
   `SKILL.md` doesn't require, then write it back unchanged) doesn't drop
   those fields — this is the "canonical model preserves unrecognized
   fields" decision from SPEC.md §4; don't remove this field to simplify
   the type.
3. No implementation in this file — no `fs` import, no path-joining logic.
   That's tasks 03.2/03.3.
4. Run `npm run typecheck` — passes (nothing implements the interface yet,
   this only confirms the file itself compiles).

**Verification**: `npm run typecheck` and `npm run lint` exit 0. One
commit containing only `src/adapters/types.ts`.
