# 03.4 — Shared skill codec, path validation, and directory payload (hardening)

> Part of [Claude + Kilo adapters](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · hardening context: [../../SPEC.md](../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) findings B2, B5, B6

**Goal**: close three gaps a second review found in the already-merged
adapters (`src/adapters/claude.ts`, `src/adapters/kilo.ts`) and detector
(`src/sources/detect.ts`): frontmatter parsing is duplicated three times
with no real YAML guarantee, a skill's supporting files (scripts,
references, assets) are silently dropped on install, and untrusted
artifact names/paths aren't validated before being joined into a
filesystem path.

**Depends on**: task 02.3 landing first (this task extends
`CanonicalSkill`, which 02.3 doesn't touch, so it can also run in
parallel with 02.3 if delegated separately — but read 02.3's task file
first to avoid duplicating the `nativeFormat`/`ResolvedRevision` changes
it already makes).

Steps:

1. **Add a real YAML dependency.** Add `yaml` (the `eemeli/yaml` npm
   package) to `package.json`'s `dependencies`. This project commits to
   **semantic preservation, not byte-verbatim preservation** (SPEC.md §7,
   finding B6) — parsing and re-serializing with a real YAML library
   will not reproduce the exact original formatting (comments, quote
   style, key order in edge cases), but it will correctly round-trip
   every value (multiline strings, lists, nested objects) instead of the
   current minimal parser's JSON-shaped assumptions. Do not attempt to
   preserve the raw YAML AST/comments in this task — that's explicitly
   out of scope per the locked-in decision in `tasks/CONTEXT.md`.
2. **Extract one shared codec module**, `src/adapters/skillCodec.ts`:

   ```ts
   import type { CanonicalSkill } from './types';

   export function parseSkillMarkdown(raw: string): CanonicalSkill; // frontmatter (via `yaml`) + body
   export function serializeSkillMarkdown(skill: CanonicalSkill): string;
   ```

   Replace the three separate/duplicated frontmatter implementations
   currently in `src/adapters/claude.ts`, `src/adapters/kilo.ts`, and
   `src/sources/detect.ts` (its `extractSkillFrontmatter`/similar helper)
   with calls to this shared module. `detect.ts` only needs `name`
   (and maybe `description`) for the detection pass — it's fine for it to
   call `parseSkillMarkdown` and only read the fields it needs, rather
   than keeping a separate lightweight parser, now that a shared one
   exists.
3. **Validate names and paths before they reach a destination join.** In
   `skillCodec.ts` or a new `src/adapters/validate.ts` (your choice, keep
   it discoverable), add:

   ```ts
   export function validateSkillName(name: string): void; // throws with a clear message on failure
   ```

   Reject: empty string, any path separator (`/` or `\`), `.` or `..` as
   the whole name, a name starting with `.` (hidden/reserved-looking),
   NUL bytes, and anything that isn't a reasonable skill-name character
   set (letters, digits, hyphen, underscore — reject everything else
   rather than trying to allow-list every safe Unicode case). Call this
   from every adapter's `skillPath()`/`writeSkill()` (`claude.ts`,
   `kilo.ts`) **before** joining the name into a path — a name that fails
   validation must throw before any `fs` call, not after. Also add a
   `validateRelativeFilePath(root: string, candidate: string): string`
   helper that resolves `candidate` against `root` and throws if the
   resolved path escapes `root` (compare the resolved absolute path
   against `root` with `path.resolve`, not a string-prefix check, which
   can be fooled) — this is what task 04.3/06 will use for each file in a
   skill's directory payload (next step), not just the skill's own name.
4. **Extend `CanonicalSkill` with a directory payload.** In
   `src/adapters/types.ts`:

   ```ts
   export interface ArtifactFile {
     relativePath: string; // relative to the skill's own root directory, e.g. "scripts/run.sh"
     content: Buffer; // read as binary — a skill's supporting files aren't guaranteed to be text
     mode?: number; // POSIX file mode bits, when meaningful (e.g. executable scripts)
   }

   export interface CanonicalSkill {
     name: string;
     description: string;
     body: string;
     extraFields: Record<string, unknown>;
     files: ArtifactFile[]; // every file under the skill directory EXCEPT SKILL.md itself
   }
   ```

   Update `claude.ts`'s and `kilo.ts`'s `readSkill`/`writeSkill` to
   actually walk the skill's directory (read every file besides
   `SKILL.md`, recursively, populate `files`; on write, create every
   entry in `files` at its `relativePath` under the target skill
   directory, validating each path with `validateRelativeFilePath` from
   step 3 before writing, and restoring `mode` with `fs.chmod` when
   present). Symlinks: for this task, **refuse** to follow or write a
   symlink anywhere in a skill's directory tree (throw a clear error
   naming the offending path) — a real symlink policy (allow-list,
   resolve-and-copy-target, etc.) is a follow-up, not silently supporting
   or silently ignoring one.
5. Update every existing test (`claude.test.ts`, `kilo.test.ts`,
   `detect.test.ts`, and any translator test that builds a
   `CanonicalSkill` literal) for the new `files: ArtifactFile[]` field —
   most can pass `files: []` where a multi-file payload isn't the point
   of that specific test. Add new tests specifically for this task:
   - Round-trip a skill with at least one supporting file (e.g. build a
     temp fixture with `SKILL.md` + `scripts/run.sh`) through
     `readSkill`/`writeSkill` and confirm the supporting file's content
     and (on POSIX) executable mode bit survive.
   - `validateSkillName` rejects each malicious case listed in step 3
     (table-test them, don't write one test per case if a loop keeps it
     readable).
   - `validateRelativeFilePath` rejects a `../`-escaping candidate.
   - A symlink inside a skill directory causes `readSkill` to throw
     rather than silently follow it (construct a real symlink in a temp
     dir with `fs.symlink` for this test, don't mock the filesystem).

**Verification**: `npm run typecheck && npm run lint && npm test` all
pass. One commit containing all changed/new files — nothing else. After
this commit, update `tasks/00-INDEX.md`.
