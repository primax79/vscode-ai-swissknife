# 03.4 — Shared skill codec and safe directory payload (hardening)

> Part of [Claude + Kilo adapters](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · accepted review decisions: [round 001](../_reviews/001-hardening-gate-SUMMARY.md) and [round 002](../_reviews/002-hardening-gate-SUMMARY.md), especially decisions 2 and 12. This is the first open hardening task: 02.3 consumes its codec, while 04.3 extends its detector contract.

## Goal

Create one codec for the complete skill directory, preserve safe relative paths and executable modes, and make malformed detected skills visible as structured diagnostics instead of silently disappearing or aborting valid siblings.

This task must produce one commit containing only its changes.

## Grounding

Read and re-`rg` all callers of `parseSkillMarkdown`, `serializeSkillMarkdown`, adapter `readSkill`/`writeSkill`, `findSkillDirs`, and both `resolveArtifactContent` functions before editing.

## Steps

1. Define `CanonicalSkillFile { path: string; content: Uint8Array; mode?: number }`, require `CanonicalSkill.files: CanonicalSkillFile[]`, and define `CanonicalSkillDocument = Omit<CanonicalSkill, 'files'>`. `parseSkillMarkdown()` parses only `SKILL.md` text and returns `CanonicalSkillDocument`; `readSkill(skillDir)` owns recursively loading the complete payload and attaching `files`.

2. Add shared functions used by both adapters and both source resolvers:

   - `readSkill(skillDir): Promise<CanonicalSkill>` reads `SKILL.md` plus every regular descendant file.
   - `writeSkill(skill, skillDir): Promise<void>` writes deterministic `SKILL.md` and `files`, creates parents, and applies each defined `mode` with `chmod`.
   - `canonicalSkillHash(skill): string` hashes a stable serialization of scalar fields, sorted extra fields, and files sorted by normalized path including content and mode. Tasks 06.1/06.2 import this exact function; there must not be two hash algorithms.

3. Validate every file path before joining it to a target. Accept normalized, non-empty POSIX relative paths only. Reject absolute paths, drive-letter/UNC forms, empty or `.` paths, `..` traversal, NUL bytes, duplicate normalized paths, and any path equal to `SKILL.md`. Use a post-resolution containment check too.

4. Traverse with `lstat`, never implicit symlink following. Reject symlinks, sockets, devices, FIFOs, and unreadable entries. Only regular files and real directories belong in a canonical payload. Preserve portable permission bits needed by the writer (at minimum executable bits); ignore ownership and timestamps.

   During source discovery, skip `.git`, `node_modules`, and explicit ignore entries, not every dot-directory: valid repositories may place skills under `.claude/skills` or another dot-directory.

5. Define in `src/sources/types.ts` a `DetectionDiagnostic` with `code`, `severity`, `path`, and `message`, plus `SkillDetectionResult { skills: DetectedSkillDir[]; diagnostics: DetectionDiagnostic[] }`. Codes cover invalid frontmatter/name, unsafe path, and unreadable skill.

6. Change `findSkillDirs()` to return `Promise<SkillDetectionResult>`. A malformed candidate is skipped and produces a diagnostic; valid siblings remain. Infrastructure failures that make the root unreadable may reject the whole operation.

7. Update every current `CanonicalSkill` constructor/copy, both adapters, translator passthroughs, tests, and the local/Git resolver call sites so the commit typechecks with required `files`. Existing translation behavior must copy the complete file array without aliasing mutable byte buffers. Resolver callers consume `result.skills` in this commit; task 04.3 subsequently transports `result.diagnostics` publicly. Export `readSkill()`/`writeSkill()`/`canonicalSkillHash()` for 02.3 and 06; do not refer to not-yet-created `resolveArtifactContent()` functions.

## Verification

- Run the full test suite, typecheck, lint, and build.
- Round-trip a directory with nested text/binary files and an executable file; content and supported mode bits survive.
- Reject traversal, absolute, duplicate-normalized, symlink, socket, unreadable, and `SKILL.md` collision cases without writing outside the destination.
- A fixture containing one valid and one malformed skill returns the valid detection plus a structured diagnostic.
- Discovery reaches a skill below `.claude/skills` while still excluding `.git` and `node_modules`.
- Test that Claude and Kilo adapters use the same codec and produce equivalent canonical content.

## Non-goals

- No byte-for-byte YAML formatting guarantee; semantic frontmatter preservation is required.
- No symlink support.
- No non-skill artifact codec.
