# 03.2 — Claude Code adapter

> Part of [Claude + Kilo adapters](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md)

**Goal**: implement the `Adapter` interface (from 03.1) for Claude Code,
covering `skill` and `rule` only.

**Grounding**: real examples already exist on this machine —
`~/.claude/skills/` has real skill folders (e.g. `conflict-resolver/`),
and `~/.claude/agents/*.md` shows the flat-file convention for a different
kind (not used here, just useful to see the sibling convention). Also read
`agentic-coding-kit/plugins/*/skills/*/SKILL.md` (several real files, e.g.
`agentic-coding-kit/plugins/common-tools/skills/gitignore/SKILL.md`) for
real frontmatter shape (`name`, `description`, sometimes extra fields —
note whatever extra fields you find, `CanonicalSkill.extraFields` must
round-trip them).

Steps:

1. Create `src/adapters/claude.ts` implementing `Adapter` from
   `src/adapters/types.ts`:
   - `assistant = 'claude-code'`.
   - `skillPath(name, loc)`: `path.join(loc.scope === 'global' ?
     os.homedir() : loc.projectRoot!, loc.scope === 'global' ? '' :
     '', '.claude', 'skills', name, 'SKILL.md')` — adjust the join logic
     so it's correct for both scopes (global: `~/.claude/skills/<name>/
     SKILL.md`; project: `<projectRoot>/.claude/skills/<name>/SKILL.md`).
     Throw a clear error if `scope === 'project'` and `projectRoot` is
     missing (same discipline as the registry store, task 02.2).
   - `readSkill(name, loc)`: read the `SKILL.md` file at `skillPath(...)`.
     Parse YAML frontmatter (delimited by `---` lines) to get `name`/
     `description`; put every other frontmatter key into `extraFields`;
     everything after the closing `---` is `body`. Return `null` if the
     file doesn't exist (use `fs.access` or catch `ENOENT` specifically —
     don't swallow other errors as "not found").
   - `writeSkill(skill, loc)`: serialize frontmatter (YAML: `name`,
     `description`, then `extraFields`'s keys in insertion order) + `---`
     + `body`, write to `skillPath(...)`, creating parent directories as
     needed (`fs.mkdir` recursive).
   - `listSkills(loc)`: read the `.claude/skills/` directory (global or
     project), return the list of subdirectory names that contain a
     `SKILL.md` — skip any subdirectory that doesn't (don't error on a
     stray non-skill folder).
   - `rulePath(loc)`: `~/.claude/CLAUDE.md` (global) or
     `<projectRoot>/CLAUDE.md` (project).
   - `readRule`/`writeRule`: plain file read/write, no frontmatter parsing
     (`CanonicalRule.content` is the raw file text) — return `null` from
     `readRule` if the file doesn't exist.
2. Use only Node built-ins (`fs/promises`, `path`, `os`) — no YAML parsing
   library dependency unless one is already in `package.json` (check
   first; if none, write a minimal frontmatter splitter — the format is
   simple `---\nkey: value\n...\n---\nbody`, doesn't need a full YAML
   parser for `skill`'s two required + arbitrary extra flat string
   fields). If a value legitimately needs full YAML (e.g. a list), you may
   add a minimal dependency (`yaml` or `js-yaml`) — state which one and
   why in your final report rather than silently picking one.
3. Write `src/adapters/claude.test.ts` covering, against a temp directory
   (never the real `~/.claude/`):
   - Round-trip: `writeSkill` then `readSkill` returns the same `name`/
     `description`/`body`, and any `extraFields` you fed in.
   - `readSkill` on a nonexistent skill returns `null`, not a throw.
   - `listSkills` returns only directories containing `SKILL.md`, given a
     fixture directory with one valid skill dir and one dir without a
     `SKILL.md`.
   - `rulePath`/`readRule`/`writeRule` round-trip for both scopes.

**Verification**: the test file passes; `npm run lint && npm run
typecheck && npm run build` all exit 0. One commit containing
`src/adapters/claude.ts`, `src/adapters/claude.test.ts`, and any new
dependency added to `package.json`/lockfile — nothing else.
