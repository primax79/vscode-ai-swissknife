**Read first:** `plan.md`, `../46-cli-access/plan.md` (il contratto della CLI), `src/cli/{definitions,commands,main,types}.ts`, `src/engine/discovery.ts` (`scanInstalledInventory(scope, projectRoot, homeRoot)`), `src/domain/registry.ts` (`manifestPath`: i manifest di workspace risiedono in `.vscode/ai-swissknife/manifest.json` o nel percorso legacy `.ai-swissknife/manifest.json`), `src/adapters/{kilo,claude}.ts` (directory di progetto `.kilo`, `.kilocode`, `.claude`).

## Cosa fare

1. **Motore** `src/engine/scanRoots.ts` (nessun import `vscode`): `findWorkspaces(roots: string[], options?: { maxDepth?: number; ignore?: string[]; extraIgnore?: string[] })` restituisce le directory sotto le root che appaiono come workspace: contengono `.claude/`, `.kilo/`, `.kilocode/`, `.vscode/ai-swissknife/` o `.ai-swissknife/`. Regole: ricerca in ampiezza (breadth-first), **maxDepth predefinito 4**, **non segue mai i symlink**, interrompe la discesa in una directory una volta individuata come workspace (i workspace annidati vengono trovati solo al proprio livello: non scendere nei figli di un workspace trovato *tranne* che per continuare a cercare nelle directory sorelle), salta per nome di directory (predefiniti: `node_modules`, `.git`, `.kilo/worktrees` (coppia di segmenti di percorso), `worktrees`, `cache`, `.cache`, `dist`, `out`, `build`, `target`, `_attic`, `_deprecated`, `old`, `very_old`, `.tmp`, `__pycache__`, `venv`, `.venv`); `ignore` sostituisce i valori predefiniti, `extraIgnore` si aggiunge ad essi. Le directory non leggibili vengono saltate e riportate in una lista `skipped` con il relativo motivo, senza mai sollevare eccezioni. Restituisce `{ workspaces: string[], skipped: { path, reason }[] }` con ordine stabile (ordinato).
2. **Aggregazione** `scanInventoryAcrossRoots(roots, { assistants, scopes, homeRoot, options })`: invoca `scanInstalledInventory` per l'ambito Global **una sola volta** e per l'ambito Workspace di ciascun workspace trovato, etichettando ogni elemento con `workspace` (percorso assoluto, oppure `null` per Global) in modo che elementi identici in workspace diversi restino distinguibili (alla chiave dell'elemento della CLI viene aggiunto il nome della cartella del workspace solo quando viene scansionato più di un workspace, ad es. `claude-code:project:skill:foo@my-repo`; le chiavi per singolo workspace restano invariate).
3. **CLI**: opzione globale `--roots <dirs...>` (ripetibile) e `--max-depth <n>`, `--ignore <names...>`, `--extra-ignore <names...>`; rispettate da `installed` e `updates` (e dalla risoluzione in `item` delle chiavi con suffisso del workspace). Con `--roots`, `--workspace` viene ignorato per quei comandi (dichiararlo in `--help`). L'output di `installed` acquisisce `workspace` per ciascun elemento; aggiungere un array `workspaces` e la lista `skipped` al JSON **solo quando viene usato `--roots`** (la forma dell'output esistente resta altrimenti invariata). Aggiornare la tabella delle definizioni dei comandi in modo che `describe` mostri le nuove opzioni.
4. Sola lettura: la scansione non scrive nulla.
