# 48.7 — Quanto è indietro ogni elemento (e ogni sorgente): arricchimento di `updates` e `sources fetch`

Punto 10 della wishlist (`specs/cli-wishlist-comparison.md`): "mostrare di quanto è indietro ciascun clone locale" (un clone di Kilo è rimasto indietro di 6 settimane senza che nessuno se ne accorgesse). Deciso dall'architetto (delegato dall'owner, 2026-10-09). Dipende da 46.1/46.4 (CLI, uniti), 44.1 (helper git irrigiditi), 47.4 (`checkDriftForAll`, unito). **Non modificare AGENTS.md** (l'architetto aggiornerà la documentazione in seguito).

**Read first:** `../46-cli-access/plan.md` (contratto), `src/engine/drift.ts` (`checkDriftForAll`, `DriftReport`), `src/sources/gitProcess.ts` (`runGit`, `validateGitRef`, `resolveAndValidateCacheDir`: ogni chiamata git usa questi validatori e i separatori `--`), `src/sources/{gitCustom,gitMarketplace,gitSingleItem}.ts` (il layout della cache dei cloni sotto `~/.ai-swissknife/cache/sources/<sanitized id>`), `src/cli/{commands,definitions,types}.ts`, `src/domain/types.ts` (`ManagedInstallation.sourceRevision.commit`).

## Cosa fare

1. **Motore** `src/engine/revisionGap.ts` (nessun `vscode`): `describeRevisionGap(inst, source, opts?)` per le installazioni di sorgenti basate su git (`git-custom`, `git-marketplace`, `git-single-item`): usando il clone esistente della sorgente (senza mai clonare qui), restituire `{ installedRevision, latestRevision, commitsBehind, installedDate, latestDate, behindDays }`. `commitsBehind` = `git rev-list --count <installedCommit>..<HEAD of the checked-out branch>`; se il commit installato non è presente nel clone (cronologia riscritta, clone shallow) restituire `commitsBehind: null` con `reason: 'installed-commit-not-found'`. Per `local-folder`, `remote-url` e le installazioni senza commit registrato restituire campi `null` e un `reason` (`'not-git'` / `'no-recorded-commit'`). Ogni invocazione di git passa attraverso `runGit` con ref validati e `--` dove applicabile.
2. **Output di `updates`**: acquisisce per ogni elemento `installedRevision`, `latestRevision`, `commitsBehind`, `behindDays` (null quando sconosciuti), calcolati una sola volta per sorgente (riutilizzare le risoluzioni già eseguite da `checkDriftForAll`; non effettuare un nuovo fetch per ogni elemento). I campi esistenti e il loro significato restano invariati.
3. **`sources fetch [--id <id>] [--scope global|project]`** (nuovo comando, registrato nell'unica tabella delle definizioni in modo che `describe` lo includa): risolve ciascuna sorgente selezionata (questo esegue il `git fetch` che i resolver già fanno) e restituisce `{ id, scope, type, ok, head, headDate, error? }` per sorgente; una sorgente che fallisce non interrompe mai le altre. Non è un comando di scrittura nel senso di `--write` (aggiorna soltanto la cache dei cloni sotto `~/.ai-swissknife/cache`); dichiararlo in `--help`.
4. Testabile con unit test: il motore riceve il percorso del clone e la ricerca dei ref tramite piccole funzioni iniettabili in modo che i test possano usare piccoli repository git reali creati in directory temporanee (init, commit, un secondo clone) anziché la rete.

## Verification

Test con repository git temporanei reali (un repository "remoto" con commit, installazioni registrate al commit 1, HEAD della sorgente al commit 4): `commitsBehind` è 3, `behindDays` calcolato dalle date dei commit, `latestRevision` è HEAD; commit installato sconosciuto al clone → `null` + reason; installazioni da cartella locale e senza commit → `null` + reason; `updates` mostra i nuovi campi e mantiene invariati quelli vecchi; `sources fetch` restituisce head/headDate per sorgente, segnala una sorgente che fallisce (URL errato) senza fermare le altre, e la cache dei cloni è l'unica cosa che modifica; `describe` elenca `sources fetch`. Un valore malevolo di commit/ref registrato viene rifiutato dai validatori prima dell'esecuzione di git. Test esistenti intatti e verdi. `npm test` verde (compila prima i bundle), `npm run build` pulito.
