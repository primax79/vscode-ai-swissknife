# 48.7 — How far behind is each item (and each source): `updates` enrichment and `sources fetch`

One task, one commit. Wishlist item 10 (`specs/cli-wishlist-comparison.md`): "show how far each local clone is behind" (a Kilo clone sat 6 weeks behind unnoticed). Decided by the architect (delegated by the owner, 2026-10-09). Depends on 46.1/46.4 (CLI, merged), 44.1 (hardened git helpers), 47.4 (`checkDriftForAll`, merged). **Do not edit AGENTS.md** (the architect documents afterwards).

**Read first:** `../46-cli-access/plan.md` (contract), `src/engine/drift.ts` (`checkDriftForAll`, `DriftReport`), `src/sources/gitProcess.ts` (`runGit`, `validateGitRef`, `resolveAndValidateCacheDir`: every git call uses these validators and `--` separators), `src/sources/{gitCustom,gitMarketplace,gitSingleItem}.ts` (the clone cache layout under `~/.ai-swissknife/cache/sources/<sanitized id>`), `src/cli/{commands,definitions,types}.ts`, `src/domain/types.ts` (`ManagedInstallation.sourceRevision.commit`).

## Do

1. **Engine** `src/engine/revisionGap.ts` (no `vscode`): `describeRevisionGap(inst, source, opts?)` for installations of git-based sources (`git-custom`, `git-marketplace`, `git-single-item`): using the source's existing clone (never cloning here), return `{ installedRevision, latestRevision, commitsBehind, installedDate, latestDate, behindDays }`. `commitsBehind` = `git rev-list --count <installedCommit>..<HEAD of the checked-out branch>`; if the installed commit is not in the clone (history rewritten, shallow) return `commitsBehind: null` with `reason: 'installed-commit-not-found'`. For `local-folder`, `remote-url` and installs without a recorded commit return `null` fields and a `reason` (`'not-git'` / `'no-recorded-commit'`). Every git invocation goes through `runGit` with validated refs and `--` where applicable.
2. **`updates` output** gains per item `installedRevision`, `latestRevision`, `commitsBehind`, `behindDays` (null when unknown), computed once per source (reuse the resolutions `checkDriftForAll` already makes; do not fetch again per item). Existing fields and their meaning are unchanged.
3. **`sources fetch [--id <id>] [--scope global|project]`** (new command, registered in the single definition table so `describe` covers it): resolves each selected source (this performs the `git fetch` the resolvers already do) and returns `{ id, scope, type, ok, head, headDate, error? }` per source; one failing source never stops the others. It is not a write command in the `--write` sense (it only refreshes the clone cache under `~/.ai-swissknife/cache`); say so in `--help`.
4. Unit-testable: the engine takes the clone path/ref lookup through small injectable functions so tests can use real tiny git repos created in temp dirs (init, commits, a second clone) instead of the network.

## Verification

Tests with real temp git repos (a "remote" repo with commits, installations recorded at commit 1, source HEAD at commit 4): `commitsBehind` is 3, `behindDays` computed from commit dates, `latestRevision` is the HEAD; installed commit unknown to the clone → `null` + reason; local-folder and no-commit installs → `null` + reason; `updates` shows the new fields and the old ones unchanged; `sources fetch` returns head/headDate per source, reports a failing source (bad URL) without stopping the others, and the clone cache is the only thing it modifies; `describe` lists `sources fetch`. A malicious recorded commit/ref value is rejected by the validators before git runs. Existing tests untouched and green. `npm test` green (it builds the bundles first), `npm run build` clean.
