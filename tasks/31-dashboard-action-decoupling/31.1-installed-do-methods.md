# 31.1 — `doUpdateInstallation`/`doUninstallItem`

**Depends on:** nothing beyond current `main` (Phase 8/29.3 confirmed
merged — `getAdapter()` is already in use at the cited lines below,
re-verified 2026-09-08 against `main` after the 29.3/29.4/30.3/30.4
merge).

## Why

`InstalledTreeDataProvider.updateInstallation` (`src/ui/installedView.ts:462`)
and `.uninstallItem` (`:789`) both require an `InstalledInstallationItem`
wrapper (`item.installation`) — a `TreeItem`-adjacent class instance, not a
plain domain object. A Dashboard webview message can only deliver a plain
`ManagedInstallation` (structured-cloned JSON), so neither method is
callable as-is from `DashboardPanel`. Confirmed independently by both the
Codex and Kilo/gemini-3.7-flash spec reviews (`specs/phase-9-spec.md` §1.1).

## Scope

- `src/ui/installedView.ts`:
  - Add `async doUpdateInstallation(inst: ManagedInstallation): Promise<void>`
    containing everything `updateInstallation` (`:462-546` roughly — the
    method body from its `const inst = item.installation;` line onward)
    does today, unchanged, including the already-registry-based
    `const targetAdapter = getAdapter(inst.assistant);` at `:495`.
    `updateInstallation(item?: InstalledInstallationItem)` becomes a thin
    wrapper: keep the `if (!item) { warn; return; }` guard, then `return
    this.doUpdateInstallation(item.installation);`.
  - Same pattern for `uninstallItem` (`:789-813`) →
    `doUninstallItem(inst: ManagedInstallation)`. `removeManagedInstallation`
    (`:771-787`, private, already uses `getAdapter(inst.assistant)` at
    `:773` for the `mcp-server` removal branch) stays private and unchanged
    — called from `doUninstallItem` exactly as it is today from
    `uninstallItem` (current call site `:804`).
- No behavior change for existing sidebar callers — `updateInstallation`/
  `uninstallItem`'s signatures and external behavior (confirmation dialogs,
  messages, refresh calls) are identical before and after; they just
  delegate to the new `do*` methods instead of inlining the logic.

  green.
- `src/ui/installedView.test.ts`: existing tests for `updateInstallation`/

- Manual: `grep -n "item.installation" src/ui/installedView.ts` should show
  exactly the two wrapper call sites (`updateInstallation`,
  `uninstallItem`) and no others — the goal is these two methods only, not
