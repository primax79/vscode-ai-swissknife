# 02.3 — Portable persistence and typed resolved artifacts (hardening)

> Part of [Domain types + registry store](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · accepted review decisions: [round 001](../_reviews/001-hardening-gate-SUMMARY.md) and [round 002](../_reviews/002-hardening-gate-SUMMARY.md), especially decisions 4, 7, 8, and 19. Requires 03.4's shared codec; this file supersedes every earlier draft.

## Goal

Make persistence genuinely portable and make the metadata-to-content boundary type-safe. A project manifest must never serialize machine-specific absolute paths, while skill content resolution must return a `CanonicalSkill` without casts and must not race a shared Git checkout.

This task is one independently verifiable unit and must produce one commit containing only its changes.

## Grounding

Before editing, re-run `rg` for every caller of `readRegistry`, `writeRegistry`, `resolveArtifactContent`, `resolveGitCustom`, and `findSkillDirs`; the code has moved during the hardening reviews. Read `src/domain/types.ts`, `src/domain/registry.ts`, `src/sources/localFolder.ts`, `src/sources/gitCustom.ts`, and `src/adapters/types.ts`.

## Steps

1. Rename every runtime data path under `src/` from `.ai-toolkit` to `.ai-swissknife`. There is no migration: no released user data exists under the old name.

2. Add revision provenance:

   ```ts
   export interface ResolvedRevision {
     commit: string;
     requestedRef?: string;
   }
   ```

   `Package.version` and `ManagedInstallation.sourceRevision` use this type. For Git sources, `commit` is the checked-out SHA and `requestedRef` is the branch/tag/ref requested by the `Source`; do not introduce any alias for `requestedRef`. Explicitly state that `sourceRevision` replaces/removes the legacy `ManagedInstallation.installedVersion` field. Local-folder packages have no resolved revision.

3. Add a typed content carrier with no default generic:

   ```ts
   export interface ResolvedArtifact<T> {
     artifact: Artifact;
     content: T;
   }
   ```

   Both skill resolver entry points must return `Promise<ResolvedArtifact<CanonicalSkill>>`. An unchecked `unknown` cast at this boundary is forbidden.

4. Implement skill content resolution in both source modules. Validate `artifact.kind === 'skill'`, locate the directory captured by detection, and call the shared `readSkill()` codec from 03.4. Reject a package/artifact/source mismatch explicitly. Each function returns `Promise<ResolvedArtifact<CanonicalSkill>>`.

5. In `gitCustom.ts`, introduce one exported per-cache-directory mutex helper. Both `resolveGitCustom()` and Git `resolveArtifactContent()` must use the same lock. The content resolver holds it across checkout of `pkg.version.commit` **and the complete directory read**, so another listing/content call cannot switch the shared checkout between those operations. Task 04.3 extends and stress-tests this same helper; it must not create a second lock map.

6. Replace the single registry file with these persisted contracts:

   ```ts
   export interface DesiredSource {
     id: string;
     type: Source['type'];
     scope: Scope;
     name?: string;
     url?: string;
     branch?: string;
     tag?: string;
     commit?: string;
     localPath?: string; // relative to the scope root; never absolute
   }

   export interface DesiredInstallation {
     sourceId: string;
     artifactId: string;
     assistant: AssistantId;
     scope: Scope;
     requestedRef?: string;
   }

   export interface ManifestFile {
     schemaVersion: number;
     sources: DesiredSource[];
     desiredInstallations: DesiredInstallation[];
   }

   export interface StateFile {
     schemaVersion: number;
     installations: ManagedInstallation[];
   }
   ```

   The manifest is shareable intent; state is observed machine-local installation state. `ObservedArtifact` is persisted in neither.

7. Add explicit conversion at the persistence boundary:

   - `toDesiredSource(source, workspaceRoot?, homeRoot?)` removes runtime-only `projectPath`. A project local path is persisted relative to `workspaceRoot`; a global local path is persisted relative to the user home. Refuse a write when the path lies outside its scope root.
   - `fromDesiredSource(desired, workspaceRoot?, homeRoot?)` reconstructs a runtime `Source`, resolving the relative `localPath` against the selected workspace root for project scope or the home root for global scope, and restoring `projectPath` only at runtime.
   - Never serialize an absolute `projectPath` or `localPath` at either scope.

8. Expose pure-Node `readManifest`, `writeManifest`, `readState`, and `writeState`. Use `~/.ai-swissknife/{manifest,state}.json` globally and `<workspace>/.ai-swissknife/{manifest,state}.json` for project scope. Keep atomic temp-file-plus-rename writes. Missing files return empty current-schema values. Unknown schema versions fail closed with a useful error.

9. Update exports and all current callers. Do not leave aliases named `installations` on `ManifestFile`; the only accepted name is `desiredInstallations`.

## Verification

- Run the full test suite, typecheck, lint, and build.
- Test round-tripping a project `DesiredSource`: persisted JSON contains neither the absolute workspace path nor `projectPath`; reading with another workspace root resolves the same relative intent under the new root.
- Test refusal of project paths outside the workspace and global paths outside the home root.
- Test missing files, atomic writes, and schema-version mismatch independently for manifest and state.
- Test local and Git content resolution as `ResolvedArtifact<CanonicalSkill>` without casts.
- Add an interleaving test in which `resolveArtifactContent()` pauses after checkout while `resolveGitCustom()` requests another ref; prove the content read remains at `pkg.version.commit` because the shared lock covers checkout plus read.

## Non-goals

- No migration from `.ai-toolkit`.
- No install writes and no UI.
- No persisted observed catalog/cache.
- No source networking beyond existing resolver behavior.
