# 02.3 — Persistence and resolved-artifact model (hardening)

> Part of [Domain types + registry store](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · hardening context: [../../SPEC.md](../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) findings B1, B3, I2, I8, I13

**Goal**: close the data-model gaps a second review found before
initiative 06 (install engine) locks in a plan/apply contract on top of
them: artifacts need a way to fetch real content, the registry needs to
stop mixing shareable and machine-local state, and the data directory
needs its final name before any real user has data under the old one.

**This is a revision of already-merged code** — `src/domain/types.ts` and
`src/domain/registry.ts` exist (initiatives 02.1/02.2). Read both in full
first. This task edits them; it does not replace them wholesale.

Steps:

1. **Rename the data directory** `.ai-toolkit` → `.ai-swissknife`
   everywhere it appears in `src/domain/registry.ts` (`registryPath()`)
   and its tests. Grep the whole `src/` tree for `ai-toolkit` first to
   make sure nothing is missed.
2. **Add `ResolvedRevision`** to `src/domain/types.ts`:

   ```ts
   export interface ResolvedRevision {
     requestedRef?: string; // what the Source asked for: a branch/tag name, or undefined for "default"
     commit: string; // the immutable resolved commit SHA
   }
   ```

   Change `Package.version` from `string | undefined` to
   `ResolvedRevision | undefined` — this is a breaking change to
   `Package`'s shape; update every place that constructs a `Package`
   (`src/sources/localFolder.ts`, `src/sources/gitCustom.ts`) and every
   test that reads `.version`. For `local-folder` sources there's no git
   commit — leave `version` undefined there, don't invent a fake commit.
   For `git-custom` (`src/sources/gitCustom.ts`), run `git rev-parse
   HEAD` in the checkout after checkout and populate `commit` with the
   real SHA; `requestedRef` is whatever `source.commit`/`source.tag`/
   `source.branch` was (or undefined for "resolved the default branch").
3. **Add a content-resolution contract.** Add to `src/domain/types.ts`:

   ```ts
   export interface ResolvedArtifact<T = unknown> {
     artifact: Artifact;
     content: T; // a CanonicalSkill (or later CanonicalRule, etc.)
   }
   ```

   Then add one function per existing resolver — `resolveArtifactContent`
   in `src/sources/localFolder.ts` and `src/sources/gitCustom.ts` — with
   this signature:

   ```ts
   export async function resolveArtifactContent(
     pkg: Package,
     artifact: Artifact,
   ): Promise<ResolvedArtifact>;
   ```

   This is the piece that was missing: `findSkillDirs` already discovers
   the real absolute path of a skill directory, but `resolveLocalFolder`/
   `resolveGitCustom` discard it when building the `Artifact`. Fix this at
   the source: have `findSkillDirs`'s result type (or a small
   accompanying map you maintain internally) retain the absolute path
   keyed by the `Artifact.id` you generate, so `resolveArtifactContent`
   can look it up and actually read the file. Don't have callers
   reverse-engineer a path from `artifact.id`/`artifact.name` — this
   function is the only place that knows how to turn an `Artifact` back
   into real content. (This function currently returns a
   `CanonicalSkill` with only `name`/`description`/`body`/`extraFields` —
   task 03.4 extends `CanonicalSkill` to include a full file payload;
   this task only needs the function to exist and return what
   `CanonicalSkill` currently has. Don't block on 03.4 landing first.)
4. **Use a neutral `nativeFormat` id.** Replace the literal string
   `'claude-skill'` (used in `src/sources/localFolder.ts` and
   `src/sources/gitCustom.ts` when constructing `Package`/`Artifact`)
   with `'skill-md'` — the `SKILL.md` format is portable across
   Claude/Codex/Gemini/Kilo (SPEC.md §1), calling it "claude-skill" when
   it isn't Claude-specific is misleading provenance.
5. **Split the registry file into shareable + local state.** Change
   `src/domain/registry.ts`:
   - `registryPath` becomes two functions: `manifestPath(scope,
     projectRoot?)` → `.../<scope-dir>/manifest.json`, and `statePath(scope,
     projectRoot?)` → `.../<scope-dir>/state.json`.
   - `RegistryFile` splits into `ManifestFile { schemaVersion: number;
     sources: Source[] }` (shareable — no `ManagedInstallation` here,
     since every field of that type is machine-specific per the second
     review's finding) and `StateFile { schemaVersion: number;
     installations: ManagedInstallation[] }` (machine-local, holds what's
     actually installed on *this* machine).
   - `readManifest`/`writeManifest`/`readState`/`writeState` replace
     `readRegistry`/`writeRegistry`, same atomic-write behavior
     (temp-file + rename) as before.
   - On read, if `schemaVersion` is missing or doesn't match the current
     constant, throw a clear error naming the file and both versions —
     don't silently coerce or ignore a version mismatch (there's no
     migration logic yet; that's a future task once a real format change
     happens, but the *detection* must exist from the start).
6. Update `src/domain/registry.test.ts` for the new split (manifest vs
   state, round-trip each independently, schemaVersion mismatch throws).

**Verification**: `npm run typecheck && npm run lint && npm test` all
pass, with tests covering: the `ResolvedRevision` round-trip through a
real git-custom resolve (reuse `gitCustom.test.ts`'s existing repo
fixture, add an assertion on the real resolved commit SHA), the new
`resolveArtifactContent` function actually reading real file content
back for both resolvers, manifest/state read/write round-trips, and a
schemaVersion-mismatch throw. One commit containing all the edited/new
files listed above — nothing else. After this commit, update
`tasks/00-INDEX.md` to reflect this task's completion.
