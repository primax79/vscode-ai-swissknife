# 02.1 — Core domain types

> Part of [Domain types + registry store](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md)

**Goal**: define every core entity from the spec as TypeScript
interfaces/types in `src/domain/types.ts` — interfaces only, no functions,
no I/O, no logic.

**Grounding**: `SPEC.md` §1 "Domain model" (repo root, one level up from
`tasks/`) is the authoritative source for every field below — read it in
full before writing any type; don't invent fields it doesn't mention, and
don't drop fields it does mention because they're not used by Phase 1's
adapters yet (e.g. `Package.nativeFormat` is needed by the domain model
even though this Phase's adapters barely touch it).

Steps:

1. Create `src/domain/types.ts` with:
   - `type AssistantId = 'claude-code' | 'kilo-code' | 'github-copilot' |
     'codex-cli' | 'gemini-cli';` — a string union, not an enum (matches
     SPEC.md §1's extensibility note; new assistants are added by
     extending the union, not by a runtime registry in this task).
   - `type Scope = 'global' | 'project';`
   - `type ItemKind = 'skill' | 'agent' | 'command' | 'mcp-server' |
     'rule' | 'hook';` — all 6, per this initiative's shared decision (see
     `plan.md`), even though only `skill`/`rule` are implemented this
     Phase.
   - `type SourceType = 'git-custom' | 'git-marketplace' | 'local-folder'
     | 'remote-url' | 'git-single-item';`
   - `interface Source { id: string; type: SourceType; scope: Scope;
     projectPath?: string; url?: string; localPath?: string; branch?:
     string; tag?: string; commit?: string; name?: string; }` — `url`/
     `localPath` are mutually exclusive depending on `type`; `branch`/
     `tag`/`commit` are the `git-custom` pin (SPEC.md §1). `projectPath`
     is set only when `scope === 'project'` (SPEC.md's "a project-level
     Source must never leak into other workspaces").
   - `interface Package { id: string; sourceId: string; version?: string;
     nativeFormat: string; artifacts: Artifact[]; }` — `nativeFormat` is a
     free-form string tag like `"claude-plugin"`/`"kilo-skill-dir"`, not
     an enum yet (don't over-constrain it in this task; a later
     initiative may tighten it once more formats are implemented).
   - `interface Artifact { id: string; packageId: string; kind: ItemKind;
     name: string; description?: string; nativeFormat: string; }`.
   - `interface ObservedArtifact { assistant: AssistantId; scope: Scope;
     projectPath?: string; kind: ItemKind; name: string; path: string;
     discoveredAt: string; }` — `discoveredAt` an ISO timestamp string.
   - `interface ManagedInstallation { assistant: AssistantId; scope:
     Scope; projectPath?: string; kind: ItemKind; name: string; path:
     string; sourceId?: string; packageId?: string; artifactId?: string;
     installedVersion?: string; installedAt: string; contentHash?:
     string; }` — `contentHash` is what SPEC.md §3.6 calls "a hash/snapshot
     saved at apply time" for later drift detection; populate the field
     now even though nothing computes drift yet (Phase 3).
   - `type ConversionDiagnostic = 'lossless' | 'adapted-with-warning' |
     'potentially-destructive' | 'unsupported';` (SPEC.md §2/§4).
   - Do **not** define `DesiredManifest` or `LocalState` in this task —
     SPEC.md §1 defines them conceptually but nothing in Phase 1 reads or
     writes them yet (they're `.ai-toolkit/registry.json`'s
     shareable-vs-machine-local split, relevant once sync/team workflows
     land in a later phase). Adding unused types now would just be dead
     weight; a later initiative introduces them alongside their first real
     consumer.
2. Export every type/interface above from `src/domain/types.ts` (no
   default export; named exports only).
3. Run `npm run typecheck` — it must pass with zero errors (nothing
   imports this file yet, so this just confirms the file itself is
   syntactically and structurally valid TypeScript).

**Verification**: `npm run typecheck` and `npm run lint` both exit 0.
Diff review: every field in the file traces to a specific sentence in
`SPEC.md` §1 — if you added a field that isn't there, remove it or justify
it in the commit message. One commit containing only
`src/domain/types.ts`.
