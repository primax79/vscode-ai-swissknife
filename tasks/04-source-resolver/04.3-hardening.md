# 04.3 — Resolver diagnostics, shared Git lock, and portable fixtures (hardening)

> Part of [Source resolver](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · accepted review decisions: [round 001](../_reviews/001-hardening-gate-SUMMARY.md) and [round 002](../_reviews/002-hardening-gate-SUMMARY.md), especially decisions 4, 8, and 12. Requires 02.3 and 03.4.

## Goal

Make resolver output diagnostic-bearing and deterministic, prove that Git listing and content reads share one critical section, and replace machine-specific live tests with committed provenance-tracked fixtures.

This task must produce one commit containing only its changes.

## Grounding

Re-`rg` all callers of `findSkillDirs`, `resolveLocalFolder`, `resolveGitCustom`, and `resolveArtifactContent`. Extend the `SkillDetectionResult` and shared mutex introduced by 03.4/02.3 rather than defining parallel contracts.

## Steps

1. Define `SourceResolution { packages: Package[]; diagnostics: DetectionDiagnostic[] }` in `src/sources/types.ts`, ensuring `DetectionDiagnostic` usage matches the concrete type defined in 03.4. `resolveLocalFolder()` and `resolveGitCustom()` return `Promise<SourceResolution>`. They map valid detections to packages and pass diagnostics unchanged. A source with only malformed candidates resolves to empty packages plus diagnostics; transport failures still reject.

2. Keep skill content APIs typed as `Promise<ResolvedArtifact<CanonicalSkill>>`. Do not add `unknown` defaults or casts.

3. Reuse the one per-cache-directory mutex exported by `gitCustom.ts` in 02.3. `resolveGitCustom()` holds it for clone/fetch/checkout plus detection. `resolveArtifactContent()` holds it for checkout of `pkg.version.commit` plus the entire `readSkill()` call. Structure unlocked internal helpers if needed to avoid re-entrant deadlock. There must be one lock map keyed by canonical cache directory.

4. Ensure each Git package records `version.commit` as the actual checked-out SHA and `version.requestedRef` as source intent. Use the field name `requestedRef` exclusively.

5. Add `src/sources/__fixtures__/` with small committed examples derived from real workspace skills. Include provenance in a README: original repository/path and capture date, with copied content reviewed for secrets/licensing. Cover root skill, nested skills, auxiliary files, and one malformed candidate beside a valid one. For Git tests, copy fixture content into a temporary directory and initialize/commit two revisions/refs at test runtime; do not try to commit a nested `.git` directory as a fixture.

6. Remove tests whose correctness depends on `~/.claude/skills`, a user name, an absolute `/Users/...` path, live network state, or a mutable skill count. Live sources may remain optional manual smoke tests, never the required suite.

## Verification

- Run the full test suite, typecheck, lint, and build.
- Assert valid packages and diagnostics travel together through both resolver types.
- Run two concurrent `resolveGitCustom()` calls for different refs and prove deterministic results.
- Interleave `resolveGitCustom()` for ref B while `resolveArtifactContent()` reads ref A; prove content A cannot be switched mid-read.
- Assert typed canonical content, actual commit SHA, and `requestedRef` from the committed Git fixture.
- Run the suite with an empty temporary home directory to prove no test depends on personal state.

## Non-goals

- No network-backed fixture in the mandatory suite.
- No new source types.
- No UI rendering; task 07.2 consumes diagnostics.
