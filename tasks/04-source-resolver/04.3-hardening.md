# 04.3 — Resolver hardening + portable fixtures (hardening)

> Part of [Source resolver](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · hardening context: [../../SPEC.md](../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) findings B7, I1, I3

**Goal**: close three gaps a second review found in the already-merged
resolvers (`src/sources/detect.ts`, `localFolder.ts`, `gitCustom.ts`):
the tests aren't portable (depend on live, mutable, machine-specific
state), dot-directory scanning skips legitimate skill layouts, and
concurrent git operations on the same cache dir have no lock.

**Depends on**: task 02.3 (uses `resolveArtifactContent`/
`ResolvedRevision` it introduces — read that task file first if it
hasn't landed yet, don't duplicate those changes here).

Steps:

1. **Fix dot-directory scanning.** `findSkillDirs` (`src/sources/
   detect.ts`) currently skips every directory whose name starts with
   `.`. Change it to skip only `.git` and, if a caller-supplied ignore
   list is added, whatever that list names — but **descend into**
   directories like `.claude/`, `.agents/`, `.github/` (these are
   legitimate skill-layout roots per SPEC.md §1, and a `git-custom`
   source is likely to have one of these at its root). Add a test
   fixture (see step 3) with a `.claude/skills/<name>/SKILL.md` layout
   and confirm it's now found.
2. **Add a per-cache-dir lock for git operations.** In
   `src/sources/gitCustom.ts`, add a simple in-process mutex keyed by the
   resolved cache directory path (a `Map<string, Promise<void>>` chaining
   pattern is enough — no need for a cross-process file lock in this
   Phase) so two concurrent `resolveGitCustom` calls against the same
   `Source` serialize their `git fetch`/`checkout` instead of racing.
   Add a test that fires two concurrent `resolveGitCustom` calls at the
   same source and confirms both complete successfully with a consistent
   final state (not that they ran literally sequentially — just that
   there's no corruption/error from the race).
3. **Replace the live-home-directory-dependent test with a committed
   fixture corpus.** The current `detect.test.ts`/`localFolder.test.ts`
   assert an exact count of 25 against `~/.claude/skills/` on this
   machine — this breaks for any other contributor, in CI, or the next
   time a skill is added/removed here. Create
   `src/sources/__fixtures__/` (committed to git, **not** gitignored —
   check this doesn't collide with anything in the root `.gitignore`,
   which currently only ignores `references`) with:
   - `__fixtures__/single-skill/SKILL.md` — a minimal one-skill repo
     root (adapt real content from
     `agentic-coding-kit/plugins/common-tools/skills/gitignore/
     SKILL.md`, trimmed, with a comment noting its real provenance).
   - `__fixtures__/plugin-nested/plugins/demo/skills/example/SKILL.md`
     — the nested `plugins/<x>/skills/<y>/` shape (adapt from
     `references/cc-swiss-knife/plugins/core/skills/
     documentation-standards/SKILL.md`, same provenance-comment
     convention).
   - `__fixtures__/dotdir-layout/.claude/skills/example/SKILL.md` — the
     dot-directory layout this task's step 1 fixes detection for.
   - `__fixtures__/with-resources/example/SKILL.md` +
     `__fixtures__/with-resources/example/scripts/run.sh` — a skill with
     a supporting file, for task 03.4's directory-payload work to also
     exercise via this same fixture set (03.4 can point its own tests at
     this fixture too — don't invent a second one there).
   - `__fixtures__/invalid/` — at least one deliberately malformed case
     (a `SKILL.md` with no frontmatter, and a skill-looking directory
     whose "name" in frontmatter contains a path separator) for the
     validation logic (task 03.4 step 3) to have something real to
     reject.
   Rewrite `detect.test.ts`/`localFolder.test.ts` to assert against these
   committed fixtures (exact, computed-by-hand-once counts, same
   discipline as before) instead of `~/.claude/skills/`,
   `agentic-coding-kit/...`, or `references/cc-swiss-knife/...`. The
   *concept* of "ground tests in real, provenance-tracked artifacts"
   stays — only the *portability* problem (uncommitted, mutable,
   machine-specific) is fixed.
4. Keep one narrow exception if useful: an **optional** integration test
   that still points at a live workspace repo (e.g.
   `agentic-coding-kit/...`), guarded so it only runs when an environment
   variable like `AI_SWISSKNIFE_RUN_LIVE_FIXTURE_TESTS=1` is set — never
   part of the default `npm test` gate. State in your report whether you
   added this or judged it unnecessary.

**Verification**: `npm run typecheck && npm run lint && npm test` all
pass using **only the committed fixtures** by default (confirm by running
the test suite in a way that doesn't depend on `~/.claude/skills/`
existing at all — e.g. temporarily rename it and re-run, then restore it,
or just don't reference `os.homedir()` anywhere in the new test code and
grep to confirm). One commit containing the new fixtures and the rewritten
test files, plus the `detect.ts`/`gitCustom.ts` source changes — nothing
else. After this commit, update `tasks/00-INDEX.md`.
