# 29.5 — "Configure enabled assistants" command

> Part of [Adapter registry & config](plan.md) · spec: [../specs/adapter-and-source-registries.md](../specs/adapter-and-source-registries.md) §4.5

## Goal

A discoverable command-palette entry point for 29.4's setting — the note's
literal "menu di configurazione" ask — so a user doesn't need to know the
setting's exact id to find it in the Settings UI.

This task must produce one commit containing only its changes.

## Steps

1. Add `aiSwissknife.configureEnabledAssistants` to `package.json`'s
   `contributes.commands` (title e.g. "Configure Enabled Assistants...",
   icon `$(gear)` or similar — pick something not already used by another
   command in the same list, check `grep -n '"icon"' package.json` first),
   `category: "AI Swissknife"` matching every other command in that list.
2. Register it in `src/extension.ts` alongside the other command
   registrations, calling a new handler (co-locate in
   `src/adapters/registry.ts` or a small dedicated function — match
   whichever existing pattern this file already follows for its simplest
   handlers, e.g. `addSource`'s handler shape).
3. Handler: read the currently-enabled set via `getEnabledAdapters()`
   (29.4), show
   `vscode.window.showQuickPick(ALL_ADAPTERS.map(a => ({ label: a.displayName, picked: enabledIds.includes(a.assistant) })), { canPickMany: true, placeHolder: 'Select which assistants to enable' })`,
   and if the user didn't cancel, write the resulting ids back via
   `vscode.workspace.getConfiguration('aiSwissknife').update('enabledAssistants', selectedIds, vscode.ConfigurationTarget.Global)`.
   Do not write anything if the QuickPick returns `undefined` (user
   pressed Escape) — same "no-op on dismiss" convention every other
   command in this codebase already follows (`tasks/CONTEXT.md`'s "zero
   mutation on every dismissed UI path" hardening decision).
4. `ConfigurationTarget.Global` (user scope), not `Workspace` — matches the
   spec's Non-goals (no per-project override in this pass).

## Verification

- Run full test suite, typecheck, lint, build.
- Unit test: mock `showQuickPick` to return a specific subset, invoke the
  command handler, assert `workspace.getConfiguration().update` was called
  with exactly that subset and `ConfigurationTarget.Global`; mock
  `showQuickPick` to return `undefined`, assert `update` was **not**
  called.
- Manually in the Extension Development Host: run "AI Swissknife: Configure
  Enabled Assistants..." from the command palette, confirm the picker
  pre-checks the currently-enabled assistants using their real display
  names (not raw ids), toggle a selection, confirm the corresponding
  sidebar section appears/disappears exactly as it does when changed
  directly through Settings (29.4's manual check).
