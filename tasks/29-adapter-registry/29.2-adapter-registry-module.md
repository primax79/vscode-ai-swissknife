# 29.2 — `src/adapters/registry.ts`

> Part of [Adapter registry & config](plan.md) · spec: [../specs/adapter-and-source-registries.md](../specs/adapter-and-source-registries.md) §4.2

## Goal

One new module that is the single source of truth for "all known
adapters" and "look one up by id" — the thing that lets every later task
delete a duplicated literal array or `if`-chain instead of hand-maintaining
one more copy.

This task must produce one commit containing only its changes. It must
**not** yet touch any of the duplicated call sites listed in the spec §0/§5
— that is task 29.3. This task only adds the new module and its own unit
tests.

## Steps

1. Create `src/adapters/registry.ts` exporting:
   - `ALL_ADAPTERS: readonly Adapter[]` — an array literal of the five
     existing singletons (`claudeAdapter`, `kiloAdapter`, `copilotAdapter`,
     `codexAdapter`, `geminiAdapter`), imported from their real modules
     (`../adapters/claude`, `./kilo`, `./copilot`, `./codex`, `./gemini` —
     confirm the exact singleton export names via
     `grep -n "^export const" src/adapters/*.ts` first, do not assume).
   - `getAdapter(id: AssistantId): Adapter` — finds the matching entry in
     `ALL_ADAPTERS`, throws `` `Unsupported assistant: ${id}` `` if none
     (matches the existing error message the four duplicated `getAdapter`
     functions already throw, so no caller-visible message changes when
     29.3 migrates them).
   - `getAdapterWithHomeRoot(id: AssistantId, homeRoot: string): Adapter`
     — replaces the "construct a fresh instance with an overridden home
     root" branch of the four duplicated functions
     (`src/engine/discovery.ts:41-55`, `drift.ts:33-46`, `sync.ts:36-49`,
     `src/ui/formEditor.ts`). **Before writing this**, open all four and
     confirm each adapter class's constructor really does accept
     `(homeRootFn: () => string)` identically — the spec's §4.2 sketch
     assumes this holds but flags it as unverified; if any class's
     constructor differs, use whatever construction each real class
     actually needs (e.g. a small per-assistant `switch`/lookup table
     inside this one function is fine — the goal is one implementation of
     this mapping, not zero branching anywhere).
2. Do not modify `src/adapters/types.ts` or any of the five adapter class
   files in this task (that was 29.1, already done).
3. Add `src/adapters/registry.test.ts` (co-located, matching this
   project's existing `*.test.ts` convention, e.g.
   `src/adapters/claude.test.ts`):
   - `ALL_ADAPTERS.length === 5` and contains exactly the five expected
     `assistant` ids, no duplicates.
   - `getAdapter('claude-code') === claudeAdapter` (identity, not just
     equality — confirms it returns the real singleton, not a new
     instance) for at least two of the five ids.
   - `getAdapter('bogus' as AssistantId)` throws with a message containing
     `Unsupported assistant`.
   - `getAdapterWithHomeRoot('kilo-code', '/some/fake/home')` returns an
     adapter whose `assistant === 'kilo-code'` and which is **not** the
     same object as `kiloAdapter` (confirms it constructed a fresh,
     home-root-scoped instance rather than returning the singleton).

## Verification

- Run full test suite, typecheck, lint, build — the new `registry.test.ts`
  must pass alongside the existing suite (238+ tests as of 2026-09-08,
  re-check the actual current count via `npm test`'s own summary line
  rather than trusting this number).
- `grep -rn "src/adapters/registry" src --include="*.ts"` should show only
  this task's own new files importing/exporting it — no other file
  references it yet (that's 29.3).
