# 07.3 — Installed view (registry-backed) (revised)

> Part of [Minimal UI](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · revised per [../../SPEC.md](../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) finding I12

**This supersedes an earlier version of this task file** only in that it
now reads the split state file (02.3) instead of the original combined
registry, and exposes a refresh hook 07.2 calls after a successful
install.

**Goal**: a tree view listing every `ManagedInstallation` from the state
file, grouped by assistant × scope, with a way for 07.2 to trigger a
refresh after installing something.

**Grounding**: `src/domain/registry.ts`'s `readState` (02.3, not the
older `readRegistry`); `src/ui/sourcesView.ts` (07.1) for the established
pattern.

Steps:

1. Add to `package.json`'s `contributes.views["ai-swissknife"]`:
   `{ "id": "aiSwissknife.installed", "name": "Installed" }`.
2. Create `src/ui/installedView.ts`:
   - `vscode.TreeDataProvider` reading `readState` (both global +
     project). Top level = one node per `(assistant, scope)` pair
     actually present, children = its `ManagedInstallation`s (label =
     name, description = kind, tooltip = `installedAt` +
     `sourceRevision`'s commit if present).
   - Expose a `refresh(): void` method that fires
     `onDidChangeTreeData` — this is what 07.2 calls after a successful
     `applyInstall`. Export the provider instance (or a small accessor)
     from wherever `src/extension.ts` constructs it so 07.2's command
     handler can reach it; don't make 07.2 re-read the state file itself
     just to trigger a UI refresh.
3. Register the provider in `src/extension.ts`.
4. Same activation-verification discipline as prior tasks.

**Verification**: `npm run lint && npm run typecheck && npm run build`
all exit 0. One commit containing the `package.json` change and
`src/ui/installedView.ts` — nothing else. After this commit, update
`tasks/00-INDEX.md`'s row for initiative `07` to `✅ done` — this
completes the hardened Phase 1 vertical slice end to end. Also verify,
as a final integration check if an Extension Development Host is
reachable in your environment: register a `git-custom` source pointing
at a small real repo, refresh the catalog, install one skill to Claude
Code at project scope, and confirm it appears in the Installed view. If
an Extension Development Host genuinely isn't reachable in your
environment, say so plainly rather than skipping this note.
