# 07.3 — Installed view (registry-backed)

> Part of [Minimal UI](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md)

**Goal**: a tree view listing every `ManagedInstallation` from the
registry, grouped by assistant × scope (SPEC.md §3.1 "respond to 'what do
I have installed where' at a glance").

**Grounding**: `src/domain/registry.ts` (initiative 02.2) for
`readRegistry`; `src/ui/sourcesView.ts` (task 07.1) for the established
pattern of a registry-backed `TreeDataProvider` in this codebase — follow
the same structure, don't invent a different one for no reason.

Steps:

1. Add to `package.json`'s `contributes.views["ai-swissknife"]`:
   `{ "id": "aiSwissknife.installed", "name": "Installed" }`.
2. Create `src/ui/installedView.ts`:
   - A `vscode.TreeDataProvider` with a two-level tree: top level = one
     node per `(assistant, scope)` pair actually present in either
     registry (global + project, merged) — e.g. "Claude Code (global)",
     "Kilo Code (project)" — only show pairs that have at least one
     installation, don't pre-list all 5×2 combinations speculatively.
   - Children = the `ManagedInstallation`s under that pair, label =
     `installation.name`, description = `installation.kind`, tooltip
     showing `installedAt` and `installedVersion` if present.
3. Register the provider in `src/extension.ts`.
4. Same activation-verification caveat as tasks 07.1/07.2.

**Verification**: `npm run lint && npm run typecheck && npm run build`
all exit 0. One commit containing the `package.json` change and
`src/ui/installedView.ts` — nothing else. After this commit, update
`tasks/00-INDEX.md`'s row for initiative `07` to `✅ done` — this
completes Phase 1 (SPEC.md §6) end to end; also add a short note at the
top of `tasks/00-INDEX.md` that Phase 1 is complete and Phase 2/3 specs
are the next planning step (don't write those specs yourself in this
task — just flag that they're next).
