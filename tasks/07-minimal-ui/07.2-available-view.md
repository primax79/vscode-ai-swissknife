# 07.2 — Available view, diagnostics, preview, and explicit install gate

> Part of [Minimal UI](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · accepted review decisions: [round 001](../_reviews/001-hardening-gate-SUMMARY.md) and [round 002](../_reviews/002-hardening-gate-SUMMARY.md), especially decisions 5, 12, 14, and 18. Requires 04.3, 06.1, and 06.2.

## Goal

Render the real resolver catalog with diagnostics and retain enough identity at every leaf to prepare and apply exactly one approved install. No dismissal path may mutate disk.

This task must produce one commit containing only its changes.

## Grounding

Read `SourceResolution`, `PreparedInstall`, `ApplyOutcome`, and the reusable workspace picker from 07.1. Re-`rg` all resolver and install-engine callers before wiring commands.

## Steps

1. Add a plain Available `TreeDataProvider`. `refreshCatalog` loads runtime sources from global/selected-project manifests, calls `resolveLocalFolder`/`resolveGitCustom`, and caches each leaf as the complete identity tuple `{ source, package, artifact }`. Do not retain only `Artifact`; planning needs `Package.version` and source identity.

2. Preserve and display `SourceResolution.diagnostics`. Attach diagnostics to their source/package group when possible, show warning/error icons and tooltips, and make a source with zero valid packages but diagnostics visible rather than disappearing.

3. The Install command obtains the cached `{ source, package, artifact }`, asks for target assistant/scope/workspace where needed, and calls `planInstall()` once. Unsupported plans show their reason and stop: no modal approval and no `applyInstall()`.

4. Show a modal preview containing target, scope, revision, file additions/replacements, conflict state, and translation diagnostics. The user must explicitly choose Install.

5. When a conflict exists, prompt for conflict policy. Phase 1's mutating policy may only replace paths present in the proposed payload. If the quick-pick returns `undefined` (Escape/dismiss) or Cancel, abort. Never default a dismissed picker to overwrite.

6. Pass the **same unchanged `PreparedInstall` object** returned by planning to `applyInstall()` exactly once after all approvals. Do not reconstruct content or recompute a hash in the UI.

7. Render every `ApplyOutcome` honestly:

   - `applied`: success plus any cleanup warnings;
   - `refused`: no-change explanation;
   - `rolled-back`: failure with proven restoration;
   - `manual-recovery-required`: prominent error listing recovery paths.

   Refresh Available and Installed views after `applied`; do not claim success for other statuses.

## Verification

- Run the full test suite, typecheck, lint, and build.
- Resolver diagnostics appear even when no valid artifact exists.
- Cached leaves retain Source + Package + Artifact and pass the correct package revision into planning.
- Behavioral spies prove: explicit Install calls `applyInstall` exactly once; modal Cancel calls it zero times; dismissed modal calls it zero times; dismissed conflict-policy picker calls it zero times; unsupported plan shows no modal and calls it zero times.
- Assert the exact `PreparedInstall` object identity reaches apply.
- Test UI messages/refresh behavior for all four outcome statuses.

## Non-goals

- No webview, bulk install, uninstall, merge conflict policy, or background auto-refresh.
- No mutation during catalog refresh or preview.
