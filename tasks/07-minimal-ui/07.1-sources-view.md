# 07.1 — Activity Bar container + Sources view

> Part of [Minimal UI](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md)

**Goal**: an Activity Bar container with a "Sources" tree view listing
registered `Source`s (from the registry, initiative 02), plus commands to
add/remove one.

**Grounding**: `references/agent-hub/package.json`'s
`contributes.viewsContainers`/`contributes.views` for the real shape of
this declaration (adapt, don't copy verbatim — different ids/titles).

Steps:

1. Edit `package.json`'s `contributes` block to add:
   ```json
   "viewsContainers": {
     "activitybar": [
       { "id": "ai-swissknife", "title": "AI Swissknife", "icon": "$(extensions)" }
     ]
   },
   "views": {
     "ai-swissknife": [
       { "id": "aiSwissknife.sources", "name": "Sources" }
     ]
   }
   ```
   Use a built-in codicon (`$(extensions)` or similar — check
   `/api/references/icons-in-labels` conventions if you have the local
   VSCode docs mirror at `references/vscode_doc/` available, otherwise
   any reasonable built-in codicon id) rather than a custom icon asset —
   no icon file exists in this repo yet and adding one is out of scope
   here.
2. Add to `contributes.commands`:
   `aiSwissknife.addSource`, `aiSwissknife.removeSource`,
   `aiSwissknife.refreshSources` (titles: "Add Source", "Remove Source",
   "Refresh Sources", category "AI Swissknife").
3. Create `src/ui/sourcesView.ts`:
   - A class implementing `vscode.TreeDataProvider<Source>` (import
     `Source` from `../domain/types`) that reads the registry (both
     global and project scope — merge the two lists, tag each tree item
     with its scope so it's visible in the label, e.g. `"[global] "`/
     `"[project] "` prefix) via `readRegistry` (`../domain/registry`).
   - `getTreeItem`: label = `source.name ?? source.id`, description =
     `source.type`, contextValue = `source.scope` (used later for
     right-click menu scoping, not needed yet but costs nothing to set
     now).
   - Register the provider in `src/extension.ts`'s `activate()` via
     `vscode.window.registerTreeDataProvider('aiSwissknife.sources',
     provider)`.
4. Implement the three commands in `src/extension.ts` (or a new
   `src/ui/commands.ts` if that's cleaner — your choice, keep
   `extension.ts` from becoming a dump of unrelated logic):
   - `addSource`: prompt via `vscode.window.showInputBox` for a git URL or
     local path, then `showQuickPick` for scope (`global`/`project` —
     disable/omit `project` if `vscode.workspace.workspaceFolders` is
     empty, per `plan.md`'s shared decision), construct a `Source` with
     `type: 'git-custom'` if the input looks like a URL (starts with
     `http`/`git@`) or `'local-folder'` otherwise, append it to the
     registry via `readRegistry`/`writeRegistry`, then refresh the view.
   - `removeSource`: prompt via `showQuickPick` listing current sources,
     remove the selected one from the registry, refresh.
   - `refreshSources`: just re-fire the tree data provider's
     `onDidChangeTreeData` event — no network/git operation yet (that's
     what "refresh catalog", a different concern, would do; this command
     only re-reads the registry file in case it changed on disk).
5. Manually verify in this environment as best you can (per task 01.2's
   precedent): if you cannot launch a real Extension Development Host,
   verify via `npm run typecheck && npm run lint && npm run build`
   and say so explicitly — do not claim to have visually confirmed the
   tree view rendering if you did not.

**Verification**: `npm run lint && npm run typecheck && npm run build`
all exit 0; `package.json`'s new `contributes` block is valid JSON
matching the schema shape above. One commit containing the `package.json`
change, `src/ui/sourcesView.ts`, and the command wiring (in
`src/extension.ts` or `src/ui/commands.ts`) — nothing else.
