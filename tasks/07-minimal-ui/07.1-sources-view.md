# 07.1 — Activity Bar container + Sources view (revised)

> Part of [Minimal UI](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · revised per [../../SPEC.md](../../SPEC.md) §7, [../_inbox/analyzed/codex-analysis-2.md](../_inbox/analyzed/codex-analysis-2.md) findings I4, I5, I6

**This supersedes an earlier version of this task file.** Corrections
from the second review: the "Refresh Sources" command name/behavior was
misleading (it only reloaded the registry, not the catalog — real
fetching happens in 07.2), multi-root workspaces were reduced to
`workspaceFolders[0]` with no way to pick, and removing a source didn't
check for installations that reference it.

**Goal**: an Activity Bar container with a "Sources" tree view listing
registered `Source`s (from 02.3's manifest file), plus commands to
add/remove one, with the corrections above.

**Grounding**: `references/agent-hub/package.json`'s
`contributes.viewsContainers`/`contributes.views` for the real shape;
`src/domain/registry.ts`'s `readManifest`/`writeManifest` (02.3, not the
older `readRegistry`/`writeRegistry` — those no longer exist after
02.3).

Steps:

1. **Create a placeholder icon asset first** — `resources/icon.svg`, a
   minimal single-color SVG (a filled square or simple shape is fine,
   this is a placeholder, not final branding). **Resolved by two
   independent reviewers in multi-engine review round 001**
   ([../_reviews/001-hardening-gate-SUMMARY.md](../_reviews/001-hardening-gate-SUMMARY.md)):
   `viewsContainers.activitybar[].icon` requires a path to a real SVG/
   PNG asset file, **not** a codicon reference string like
   `$(extensions)` (codicon strings are valid in several *other*
   VSCode contribution points, e.g. individual command/view icons, but
   not this one) — don't re-litigate this, just create the asset.
2. Edit `package.json`'s `contributes` block to add:

   ```json
   "viewsContainers": {
     "activitybar": [
       { "id": "ai-swissknife", "title": "AI Swissknife", "icon": "resources/icon.svg" }
     ]
   },
   "views": {
     "ai-swissknife": [
       { "id": "aiSwissknife.sources", "name": "Sources" }
     ]
   }
   ```

3. Add to `contributes.commands`: `aiSwissknife.addSource`,
   `aiSwissknife.removeSource`, `aiSwissknife.reloadRegistry` (**not**
   "Refresh Sources" — that name is reserved for 07.2's real
   fetch/resolve action; this command only re-reads the manifest file
   from disk in case it changed externally, title "Reload Registry",
   category "AI Swissknife").
4. Create `src/ui/sourcesView.ts`:
   - A class implementing `vscode.TreeDataProvider<Source>` reading
     `readManifest` (02.3) for both global and project scope, merged,
     each tagged with its scope in the label (`"[global] "`/
     `"[project] "` prefix).
   - `getTreeItem`: label = `source.name ?? source.id`, description =
     `source.type`, contextValue = `source.scope`.
   - Register via `vscode.window.registerTreeDataProvider(...)` in
     `src/extension.ts`.
5. Implement the commands:
   - `addSource`: prompt for URL/path + scope (`showQuickPick`), same
     `git-custom` vs `local-folder` type inference as before. **Scope
     picker for `project`**: if `vscode.workspace.workspaceFolders` has
     more than one entry, prompt with `showQuickPick` over the folder
     names to choose which one — do not default to `[0]` silently. If
     there are zero folders, disable/omit the `project` option entirely.
   - `removeSource`: before removing, read the **state file** (02.3) for
     both scopes and check whether any `ManagedInstallation` references
     the source being removed (via `sourceId`). If any do, warn the user
     with the count and ask for explicit confirmation
     (`showWarningMessage` with "Remove Anyway"/"Cancel" actions) before
     proceeding — removing a source must never silently orphan/destroy
     provenance for installations that reference it. This Phase does not
     need a "detach installed items" UI flow beyond this confirmation;
     the installations simply keep a `sourceId` that no longer resolves
     to a registered `Source`, which is an acceptable, visible state (a
     later Phase can add cleanup tooling).
   - `reloadRegistry`: re-fire `onDidChangeTreeData` after re-reading the
     manifest — no network/git operation (see the naming correction
     above).
6. Same activation-verification discipline as prior tasks: state
   explicitly in your report whether you launched a real Extension
   Development Host or only verified build/lint/typecheck, and don't
   claim otherwise.

**Verification**: `npm run lint && npm run typecheck && npm run build`
all exit 0; the `viewsContainers.activitybar[].icon` question from step 1
is answered with a citation (docs page or schema), not assumed. One
commit containing the `package.json` change, `src/ui/sourcesView.ts`, and
the command wiring — nothing else.
