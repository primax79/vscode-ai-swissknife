# 07.1 — Activity Bar container and Sources view

> Part of [Minimal UI](plan.md) · spec: [../specs/foundations.md](../specs/foundations.md) · accepted review decisions: [round 001](../_reviews/001-hardening-gate-SUMMARY.md) and [round 002](../_reviews/002-hardening-gate-SUMMARY.md), especially decisions 7 and 13. Requires 02.3.

## Goal

Add the shared Activity Bar container and a registry-backed Sources tree that correctly converts portable manifest sources to runtime sources, handles multi-root workspaces, and prevents accidental removal of source-backed desired state.

This task must produce one commit containing only its changes.

## Grounding

Read the actual `ManifestFile`, `DesiredSource`, conversion helpers, `StateFile`, and current VS Code contribution manifest. Re-`rg` all registry callers before editing.

## Steps

1. Contribute one Activity Bar container with id `ai-swissknife` and a plain `TreeDataProvider` Sources view. Do not create a webview.

2. Provide one reusable workspace-folder picker for all project-scope UI. With multiple roots, prompt; with one, select it; with zero, disable project actions. Never silently use `workspaceFolders[0]`.

3. Load global and selected-project manifests with `readManifest()`. Convert each `DesiredSource` through `fromDesiredSource(desired, workspaceRoot?)` before passing it to runtime resolver/UI logic. Display scope and source type without exposing machine-local credentials.

4. Add source commands using the portable boundary:

   - Add creates a runtime `Source`, converts it with `toDesiredSource()`, and writes the manifest atomically.
   - Edit preserves stable source id and converts again before persistence.
   - `reloadRegistry` only re-reads files from disk; it performs no Git/network refresh.

5. Before removal, inspect both:

   - `StateFile.installations` whose `sourceId` matches; and
   - `ManifestFile.desiredInstallations` whose `sourceId` matches.

   If either exists, show counts and require explicit confirmation. **Locked behavior:** “Remove Anyway” atomically removes the source and its dependent `desiredInstallations` from that same manifest. It does not uninstall files and does not delete machine-local `ManagedInstallation` records; those remain as visible orphaned installations until a later explicit uninstall/reconciliation feature. Cancel/dismiss changes nothing.

6. Refresh the view after successful writes and surface read/write/schema/path errors through VS Code messages plus a testable provider error state.

## Verification

- Run the full test suite, typecheck, lint, and build.
- Test zero/one/multiple workspace roots and reuse the picker from later views.
- Persisting a project local-folder source produces a relative `DesiredSource`; reopening under another workspace root reconstructs the runtime path there.
- Removal checks both state installations and desired installations.
- Confirmed removal deletes the source and dependent desired entries but leaves installed files/state untouched; cancel/dismiss leaves everything untouched.
- `reloadRegistry` performs no resolver/network call.

## Non-goals

- No catalog resolution; task 07.2 owns `refreshCatalog`.
- No uninstall or orphan reconciliation.
- No secrets UI.
